ISSUE-007 · 2026-07-30

초기 6D pose를 temporal tracking의 첫 상태로 연결했다.

물체를 한 장면에서 처음 찾는 일과 이후 frame에서 같은 물체를 계속 따라가는 일은 역할이 다르다. BeltBench는 FoundationPose가 만든 robot-base 좌표계의 초기 pose를 GoTrack 입력으로 자동 변환하고, tracking 결과를 다시 공통 pose 기록으로 되돌린다.

두 단계의 역할

초기화: 무엇이 어디에 있나?

RGB, metric depth, object mask, camera intrinsic, camera-to-base extrinsic을 함께 사용한다. 각 camera의 추정을 robot base 좌표계로 옮겨 여러 view의 초기 pose를 합친다.

tracking: 다음 순간에도 같은 물체인가?

초기 pose에서 mesh를 렌더링하고 이전·현재 RGB의 대응점을 추적한다. 여러 camera anchor를 3D로 삼각측량한 뒤 rigid transform을 맞춘다.

구현한 데이터 흐름

scene manifest → FoundationPose → base-frame initial poses.jsonl; scene adapter → RGB/mask video + camera_from_base + initial pose records; GoTrack anchor tracking → world pose records → BeltBench tracking poses.jsonl

base_from_camera는 camera 좌표의 점을 robot base로 옮기는 변환이고, GoTrack이 요구하는 camera_from_base는 그 역변환이다. adapter가 이를 계산하므로 사람이 행렬 방향을 바꿔 적지 않는다.

검증한 범위

두 camera 합성 scene으로 adapter를 실행한 뒤, GPU에서 GoTrack checkpoint와 anchor renderer를 실제로 load하고 한 frame을 처리했다. 마지막으로 tracker world pose record를 append-only pose artifact로 import했다. 합성 image에는 실제 물체 특징이 없으므로 유효 pose를 기대하지 않는 구조 검증이다.

다음 실제 검증: 같은 timestamp의 RGB·metric depth·object mask와 새 calibration 결과를 manifest에 넣어, robot motion 없이 offline 초기화·tracking을 실행한다.

재현성과 안전

모든 결과 run은 기존 directory를 덮어쓰지 않는다. raw image, camera ID, calibration 수치, device 경로는 private storage에만 둔다. 공개 기록에는 일반화 가능한 구조와 검증 범위만 남긴다.

two-camera observation과 extrinsic·hand-eye calibration, GPU runtime이 이 단계의 입력 조건을 설명한다.
