코드는 가볍게, 실험 데이터는 확장 가능하게.

새 object와 실험 환경을 추가해도 repository 구조를 바꾸지 않도록, 코드·설정과 private asset·실험 기록을 분리했다.

한 개의 private data root

실행 시 BELTBENCH_DATA_ROOT를 지정한다. 이 경로는 Git에 올리지 않으며, 기존 AutoDex·ParaDex checkout을 runtime dependency로 쓰지 않는다.

export BELTBENCH_DATA_ROOT=/private/path/beltbench

assets/objects/OBJECT/       # mesh, URDF, candidate, provenance
assets/robots/ROBOT/         # robot description asset
assets/models/MODEL/REV/     # 실제 runner가 쓰는 model revision만
calibration/archive/RUN/     # 보정 이미지, session, result
observations/OBJECT/RUN/     # 두 camera observation
plans/OBJECT/RUN.json        # execution-blocked proposal
trials/PROTOCOL/RUN/         # 평가 기록
visualizations/OBJECT/RUN.glb

왜 archive인가

Calibration, observation, plan, trial은 이전 결과를 덮어쓰지 않는다. 새 run 이름으로 저장하고, 어느 결과를 사용할지는 다음 명령에서 명시적으로 선택한다. 따라서 calibration이 바뀌어도 과거 observation과 실험 기록의 근거가 사라지지 않는다. 재생성 가능한 중간 파일만 cache에 둔다.

asset 추가 원칙

object별 asset은 필요한 최소 mesh, URDF, candidate만 독립 data root로 복사한다. 큰 learned model은 실제 BeltBench runner가 소비할 때에만 revision 단위로 추가하며, source revision과 checksum을 함께 남긴다. 이렇게 하면 특정 object의 예외 코드나 사용하지 않는 model 사본이 쌓이지 않는다.

공개 기록의 경계

이 페이지는 구조와 재현 원칙만 공개한다. 실제 private path, network address, device identifier, transform, calibration 수치, raw observation은 저장소 밖의 local configuration과 private data root에 남긴다.
