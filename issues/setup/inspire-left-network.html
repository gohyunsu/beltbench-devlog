ISSUE-004 · 구성 불일치 · 2026-07-28

Inspire left hand의 물리 link는 살아 있지만 제어 연결은 아직 성립하지 않았다.

xArm과 Inspire left hand를 별도 Ethernet 포트로 분리하려는 구성에서 두 NIC 모두 carrier와 link를 감지했다. 그러나 인터페이스별 ARP 검사 결과는 기대한 배선·IP profile과 일치하지 않았다.

현재 판단: hand 자체의 고장으로 단정하지 않는다. 먼저 케이블이 어떤 NIC에 실제로 연결됐는지, 각 NIC가 어떤 독립 서브넷을 사용해야 하는지, 그리고 profile이 그 설계대로 적용됐는지를 확인해야 한다.

관측 증거

검사결과와 해석
두 NIC의 physical link둘 다 link up이다. 케이블이 완전히 빠진 상태는 아니다.
xArm 대상 ARPxArm 응답은 사용자 설명과 다른 NIC에서만 확인됐다. 현재 OS가 보는 실제 배선과 계획한 배선이 다를 가능성이 있다.
hand 대상 주소hand가 사용하는 별도 네트워크 대역용 IPv4 profile이 NIC에 적용되지 않았다.
hand 제어 포트응답이 없어 아직 software control을 시작할 수 없다.

왜 바로 IP를 바꾸지 않았는가

두 NIC에 같은 로봇 서브넷 경로가 동시에 존재하면 OS의 route 선택이 모호해진다. hand용 주소를 추정해 설정하면 현재 살아 있는 xArm 경로를 끊거나, 문제를 더 복잡하게 만들 수 있다. 따라서 자동 수정 대신 물리 연결과 의도한 IP plan을 먼저 확정한다.

다음 확인 순서

  1. 각 케이블을 한 번에 하나씩 분리·재연결해 NIC carrier가 변하는지 기록한다.
  2. xArm NIC와 hand NIC를 물리적으로 확정한다.
  3. 두 장치에 서로 다른 subnet과 static host address를 배정한다.
  4. 각 NIC에서 ARP → ping → 제어 포트 순서로 독립 검증한다.
  5. hand API의 상태 조회와 open/close 명령은 비상 정지와 안전 공간을 확인한 뒤에만 수행한다.

관련 이슈

ISSUE-001은 xArm의 host routing 문제를 해결한 기록이다. 이 이슈가 해결돼야 M0 table-top trial에서 robot arm과 hand를 함께 사용할 수 있다.

상태 갱신

후속 배선 점검에서 hand는 별도 NIC에서 physical link, ARP, ICMP 응답이 모두 확인됐다. 따라서 전원·케이블·기본 IP 도달성은 확보됐다. 다음 검증은 hand 전용 제어 API로 상태를 조회하고, 안전한 open/close 명령을 확인하는 일이다.
