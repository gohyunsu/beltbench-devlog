ISSUE-004 · 연결과 제어 경로 · 2026-07-28

Inspire left hand는 보이지만, 아직 제어할 수는 없다.

hand를 별도 Ethernet 링크에 연결한 뒤 physical link, ARP, ICMP까지는 확인했다. 그러나 실제 관절을 읽고 움직이게 하는 Modbus TCP 서비스에는 아직 연결되지 않았다. 이 구분이 중요한 이유는 ping 성공이 곧 제어 가능을 뜻하지 않기 때문이다.

현재 상태: hand에 motion command를 보내지 않았다. 상태 레지스터를 먼저 읽는 단계에서 TCP 연결이 timeout됐으므로, workspace가 비어 있어도 open/close를 시도하지 않는 것이 맞다.

제어가 성립하는 경로

초기 hand 제어는 다음 순서를 모두 통과해야 한다. 앞 단계가 성공해도 뒤 단계가 자동으로 보장되지는 않는다.

  1. Physical link: NIC carrier와 link speed가 케이블 연결을 알려 준다.
  2. Network reachability: ARP와 ICMP는 같은 링크의 장치가 응답하는지 확인한다.
  3. TCP session: hand controller가 Modbus TCP 서비스를 실제로 열고 있어야 한다.
  4. Register protocol: 프로그램이 actual angle·force·error·status 레지스터를 읽는다.
  5. Explicit motion: 상태가 정상이고 workspace를 확인한 뒤에만 목표 관절값을 한 번 쓴다.

Inspire hand 제어 원리

ParaDex의 reference controller는 Modbus TCP로 여섯 손가락 관절을 다룬다. read는 현재 angle, force, error, status를 가져오고, write는 speed·force·목표 angle을 여섯 값으로 보낸다. 목표 angle은 손을 여는 방향과 닫는 방향을 표현하지만, 실제 grasp는 이 저수준 명령 위에 있는 policy가 언제 얼마나 닫을지를 결정해야 한다.

기존 controller는 객체를 생성하는 순간 기본 설정을 쓰고 background loop를 시작한다. teleoperation에는 편리하지만, 연결이 불확실한 새 환경에서 단순 점검을 하기에 적합하지 않다. 그래서 BeltBench 구현은 연결·상태 읽기·motion을 분리했다.

BeltBench에 통합한 구현

private BeltBench에는 표준 library 기반의 작은 InspireModbusHand adapter를 추가했다. 이 adapter는 import나 생성만으로 움직이지 않으며, 한 요청씩 Modbus TCP frame을 만들어 처리한다. status는 읽기만 하고, open은 workspace를 확인했다는 명시적 confirmation 없이는 실행되지 않는다. hand endpoint와 NIC 주소는 local configuration으로만 전달하며 repository와 public devlog에는 넣지 않는다.

이 설계는 ParaDex의 기능을 다시 복제하기 위한 것이 아니다. M0 benchmark에 필요한 공통 계약—관측, 상태 확인, 단일 action, evidence—만 남긴 얇은 hardware adapter다. continuous hand loop와 grasp policy는 이후 method adapter 계층에서 다룬다.

다음 해결 순서

  1. controller가 부팅 완료·원격 제어 가능 상태인지 hand UI 또는 vendor tool에서 확인한다.
  2. 현재 firmware가 제공하는 Modbus TCP service와 포트를 확인한다.
  3. 전용 NIC를 명시한 상태로 status read가 성공하는지 검증한다.
  4. error·status가 정상이고 workspace가 비어 있을 때에만 단일 open을 실행한다.
  5. 그 뒤에만 xArm–hand joint control과 M0 pick-place sequence로 확장한다.

관련 이슈

ISSUE-001은 xArm에서 physical link와 host routing을 분리해 해결한 사례다. hand의 route 문제도 같은 방식으로 분리했지만, 현재 남은 병목은 controller service다. 이 문제가 해결돼야 M0 table-top trial에서 arm과 hand를 함께 평가할 수 있다.
