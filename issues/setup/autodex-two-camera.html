ISSUE-006 · 구현 중 · 2026-07-30

두 camera를 AutoDex-style pipeline의 재현 가능한 입력으로 묶는다.

현재 선정한 두 fixed camera는 table-top pick-place의 시작점으로 충분하다. 다만 “영상이 보인다”만으로 robot이 움직여서는 안 된다. BeltBench는 두 영상, 각 camera의 현재 calibration, 그리고 이후 지각·계획 결과를 분리된 artifact로 연결하는 observation gate를 먼저 구현했다.

무엇을 구현했나

private BeltBench에는 upstream AutoDex와 ParaDex 전체를 복사하지 않고, 두 camera만 받는 작은 observation module을 추가했다. viewer에서 fresh frame을 읽고, 현재 local intrinsic·extrinsic 결과가 두 camera 모두에 있는지 확인한 뒤, image와 calibration을 한 번의 observation.json으로 고정한다. 이 단계는 xArm이나 hand를 연결하지 않으므로 robot motion을 보내지 않는다.

frames = HttpViewerFrames(viewer_url, max_frame_age_s=2.0).read(camera_ids)
calibration = load_calibrations(camera_ids, intrinsic_path, extrinsic_path)
observation = capture_observation(frames, calibration, run_dir / "images")

저장된 각 image에는 SHA-256 hash를 남긴다. 나중에 segmentation·6D pose·grasp plan 결과가 생겼을 때, 어떤 두 image에서 나온 판단인지 바뀌지 않게 추적할 수 있다. raw image·camera ID·행렬은 private local storage에만 보존한다.

왜 두 camera로 가능한가

두 view가 모두 object를 보고, 각 view가 robot base와 정확히 연결되어 있다면, mask·depth 또는 6D pose estimator가 낸 관측을 같은 3D 좌표계에서 비교할 수 있다. 한 camera가 가려지거나 confidence가 낮을 때 다른 view가 확인 근거가 되는 것도 장점이다. 원본 AutoDex도 multi-view camera input을 mask, depth, pose estimation의 입력으로 사용한다.

현재 범위: viewer adapter는 각 frame이 오래된 cache가 아닌지만 검사한다. 두 camera의 exposure가 같은 시각이라는 hardware synchronization이나 timestamp skew는 아직 증명하지 않는다. 따라서 지금 구현은 정지 물체의 table-top 관측 gate에 한정한다. moving belt 단계에서는 shared trigger 또는 source timestamp와 허용 skew를 artifact에 함께 기록하도록 확장해야 한다.

반대로 두 camera가 있다고 해서 depth·object pose·grasp가 자동으로 생기지는 않는다. 최신 calibration에서 두 camera 모두가 residual 검토를 통과해야 하고, object별 mesh/reference/candidate grasp, collision model, planner, hand 실행 검증이 추가로 필요하다.

원본 AutoDex를 읽어 확인한 실행 구조

  1. capture: 여러 camera image와 calibration을 저장한다.
  2. perception: segmentation(SAM3/YOLOE), depth(FoundationStereo 등), object 6D pose(FoundationPose 등)를 계산한다.
  3. planning: object별 grasp candidate를 collision check와 IK로 걸러 cuRobo trajectory를 만든다.
  4. execution: arm approach, hand pregrasp/grasp, lift, place, release 순서로 실행하고 결과를 label한다.

원본 runtime은 별도 conda environment, GPU model weights, third-party repository, object asset, capture orchestration에 의존한다. BeltBench는 이 의존성을 숨기는 fallback을 만들지 않는다. 대신 각 단계가 위 observation artifact를 입력으로 받아 공통 trial contract를 쓰도록 one adapter씩 연결한다.

현재의 안전한 위치

단계상태다음 gate
두 camera live observation구현·unit test 완료실시간 viewer를 연결해 local artifact capture
두 camera calibrationfirst-pass 결과 존재다양한 safe pose를 더 확보하고 residual 검토
object perception미연결saved observation에서 offline overlay 검증
grasp planning미연결object asset·candidate·collision model을 offline에서 검증
robot execution의도적으로 차단supervised pregrasp→lift→place gate 통과 후에만 연결

실행 전에 준비할 것

  1. 두 camera가 움직이지 않은 상태에서 현재 workcell calibration을 확정한다.
  2. 각 seen object의 mesh/URDF, reference data, compatible grasp candidates를 private asset store에 준비한다.
  3. table·basket·robot/hand collision geometry와 measured workspace를 planner input으로 만든다.
  4. model checkpoint와 upstream revision을 고정한 뒤 saved observation으로 mask/pose overlay를 검토한다.
  5. motion은 operator가 있는 상태에서 open → pregrasp → grasp → lift → place → retreat을 하나씩 승인한다.
