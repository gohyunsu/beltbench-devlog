ISSUE-005 · 설계와 구현 · 2026-07-29

자동 calibration 코드는 무엇을 입력으로 받고, 무엇을 계산하는가?

BeltBench는 ParaDex의 흐름을 참고했지만, 전체 runtime을 복사하지 않았다. xArm·camera transport와 무관하게 동작하는 작은 calibration core를 만들고, 실제 장비 연결은 두 개의 thin adapter로 제한했다. 이 페이지는 코드의 데이터 흐름과 수학을 함수 단위로 설명한다.

핵심 아이디어: Charuco board를 xArm tool에 단단히 고정한다. robot이 여러 안전 pose로 이동하면, 매 pose에서 robot은 base_to_tool을, camera는 camera_to_board를 제공한다. 둘은 같은 물리 board를 가리키므로 이 반복 관측으로 camera extrinsic과 board mount transform을 함께 찾을 수 있다.

0. 좌표계를 먼저 읽는 법

A_to_B는 B 좌표계에서 표현된 점을 A 좌표계로 옮기는 4×4 homogeneous transform이다. 위쪽 3×3은 방향(rotation), 오른쪽 3×1은 위치(translation)다. 따라서 매 pose에서 동일한 board 위치는 다음 두 경로로 표현된다.

base_to_tool · tool_to_board
    =
base_to_camera · camera_to_board

왼쪽은 xArm base에서 tool을 거쳐 board로 가는 경로, 오른쪽은 xArm base에서 fixed camera를 거쳐 board로 가는 경로다. 미지수는 고정된 tool_to_board와 base_to_camera다. robot pose와 board 영상 pose가 다양하게 쌓일수록 두 값을 안정적으로 찾을 수 있다.

1. charuco.py: image를 board pose로 바꾼다

Board dataclass는 Charuco board의 square 수·실제 길이·marker dictionary를 정의한다. Charuco는 chessboard의 정밀한 corner와 ArUco marker의 식별성을 결합한 calibration pattern이다. image마다 detect()는 다음을 수행한다.

  1. private intrinsic에서 3×3 camera matrix와 lens distortion을 읽는다.
  2. cv2.aruco.CharucoDetector로 corner와 ID를 찾는다.
  3. corner 수가 최소 기준보다 작으면 None을 돌려 그 image를 버린다.
  4. board의 알려진 3D corner와 image의 2D corner를 짝지어 cv2.solvePnP를 실행한다.
  5. rotation vector와 translation을 4×4 camera_to_board transform으로 만든다.
corners, ids = CharucoDetector(board).detectBoard(image)
if ids is None or len(ids) < minimum_corners:
    return None
ok, rvec, tvec = cv2.solvePnP(object_points, image_points,
                              camera_matrix, distortion)

이 단계는 “카메라가 board를 본다”를 숫자로 만드는 단계다. blur·가림·너무 작은 board 때문에 corner가 부족하면 억지로 pose를 만들지 않는다.

2. capture.py: 장비 의존성을 두 interface로 제한한다

capture_session()은 xArm SDK나 특정 camera SDK를 import하지 않는다. 대신 다음 두 protocol만 요구한다.

Robot:  move_joints(joints), base_to_tool()
Frames: read(camera_ids)

실제 xArm adapter는 승인된 joint waypoint로 이동하고, 실제 camera adapter는 선택 camera의 동기화된 frame을 반환하면 된다. core는 각 waypoint 뒤 image를 읽고, 유효한 Charuco observation만 JSON session에 넣는다.

for joints in waypoints:
    robot.move_joints(joints)
    for camera, image in frames.read(camera_ids).items():
        observation = detect(image, intrinsics[camera])
        if observation is not None:
            board_poses[camera] = observation.camera_to_board.tolist()
    samples.append({"base_to_tool": robot.base_to_tool().tolist(),
                    "camera_to_board": board_poses})

중요: robot 정지 확인, collision-free waypoint, E-stop, camera timestamp 동기화는 core가 임의로 추측하지 않는다. live adapter와 실험 operator가 명시적으로 보장해야 한다. 이 분리는 solver가 조용히 robot을 움직이거나 특정 연구실 network에 묶이는 것을 막는다.

3. geometry.py: transform을 안전하게 다룬다

transform()은 4×4 모양, 마지막 행, rotation matrix의 직교성을 검사한다. inverse()는 일반적인 matrix inverse 대신 rigid transform의 성질 R⁻¹ = Rᵀ를 이용한다. pose_error()는 두 pose의 translation 차이와 rotation-vector 차이를 각각 metre와 radian으로 반환한다.

이 검증이 없으면 image pose의 축 순서가 바뀌거나 잘못된 행렬이 들어와도 solver가 숫자를 내놓을 수 있다. calibration에서는 “결과가 있음”보다 “입력 convention이 맞음”이 먼저다.

4. handeye.py: 여러 자세를 하나의 고정 관계로 압축한다

두 pose i, j를 빼면 고정 camera와 고정 board mount 항이 사라져 상대 운동 관계 A X = X B가 된다. 구현은 모든 pose 쌍을 만들어 information을 늘린 뒤, 여섯 변수(회전 vector 3 + 이동 3)로 표현한 X를 찾는다.

for first in range(n - 1):
    for second in range(first + 1, n):
        A.append(inverse(base_to_tool[second]) @ base_to_tool[first])
        B.append(inverse(camera_to_board[second]) @ camera_to_board[first])
tool_to_board = solve_ax_xb(A, B)

solve_ax_xb()는 SciPy least_squares를 사용한다. 각 candidate X에 대해 A·X와 X·B가 얼마나 다른지를 rotation vector와 translation residual로 쌓는다. soft_l1 loss는 일부 image observation이 나빠도 한 장의 이상치가 전체 해를 과도하게 끌어가지 않도록 한다.

X를 얻으면 각 absolute pose가 base_to_camera 후보 하나를 만든다. 여러 후보의 translation 평균과 SVD 기반 rotation 평균을 취하고, 마지막으로 각 후보와 평균 사이의 translation·rotation RMS를 report한다.

candidate = robot_pose @ tool_to_board @ inverse(board_pose)
base_to_camera = average_transforms(candidates)
translation_rms, rotation_rms = residuals(base_to_camera, candidates)

5. session.py와 CLI: 재현 가능한 입출력

solve_session()은 portable JSON의 sample을 camera별로 모아, 네 장 이상 유효 observation이 있는 camera만 푼다. scripts/calibrate.py는 결과 transform, sample 수, RMS를 새 JSON으로 쓰고 console에도 요약한다. raw image나 network 설정은 session format에 포함하지 않는다.

python3 scripts/calibrate.py session.json --output calibration.json
# camera: samples=... translation_rms_mm=... rotation_rms_deg=...

6. 지금 무엇까지 검증됐나

검증방법의미
SE(3) solver알려진 synthetic camera·board transform을 생성해 복원수식·상대 운동·평균·RMS 경로 검증
Charuco detection생성한 board image에서 corner와 PnP 실행OpenCV image-to-pose 경로 검증
live xArm/camera capture아직 연결 전adapter, waypoint, 동기화, workspace 안전 검토가 필요

실제 자동화 전의 gate

  1. camera live stream을 다시 확인하고 selected intrinsic을 board reprojection으로 검증한다.
  2. Charuco board를 tool에 강하게 고정하고, board가 여러 camera에서 충분히 크게 보이는 waypoint를 승인한다.
  3. xArm adapter가 move_joints 뒤 실제 정지와 base_to_tool timestamp를 보장하게 한다.
  4. camera adapter가 같은 순간의 frame 또는 허용 가능한 timestamp 차이를 기록하게 한다.
  5. RMS, corner 수, pose 다양성 기준을 통과한 camera만 M0 observation에 채택한다.
