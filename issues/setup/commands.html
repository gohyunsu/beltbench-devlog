실행 순서를 한 곳에 고정한다.

BeltBench 실행 코드는 private repository에만 있고, 이 페이지는 안전하게 재현할 수 있는 순서와 placeholder만 공개한다. network address, camera ID, calibration 수치, adapter transform은 각자 local configuration으로 제공한다.

1. 환경과 test

conda activate beltbench
cd /path/to/beltbench
export BELTBENCH_DATA_ROOT=/private/path/beltbench
python -m unittest discover -s tests -v

전용 environment에는 calibration, camera observation, xArm SDK, URDF visualization에 필요한 기본 의존성만 둔다. learned perception이나 GPU candidate generation은 별도 hardware requirement가 충족될 때 추가한다.

2. calibration

python scripts/capture_calibration.py \
  --trajectory-dir calibration/trajectories/paradex2-xarm \
  --camera CAMERA_A --camera CAMERA_B \
  --intrinsics REVIEWED_INTRINSICS.json \
  --viewer-url http://127.0.0.1:VIEWER_PORT \
  --host XARM_HOST \
  --run-dir "$BELTBENCH_DATA_ROOT/calibration/archive/RUN" \
  --confirm-trajectory paradex2-xarm \
  --confirm-workspace-clear --execute

python scripts/calibrate.py \
  "$BELTBENCH_DATA_ROOT/calibration/archive/RUN/session.json" \
  --output "$BELTBENCH_DATA_ROOT/calibration/archive/RUN/result.json"

이 단계만 xArm motion을 포함한다. 승인된 trajectory, clear workspace, operator supervision 없이 실행하지 않는다. 새 RUN으로 실행해, 이전 evidence를 덮어쓰지 않는다.

3. two-camera observation

python scripts/capture_autodex_observation.py \
  --camera CAMERA_A --camera CAMERA_B \
  --intrinsics REVIEWED_INTRINSICS.json \
  --extrinsics REVIEWED_RESULT.json \
  --viewer-url http://127.0.0.1:VIEWER_PORT \
  --run-dir "$BELTBENCH_DATA_ROOT/observations/OBJECT/RUN" \
  --max-frame-age-s 2

observation은 fresh frame, calibration, image hash를 immutable artifact로 저장한다. 이 명령은 robot이나 hand에 motion을 보내지 않는다.

4. object dry-run과 3D inspection

python scripts/plan_object_dry_run.py \
  --observation "$BELTBENCH_DATA_ROOT/observations/OBJECT/RUN/observation.json" \
  --object-config config/objects/OBJECT.json \
  --workspace-min XMIN YMIN ZMIN --workspace-max XMAX YMAX ZMAX \
  --output "$BELTBENCH_DATA_ROOT/plans/OBJECT/RUN.json"

python scripts/visualize_grasp_proposal.py \
  --proposal "$BELTBENCH_DATA_ROOT/plans/OBJECT/RUN.json" \
  --object-mesh OBJECT_MESH.obj --xarm-urdf XARM.urdf --inspire-urdf INSPIRE.urdf \
  --tool-from-hand T00 T01 T02 T03 T10 T11 T12 T13 T20 T21 T22 T23 0 0 0 1 \
  --xarm-joints Q1 Q2 Q3 Q4 Q5 Q6 --hand-joints H1 H2 H3 H4 H5 H6 \
  --output "$BELTBENCH_DATA_ROOT/visualizations/OBJECT/RUN.glb"

GLB에는 xArm, Inspire hand, adapter, object, selected wrist frame을 함께 넣는다. candidate generation과 collision/IK validation을 통과하지 않은 proposal은 visualization까지만 가능하며, execution은 차단된다.

실험 데이터는 코드와 분리한다

향후 object와 workcell을 늘릴 때 repository 안에 결과가 섞이지 않도록, private data root를 한 곳에 정하고 명시적으로 전달한다. 코드와 설정은 repository에, 큰 asset과 실행 산출물은 private storage에 둔다.

assets/objects/OBJECT/       # mesh, URDF, candidate와 출처 정보
assets/robots/ROBOT/         # robot description asset
assets/models/MODEL/REV/     # 실제 runner가 쓰는 model revision만
calibration/archive/RUN/     # 보정 이미지·session·result
observations/OBJECT/RUN/     # 두 camera observation
plans/OBJECT/RUN.json        # execution-blocked proposal
trials/PROTOCOL/RUN/         # 평가 기록
visualizations/OBJECT/RUN.glb

보정·관측·계획·trial은 이전 결과를 덮어쓰지 않고 새로운 RUN 이름으로 저장한다. cache만 재생성 가능한 영역이다. 이 분리는 특정 object나 초기 실험 환경에 코드가 묶이지 않게 하며, public devlog에는 경로·주소·식별자·보정 수치를 올리지 않는 경계도 만들어 준다.

안전 경계

  • camera·calibration·object asset은 local/private storage에 둔다.
  • dry-run과 visualization은 hardware motion을 호출하지 않는다.
  • candidate generation에는 CUDA와 complete object/robot scene asset이 필요하다.
  • 실제 execution은 collision-checked trajectory와 operator approval이 별도 필요하다.
