ISSUE-003 · 진행 중 · 2026-07-28

같은 이름의 저장소가 같은 역할을 하지는 않는다.

새 환경에서 재현하려면 프로젝트 소개 사이트, 로봇·카메라 프레임워크, 실제 AutoDex 실행 코드의 역할을 먼저 분리해야 했다. 이를 구분하지 않으면 실행 불가능한 저장소에 설정을 쌓거나 동일 코드를 여러 곳에 복사하게 된다.

정리한 역할

구성 요소역할
gohyunsu/ParaDexxArm과 다중 카메라를 연결하는 재사용 프레임워크
willi19/AutoDex지각·계획·실행 파이프라인의 참조 구현
private BeltBench공통 task contract, method adapter, trial log, scoring을 소유하는 구현 기준 저장소
public devlog정제된 이슈·미디어·설계 근거를 설명하는 공개 기록

현재 차단 요인

GPU 런타임은 드라이버와 NVML userspace의 버전 불일치로 아직 추론 검증에 적합하지 않다. 또한 새 workcell profile과 카메라 보정이 없다. 따라서 바로 하드웨어 실행으로 가지 않고, import와 simulation을 먼저 확인한 뒤 관측·보정·실행을 차례로 연결한다.

통합 원칙

BeltBench에는 외부 코드 전체를 복사하지 않는다. 각 방법은 하나의 얇은 adapter로 공통 관측·결정·행동·증거 계약을 구현한다. fallback은 명시적으로 평가할 방법일 때만 두며, 같은 행동을 중복 구현하지 않는다.

연결 기반은 ISSUE-001, 카메라 게이트는 ISSUE-002에서 확인한다.
