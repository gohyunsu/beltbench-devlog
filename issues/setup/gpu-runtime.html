RUNTIME · 2026-07-30

GPU는 host에서 확인하고, runtime은 BeltBench에 고정한다.

처음에는 격리된 실행 환경에 GPU device node가 없어서 CUDA가 보이지 않았다. host 수준 probe로 GPU와 CUDA renderer를 확인한 뒤, 외부 checkout에 남아 있던 runtime source와 model을 독립 구조로 옮겼다.

확인된 것

  • host GPU와 CUDA renderer가 동작한다.
  • FoundationPose score/refiner checkpoint를 private model storage에서 GPU로 load했다.
  • BODex source는 private implementation repository의 third-party 영역으로 복사했다.
  • DA3 depth source와 model은 FoundationPose의 metric depth 입력을 위해 private model storage에 분리했다.
  • GoTrack의 AutoDex용 source revision과 object별 anchor bank를 확보했다.

왜 source와 model을 나누나

실행 코드는 version-controlled private repository에 남기고, 큰 checkpoint와 raw experiment data는 private data root에 둔다. 따라서 Git history는 가벼운 코드·설정 중심으로 유지하면서도 runtime은 이전 AutoDex checkout이나 NAS path를 직접 읽지 않는다.

GoTrack source 확보

처음에는 checkpoint만 보관했고, temporal tracker source는 확보하지 못했다. 이후 AutoDex용으로 정리된 GoTrack revision을 확보해 BOP toolkit·DINOv2를 포함한 실행 source를 private BeltBench repository에 옮겼다. checkpoint와 object별 anchor bank는 private data root로 분리했다. 다음 검증은 외부 AutoDex checkout이 아니라 BeltBench source와 private runtime asset만 사용한다.

다음 검증

현재 source와 model asset의 위치는 고정됐지만, GoTrack 전용 dependency environment의 import와 실제 multi-view sequence 실행은 아직 완료하지 않았다. 이 단계가 통과되기 전에는 tracking이 동작한다고 주장하지 않는다. candidate generation, collision/IK, 실제 robot motion은 별도의 validated workcell input과 operator supervision 뒤에 수행한다.
