RUNTIME · 2026-07-30

GPU runtime을 BeltBench 내부 source와 private asset으로 고정했다.

CUDA device 확인만으로는 재현 가능한 tracker가 되지 않는다. source, CUDA renderer, model checkpoint, DINO backbone cache가 서로 맞는 version으로 준비되어야 한다.

정리한 구조

  • GoTrack source와 NVIDIA renderer source는 private BeltBench repository에 둔다.
  • 큰 checkpoint와 object별 anchor bank는 private data root에 둔다.
  • 전용 environment는 workspace 안에 만들고, 공용 Python environment는 바꾸지 않는다.
  • 원래 후보 repository 두 개는 source와 asset을 옮긴 뒤 제거했다.

검증 과정

처음에는 renderer binary를 다른 environment에서 복사했지만 PyTorch ABI가 달라 import되지 않았다. 이를 해결하기 위해 CUDA 12 계열 PyTorch에 맞춰 renderer를 source에서 다시 빌드했다. 이어서 NumPy 2.x와 FAISS binary의 ABI 충돌을 확인했고, NumPy 1.26으로 고정했다. 최종적으로 CUDA renderer context 생성, GoTrack module import, private checkpoint의 GPU load, multi-view CLI argument parsing까지 통과했다.

모델 cache의 위치

GoTrack이 사용하는 DINO backbone은 첫 load에서 자동 다운로드될 수 있다. 이 파일도 private data root의 Torch cache layout에 보관하고 TORCH_HOME으로 위치를 지정한다. 따라서 이후 run은 이전 AutoDex checkout이나 사용자 home cache를 읽지 않는다.

안전한 검증 경계

여기까지는 offline tracking runtime의 준비와 model load 검증이다. 실제 camera sequence tracking, candidate generation, collision/IK, robot motion은 별도의 validated input과 operator supervision 뒤에 수행한다.
