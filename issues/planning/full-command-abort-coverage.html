ISSUE-048 · 2026-08-11 · full-command abort coverage

Nominal full path가 안전해도 어느 상태에서나 취소 가능한 것은 아니다.

Full-task object collision lifecycle 다음에 바로 GPU output lease를 만들려 했으나 stop-path 의미를 재감사했다. 현행 compiler와 validator는 replan cutoff의 conveyor 상태에서 시작하는 단 하나의 braking path만 허용한다. 이는 contact, attachment, transport, release, return에서 controller cancel을 처리할 수 있다는 증거가 아니다. 이 누락을 닫기 전 full-command lease를 controller-ready로 선언하면 nominal path 검증과 runtime fault recovery를 혼동하게 된다.

현재 효력: source dd9978f는 full-command request가 cuRobo output·독립 validation뿐 아니라 phase_conditioned_abort_coverage도 요구하도록 blocked reason을 강화했다. docs/full-command-abort-strategy.md에 hardware protective stop과 software cancel의 책임, object-state별 abort mode와 resident catalog 요구를 고정했다.

확인된 사실

  • generate_sampled_cutoff_stop_path는 source frame의 object state가 conveyor가 아니면 즉시 거부한다.
  • Sampled path validator도 replan cutoff source와 stop path의 모든 frame이 conveyor인지 검사한다.
  • CompiledConveyorPathFamily의 모든 certified latch는 replan cutoff 이전에 있어야 한다. 기존 latch를 post-contact abort latch로 재사용할 수 없다.
  • 따라서 기존 stop_path metric이 통과해도 contacting·attached·released 상태의 취소 coverage는 0이다.

배제한 접근

접근배제 이유
Fault 시 CPU global replanningPerception/controller가 이미 degraded된 시점에 variable search latency와 allocation을 추가한다.
모든 sample에서 즉시 nominal holdContacting 중 정지는 object/hand 상대 운동을 남기고, attached transport 중 hold는 object-workcell collision을 만들 수 있다.
Nominal suffix를 그대로 끝까지 실행취소 의미가 없어지고, long non-interruptible interval을 안전 근거 없이 허용한다.
Software stop을 hardware E-stop으로 간주로봇 controller와 safety system의 measured protective-stop 성능을 planning code가 대체할 수 없다.

채택한 구조

  1. 즉시 protective stop은 hardware controller/safety system의 독립 책임으로 남긴다.
  2. Software cancel은 현재 command sample을 exact abort window로 lookup한다.
  3. Immutable nominal command를 bounded 시간만 다음 certified abort latch까지 계속한다.
  4. 그 latch에서 startup에 upload·warm-up된 resident abort maneuver로 전환한다.
  5. Abort maneuver는 object state에 따라 dynamic world, attached spheres, release envelope 또는 static world collision을 사용한다.
  6. 각 nominal sample은 정확히 하나의 abort window에 포함되어야 하며, deployment policy의 maximum time-to-abort-latch를 넘으면 compiler가 latch를 추가하거나 family를 거부한다.

실시간성 판단

Abort 경로는 online search하지 않는다. Nominal catalog와 함께 fixed shape tensor, collision pass, result buffer를 preallocate하고 CUDA graph를 warm-up한다. Runtime critical path는 current sample/state lookup, device-resident route selection, validation event와 one-shot lease handoff뿐이다. GPU는 FK·dynamics·continuous collision·hard reduction을 수행하고 CPU는 cancellation state, deadline, controller transport와 lease ownership만 담당한다.

검증 결과와 현재 제한

  • Blocked reason 변경 후 full-command 집중 테스트 6개가 통과했다.
  • 현재 phase-conditioned abort command, coverage manifest, resident abort lease와 controller adapter는 아직 구현하지 않았다.
  • Contact-to-attach commit interval의 허용 최대 시간은 hardware tracking과 protective-stop 측정 전에는 승인할 수 없다.
  • 다음 구현은 nominal sample 전체를 덮는 typed abort-window/catalog contract와 offline compiler다. 그 다음에만 full-task output lease와 independent validator를 조립한다.

Segmented object collision, Resident full-command template, Resident controller lease ownership을 함께 참고한다.
