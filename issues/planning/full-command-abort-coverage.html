ISSUE-048 · 2026-08-11 · full-command abort coverage

Nominal full path가 안전해도 어느 상태에서나 취소 가능한 것은 아니다.

Full-task object collision lifecycle 다음에 바로 GPU output lease를 만들려 했으나 stop-path 의미를 재감사했다. 현행 compiler와 validator는 replan cutoff의 conveyor 상태에서 시작하는 단 하나의 braking path만 허용한다. 이는 contact, attachment, transport, release, return에서 controller cancel을 처리할 수 있다는 증거가 아니다. 이 누락을 닫기 전 full-command lease를 controller-ready로 선언하면 nominal path 검증과 runtime fault recovery를 혼동하게 된다.

현재 효력: source 236d879은 full-grid abort catalog schema 1.1과 compiler를 구현했다. Controller가 보고한 greatest-reached nominal sample마다 정확히 하나의 phase-conditioned route를 O(1)로 선택하고, non-terminal window는 반드시 미래 latch를 사용한다. 다만 catalog는 실제 abort tensor와 collision lifecycle의 digest만 참조하므로 실행 권한은 계속 차단된다.

확인된 사실

  • generate_sampled_cutoff_stop_path는 source frame의 object state가 conveyor가 아니면 즉시 거부한다.
  • Sampled path validator도 replan cutoff source와 stop path의 모든 frame이 conveyor인지 검사한다.
  • CompiledConveyorPathFamily의 모든 certified latch는 replan cutoff 이전에 있어야 한다. 기존 latch를 post-contact abort latch로 재사용할 수 없다.
  • 따라서 기존 stop_path metric이 통과해도 contacting·attached·released 상태의 취소 coverage는 0이다.

구현 중 발견한 추가 원인

첫 구현은 nominal sample의 object state만으로 abort mode를 자동 선택했다. 집중 테스트는 통과했지만 controller cancel은 sample 시각에만 도착하지 않는다. 두 sample 사이에서 cancel이 오면 현재 window의 latch가 이미 과거가 될 수 있었다. 또한 object state가 attached인 동안에도 transport 구간과 release_open_start 이후 commit 구간은 취소 의미가 다르다. 따라서 object state-only routing은 실제 controller semantics를 표현하지 못한다.

  • Runtime key를 exact event가 아니라 controller-reported greatest_reached_nominal_sample로 정의했다.
  • 마지막 command sample을 제외한 모든 window에서 abort_latch_sample_index > last_nominal_sample_index를 강제했다.
  • Contact와 release/placement commit guard를 물리 event보다 앞에서 시작하도록 route spec이 명시적으로 mode를 선언한다.
  • Drop의 released → contained와 이미 containment가 끝난 contained robot-only stop을 분리했다.
  • pick_and_place도 지원하도록 complete_placement_then_robot_stop을 drop commit과 별도 terminal state로 정의했다.

채택한 구조

  1. 즉시 protective stop은 hardware controller/safety system의 독립 책임으로 남긴다.
  2. Software cancel은 현재 command sample을 exact abort window로 lookup한다.
  3. Immutable nominal command를 bounded 시간만 다음 certified abort latch까지 계속한다.
  4. 그 latch에서 startup에 upload·warm-up된 resident abort maneuver로 전환한다.
  5. Abort maneuver는 object state에 따라 dynamic world, attached spheres, release envelope 또는 static world collision을 사용한다.
  6. 각 nominal sample은 정확히 하나의 abort window에 포함되어야 하며, deployment policy의 maximum time-to-abort-latch를 넘으면 compiler가 latch를 추가하거나 family를 거부한다.

실시간성 판단

Abort 경로는 online search하지 않는다. Nominal catalog와 함께 fixed shape tensor, collision pass, result buffer를 preallocate하고 CUDA graph를 warm-up한다. Runtime critical path는 current sample/state lookup, device-resident route selection, validation event와 one-shot lease handoff뿐이다. GPU는 FK·dynamics·continuous collision·hard reduction을 수행하고 CPU는 cancellation state, deadline, controller transport와 lease ownership만 담당한다.

모든 모듈을 무조건 GPU로 옮기지는 않는다. cuRobo V2는 batched FK/IK, self/world/object collision, trajectory optimization과 compact reduction처럼 병렬성이 크고 tensor를 계속 resident로 유지할 수 있는 연산의 online authority로 둔다. Timestamp/freshness, greatest-reached index, cancel escalation, hardware protective stop과 controller acknowledgement는 작은 ordered state와 I/O이므로 CPU에 둔다. HPP-FCL exact mesh는 online fallback이 아니라 cuRobo sphere representation의 false-negative를 찾는 offline deployment oracle이다.

구현된 계약

  • ResidentAbortRouteSpec은 각 window의 coverage, 미래 latch, abort mode, fixed-shape command/tensor/collision digest와 CUDA catalog slot/event를 입력한다.
  • ResidentFullCommandAbortCatalog은 nominal time/phase/object-state grid, attach/detach에서 겹치는 collision pass, per-sample window index와 최대 continuation 시간을 source digest에 고정한다.
  • Nominal과 abort slot/event alias, coverage 누락·중복, 잘못된 source state, 과거 latch, policy deadline 초과, runtime/template/lifecycle source mismatch를 fail closed한다.
  • Contract 자체는 execution_blocked다. Fake fixture digest가 존재해도 cuRobo output, continuous validation 또는 controller lease로 승격되지 않는다.

검증 결과와 현재 제한

  • Abort/full-command 집중 테스트 10개가 통과했다.
  • Planning 환경 전체 683개 중 678개가 통과하고 2개가 skip됐다. Error 3개는 기존 planning 환경의 cv2 미설치에 따른 import error뿐이다.
  • OpenCV가 설치된 beltbench-calibration 환경에서 해당 3개 모듈의 14개 테스트가 모두 통과했다.
  • Phase-conditioned coverage catalog는 구현했지만 실제 abort time/q/qd/qdd, abort object collision lifecycle, cuRobo upload/validation event, resident abort lease와 controller adapter는 아직 구현하지 않았다.
  • Contact-to-attach commit interval의 허용 최대 시간은 hardware tracking과 protective-stop 측정 전에는 승인할 수 없다.
  • 다음 구현은 각 route의 실제 fixed-shape abort command와 independently generated collision/dynamics evidence다. 그 다음에만 full-task output lease와 independent validator를 조립한다.

Segmented object collision, Resident full-command template, Resident controller lease ownership을 함께 참고한다.
