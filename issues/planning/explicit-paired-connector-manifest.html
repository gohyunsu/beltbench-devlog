ISSUE-041 · 2026-08-11 · explicit paired connector manifest

구형 connector fallback을 복원하지 않고 두 CAD pose를 arm-tip assembly frame에 명시한다.

Source-consistent full grasp evaluation을 복구한 뒤 deployment assessment를 실행했지만, private robot manifest가 제거된 paired_mount_meshes schema를 사용해 strict loader에서 중단됐다. 기존 파일을 고치거나 예시 transform으로 바꾸지 않고, 구형 field 이름이 선언하던 mount-frame 의미를 explicit assembly pose로 한 번만 컴파일하는 append-only 경계를 구현했다.

현재 효력: source 33b94d5와 server checkout을 일치시켰다. 새 private manifest SHA-256은 a43510455c723f32cc98a504dd0b2b9d54b97564df367d66fd106e73466df73f이다. Mount transform은 측정값이 아니므로 provisional이며 hardware execution authority가 없다.

발생한 문제

실행관찰판정
Deployment 115695Full evaluation source verification은 통과했지만 unsupported arm-hand connector visual type: paired_mount_meshes에서 실패Grasp나 IK 실패가 아니라 private asset schema drift다.
Server robot manifestxArm-side OBJ는 arm_tip_visual_mesh, Inspire-side OBJ는 hand_root_visual_mesh로만 선언각 mesh frame이 이름에 암묵적으로만 들어 있다.
Current loaderpaired_assembly_meshes와 두 개의 arm_tip_from_*_mesh transform을 요구시각화뿐 아니라 cuRobo·MuJoCo collision assembly가 같은 rigid placement를 사용한다.

원인

Commit e4e6adf에서 connector contract가 PairedMountConnectorAsset에서 PairedAssemblyConnectorAsset으로 바뀌었다. 이전에는 arm-side CAD가 arm-tip frame, hand-side CAD가 hand-root frame에 있다는 것을 field 이름으로만 해석했다. 현행 계약은 두 CAD 모두 arm-tip assembly frame에 놓는 transform을 요구해 시각화, HPP-FCL, cuRobo sphere assembly와 MuJoCo import의 배치를 하나로 고정한다. Source code와 example manifest는 바뀌었지만 private server manifest는 재컴파일되지 않았다.

배제한 해결

  • Runtime loader에서 paired_mount_meshes를 다시 받아들이지 않았다. 암묵 transform 해석이 online path에 영구 fallback으로 남는다.
  • Procedural white bridge로 대체하지 않았다. 실제 xArm/Inspire adapter CAD와 connector collision model을 잃는다.
  • Current example의 47.5 mm mount transform을 복사하지 않았다. Server legacy manifest는 4.5 mm x offset과 35 mm z offset을 선언하며 둘 다 측정값이 아니다.
  • 기존 private manifest.json을 수정하지 않았다. 이전 run의 재현성과 digest를 깨뜨린다.

구현한 compiler

  1. Legacy top-level과 connector field set이 정확히 일치하고 visual type이 paired_mount_meshes인지 검사한다. 알 수 없는 field는 거부한다.
  2. 두 OBJ를 source manifest 기준으로 해석하고 저장된 SHA-256과 다시 비교한다.
  3. Arm-side CAD의 arm_tip_from_arm_side_mesh는 identity로 만든다.
  4. Hand-side CAD의 arm_tip_from_hand_side_mesh는 exact legacy arm_tip_from_hand_root를 사용한다.
  5. Output이 source asset directory 밖으로 나가거나 기존 파일을 덮어쓰는 것을 거부한다.
  6. Sibling temporary file을 current strict loader로 완전히 reload한 뒤 atomic rename한다.
python -m scripts.compile_paired_connector_robot_manifest \
  --source ASSET_DIR/manifest.json \
  --output ASSET_DIR/manifest-paired-assembly-v2.json

검증과 현재 결과

  • Compiler, strict robot loader, cuRobo asset, MuJoCo admission과 collision activation 회귀 35개가 통과했다.
  • 새 manifest를 서버 current loader로 다시 읽어 arm-side identity와 hand-side [0.0045, 0, 0.035] translation 및 반전 rotation을 확인했다.
  • 기존 OBJ digest 44ebf1d9…d088, 955240d2…4620을 그대로 유지했다.
  • 새 manifest를 사용하는 deployment assessment 115696을 append-only v13 run으로 제출했다. 아직 결과를 execution evidence로 사용하지 않는다.

cuRobo real-time collision 방향과 actual assembly physics validation을 함께 참고한다.
