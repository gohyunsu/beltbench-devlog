ISSUE-109 · 2026-08-31 · partitioned online self-collision

Sphere와 exact mesh의 책임을 나누고 한 개의 online self-collision 판정으로 합친다.

Nearest grasp는 같은 물체·stable pose·hand 안의 top-K 계산 순서로 사용할 수 있다. 하지만 어느 후보를 실행할지는 현재 RGB 관측, belt track과 robot state에서 새로 만든 동일 command tensor를 독립 충돌 검사한 뒤 결정해야 한다. 이번 단계는 부적격 v28 모델을 대체해 204개 pair를 GPU sphere, 네 pair를 exact mesh에 맡기는 source-bound 경계를 구현하고 실제 비용과 남은 실패를 측정했다.

현재 효력: beltbench@2fb8647은 pair ownership, 동일 command digest, canonical joint order와 continuous limiting-cell 진단을 검증한다. 그러나 측정 입력은 29.81초 legacy full-command이며 actual RGB observation에서 생성한 command가 아니다. 20/10/5 ms sphere 검사는 모두 fail-closed였고 Isaac positive execution도 없으므로 실행 권한은 없다.

Nearest grasp는 어디까지 허용하는가

단계정책
Hard context동일 object, admitted stable pose, target hand, capability와 source evidence가 먼저 일치해야 한다.
Candidate retrieval측정된 full object pose로 object-relative grasp를 변환하고 bounded SE(3) 거리로 최대 8개를 정렬한다.
비대칭 object측정 yaw를 그대로 보존한다. Source-closed symmetry가 없는 banana류 object를 회전 대칭으로 간주하지 않는다.
Final selectionOnline IK, self/connector/world/moving-object collision, dynamics, timing과 robust maximin으로 결정한다. Nearest rank와 distance는 final key에 없다.
후보 부재다른 stable pose나 hand의 nearest grasp로 넘어가지 않는다. No-pick 또는 별도로 적격화한 grasp generator를 호출한다.

따라서 nearest 자체가 문제는 아니다. 정적 library의 가까운 grasp를 곧바로 실행 명령으로 승격하거나, 다른 context의 grasp를 fallback하는 것이 문제다. Pepsi top-8 retrieval의 warm p95는 7.193 ms였으므로 지금 병목도 아니다.

왜 sphere만 쓰지 않았는가

v36에서는 exact mesh holdout의 네 false positive를 없애기 위해 관련 sphere를 일괄 축소했다. 필요한 축소량은 다른 표면의 source coverage를 깨뜨렸다. 보기 좋은 parity 수치를 위해 false negative 가능성을 키우는 수정이므로 기각했다.

v38은 모든 eligible pair를 정확히 한 owner에 배정한다. 204개 일반 pair는 보수적인 cuRobo sphere, source에서 false positive가 확인된 네 hand pair는 HPP-FCL exact mesh, 인접하거나 의미상 검사 대상이 아닌 23개 pair는 명시적 ignore set이 소유한다. Partition digest 4f7efad0...d8b4c4, robot config ab0a35ee...e6d43, sphere certificate 6c1eb75a...69ddfd, exact certificate d9aae72b...435e5를 함께 결속했다.

Canonical joint mappingArm과 hand column을 이름으로 checker 순서에 재배열위치 기반 silent reuse 금지

cuRobo 환경에는 Torch/CUDA가 있지만 Pinocchio가 없고 HPP-FCL 환경에는 Pinocchio/HPP-FCL이 있지만 Torch가 없다. 첫 구현은 concrete HPP class를 cuRobo process에서 import해 시작조차 못 했다. 3ee14be에서 typed evaluator protocol로 의존성을 끊었다. Production에서는 두 환경을 억지로 합치거나 CPU fallback을 추가하지 않고 source-bound resident exact worker를 연결한다.

또한 legacy command는 hand joint를 thumb-first로 저장하지만 v38 checker와 certificate는 index/little/middle/ring/thumb 순서다. aa96527에서 이름 기반 canonical mapping을 넣었다. 이 수정이 없으면 숫자 shape는 맞아도 다른 robot state를 검증하게 된다.

Robot config setup은 각 process에서 약 91-93초였다. 이는 acquisition을 열기 전에 한 번 끝낼 resident startup 비용이지 event latency가 아니다. Exact 검사는 legacy full-command 전체를 통과했지만, sphere 연속 검사의 limiting segment는 1683번 post-drop return이었다. 이때 hand는 열려 정지해 있고 arm이 빠르게 움직였으므로 네 exact-hand pair로 위임할 문제가 아니라 arm sphere swept approximation의 보수성 문제다.

29.81초 legacy template 전체를 5 ms로 더 촘촘히 훑는 것은 실시간 pipeline 최적화가 아니다. Deadline-critical pick/drop의 실제 online command와 post-drop return command를 별도 horizon으로 다루고, 거기서 표시된 cell만 adaptive refinement할 필요가 있는지 다시 판단해야 한다.

더 작은 timestep일수록 최소 margin이 감소빠른 return segment의 swept sphere 근사가 더 보수적으로 드러남전역 refinement를 중단하고 actual online short horizon을 먼저 생성·저장·검증하기로 했다.

검증과 남은 경계

  • Partition contract, dependency decoupling, canonical order와 diagnostics 구현: f4693de부터 2fb8647.
  • Local targeted regression: 25 passed, 5 skipped. Skip은 설치되지 않은 optional runtime dependency 경계다.
  • RTX cuRobo/Torch component regression: 9 passed.
  • HPP/source regression: 16 passed, 1 skipped. Skip은 HPP 환경의 Torch 부재다.
  • 현재 모든 benchmark와 materialized v38 artifact는 execution_authorized=false다.
  • Actual OnlineMotionGenerationResult persistence, 별도 exact worker IPC, complete collision/lifecycle/dynamics 조합, maximin admission과 Isaac RGB positive execution은 아직 없다.

다음 단계

  1. 실제 RGB-derived track, full yaw, belt state와 current robot q/qd/qdd에서 만든 short-horizon OnlineMotionGenerationResult를 그대로 저장한다.
  2. 동일 command tensor를 sphere worker와 exact worker에 전달하고 self/connector/workcell/time-indexed object collision, dynamics와 event lifecycle을 독립 검증한다.
  3. 통과 후보만 nearest rank와 무관한 robust maximin으로 고르고 pick/drop와 post-drop return을 별도 deadline으로 handoff한다.
  4. 동일 application graph에 Isaac RGB sensor와 simulated articulation feedback을 연결한다. Prim truth나 precomputed command로 빈 구간을 채우지 않는다.
  5. 실제 단계 timestamp와 색상 전환이 포함된 positive actual-time 영상을 검증 보고서에서만 생성한다.
