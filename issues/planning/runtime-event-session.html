ISSUE-016 · 2026-08-08 · causal runtime evidence

계획 애니메이션과 실제로 발생한 event를 같은 것으로 보이지 않는다.

기존 runtime trace는 한 grasp-selection decision을 설명하지만 observation 도착, supersession, command와 feedback의 실제 순서를 재현하지 못했다. Ideal PickPlayback에서 그 event를 역으로 만들어 내지 않고, monotonic timestamp와 typed evidence를 가진 독립 session 계약과 Viser 시간축을 구현했다.

현재 효력: revision e9c56c9은 event/session 계약에 synchronized command robot, measured robot, measured object stream과 measured-layer Viser replay를 연결한다. 다만 제공된 simulation adapter는 계획 kinematics를 그대로 복사하는 plumbing fixture다. Dynamics, contact, tracking, controller와 hardware execution evidence는 없으며 실행은 계속 차단된다.

구현한 계약

  1. RuntimeArtifactEvidence가 observation, belt state, fused track, prediction, trajectory, playback, command, measured state와 outcome evidence를 통제된 type·role로 참조한다.
  2. RuntimeEvent는 contiguous sequence, monotonic timestamp, generation, module, event type, 허용 status, duration, input/output artifact와 reason code를 가진다.
  3. 각 event SHA-256은 이전 event digest를 포함한다. Session은 terminal event digest와 전체 manifest digest를 다시 검사해 순서 변경·중간 삽입·payload 변조를 거부한다.
  4. planned_only는 commit·setpoint·feedback·contact·release event를 금지한다. command_only는 command가 있지만 measured feedback이 없음을 뜻한다. Feedback session은 command robot, measured robot, measured object artifact를 정확히 하나씩 요구하며 simulation/hardware evidence role이 일치해야 한다.
  5. Published observation·belt·track·prediction, accepted query·trajectory, controller setpoint, measured state와 outcome event는 각자 요구되는 output artifact type이 없으면 실패한다.
  6. validate_runtime_event_session.py가 hash chain과 모든 source를 검증하고, serve_pick_playback.py --runtime-session은 trace 모드와 상호 배타적으로 session 시간을 재생한다.
  7. Robot stream은 arm과 end effector의 named position·velocity·acceleration을 한 timestamp에 묶는다. 독립 hand stream을 두어 두 장치가 동기화된 것처럼 보이는 경로는 허용하지 않는다.
  8. Object stream은 object·stable pose·generation·SE(3) pose·physical state와 evidence basis를 기록한다. Hardware stream은 simulation ground truth를 사용할 수 없고, attached와 contained는 각각 attachment 또는 containment 근거가 필요하다.
  9. Playback request와 결과 schema 2.0은 object와 stable-pose identity를 직접 보존한다. Intercept template, motion prediction, resident atlas, runtime trace와 measured stream 중 하나라도 이 identity와 다르면 startup 또는 load 단계에서 실패한다.

Viser 시간 의미

RuntimeSessionTimeline은 viewer startup에서 playback activation과 최대 1 ms GUI step을 계산한다. 재생 시간은 event.timestamp_s - session.started_timestamp_s이며 기본 1x·자동 반복이다. 현재 event와 stream sample은 각각 binary search로 찾으므로 frame당 전체 기록을 순회하지 않는다.

선택 playback은 정확히 한 diagnostic_selected 또는 plan_committed event가 출력한 artifact여야 한다. Planned·command-only mode에서는 그 event 이전 mesh를 숨긴다. Feedback mode에서는 검증된 measured arm·end-effector·object sample만 zero-order hold로 표시하고, robot/object stream의 겹치는 시간 밖에서는 geometry를 숨긴다. 측정하지 않은 중간 상태를 보간하지 않으며 planned object path도 감춘다.

simulate_ideal_kinematic_feedback.py는 이 measured 경로를 실제 장치 없이 검사하기 위해 playback의 301개 frame을 command와 measured-simulation stream으로 변환한다. Source는 no-dynamics-no-contact를 명시하고 object state 근거는 simulation ground truth로 제한한다. 화면에서 자연스럽게 움직여도 tracking error, contact stability, actuator response 또는 real-time 성능을 검증한 것이 아니다.

검증 결과

Round-trip, write-once, event/manifest digest 변조, orphan·unknown artifact, strict boolean, sample source와 joint identity, object state transition과 evidence basis, session·scene context, playback object/stable-pose ancestry, exact event boundary, measured stream overlap과 zero-order-hold를 검사했다. Grasp shortlist·yaw atlas·rolling planner까지 포함한 집중 test 79개가 로컬과 junjinyong 고정 planning 환경에서 각각 통과했다.

전체 planning discovery는 326개 항목 중 OpenCV가 없는 planning 환경의 세 module import만 실패했고 나머지는 모두 통과했다. 그 세 module의 실제 14개 test는 calibration 환경에서 모두 통과했다. git diff --check, schema-2.0 playback 생성, 301-sample ideal feedback session 생성, 네 artifact의 hash/context 검증과 실제 xArm·Inspire·Pepsi·workcell asset을 사용하는 Viser 기동도 통과했다.

Smoke session은 10.000001초, event 4개, artifact 4개를 기록했다. 이는 runtime evidence plumbing의 구조적 검증 결과다. Ideal measured state가 command와 동일하므로 tracking 정확도나 contact 성공률 수치로 보고하지 않는다.

남은 한계

  • 현재 최종 session JSON은 write-once contract다. Control loop를 막지 않는 bounded queue/async recorder와 crash-safe chunk writer는 아직 없다.
  • Typed desired/measured stream과 Viser measured layer는 구현됐지만 실제 simulator physics·controller·camera·encoder adapter가 아직 없다.
  • Deadline miss, supersession, cutoff, watchdog와 abort의 recorded simulation fixture가 없다.
  • Attachment와 containment의 hardware evidence schema는 개념적 basis만 정의한다. Force/tactile/vision sensor별 판정 protocol과 false-positive 측정이 필요하다.
  • Desired와 measured trajectory를 동시에 겹쳐 tracking error를 비교하는 viewer layer와 정량 metric은 아직 없다.
  • Event replay는 증거 시각화다. Planner·controller deadline이나 hard real-time 성능을 증명하지 않는다.

다음 단계는 기존 path-family/latch/cutoff 계약 뒤에 물리 simulator adapter를 붙여 command와 measured state를 독립 생성하고, bounded async recorder로 deadline miss·supersession·stop까지 기록하는 것이다. 그 기록에서 desired/measured tracking error, accelerated backend의 reference agreement, p50/p95/p99, worst case와 cancellation latency를 측정한다.

실시간 conveyor architecture ADR과 single-generation decision trace가 이 session의 상위 방향과 입력 근거다.
