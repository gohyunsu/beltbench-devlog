ISSUE-103 · 2026-08-28 · multi-pose grasp generation and support-normal approach

NAS grasp를 runtime에 검색하지 않고 pose별 resident 후보로 만들며, 접근 방향은 target support normal에서 파생한다.

Object ID만 주어지고 stable pose·yaw·위치를 RGB가 측정하는 runtime을 준비하려면 모든 허용 stable-pose class에 비어 있지 않은 grasp set이 필요하다. 보존된 512개 Inspire Left proposal을 먼저 재사용하고, 비어 있는 class에만 BODex를 실행했다. 이 과정에서 grasp 부족처럼 보인 0개 결과가 실제로는 canonical pose의 고정 접근 방향을 다른 pose에 복사한 오류였음을 확인했다.

현재 판정: BeltBench da0eda5에서 pose별 guarded retreat를 target support normal로 교정했다. 동일한 후보와 동일한 threshold에서 source-001은 full-path geometry-clear 0/47에서 44/47로 회복했고, source-002도 44/46을 재현했다. source-000은 settling class 자체가 탈락했고 grasp도 0/3이므로 runtime label set에서 제외한다. 전체 stable-pose campaign과 validation protocol은 여전히 rejected/provisional이어서 runtime·execution 권한은 없다.

BODex native success가 모두 false여도 BeltBench endpoint gate는 47개를 남겼다. 반대로 provider success가 true여도 실행 권한을 주지 않는다. Generator metric은 proposal evidence이고 contact, wrench, support, hand self-collision, approach, closure, retention과 release는 BeltBench가 다시 계산한다.

0/47의 실제 원인

초기 intrinsic config는 canonical source-002의 approach_direction_object=[0,-1,0]을 모든 pose에 복사했다. 이 방향은 source-002의 object-frame support normal과 거의 같지만 source-001의 support normal [0.000636, 1.000000, 0.000567]과는 반대다. 따라서 유효한 side grasp도 pregrasp를 belt 아래쪽으로 이동시켜 approach support collision으로 탈락했다. 512개를 더 생성해도 이 오류는 해결되지 않는다.

BODex의 pregrasp_wrist_se3.npy는 checksum evidence로 보존하지만 runtime approach authority로 사용하지 않는다. 최종 object-relative grasp를 재사용하면서 BeltBench가 다음 식으로 pose별 guarded retreat를 생성하고 sampled collision을 다시 검사한다.

approach_direction_object = R_support_from_object.T @ [0, 0, 1]
pregrasp_translation = grasp_translation + direction * offset

Contact geometry, offset 0.06 m, support/object/self clearance, closure, retention, wrench, capability와 release 기준은 바꾸지 않았다. Derived direction과 stable-pose evidence는 새 manifest identity에 포함된다.

다음 작업

  1. Stable-pose settling campaign을 다시 실행해 허용 class set을 승인한다. source-000은 현재 label set에서 제외하고, source-002 global observation 부족과 전체 unresolved 원인을 해결한다.
  2. source-001/002 44개씩에 retention·drop capability와 object/hand/robot deployment gate를 적용해 bounded shortlist를 만든다.
  3. Pose×yaw×intercept horizon atlas를 offline compile하고 local NVMe/GPU startup verifier를 추가한다.
  4. RGB simulation sensor가 pose class·x/y·yaw를 추정하면 resident atlas를 O(1) 조회하고, unsupported/unknown class는 drop/skip으로 fail closed한다.
