ISSUE-055 · 2026-08-11 · measured MuJoCo Viser replay

계획 animation과 measured simulation replay를 분리하고 1.0x로 재생한다.

기존 Viser는 planning-validated command와 lifecycle을 재생했지만 MuJoCo가 실제로 측정한 servo q, object pose, contact와 실패를 보여주지는 않았다. Source commit 7a80842는 scenario, admission, evidence를 다시 독립 검증한 뒤 실제 arm, Inspire hand, paired connector, object, conveyor, table과 drop bin 위에 measured state를 1.0x로 자동 반복한다. ea842e1은 GPU smoke 결과를 PBS stdout stage-out과 분리해 capability evidence를 직접 남긴다. 보간은 display 전용이며 새로운 접촉이나 성공 상태를 만들지 않는다.

현재 효력: measured rollout이 존재할 때만 새 viewer를 열 수 있다. Viewer는 physics_validation=false, online_collision_authority=false, execution_authorized=false를 유지하며 planner나 controller로 어떤 값도 되돌려 보내지 않는다. Local에 actual cuRobo V2 resident Pepsi bundle이 없으므로 actual grasp replay 성공은 아직 주장하지 않는다.

시작 시점의 문제

  1. 계획과 측정의 혼동: 기존 serve_resident_full_command.py는 source-bound planning diagnostic이다. 여기에 measured q를 선택적으로 덧붙이면 같은 화면이 상황에 따라 계획 또는 측정을 의미하게 된다.
  2. SHA만 확인하는 위험: Evidence 파일 자체 digest가 맞더라도 commanded trace를 바꾸고 다시 hash할 수 있다. 화면을 띄우기 전에 원 command, model, admission과 frame별 trace를 독립 재계산해야 한다.
  3. 10 ms 기록과 60 Hz 화면의 rate 차이: Evidence frame만 그대로 전환하면 실제시간 의미는 유지되지만 animation이 불연속이다. 반대로 모든 값을 보간하면 기록에 없는 contact/event 시점을 만들어낸다.
  4. MuJoCo full hand와 URDF mimic 차이: Simulator는 모든 hand joint를 servo로 측정하지만 현재 Viser URDF adapter는 mimic joint를 독립 degree of freedom으로 렌더링하지 않는다.
  5. Measured overshoot 표시: Servo가 URDF limit을 약간 넘은 것이 실패 증거일 수 있다. 계획 궤적용 limit gate를 그대로 적용하면 viewer가 그 측정값을 숨기거나 로드를 거부한다.
  6. GPU 경로 오염 위험: Viser와 evidence serialization은 비동기 diagnostic이다. 이를 cuRobo resident worker와 같은 GPU deadline 경로에 넣으면 planner latency만 증가한다.

Source closure와 fail-closed load

CLI는 --scenario, --admission, --evidence 세 경로를 필수로 받는다. Scenario loader가 command, leases, lifecycle, robot/object/workcell assets, collision semantics, calibration, physics/actuation config, rollout policy, simulator capability와 exact MJB의 bytes를 검증한다. 이후 persisted admission과 evidence를 읽고 기존 independent verifier를 다시 실행한다.

Verifier는 command tensor, validated lease, rollout policy, model과 admission digest뿐 아니라 control time grid, commanded q/qd, phase/event, planned object pose/state, transport flag와 diagnostic decision까지 원 source에서 재계산한다. 따라서 Viser 전용 fallback loader는 없다.

Actual-time sampling 규칙

Playback clock은 monotonic wall time을 1.0배로 진행하며 기본 Play=true, Loop=true다. 10 ms evidence control frame 사이의 화면만 다음 규칙으로 생성한다.

  • Measured arm/full-hand joint position: linear interpolation
  • Measured object와 planned object SE(3): position linear interpolation + orientation Slerp
  • Phase, reached event, planned/measured lifecycle, active contact pair, kinematic transport: 직전 evidence frame zero-order hold
  • Evidence timestamp와 정확히 일치할 때: exact measured frame으로 표시

상태 markdown에는 continuous source와 discrete source를 별도로 출력한다. 따라서 60 Hz 화면 frame이 simulator의 새 측정값으로 오인되지 않는다. Contact evidence에는 geometry pair만 있고 point가 없으므로, 임의의 접촉 위치를 그리지 않고 pair를 텍스트로 표시한다.

실제 자산 장면

기존 shared scene을 사용하므로 선택된 arm URDF, hand URDF, white paired connector CAD, object GLB, calibrated workcell primitive가 그대로 나타난다. Measured robot과 object가 주 상태이며 measured path는 녹색, planned path는 주황색으로 분리했다. Planned object pose frame은 기본 off이고, arm, hand, connector, object, workcell, 두 path, coordinate frame과 전체 label을 각각 제어할 수 있다.

Measured hand에서 command-independent joint를 Viser에 전달하고 URDF mimic relation으로 hand mesh를 구성한다. 동시에 measured full joint와 URDF realization 사이 관절별 최대 residual을 계산해 화면에 공개한다. 종속 joint를 실제 measured 자유도로 독립 렌더링하지 못하는 제한을 성공처럼 숨기지 않는다.

발생한 문제, 원인과 해결

  1. JointState.values_for 부분 선택 오류: 첫 테스트에서 full state에서 arm subset을 읽으려다 joint state names disagree with model이 발생했다. 이 API는 subset selector가 아니라 전체 model identity guard다. Evidence의 canonical concat order로 arm/hand를 분리하고, hand projection은 이름 dictionary로 명시해 해결했다.
  2. Visualization 환경의 hppfcl 부재: 새 replay와 무관한 test_end_effector를 visualization 환경에 함께 넣자 native planning module import가 실패했다. Visualization 회귀와 planning hand-model 회귀를 각 Conda 환경으로 분리했다.
  3. Sandbox에서 Conda temp 생성 실패: 비승인 style probe가 writable temp directory를 찾지 못해 Conda 자체 예외를 냈다. Test write가 필요한 실행은 승인된 환경에서 수행하고, 설치되지 않은 formatter를 새 의존성으로 추가하지 않았다. git diff --check와 기존 형식 기준으로 검사했다.
  4. Measured limit overshoot: Shared scene은 계획 상태에 URDF limit을 강제한다. enforce_urdf_limits를 명시적 boolean으로 분리하고 measured viewer만 false를 사용하되 joint identity와 finite state validation은 항상 수행하도록 했다.
  5. PBS stdout stage-out 실패: junjinyong job 115836.ECE-util1은 A6000 node에서 exit 0이었지만 Post job file processing error로 driver 출력이 login node에 전달되지 않았다. Smoke script가 beltbench-runs/gpu-smoke/JOB_ID.txt를 임시 파일 뒤 atomic rename으로 직접 만들도록 수정했다. 재실행 115838.ECE-util1의 artifact는 정상 회수됐다.

실행 방법

conda run -n beltbench-visualization \
  python -m scripts.serve_resident_full_command_mujoco \
  --scenario local/simulation/resident-full-command/scenario.json \
  --admission local/simulation/resident-full-command/admission.json \
  --evidence local/simulation/resident-full-command/rollout.json

Viewer가 열리려면 세 파일뿐 아니라 scenario가 결속한 모든 source asset과 exact MJB가 원래 상대 경로에 있어야 한다. Diagnostic failure evidence도 재생할 수 있으며 화면 상단에 FAIL과 failure code가 그대로 나타난다.

현재 남은 제한과 다음 gate

  1. Local에 actual source-closed resident Pepsi command와 measured rollout bundle이 없어 실제 xArm, Inspire hand, Pepsi success replay를 end-to-end로 띄우지 못했다.
  2. Contact point/normal/force가 frame evidence에 없어서 geometry pair만 표시한다. 향후 위치 시각화가 필요하면 simulator가 측정한 contact point를 evidence schema에 추가해야 하며 viewer가 추정하면 안 된다.
  3. Viser URDF adapter는 full measured mimic-dependent joint를 독립 렌더링하지 않는다. Residual이 무시할 수 없으면 explicit full-joint renderer 또는 measured link-transform trace가 필요하다.
  4. junjinyong A6000 driver 535는 선택한 cuRobo V2 0.8.0 최소 580.65.06에 미달한다. Exact sphere fitting, HPP-FCL zero-false-negative parity와 target GPU p99가 통과하기 전 online collision authority는 없다.
  5. 실제 belt와 robot이 준비되면 controller receipt, perception freshness, grasp close/retention, drop containment와 abort timing을 measured hardware trace로 별도 연결해야 한다.

Resident MuJoCo measured rollout, Planning full-command actual-asset diagnostic, cuRobo real-time collision audit을 함께 참고한다.
