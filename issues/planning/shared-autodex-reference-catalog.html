ISSUE-095 · 2026-08-27 · content-addressed pose/grasp/outcome lookup

공유 원본을 복제하지 않고 pose, grasp와 결과를 재현 가능한 한 행으로 조회한다.

AutoDex episode, candidate, stable-pose ID와 성공 라벨은 서로 다른 디렉터리에 저장돼 있다. 이를 파일명이나 mutable index로 연결하면 출처가 쉽게 끊기므로, 기존 source-closed record를 다시 결속하는 content-addressed query view를 추가했다.

현재 판정: revision 2759b9f에서 실제 NAS Pepsi 3개 episode를 전부 재해시해 성공 2개와 실패 1개를 연결했다. Catalog는 offline provider proposal 조회만 허용하며 pepsi/008/Allegro를 pepsi_light/upside_down/Inspire Left로 승격하지 않는다.

발생한 문제와 원인

문제원인과 위험
Pose, grasp와 outcome이 분리돼 있다.Episode, producer candidate와 label의 경로가 달라 디렉터리 이름만으로 join하면 다른 실험 결과를 섞을 수 있다.
Source object와 BeltBench object 이름이 다르다.pepsi와 pepsi_light의 mesh frame, scale와 semantic identity가 동일하다는 resolution이 없다.
Provider pose 008의 의미가 불명확하다.Pose template에는 RGB와 C2R.npy가 있지만 008=upside_down을 선언한 검증 메타데이터를 찾지 못했다.
Provider 성공을 곧바로 재사용할 수 없다.실행 hand는 Allegro이고 정적 provider episode label이다. Inspire Left moving pick의 성공률이 아니다.
NFS를 runtime lookup에 쓰면 deadline이 흔들린다.Archive traversal, JSON parse와 hash는 offline/startup 작업이며 60 Hz 제어 경로에 들어가면 안 된다.

선택한 저장 경계

계층저장 위치와 역할
Shared source/mnt/paradex2/<source-tree>, 논리적 read-only 원본. 수정하거나 통째로 복사하지 않는다.
Immutable records/mnt/paradex2/hyunsu/beltbench/registry/v1/episodes와 resolutions/autodex-candidate. 원본 URI, symlink target, size와 SHA-256이 authority다.
Derived viewregistry/v1/views/autodex-source-reference/<dataset>/<entry-set-sha256>/catalog.json. Source record를 빠르게 조회하기 위한 불변 snapshot이며 authority를 추가하지 않는다.
Semantic evidenceassets, grasps, plans, trials 아래의 append-only object/pose resolution, grasp qualification와 exact-context trial.
Runtime stage선택·검증된 최소 bundle만 RTX local NVMe로 복사한다. NFS와 catalog는 event/control 경로에서 읽지 않는다.

Catalog가 실제로 결속하는 항목

  • Episode와 candidate resolution의 record ID, 상대 경로와 canonical digest
  • Source object mesh와 episode initial world pose digest
  • Provider stable-pose ID와 end-effector ID
  • Candidate wrist, pregrasp와 grasp command digest
  • Provider outcome label digest, success/failure 값과 candidate-result join
  • 남은 여섯 gate와 runtime_eligible=false, hardware_reliability_eligible=false

재사용 전에 필요한 여섯 gate

  1. Source mesh digest, 단위와 frame을 BeltBench object identity에 연결한다.
  2. Provider pose와 BeltBench stable pose의 양방향 transform 및 support semantics를 검증한다.
  3. Object-relative wrist를 해석한 뒤 Inspire Left grasp를 transfer하거나 새로 생성한다.
  4. Hand-object contact, penetration, self/support clearance와 retention을 독립 검증한다.
  5. xArm6, connector, workcell, moving object에 대한 IK·collision·timing을 검증한다.
  6. 동일 hardware/protocol에서 분리된 moving-pick trial batch와 보수적 성공률을 확보한다.

2026-08-27 후속: 기존 경로를 보존한 채 새 write namespace를 고정

실제 /mnt/paradex2/hyunsu/beltbench를 다시 조사하니 초기 실험에서 만든 root-level bodex/, candidates/, trajectories/와 현재 규약의 grasps/*, plans/*가 함께 존재했다. 기존 디렉터리를 보기 좋게 재배치하면 과거 artifact의 상대 참조와 checksum lineage를 깨뜨릴 수 있으므로 이동하지 않는다.

문제원인선택한 해결결과
초기 경로와 canonical 경로 혼재데이터 레이아웃 계약이 생기기 전에 BODex 후보와 trajectory가 root에 기록됨세 기존 root를 legacy read-only evidence로 동결하고 새 run은 grasps/bodex-runs, grasps/proposals, plans/deployment-bundles에만 기록기존 lineage를 보존하면서 이후 artifact의 의미와 수명주기가 분리됨
Provider success와 BeltBench success 혼동 가능같은 catalog 행에서 pose, grasp와 outcome을 함께 조회할 수 있음Catalog는 provider evidence만 유지하고 intrinsic, deployment, moving reliability를 별도 digest-linked record로 누적성공 2개는 우선 검증 후보가 되지만 Inspire moving-pick 권한은 계속 false

Runtime은 이 NAS 구조를 직접 조회하지 않는다. Offline bundle compiler가 선택된 object mesh, stable-pose resolution, exact object-relative grasp, hand command, qualification와 calibration의 digest를 검증해 local NVMe에 최소 bundle을 만들고, startup 이후 event와 60 Hz loop는 그 resident bundle만 사용한다.

실행 중 발생한 환경 문제

서버의 새 checkout은 package가 editable-install되지 않아 script 파일을 직접 실행했을 때 ModuleNotFoundError: beltbench가 발생했다. Unit test는 같은 revision에서 이미 통과했고 원인은 source tree import path 누락이었다. 검증 명령에는 PYTHONPATH=.를 명시해 동일 checkout을 사용했다. 실제 배포에서는 ad-hoc path 대신 pinned environment에 BeltBench revision을 설치해야 한다.
