ISSUE-051 · 2026-08-29 update · 5 ms full-task collision closure

Nominal과 모든 abort route를 한 fixed-shape GPU validation lease로 닫는다.

교수님의 inference demo 우선 방향과 사수님의 “충돌에 cuRobo를 왜 사용하지 않는가”라는 질문을 실제 runtime 경계로 반영했다. Online에서는 cuRobo가 self/world/object continuous collision과 dynamics의 수치 authority를 맡고, CPU는 compact hard reduction, deadline, cancel과 controller I/O만 맡는 것이 타당하다. 하지만 단순히 cuRobo라는 backend 이름을 기록하는 것으로는 어떤 command, collision lifecycle과 abort route가 검증됐는지 증명할 수 없으므로 exact pass coverage와 CUDA event lineage를 typed lease로 강제했다.

현재 효력: 4f9c545의 RTX r22는 1,800-sample nominal command, 12개 abort route와 40개 pass를 source-closed하게 검사했다. 5 ms continuous cell, source-bound takeoff support, 단일 multi-environment cuRobo world query와 time-indexed release cylinder를 적용한 결과 32/40 pass를 통과했고 event 20회 p50 17.918 ms, p95 18.025 ms, 최대 18.542 ms를 기록했다. 그러나 nominal pre-contact, attached takeoff, post-detach clearance와 abort 002·003·005·006·010이 거절되므로 validated lease, working grasp demo와 hardware execution 권한은 계속 차단한다.

왜 cuRobo와 GPU resident인가

책임선택이유

발견한 문제와 원인

  1. Full-task validation artifact 부재: Producer lease는 command tensor 쓰기 완료만 나타냈다. Nominal segmented collision, dynamics와 abort collision·dynamics·terminal coverage를 한 번에 확인할 방법이 없었다.
  2. Host transfer 증가 위험: Pass마다 전체 result tensor를 host로 복사하거나 파일 evidence를 쓰면 GPU 가속 이득이 사라진다.
  3. Validator 독립성 모호: Solver output을 같은 graph 결과로 승인하면 최적화 과정의 누락을 독립 검증이라고 부를 수 없다.
  4. Producer backend lineage 누락: Producer lease가 output의 backend ID와 warmed runtime session backend를 비교하지 않았다. 임의 backend가 같은 allocation을 생산한 것처럼 기록될 수 있었다.
  5. Draft motion limit 승격 위험: 형식상 정상인 draft limit으로 full-task validated lease를 만들면 hardware 의미가 과장된다.

구현한 해결

  • Pass 순서를 nominal collision lifecycle 전체, nominal dynamics, 각 abort window의 collision·dynamics·terminal-region으로 고정했다. Current pick-and-drop fixture는 3+1+5×3으로 19 slot이다.
  • Dynamic-world pass는 world pose update와 time-indexed target contact를, attached pass는 attached-object collision을, drop pass는 release-envelope collision을 요구한다. 모든 collision pass는 robot self/world와 continuous collision operation을 포함한다.
  • 각 pass evidence는 exact command/tensor/lifecycle digest, sample range, resident source slot, source completion event와 operation set을 결속한다. Caller는 이 metadata를 지정하지 못하고 compact outcome만 제공한다.
  • Validator backend와 CUDA graph는 producer와 달라야 한다. Final validation event는 nominal producer와 모든 abort upload event와 달라야 하며 source-aware verifier가 전체 lease를 재생성한다.
  • GPU는 pass별 minimum normalized margin과 accept mask를 fixed result slot에 쓴다. Host readback은 1회, deadline 경로의 synchronous artifact write는 0으로 고정했다.
  • Motion limits는 template digest와 정확히 같고 authority가 manufacturer 또는 measured여야 한다. Draft profile은 fail-closed한다.
  • Producer lease도 output planner backend가 warmed runtime session backend와 같아야 생성되도록 강화했다.

구현 중 문제와 처리

  • 첫 validation fixture에서 abort latch maximum을 0.5초로 임의 지정해 기존 abort catalog가 route continuation을 올바르게 거부했다. Production gate를 완화하지 않고 기존 exact fixture와 동일한 3.0초 bound로 수정했다.
  • 새 테스트가 통과한 뒤 source lineage를 다시 검토해 producer backend/session 불일치를 발견했다. Producer lease builder에 equality gate를 추가하고 foreign backend 회귀 테스트를 넣었다.
  • Fixture motion profile은 원래 draft였다. Validated lease 성공 fixture만 manufacturer authority로 바꾸고 별도 draft rejection 테스트를 추가해 권한 차이를 숨기지 않았다.
  • Contract payload 자체는 source 객체를 알 수 없으므로 generic validate()와 source-aware verify()를 분리했다. Verification은 producer output, request, template, nominal lifecycle, runtime session, abort catalog, route command/lifecycle와 motion profile에서 전체 pass를 재구성한다.

2026-08-28 continuous self-sweep 구현 감사

발생한 문제원인해결과 결과

Command segment가 길어도 subinterval 수가 전역 상수 1로 남을 수 있었다.전체 command의 고정 subdivision을 사용해 segment별 시간 길이와 20 ms 최대 cell 폭을 결속하지 않았다.8aec7c8에서 각 segment의 cell 수를 startup에 ceil(dt / maximum_cell_duration)으로 계산하고 ragged segment를 고정 resident index로 평탄화했다. Event path에는 allocation을 두지 않고 전체 cell 상한을 startup에서 검사한다.
첫 실제 benchmark에서 collision 0으로 보였지만 command hand joint와 cuRobo cspace joint 순서가 달랐다.두 입력의 joint 개수만 같다고 보고 tensor column을 이름으로 재정렬하지 않았다. Thumb-first command를 index-first kinematics에 그대로 전달했다.50011c9에서 command와 kinematics joint inventory의 exact equality를 요구하고 q/qd/qdd에 같은 startup permutation을 적용했다. 이전 collision 결과는 폐기했으며 순서 불일치는 회귀 테스트로 고정했다.
Corrected 연속 팽창이 현재 prefix를 거절했다.구간 내부 motion을 sphere radius에 보수적으로 더하자 endpoint-only 검사에 없던 near self-clearance가 드러났다.ac1d932의 source-bound benchmark에서 replan cutoff까지 144 cell을 100회 측정했다. p50 18.949 ms, p95 19.082 ms, p99 19.996 ms, 최대 20.002 ms, 50 ms miss 0이었으나 80 cell에서 최대 2.044e-5 collision cost가 검출돼 fail-closed했다. Threshold를 완화하거나 결과를 clear로 재해석하지 않는다.

Checker 구성 118.39초와 첫 호출 0.591초는 startup workload다. Event hot path는 resident 144-cell prefix 한 번만 실행했다. 이 수치는 self-collision component에만 유효하며 static world, dynamic target, attached object, release envelope, suffix certificate, abort route나 controller 실행을 검증한 end-to-end 수치가 아니다.

2026-08-29 actual full-task와 startup/event 분리

Prefix component 수치만으로 full-task 실시간성을 주장할 수 없으므로 source-closed singleton command 전체를 actual xArm6+Inspire Left cuRobo model에 올렸다. 입력은 1,531-sample nominal command, 11개 abort route, 37 validation pass, 5,882 robot sphere와 6 attached-object sphere다. Dynamic-world, attached-object, release-envelope, continuous dynamics와 terminal region을 모두 같은 pass order로 평가한다.

발생한 문제원인해결과 결과
Full validator를 event마다 반복하면 약 1초가 필요했다.Object pose와 무관한 robot self/world, attached, release, dynamics와 terminal 검증까지 매 perception event에 다시 실행했다.1f558c5에서 startup 불변 operation과 event 동적 operation을 분리했다. 각 pass에서 두 operation 집합은 겹치지 않고 합집합이 기존 full pass와 정확히 같아야 하며, certificate와 event result는 서로 다른 completion event를 갖는다.
첫 authoritative 분리 구현의 event p50이 582.975 ms로 악화됐다.GPU kernel은 빠르지만 event마다 1,531개 nominal sample과 11개 abort lifecycle을 다시 validate하고 JSON으로 직렬화해 SHA-256을 계산했다. GPU 가속 문제가 아니라 source-evidence 경계를 잘못 둔 CPU 병목이었다.3ce2007에서 event kernel이 실제로 읽는 pass ID, lifecycle ID, object state, trajectory time, 4×4 object pose와 belt-frame velocity의 canonical binary digest만 계산했다. 같은 50회에서 p50 10.843 ms, p95 11.323 ms, 최대 12.050 ms로 줄었다.
Float32 command tensor로 dynamics를 재구성하자 매우 작은 반올림 오차가 false failure가 됐다.Collision용 source shape와 source q/qd/qdd 정밀도를 하나의 dtype으로 취급했다.dcf6fd5와 cb90d91에서 collision은 cuRobo source shape인 float32를 유지하고 dynamics sidecar는 float64로 분리했다. Machine epsilon 수준만 canonical zero로 처리하며 물리 margin이나 threshold는 완화하지 않았다. Nominal position 0, velocity 0.199992, acceleration 0.087240, jerk 0.200000 margin을 재현했다.
Attached failure 하나만 보고하면 connector/grasp와 workcell 중 무엇이 원인인지 알 수 없었다.Robot-object와 object-world, knot와 swept margin을 하나의 minimum으로 축약했다.799bff2에서 네 component를 분리했다. Nominal knot robot-object는 +0.451968로 clear지만 object-world knot는 -0.027384, swept robot-object는 -2.079545, swept object-world는 -0.028944다. Connector threshold를 임의 조정하지 않고 trajectory·grasp·workcell 문제를 별도로 수정할 수 있게 됐다.
재현 명령 두 번이 artifact 생성 전에 중단됐다.첫 시도는 nominal continuation 3.0초 조건을 누락했고, 두 번째는 source-revision에 BeltBench commit을 넣어 cuRobo source revision 의미를 혼동했다.정확한 continuation bound와 cuRobo revision을 명시하고, 실패 시 output directory를 남기지 않는 write-once 동작을 확인했다. 이후 source manifest가 repository revision, robot config, assembly, scene과 모든 입력 파일 digest를 분리해 기록한다.

RTX 3090 source-closed 결과

  • 기존 full 37-pass validation은 p50 999.239 ms였고 startup 불변 certificate 생성은 1.653초였다. 둘은 acquisition 이전 1회 비용이며 frame event deadline 수치가 아니다.
  • Authoritative event validation은 dynamic world pose update, time-indexed target contact와 swept dynamic-object collision만 실행한다. Artifact write 없이 50회 p50 10.843 ms, p95 11.323 ms, 최대 12.050 ms를 기록했다.
  • 느린 구현과 경량 구현의 37개 outcome 및 모든 component margin은 byte-level JSON 비교에서 동일했다. 최적화가 collision 판정을 바꾸지 않았음을 확인했다.
  • Current command는 26/37 full pass, 27/37 startup invariant partition, 2/4 event pass만 통과했다. Nominal pre-attach는 bounded contact -1, violation count -22이며 abort dynamic pass 하나도 violation count -1이다.
  • Nominal attached pass는 robot-object swept, object-world knot/swept와 작은 continuous self margin에서 실패한다. Post-detach release envelope와 일부 abort attached/release/self-sweep도 실패한다.
  • startup-invariant-certificate.json, event-validation-result.json, partitioned-full-task-validation.json을 별도 보존한다. 현재 validated lease schema가 두 digest를 아직 결속하지 않으므로 complete operation coverage와 낮은 지연만으로 lease를 만들지 않는다.

r13에서 특정된 실제 병목

  • Pre-attach swept minimum은 8.641667초의 left_ring_2이며 물체 margin은 -3.492 mm다. 8.7초 contact knot에서는 최소 contact count가 1개 부족하다. Threshold를 낮출 문제가 아니라 guarded closure와 grasp command를 함께 재최적화해야 한다.
  • Attached knot의 robot-object margin은 +4.520 mm지만 13.028156초 swept cell에서 left_middle_1 대 sphere-000이 -20.795 mm다. 정적 grasp 하나만 보지 말고 운반 속도와 continuous inflation을 포함한 궤적 후보를 다시 만들어야 한다.
  • Attached object-world는 attach 경계 9.0초부터 실패한다. 물체가 벨트 지지면과 의도적으로 접촉한 상태를 generic world collision로 검사한 것이므로, 다른 환경 충돌을 숨기는 전역 mask가 아니라 source-bound transient support-contact model이 필요하다.
  • Detach 직후 release envelope는 16.895760초의 left_middle_1에서 -16.106 mm다. 현재 allowed contact는 distal geometry만 포함하므로 proximal link를 근거 없이 허용하지 않고 grasp/release 형상을 수정해야 한다.
  • 11개 abort collision pass 중 8개가 실패했다. Early dynamic route 2개와 attached/release route 3개는 작은 swept self cost만 남았고, 나머지는 nominal과 같은 object/support/release 병목을 상속했다. Abort threshold를 따로 완화하지 않는다.

r13은 RTX 3090, Torch 2.5.1+cu121, CUDA 12.1과 고정된 cuRobo revision에서 실행했다. 37개 outcome과 모든 component diagnostic은 r9와 동일했다. Witness 추출은 0.605초의 별도 진단 비용이었으며 event p50/p95에는 포함되지 않는다.

  • Nominal attached robot-object swept는 +0.487 mm로 통과했지만 takeoff sphere-world는 -26.722 mm다. Exact mesh deck clearance는 9.14852초 1.134 mm이므로 source-bound cylinder/world parity 또는 fixed-command exact oracle 결속이 필요하다.
  • Nominal release cylinder swept는 21.35317초 left_ring_2 -3.333 mm다. 실제 mesh 비충돌만으로 robust clearance를 통과시킬 수 없으므로 hand-open/arm-separation suffix를 motion limits 안에서 재계획해야 한다.
  • Abort 005·006·010은 각각 1.07e-5, 8.82e-7, 3.56e-5 수준의 5 ms swept self margin만 남았다. 이를 zero 처리하지 않고 동일 source의 1 ms certificate를 별도 생성해 temporal convergence를 검사한다.

현재 제한과 다음 단계

Actual full-task validator와 실시간 event partition은 구현됐지만 현재 singleton grasp와 command가 gate를 통과하지 않는다. 또한 partition digest를 controller lease가 아직 재현하지 않고 Isaac RGB runner도 이 concrete validator를 호출하지 않는다. 따라서 18.025 ms component가 확인됐다는 사실을 working grasp demo 또는 end-to-end latency로 승격하지 않는다.

  1. 완료한 8개 shortlist 일괄 qualification 결과 rank 1만 dense-valid였으므로, 8.641667초 left_ring_2와 13.028156초 left_middle_1 witness를 objective로 삼아 object-relative grasp·guarded closure·운반 속도를 공동 재최적화한다.
  2. Attach 경계의 의도된 벨트 지지 접촉은 다른 object-world 충돌을 숨기지 않는 obstacle-specific transient support model로 표현한다. Release의 proximal link 충돌은 contact allowlist 확장이 아니라 grasp/release 형상으로 해결한다.
  3. Partition startup certificate와 event result digest를 validated lease와 controller handoff에 추가하고, 둘 중 하나라도 foreign·stale·reordered이면 publication을 차단한다.
  4. Isaac RGB camera에서 얻은 object identity, stable pose, planar x/y/yaw와 belt velocity를 dynamic event input으로 연결한다. Perception uncertainty와 timestamp는 collision margin과 별개로 deadline/slack gate가 소비해야 한다.
  5. 실제 accepted route가 생긴 뒤에만 Isaac physics/controller를 같은 command에 연결하고, perception→selection→GPU validation→handoff→grasp→drop 상태를 실제 시간 색상 overlay로 영상화한다.

Exact full-command producer lease, Resident abort collision, cuRobo real-time collision audit를 함께 참고한다.
