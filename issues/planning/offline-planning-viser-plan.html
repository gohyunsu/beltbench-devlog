프로젝트이슈
ISSUE-009 · 2026-08-06 · 진행 중

실제 로봇 없이 planning 결과와 실패 원인을 Viser에서 검증한다.

현재 가능한 연구 범위를 offline planning과 visualization까지로 제한했다. 목표는 conveyor animation을 빠르게 만드는 것이 아니라, 저장된 scene과 plan만으로 grasp 후보가 왜 가능하거나 불가능한지 재현하고 검사할 수 있는 기반을 만드는 것이다.

현재 구현에서 확인한 한계

기존 xArm trajectory는 URDF의 여섯 revolute joint를 읽어 numerical IK와 cubic interpolation을 수행한다. joint limit과 velocity는 확인하지만 fixed joint를 포함한 전체 robot geometry, self-collision, table·conveyor collision, 여러 grasp 후보 비교, object motion과 intercept time은 다루지 않는다. 기존 visualizer는 최종 상태와 tool path를 GLB로 내보내므로 공유에는 적합하지만 timeline과 실패 진단을 대화형으로 확인할 수 없다.

설계 원칙

Artifact가 기준이다

scene, request, plan, validation을 versioned JSON으로 먼저 저장한다. planner와 Viser는 같은 artifact를 사용하며 UI가 pose나 trajectory를 임의로 다시 계산하지 않는다.

Viewer는 계산하지 않는다

Viser는 robot·hand·object·conveyor, candidate, trajectory, collision 진단을 표시할 뿐이다. FK, IK, collision, candidate ranking과 timing은 planning module이 담당한다.

검증기는 planner와 독립적이다

planner가 성공을 선언해도 별도 validator가 joint, velocity, acceleration, clearance와 timing margin을 다시 계산한다. validator를 통과하지 못한 plan은 항상 execution-blocked다.

실환경 입력은 adapter다

지금은 synthetic object state를 사용한다. 이후 FoundationPose·GoTrack 결과는 같은 ObjectState contract로 변환하므로 planning과 Viser 내부를 바꾸지 않는다.

구현 단계

  1. P0 · fixture와 contract: frame, unit, asset checksum을 가진 planning scene과 request/result schema를 고정하고 synthetic fixture를 만든다.
  2. P1 · Viser scene: robot link, Inspire hand, object, conveyor, collision proxy와 좌표계를 표시한다. joint slider 결과와 Pinocchio FK가 일치하는지 검사한다.
  3. P2 · static grasp feasibility: 여러 object-frame grasp를 workspace, approach, multi-seed IK, joint limit, self/environment collision 순서로 거르고 rejection reason을 색으로 표시한다.
  4. P3 · collision-aware motion: start, pre-grasp, grasp, lift, retreat를 계획하고 time parameterization 후 더 촘촘한 sample로 독립 재검증한다.
  5. P4 · plan playback: play/pause, scrubber, phase 이동, tool/object path, minimum-clearance pair, score와 timing을 표시하고 두 plan을 비교한다.
  6. P5 · moving interception: 일정 속도 object의 미래 pose와 후보 intercept time을 탐색하고 latency를 포함한 도착 가능성과 dynamic collision을 검사한다.
  7. P6 · 반복 평가: object pose, belt speed, robot start, latency, obstacle, grasp set을 seeded matrix로 실행해 feasibility, failure taxonomy, planning time, clearance와 timing margin을 집계한다.

도구의 역할

Pinocchio는 robot kinematics와 geometry model, hpp-fcl은 collision과 distance query에 사용한다. sampling planner와 time parameterizer는 교체 가능한 interface 뒤에 둔다. Viser는 interactive diagnostic frontend로만 사용하고 기존 GLB export는 정적 공유 수단으로 유지한다. CPU core, offline planning, GoTrack GPU 환경은 서로 분리해 pinning한다.

첫 번째 완료 기준

첫 milestone: 저장된 static scene 하나를 Viser에서 열고, 모든 grasp 후보의 accepted/rejected 상태와 이유를 확인하며, 같은 결과를 독립 validation artifact로 재현한다.

그 다음에만 collision-aware trajectory와 playback을 추가한다. 움직이는 object는 static planning의 FK·collision·timing 검증이 끝난 뒤 도입해 원인 혼합을 방지한다. 현재 단계는 계획 수립이며 Pinocchio, hpp-fcl, Viser dependency 설치 smoke와 license 확인은 아직 수행하지 않았다.

2026-08-06 · P0/P1 첫 vertical slice

PlanningScene, entity, trajectory frame을 versioned JSON으로 정의하고 arm, hand, target, distractor, conveyor가 반드시 존재하는지 검증하도록 구현했다. synthetic selective-pick fixture는 target만 들어 올려 destination으로 옮기고 다른 object는 belt를 따라 계속 이동한다. live Viser에는 play/pause, timeline, speed와 arm·hand·target·other objects·conveyor·environment·trajectory·frame toggle을 추가했다.

같은 scene adapter를 live viewer와 exporter가 공유한다. 121 frame, 8초 trajectory를 JSON으로 저장하고 Viser serializer로 timeline이 포함된 self-contained HTML animation을 만들었다. UI는 FK나 trajectory를 다시 계산하지 않고 저장된 frame pose만 표시한다.

구현 중 발생한 문제

가변 link처럼 보이는 fixture

초기 arm pose 계산은 elbow를 wrist 위치의 비율로 정해 link 길이가 trajectory 동안 달라질 수 있었다. 실제 planning과 혼동되는 잘못된 표현이므로 고정 길이 two-link 기하를 도입하고 모든 wrist waypoint에 reachability guard를 적용했다.

reachability 실패

첫 artifact 생성에서 최대 wrist 거리가 설정 reach를 약간 초과해 즉시 실패했다. guard를 우회하지 않고 link 길이와 workcell fixture를 함께 검토해 모든 waypoint가 명시적 reach 안에 들도록 수정했다.

회전 경고

한 vector만으로 link orientation을 맞추자 roll이 유일하지 않다는 SciPy 경고가 발생했다. local Z를 link 방향으로 보내는 최소 회전을 axis-angle로 직접 계산해 결정적 orientation으로 교체했다.

중복 가능성

live viewer와 animation exporter가 scene 생성 코드를 각각 가지면 display가 달라질 수 있다. 공통 Viser scene adapter를 만들고 두 command가 같은 entity handle과 frame 적용 함수를 사용하도록 정리했다.

검증 결과와 경계

로컬에 별도 Python 3.10 visualization 환경과 Viser 1.0.29를 생성했다. 신규 planning contract·playback test 5개가 통과했고, GPU 서버에서는 기존 test와 합쳐 23개가 통과했다. live server의 HTTP 응답과 121-frame standalone animation 생성을 확인했다.

아직 실행 불가: 현재 arm과 hand는 contract·playback 검증을 위한 schematic geometry다. xArm URDF FK, 실제 Inspire mesh, grasp candidate IK, self/environment collision은 아직 연결하지 않았다. artifact의 execution-blocked reason에 이 경계를 기록한다.

2026-08-06 · 외부 robot asset 연결

특정 checkout 경로를 코드에 넣지 않고 arm URDF, hand URDF, arm tip link, hand root link, world transform과 mount transform을 별도 manifest로 정의했다. 실제 xArm mesh와 Inspire left-hand mesh를 Viser에 로드해 각각 6개의 independent joint control을 확인했고, mimic finger joint는 URDF 정의에 따라 확장된다. arm joint가 바뀔 때 arm tip FK로 hand root frame도 함께 갱신한다.

첫 실행에서 xArm 6축과 Inspire 6축이 모두 로드되고 local Viser endpoint가 정상 응답했다. joint lower limit이 정확히 0인 경우 일반적인 or 표현을 사용하면 fallback 값으로 바뀔 수 있는 문제를 코드 검토에서 발견해, None만 대체하도록 수정했다.

검증 경계: 현재 local manifest의 arm-tip-to-hand-root 값은 표시 경로 검증용 identity다. 실제 mount 측정값, collision geometry 승인, IK와 trajectory validation 전에는 execution에 사용할 수 없다.

2026-08-06 · 실제 URDF joint trajectory playback

planner와 executor가 함께 사용할 수 있도록 arm·hand joint 상태를 이름 기반으로 저장하는 versioned trajectory contract를 추가했다. frame마다 time, phase, arm joints, hand joints를 기록하고 시간 증가, joint set 불변, finite radian 값과 execution-block reason을 검증한다.

URDF joint limit에서 안전한 표시용 121-frame fixture를 생성하고 기존 xArm·Inspire inspector에 timeline, play/pause, speed와 phase 표시를 연결했다. trajectory joint 이름이 로드된 URDF와 다르면 표시 전에 거부한다. playback 중 arm configuration, Inspire mimic configuration, arm-tip FK와 hand mount가 같은 frame에서 갱신된다.

로컬 포트 8092에서 xArm 6축과 Inspire 6축 playback startup 및 HTTP 응답을 확인했다. 이 fixture는 IK와 collision이 없는 UI 검증이므로 실행 차단 상태를 유지한다.

2026-08-06 · playback 코드 재검토

전체 연결을 다시 검토해 외부 trajectory가 URDF joint 이름만 맞으면 position limit를 넘더라도 표시될 수 있는 누락을 발견했다. 모든 frame을 URDF lower·upper limit와 다시 대조하는 독립 validator를 추가하고 limit 초과 regression test를 작성했다.

trajectory playback 중 manual joint slider가 활성화되어 두 입력 source가 경쟁할 수 있었으므로 playback mode에서는 slider를 비활성화했다. timeline callback마다 timestamp 배열을 다시 만들던 불필요한 처리도 초기화 시 한 번만 계산하도록 정리했다. 수정 후 로컬 관련 테스트 11개와 GPU 서버 전체 테스트 29개가 통과했다.

2026-08-06 · 특정 robot·hand 의존성 재검토

core PlanningScene이 arm, hand, target, distractor, conveyor category를 모두 요구하고 live viewer도 같은 이름으로 toggle과 path를 만들고 있었다. 이는 synthetic demo의 구체적 구성을 공통 계약으로 잘못 끌어올린 것이다. entity category를 scene-safe한 개방형 문자열로 바꾸고, viewer는 실제 scene에 존재하는 category와 움직이는 entity를 탐색해 toggle과 path를 자동 생성하도록 리팩터링했다.

hand demo도 모든 관절이 0에서 양의 upper 방향으로 닫힌다고 가정했다. 각 URDF joint의 lower·upper 안에서 0에 가장 가까운 neutral을 구하고 neutral에서 upper 방향으로 이동하도록 수정해 음수 범위나 0을 포함하지 않는 joint에도 적용 가능하게 했다. 외부 trajectory는 표시 전 모든 frame을 URDF position limit와 다시 대조한다.

구체적인 xArm·Inspire 이름과 conveyor 치수는 검증 fixture와 local manifest에만 남는다. 공통 contract, Viser adapter, trajectory validator에는 joint 수, joint 이름, entity category 목록을 하드코딩하지 않는다. 관련 로컬 테스트 13개와 서버 전체 테스트 31개가 통과했다.

2026-08-06 · P2 kinematic feasibility 경계

기존 xarm_trajectory.py에 기능을 더 붙이지 않고 공통 RobotModel과 SingleSeedIK interface를 만들었다. object frame grasp에서 pre-grasp와 grasp tool target을 구성하고, 여러 seed의 IK를 결정적으로 비교하며, 두 target이 모두 통과할 때만 kinematic_feasible로 기록한다. pre-grasp 실패와 grasp 실패는 후보별 attempt와 함께 구분해 저장한다.

IK 오차를 하나의 무차원 residual로 합치지 않고 translation metre와 rotation radian으로 분리했다. backend가 limit 밖 configuration, NaN 또는 예외를 반환해도 통과하지 못하며, 실패값은 JSON의 비표준 Infinity 대신 null로 저장한다. 이 결과는 collision clearance를 뜻하지 않으므로 valid나 executable이라는 이름을 사용하지 않았다.

Pinocchio adapter와 환경 문제

Conda solver 조기 종료

최초 환경 생성은 설정된 libmamba plugin을 찾지 못해 실제 환경 없이 종료됐다. CONDA_NO_PLUGINS=true 진단에서 원인을 확인하고 classic solver로 재실행했다. 생성이 늦게 완료된 뒤 Pinocchio 3.4.0, hpp-fcl 3.0.1, NumPy 1.26.4를 확인했다.

서버 pip 설치 중단

junjinyong 공용 Python에는 Pinocchio가 없었다. 임시 pip 설치는 binary wheel이 아니라 약 100MB source package와 build dependency를 받아 적합하지 않아 중단했다. source build fallback을 남기지 않고 conda-forge binary를 쓰는 별도 planning environment만 공식 경로로 유지했다.

private Git 인증 부재

서버 checkout은 GitHub credential이 없어 pull할 수 없었다. 로컬 main의 Git bundle을 전송하고 clean server tree를 fast-forward하여 소스 revision을 정확히 4448ad3으로 맞췄다.

테스트 skip 은폐 위험

초기 dependency guard가 넓은 ImportError를 잡으면 adapter 내부 import 오류도 package 부재처럼 skip될 수 있었다. Pinocchio module 존재만 먼저 검사하고, 존재할 때 adapter import 오류는 그대로 실패하도록 수정했다.

검증 결과와 다음 gate

로컬 beltbench-planning 환경에서 generic revolute·prismatic 2-joint URDF의 joint name, limit, FK와 reachable IK를 포함한 10개 테스트가 통과했다. junjinyong에서는 OpenCV가 격리된 기존 CPU 경로로 전체 41개 테스트가 통과했고, 공용 Python에 Pinocchio가 없어 adapter 전용 3개만 명시적으로 skip됐다. 두 결과를 합쳐 core 회귀와 실제 Pinocchio 수치 경로를 각각 검증했다.

아직 P2 완료가 아니다: 현재 결과는 robot-independent kinematic feasibility까지다. 다음 구현은 hpp-fcl self/environment collision, 후보 ranking, 독립 revalidation과 Viser rejection diagnostics이며, 이 gate 전에는 실제 robot 실행으로 연결하지 않는다.

2026-08-06 · hpp-fcl collision gate

pre-grasp와 grasp configuration 각각에 대해 explicit self-collision pair와 모든 robot-to-environment pair의 signed distance를 계산하는 CollisionChecker 경계를 추가했다. 결과는 clearance margin, 모든 geometry pair의 거리·판정, minimum pair를 저장한다. 하나라도 margin을 만족하지 못하면 최종 static evaluation은 실패하며, IK-only 결과는 계속 kinematic_feasible로만 남는다.

독립 validator는 minimum distance만 보지 않고 저장된 pair 집합 전체, pair별 거리·판정, margin과 minimum pair를 다시 계산한다. 한 pair의 결과라도 바뀌면 validation이 실패한다. infeasible IK 후보에는 collision checker를 호출하지 않아 존재하지 않는 configuration을 검사하는 fallback도 두지 않았다.

실제 xArm collision asset smoke

mesh package root 누락

첫 실제 URDF load는 xarm/meshes/base.obj를 찾지 못했다. parent directory를 탐색하는 fallback 대신 robot asset manifest에 package_directories를 필수 key로 추가하고 ParaDex rsc/robot root를 명시했다.

geometry 이름 불일치

URDF의 collision name이 그대로 유지될 것으로 예상했지만 Pinocchio는 link_base_0부터 link6_0까지 link 기반 이름을 생성했다. 실제 loader 결과를 확인하고 semantic config가 geometry sequence 전체를 고정하도록 했다.

model drift 방지

이름만 같은 변경 URDF가 semantic pair를 재사용하지 못하도록 외부 xArm URDF SHA-256도 config에 고정했다. checksum 또는 geometry 순서가 달라지면 planning 전에 즉시 실패한다.

실행 command import

파일 경로로 script를 실행하면 checkout root가 import path에 없어 실패했다. sys.path fallback을 추가하지 않고 새 planning command를 모두 python -m scripts... 형식으로 통일했다.

실제 xArm collision mesh 7개와 비인접 self pair 15개를 확인했다. neutral configuration에서 5 mm margin을 적용한 최소 거리는 link4_0–link6_0의 41.466 mm였고 clearance를 통과했다. 이 검사는 neutral state 하나의 asset smoke이며 trajectory clearance를 의미하지 않는다.

후보 ranking과 Viser rejection diagnostics

collision-feasible 후보만 grasp prior, minimum clearance(m), start→pre-grasp→grasp joint travel(rad)로 ranking한다. weight의 단위를 field 이름에 표시하고 score tie는 candidate id로 결정한다. rejected 후보는 score 경쟁에서 제외하고 IK 또는 clearance 실패 이유를 그대로 보존한다.

StaticGraspDiagnostics artifact에 object pose, 후보 target, IK attempt, collision pair evidence, ranking과 execution block reason을 저장한다. Viser는 이 artifact만 읽어 accepted는 녹색, IK rejected는 빨간색, clearance rejected는 주황색으로 표시하며 세 그룹을 독립적으로 켜고 끈다. viewer는 IK, collision, ranking module을 import하지 않는다.

로컬 포트 8093에서 synthetic artifact를 로드해 HTTP 200을 확인했다. planning 환경의 collision·asset 관련 20개 테스트와 artifact·ranking·Viser 관련 16개 테스트가 통과했다. junjinyong revision 3cf0530에서는 전체 54개 테스트가 통과했고, 공용 Python에 Pinocchio가 없어 전용 5개만 명시적으로 skip됐다.

다음 gate: P2의 contract와 visualization은 연결됐지만 실제 BODex grasp set을 xArm+Inspire combined collision model에 적용하지 않았다. 다음 단계는 hand collision geometry, measured mount transform, conveyor/table obstacle 변환과 실제 후보 artifact를 연결한 뒤 P3 collision-aware motion으로 진행하는 것이다.

2026-08-06 · arm과 hand를 하나의 collision state로 결합

arm-only NumPy configuration에 hand 처리를 덧붙이지 않고 collision 입력을 이름 기반 RobotCollisionState로 교체했다. arm과 end-effector joint group을 분리하며 arm-only checker는 hand state가 들어오면 무시하지 않고 실패한다. static evaluator는 후보에 저장된 pre-grasp·grasp hand command를 각각 arm IK state와 결합해 두 상태를 모두 검사한다.

Inspire URDF는 6개 독립 command joint와 6개 mimic joint를 가지지만 Pinocchio는 full 12-joint model을 만든다. generic URDF adapter가 mimic source, multiplier, offset과 limit를 검증해 6-command state를 12-joint collision state로 확장한다. mimic joint를 hardware command처럼 직접 입력하면 거부한다.

combined model 구현 중 발견한 frame·policy 문제

Pinocchio joint 순서

실제 hand에서 Pinocchio tree traversal 순서와 URDF 선언 순서가 달라 첫 smoke가 중단됐다. 순서가 같다고 가정하지 않고 joint 이름 집합을 검증한 뒤 Pinocchio order로 명시적으로 재정렬했다.

hand root frame 가정

초기 combined checker는 hand model universe가 mount frame이라고 가정했다. Inspire에서는 우연히 identity지만 다른 URDF에는 성립하지 않는다. manifest의 hand_root_link FK 역변환으로 모든 hand geometry를 지정 root에 정렬하도록 수정했다.

reflection mount

기존 legacy mount JSON의 회전은 orthonormal이지만 determinant -1인 reflection이었다. 공통 transform validator에 determinant +1 gate를 추가하고 ParaDex combined URDF의 proper fixed joint 회전으로 수정했다. mount는 여전히 measured가 아닌 provisional이다.

단일 5 mm margin

proper mount 후 arm-hand overlap은 사라졌지만 open hand의 정상 finger 간격은 0.22–3.15 mm라 global 5 mm margin을 통과할 수 없었다. pair evidence마다 required clearance를 저장하고 arm self, hand self, cross, environment margin을 분리했다. 정상 hand self와 mount cross는 collision-free 0 mm, environment는 5 mm 정책을 사용한다.

semantic pair와 실제 assembly smoke

hand geometry 13개와 URDF checksum을 고정하고 kinematic-adjacent self pair만 allowed로 기록했다. arm-hand는 mount 접촉 pair 하나만 allowed이며, checker는 전체 Cartesian pair에서 allowed 집합을 제외한 모든 pair를 자동 검사한다. geometry가 추가되거나 이름·checksum이 바뀌면 planning 전에 실패한다.

provisional ParaDex fixed-joint mount, xArm neutral 6축, Inspire open 6-command state에서 총 171개 pair를 검사했다. 최소 거리는 hand base와 thumb link 사이 0.221 mm이고 해당 hand-self policy의 required clearance는 0 mm라 collision check는 통과했다. artifact는 mount status와 source를 포함하고 provisional mount 및 trajectory 미검증 때문에 실행 차단 상태를 유지한다.

BODex candidate schema 정리

기존 NPZ key wrist_from_object는 실제 코드가 object_from_wrist로 사용해 transform 방향이 모호했다. compatibility fallback을 두지 않고 schema 2로 올려 object_from_end_effector_root, named pre-grasp/grasp command state, generator·hand·robot identity와 quality evidence를 필수화했다.

planning adapter는 provisional/measured mount의 arm_tip_from_end_effector_root를 이용해 arm-tip IK target으로 변환하고, 접근 방향도 end-effector-root frame에서 object frame으로 변환한다. generator quality의 방향을 임의 해석하지 않고 호출자가 candidate별 grasp prior를 명시해야 한다.

검증 결과

로컬 planning 환경에서 combined model, mimic expansion, pair-specific clearance, static evaluation, artifact와 semantic config 관련 30개 테스트가 통과했다. 실제 assembly neutral artifact도 171개 pair clearance를 통과했고 mount status는 provisional로 저장됐다. schema-2 static diagnostic을 포트 8093에서 다시 열어 89개 persistent Viser message와 HTTP 200을 확인했다.

junjinyong revision 8247f42에서는 전체 60개 테스트가 통과했다. 공용 Python에 Pinocchio가 없어 combined 2개와 기존 Pinocchio 5개, 총 7개는 명시적으로 skip됐고 이 경로는 로컬 planning 환경에서 별도로 통과했다.

남은 실행 gate: mount 실측, conveyor/table primitive의 실제 base-frame 배치, schema-2 BODex artifact 재생성, 실제 후보의 xArm IK·combined collision 평가가 필요하다. 그 다음에만 collision-aware trajectory와 timing validation으로 진행한다.

모듈 재구축 감사와 초기 pose·tracking 연결이 이 계획의 선행 기록이다.
