ISSUE-091 · 2026-08-27 · append-only pose/grasp/outcome registry

공유 AutoDex pose·grasp·결과를 출처가 닫힌 불변 레코드로 연결한다.

공유 archive의 pose, tracking, executed grasp, candidate와 outcome은 서로 다른 파일과 producer 경로에 흩어져 있었다. 파일을 직접 찾아 쓰는 방식은 어떤 pose와 grasp가 어떤 결과를 냈는지 재현하기 어렵고, Allegro 결과를 Inspire Left의 검증된 명령으로 오인할 위험이 있다. 원본은 읽기 전용으로 유지하고 사용자 namespace에 append-only registry를 구현했다.

현재 판정: Pepsi 세 episode의 episode record와 candidate-resolution record를 실제 공유 source의 SHA-256으로 검증했다. Provider outcome은 success 2건, failure 1건이며 candidate result와 모두 일치한다. 그러나 stable-pose 의미, provider world frame, Allegro→Inspire 전이는 미해결이므로 모든 레코드는 runtime_eligible=false, hardware_reliability_eligible=false다.

발생한 문제

문제실패 가능성
Episode manifest, pose, GoTrack, grasp와 outcome이 별도 tree에 저장돼 있다.파일명과 디렉터리 관례에 의존해 서로 다른 trial을 잘못 결합할 수 있다.
Executed-grasp metadata의 success는 null이고 outcome은 companion label에 있다.성공 결과를 누락하거나 candidate 결과를 새 robot의 성공률로 과장할 수 있다.
Candidate 경로는 producer host의 절대경로로 남아 있다.다른 machine에서 재현할 수 없고 source가 바뀌어도 감지하기 어렵다.
NFS를 actual-time loop에서 직접 탐색할 가능성이 있다.Directory scan과 I/O jitter가 perception·planning deadline에 들어온다.

설계 결정

  1. registry/v1/episodes/<dataset>/<object>/<episode>/record.json은 raw episode inventory다. Camera calibration, object mesh, initial/recomputed pose, GoTrack 기록, executed wrist/hand metadata와 outcome source를 URI·resolved URI·size·SHA-256으로 결속한다.
  2. registry/v1/resolutions/autodex-candidate/<object>/<episode>/record.json은 후속 source resolution이다. 기존 episode를 고치지 않고 candidate wrist, pregrasp, grasp와 result를 episode record ID와 digest에 연결한다.
  3. Candidate의 episode ID와 success가 companion outcome과 정확히 같아야 record를 생성한다. 하나라도 다르면 fail closed한다.
  4. 동일 내용 재색인은 no-op이고 같은 경로의 내용 변경은 거부한다. 임시 파일, fsync와 hard link로 NFS에서도 덮어쓰기 없는 atomic create를 사용한다.
  5. 원본 source tree에는 쓰지 않는다. 사용자 namespace에는 registry와 derived evidence만 쓰며, runtime에는 승인된 최소 bundle만 local NVMe로 stage한다.

구현 commit 414fecb의 clean server checkout에서 단위 테스트 3개를 통과했다. 세 episode는 기존 불변 record와 digest가 유지돼 created=false였고 candidate resolution만 최초 생성됐다. 전체 query에서 episode·candidate source re-hash와 join이 모두 통과했으며 동일 episode 재색인은 양쪽 모두 created=false였다.

의도적으로 부여하지 않은 권한

  • Provider stable-pose ID 008을 BeltBench의 upside_down으로 자동 매핑하지 않는다.
  • 깨진 selected C2R link와 존재하는 R2C 파일명만 보고 frame transform을 추론하지 않는다.
  • Allegro hand command를 Inspire Left command로 재사용하지 않는다. Object-relative wrist proposal만 별도 retarget·collision·contact 검증의 입력 후보가 된다.
  • Provider의 2/3 성공을 moving-belt, xArm, Inspire, 현재 calibration에서의 reliability로 사용하지 않는다.
  • 약 5.15초/frame인 24-view GoTrack 결과를 online tracker로 승격하지 않는다.

Pipeline 사용 방식

  1. Offline query가 known object, provider pose, hand와 outcome으로 episode를 찾고 source digest를 검증한다.
  2. 명시적 stable-pose/frame mapping이 승인된 뒤 object-relative wrist proposal을 추출한다.
  3. Target end effector용 hand command를 다시 생성하고 complete approach·close·lift·transfer·release path를 독립 검증한다.
  4. 승인된 mesh, grasp proposal과 calibration snapshot만 content-addressed runtime bundle로 local NVMe에 stage한다.
  5. Runtime은 registry나 NFS를 조회하지 않고 bundle ID만 trace에 남긴다. 실행 결과는 새 BeltBench trial record로 기록하며 provider outcome과 섞지 않는다.

다음 작업

  1. Pose ID 008의 canonical stable-pose source와 world-frame 정의를 producer source에서 닫는다.
  2. Object-relative wrist proposal adapter와 Inspire Left retarget 결과를 별도 derived record로 설계한다.
  3. cuRobo에서 moving-contact tracking, collision, dynamics와 timing feasibility를 component별로 기록한다.
  4. Independent validator를 통과한 bundle만 simulation runtime에 승격하고 actual-time trace와 실행 outcome을 새 trial namespace에 저장한다.
