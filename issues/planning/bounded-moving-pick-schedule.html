ISSUE-032 · 2026-08-10 · bounded moving-pick schedule

AutoDex grasp filter와 moving 실행 gate를 다시 분리하고, 접촉 사건의 시간창을 exact trajectory에 재현 가능하게 결속한다.

정적 grasp가 유효하다는 것, 특정 robot/workcell에서 complete path가 가능하다는 것, 최신 conveyor 상태에서 그 path를 deadline 안에 실행할 수 있다는 것은 서로 다른 판단이다. AutoDex의 squeeze·MuJoCo·coverage·first-success 규칙을 하나의 moving-grasp 점수로 가져오지 않고 세 권한으로 분리했다. 이번 vertical slice는 그중 deployment의 사건 순서를 손으로 맞추는 데서 멈추지 않고, 유한 event window와 인접 duration 제약을 선형 시간에 풀어 exact synchronized trajectory에 결속한다.

현재 효력: source commit 29f64ea가 실시간 target architecture ADR, immutable schedule problem/allocation/binding, O(N) allocator, CLI와 Viser fail-closed loading을 구현한다. Transition bound는 아직 caller가 제공하며 continuous collision, measured latency, controller tracking과 hardware reliability가 없으므로 execution_blocked다.

먼저 확정한 방향

Production target은 매 camera frame마다 global planner를 다시 돌리는 구조가 아니다. Object identity와 stable tabletop pose는 사전에 주어지고, 초기 planar position과 yaw를 측정한다. Nominal object motion은 calibrated belt 방향의 translation뿐이며 yaw와 lateral offset은 유지된다. Offline compiler가 grasp, path family, event schedule, stop과 terminal path를 만들고 startup verifier가 exact source를 확인한다. Online runtime은 encoder와 camera track으로 저차원 상태를 갱신하고 resident path를 bounded query·retain·latch한다. Replan cutoff 이후에는 certificate가 허용한 longitudinal phase correction만 사용하며 controller와 safety monitor가 command authority를 소유한다.

xArm, Inspire와 Pepsi는 이 구조의 실제 예시 asset일 뿐 기본 가정이 아니다. Arm, hand, connector, object, calibration, workcell과 controller는 manifest와 digest로 선택한다. FoundPose는 acquisition, GoTrack 또는 FoundationPose는 tracking backend가 될 수 있지만 planning state나 command authority를 소유하지 않는다.

AutoDex public source 재감사

감사 기준은 willi19/autodex-code:main@5ada1c이다. Public remote branch는 main 하나였다. 로컬 checkout은 remote보다 5 commit 뒤였고 autodex/utils/path.py, world_cfg_generator.py, adaptive_orchestrator.py, generate_scene.py에 기존 수정이 있어 git pull --ff-only이 안전하게 중단됐다. 이를 stash·overwrite하지 않고 remote blob을 직접 감사했다.

BeltBench가 채택한 grasp 기준

1. Intrinsic qualification

Object·stable pose·hand·task capability identity, approved protocol, measured stable pose, named allowed contact와 최소 contact 수, allowed penetration, non-contact object·self·support clearance, task wrench, object-relative approach·closure·release 전체 경로와 hardware reliability를 서로 독립 hard gate로 둔다. Generator success와 AutoDex/BODex metadata는 provenance일 뿐 승인 점수가 아니다. Endpoint screen 통과는 expensive full evaluation worklist에 들어간다는 뜻만 갖는다.

2. Robot/workcell deployment qualification

Exact arm·hand·connector·calibration·workcell, yaw/lateral/speed/horizon uncertainty support, event별 IK와 pose tolerance, joint·workspace·singularity margin, synchronized velocity·acceleration·jerk, 사건 시간창, complete robot/workcell/object collision, first-contact-to-attach chase, transport·release·retreat·stop을 검사한다. Sampled collision과 sampled chase는 현재 diagnostic이며 continuous 또는 보수적으로 bounded된 certificate가 없으면 실행 승인을 내리지 않는다.

3. Runtime complete-path selection

Fresh state, supported speed/state cell, intrinsic·deployment evidence, measured latency, path start와 cutoff, deadline/collision/uncertainty/workspace/joint/singularity slack, controller와 stop·latch availability를 먼저 hard gate한다. 남은 complete source-to-terminal path만 각 단위별 normalized slack의 최솟값을 최대화하도록 정렬하고 deadline으로 tie-break한다. Active path는 선언된 개선 threshold를 넘는 대안이 있을 때만 바꾼다.

이번에 닫은 시간 계약

기존 event trajectory는 replan_cutoff ≤ hand_close_start < contact < hand_close_complete ≤ attach 순서를 검사했지만, 각 사건의 유한 가능 시간과 인접 transition의 최소·최대 duration을 독립 problem으로 풀고 그 결과를 exact trajectory에 재현하지 않았다. 시각적으로 순서가 맞는 waypoint를 직접 고르면 hand closure, chase와 cutoff가 서로 양립하지 않는 schedule도 늦게 발견할 수 있다.

  • MovingPickScheduleProblem은 geometric path, motion-limit profile, moving-contact policy SHA-256과 5개 유한 event window, 4개 인접 min/max duration requirement를 묶는다.
  • Forward interval propagation이 각 event의 reachable interval을 구하고 backward pruning이 뒤 event에 도달할 수 없는 시간을 제거한다.
  • Canonical witness는 남은 interval에서 가장 이른 feasible time을 선택한다. 연산은 event 수에 선형이고 optimizer retry나 permissive fallback이 없다.
  • MovingPickScheduleAllocation은 feasible interval, 선택 시간, allocated duration과 원 problem digest를 저장하며 loader가 파생 schedule 변조를 거부한다.
  • MovingPickTrajectoryScheduleBinding은 allocation과 exact event trajectory SHA-256을 묶는다. Verifier는 원 problem에서 allocation을 다시 계산하고 path·motion digest, event window와 waypoint time을 모두 대조한다.
  • Viser는 problem·allocation·binding 세 파일을 모두 받았을 때만 full verifier를 통과시켜 선택 event time을 표시한다. 하나라도 빠지면 시작 전에 실패한다.

이 allocator는 후보 path의 robust 순위를 정하지 않으며 collision·dynamics를 계산하지도 않는다. Caller가 제공한 transition bound가 검증됐다는 사실을 스스로 증명하지 않으므로 현재 allocation은 reference evidence다. 다음 compiler가 motion/contact evidence에서 bound를 유도해야 한다.

확인하지 못한 것

현재 local에는 actual xArm·Inspire·connector·Pepsi asset과 legacy playback이 있지만, 새 schema의 EventScheduledTrajectoryRequest, PlannedMovingContact, schedule problem/allocation/binding이 모두 일치하는 실제 artifact set은 없다. Legacy position-only playback을 변환하면 derivative, contact twist와 event-window 근거를 발명하게 되므로 변환하지 않았다. 따라서 이번 검증은 Viser의 fail-closed loading과 status renderer까지이며, schedule이 결속된 장면을 실제 시간으로 띄웠다는 증거는 아니다.

다음 vertical slice

  1. Path dynamics와 moving-contact policy에서 adjacent transition bound를 유도하는 compiler를 구현한다. Hand closure duration, chase tolerance, fixed-path time parameterization과 cutoff latency budget이 source evidence가 돼야 한다.
  2. 같은 compiler가 synchronized event trajectory, moving-contact와 chase assessment를 만들고 schedule binding을 소비하게 한다. 사람이 별도 JSON 시간을 맞추지 않는다.
  3. Complete robot/self/workcell/object swept collision, uncertainty tube, stop·drop·retreat terminal path를 하나의 certificate에 결속한다.
  4. 그 certificate만 path-family compiler와 resident runtime에 넣고 unsupported yaw/lateral/speed/phase/robot-start cell을 fail-closed한다.
  5. Actual xArm·Inspire·connector·Pepsi·belt·table·bin asset으로 exact event artifact를 1x 자동 반복 재생하고 desired, simulated-measured, authority layer를 분리한다.
  6. Monotonic per-stage timestamp를 기록하는 controller simulator에서 delay, tracking error, stale pose, object slip, missed update와 stop fault를 주입해 deadline과 recovery를 검증한다.

관련 맥락은 complete moving chase, AutoDex filter와 task events, synchronized event trajectory, real-time architecture에서 이어진다.
