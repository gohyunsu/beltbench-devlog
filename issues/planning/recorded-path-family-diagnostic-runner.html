ISSUE-057 · 2026-08-11 · recorded inference edge composition

한 observation을 bounded planning에서 진단 handoff까지 실제 코드로 연결한다.

Resident path, runtime planning, controller mailbox, feedback와 Viser 모듈은 각각 있었지만, checksummed 입력을 받아 한 세대를 실제로 통과시키는 production-shaped 실행 경로가 없었다. Source commit 83ec080은 기존 계약을 우회하지 않고 startup verification, latest-generation planning, future-start handoff, causal evidence를 하나의 CLI edge composition으로 연결한다.

결론: 새 runner는 controller나 simulator를 내장하지 않는다. 한 recorded observation을 측정 가능한 planning 경로로 통과시키고, 허용된 future-start trajectory만 capacity-one mailbox에서 diagnostic acknowledgement한다. 이후 kinematic feedback과 1.0x Viser는 immutable output을 소비하는 별도 단계로 유지한다.

확인한 문제

  1. 실행 edge 부재: RuntimePlanningRunner, RuntimeSelectionControlCoordinator, atomic handoff materializer가 있었지만 source artifact에서 이들을 조합하는 production CLI가 없었다.
  2. 과거 smoke artifact의 한계: local wall-clock fixture는 planned-only session이며 현재 controller-handoff evidence까지 재현하지 못했다.
  3. 실제 continuous bundle 부재: Pepsi, xArm6, Inspire Left actual-asset playback과 MuJoCo MJB는 있지만 source-closed continuous path-family bundle과 resident event request 묶음은 없다.
  4. Capability 과장 위험: offline consumer가 acknowledgement할 수 있다는 사실은 실제 xArm adapter의 future-start, synchronized arm-hand, cancel, prevalidated stop 지원을 증명하지 않는다.

Feedback와 Viser동일 handoff에서 지연 feedback과 actual-asset scenario 생성, 1.0x auto-loop별도 비동기 단계

이 경계는 파일 I/O와 SHA-256을 planning deadline 밖으로 밀어내고, viewer나 physics가 command 선택 latency를 늘리지 않게 한다. 한편 timestamp join, deadline, mailbox와 causality는 CPU state machine으로 유지한다. 이 작업은 cuRobo resident collision worker를 대체하지 않으며, 이후 GPU gate가 들어갈 위치를 분명히 한다.

구현 내용

  1. scripts/run_recorded_path_family.py가 atlas와 deployment source를 먼저 검증하고 resident projector와 event catalog를 준비한다.
  2. Conveyor state, fused planar track, synchronized robot motion state를 같은 generation에 넣고 기존 RuntimePlanningRunner를 그대로 실행한다.
  3. process_one_offline_diagnostic_generation()은 기존 coordinator와 mailbox만 조합한다. 새 selection path나 fallback planner를 만들지 않는다.
  4. source_anchored replay clock은 기록된 timestamp 차이를 바꾸지 않고 실제 경과 시간만 source epoch에 더한다. wall mode는 current-boot 입력만 허용한다.
  5. Future-start가 아니면 handoff를 만들지 않고 verified runtime session만 저장한 뒤 exit 2로 종료한다.
  6. 공간, yaw, belt-speed 또는 active-phase correction이 materialize되지 않았으면 기존 runtime_trajectory_correction_not_materialized gate에서 fail-closed한다.

발생한 문제, 원인, 해결

  1. 잘못된 test module 지정: 처음 회귀 명령에 존재하지 않는 tests.test_controller_feedback 두 개를 넣어 import error가 발생했다. 기능 실패가 아니라 명령 오류임을 확인하고 실제 test_kinematic_feedback와 visualization suite로 교정했다.
  2. Base 환경 dependency 부족: 기본 Python에는 numpy가 없어 기존 planning import가 실패할 수 있다. 프로젝트가 고정한 beltbench-planning conda 환경에서 실행했다.
  3. 진단 capability의 허위 선언: 초기 초안은 xArm/Inspire 이름으로 cancel과 stop을 true로 둔 example capability를 포함했다. 실제 adapter가 없으므로 해당 파일을 제거했다. CLI는 향후 adapter에서 생성하거나 측정한 capability를 외부 입력으로 요구한다.
  4. 통합 fixture 재사용 불가: bundle verifier fixture는 resident event trajectory까지 source-closed하지 않는다. 억지로 두 fixture 계층을 결합하지 않고 하위 계약 회귀와 CLI import 검증을 사용하며, 실제 continuous bundle을 별도 생산 게이트로 남겼다.

아직 주장할 수 없는 것

  1. 실제 Pepsi continuous path-family bundle이 없으므로 새 CLI의 actual-asset grasp run은 아직 없다.
  2. Diagnostic acknowledgement는 ROS transport, controller interpolation, cancel, stop 또는 hardware tracking을 증명하지 않는다.
  3. cuRobo V2 resident collision gate와 이 runner는 아직 실제 GPU output으로 결합되지 않았다.
  4. Source-anchored replay는 recorded timestamp 관계를 보존할 뿐 원래 sensor cadence의 실시간 동작을 증명하지 않는다.

다음 순서

  1. Pepsi upside-down stable pose와 selected grasp를 사용하는 source-closed continuous path-family 및 exact resident event request를 생산한다.
  2. 동일 세대의 fixed-shape command batch를 cuRobo collision worker에 넣고, late/error/collision이면 handoff 전에 거부한다.
  3. Accepted handoff를 기존 kinematic feedback과 actual-asset Viser scenario에 연결해 1.0x auto-loop vertical slice를 실행한다.
  4. Supported driver host에서 1,000회 post-warmup p99와 HPP-FCL zero-false-negative parity를 확보한다.
  5. 실제 xArm controller adapter를 구현한 뒤에만 truthful capability, ack, cancel/stop과 measured feedback을 활성화한다.

cuRobo resident collision gate 방향, Runtime path-family harness, Measured MuJoCo Viser replay를 함께 참고한다.
