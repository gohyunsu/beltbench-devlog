ISSUE-027 · 2026-08-09 · grasp hard-gate evidence

통과한 grasp만 저장하지 않고, 모든 후보가 왜 탈락했는지 재현한다.

AutoDex의 생성, simulation filter, runtime planner와 hardware 통계 순서를 pinned source에서 다시 확인하고 BeltBench의 intrinsic, deployment, shortlist 기준과 대조했다. 기존 BeltBench는 기준 자체는 더 엄격했지만 horizon coverage 또는 endpoint threshold에서 탈락한 후보를 continue로 버려, 최종 shortlist만으로는 어떤 기준이 후보를 제거했는지 설명할 수 없었다. 후보별 normalized hard-gate vector를 보존하는 schema 2.0 decision ledger를 구현하고, hard gate와 coverage·maximin·diversity ranking을 계약 수준에서 분리했다.

현재 효력: source commit 9f26612이 complete candidate ledger와 schema authority 경계를 구현했고, 후속 2962269이 normalized horizon coverage를 redundancy maximin에 포함했다. e3aeb7d은 0-margin penetration을 통과시킬 수 있던 unsigned FCL distance를 signed distance로 수정하고 intrinsic protocol을 revision 3으로 올렸다. c8da10c은 deployment contact semantics가 intrinsic gate를 약화하지 못하게 결속했다. c30a3e1은 deployment를 exact intrinsic object manifest와 content-equivalent hand collision model에 결속한다. 실제 Pepsi revision-3 schema-2 shortlist, continuous trajectory, hardware reliability와 controller commit 권한은 아직 없다.

BeltBench가 채택한 filtering funnel

  1. Identity와 provenance: object, stable pose, hand, provider revision, command joint, source checksum과 non-pickled schema가 정확히 일치해야 한다.
  2. Intrinsic endpoint: named intended contact, 최소 contact 수, allowed penetration, non-contact object clearance, hand self-clearance, support clearance와 12-direction task-wrench margin을 검사한다.
  3. Intrinsic path: object-relative approach, fixed-pose closure와 task-required release를 sampled path 전체에서 검사한다. 이 단계 실패는 geometry-clear worklist에 들어올 수 없다.
  4. Robot deployment: exact intrinsic object manifest와 content-equivalent hand collision model을 먼저 확인한 뒤, sampled moving-object horizon마다 multi-seed pregrasp/grasp IK, arm·hand·connector assembly·workcell collision, non-intentional robot/object clearance를 검사한다.
  5. Shortlist hard gate: 최소 horizon coverage, task-wrench quality, support, assembly·object clearance, normalized joint-limit margin과 characteristic-length-normalized Jacobian singular value를 모두 threshold 이상으로 요구한다.
  6. Portfolio ranking: 통과 후보만 대상으로 새 context 수를 먼저 최대화한다. 동률과 redundancy는 normalized horizon coverage, endpoint, intrinsic-path slack의 lexicographic maximin과 configured grasp/hand diversity로 정한다.
  7. Online narrowing: resident yaw/horizon atlas 교집합, exact latest observation, path-family evidence, correction·deadline·stop gate로 다시 좁힌다. Shortlist 통과는 실행 권한이 아니다.

static_quality는 normalized contact-force budget을 사용한 접촉 기하 비교이며 실제 payload capacity가 아니다. Finger force, actuator torque, object mass·acceleration, compliance와 friction uncertainty는 hardware-context gate에 남는다. 어떤 weighted sum도 collision 또는 timing 실패를 품질 점수로 보상하지 않는다.

구현한 schema 2.0 decision ledger

Compiler는 deployment worklist의 source order를 보존해 모든 후보에 ScreenedGraspShortlistCandidateDecision을 하나씩 만든다. 각 metric은 dimensionless slack이며 1이 hard-gate 경계다.

Namespace저장 내용판정
horizon_coverageFeasible horizon fraction / policy minimum fraction>= 1일 때만 eligible
intrinsic_path/*Configured positive approach, closure, self, support와 required release marginGeometry-clear ancestry이므로 하나라도 1 미만이면 shortlist 탈락이 아니라 upstream integrity failure
endpoint/*Static quality, support, assembly, non-contact object, joint-limit, singularity의 complete setFeasible horizon이 하나라도 있으면 여섯 metric을 모두 요구
  • eligible, coverage fraction과 failure_metric_ids는 저장값을 신뢰하지 않고 vector에서 다시 계산한다.
  • Zero-horizon 후보는 endpoint configuration이 없으므로 coverage와 intrinsic path만 저장한다. Horizon별 IK·collision 상세 실패는 source deployment assessment에 남긴다.
  • Feasible horizon이 있는데 endpoint set을 비우거나 일부만 넣으면 contract가 거부한다.
  • 모든 decision의 total horizon 수와 policy-derived coverage slack이 일치해야 한다.
  • Selected entry의 horizon, endpoint와 intrinsic path 수치는 같은 candidate decision과 tight numeric tolerance로 결속한다.
  • Transitive verifier는 eligible count나 top-K만 믿지 않고 compiler를 다시 실행해 rejected candidate를 포함한 decision payload 전체를 비교한다.
  • Schema 1.0은 누락된 path field까지 원문 그대로 load/round-trip할 수 있지만 verifier가 명시적으로 거부한다. 열람 가능성과 현재 authority를 분리했다.

Coverage와 robustness ranking 보완

집합 coverage와 개별 robustness는 다른 역할이다. 먼저 각 iteration에서 아직 덮이지 않은 context 수가 가장 큰 후보를 고른다. 같은 수를 추가하거나 모든 context가 이미 덮인 뒤에는 각 후보의 normalized coverage, endpoint와 path slack을 작은 값부터 비교하는 lexicographic maximin을 적용한다. 마지막에만 deterministic grasp ID를 사용한다.

반례 test에는 세 horizon을 모두 지원하는 universal-a, universal-z와 첫 horizon만 지원하는 narrow-a를 같은 물리 margin으로 구성했다. 이전 order라면 첫 universal 뒤에 ID가 앞선 narrow 후보가 redundancy가 될 수 있었다. 수정 후에는 universal-a, universal-z가 선택된다. Coverage는 threshold 실패를 보상하지 않고, 이미 통과한 후보 사이에서 더 넓은 재사용 범위를 보존한다.

추가 감사: zero-margin collision의 의미

새로 발견한 결함: checked pair의 clearance threshold가 0이면 기존 공통 FCL adapter가 관통 상태도 unsigned distance 0으로 반환할 수 있었고, 계약의 distance >= required_clearance가 이를 통과시킬 수 있었다. 따라서 이전의 117 geometry-clear 수는 재현 가능하지만 current authority가 아닌 baseline이다.
구분내용
문제Intrinsic hand self와 assembly hand-self/cross pair 중 일부가 zero clearance를 사용했다. 실제 overlap과 정확한 접촉을 unsigned distance 0에서 구분하지 못했다.
원인_distance_evidence()가 default hppfcl.DistanceRequest()를 사용했고, CollisionPairEvidence는 거리와 threshold만으로 pass 여부를 재구성했다.
해결공통 collision과 proximity distance query 모두 enable_signed_distance=true를 사용한다. Penetration은 음수 거리이므로 threshold가 0이어도 fail closed한다. Intentional contact는 zero threshold가 아니라 explicit allowed-pair 또는 object-interaction semantics가 소유한다.
회귀 검증실제로 겹치는 sphere obstacle을 clearance 0으로 구성한 test가 음수 pair를 확인하고 전체 collision check가 실패하는지 검증한다.

Threshold를 임의로 정하지 않은 근거

수정 전 commit의 immutable full evaluation을 서버에서 다시 생성하고 10,313개 direct/transitive source를 verifier로 확인했다. 140개 full-path 평가 중 117개가 기존 geometry-clear 정의를 통과했다. 그 117개의 최소 closure non-contact distance는 1.013 mm, 최소 approach/closure self-distance는 1.075 mm였다. Fixed release command는 모든 후보에서 더 좁은 0.221 mm self-distance를 만들었다.

따라서 draft-2026-08-09.1은 closure non-contact gate를 1 mm, checked hand self gate를 provisional 0.1 mm로 둔다. 전자는 기존 geometry-clear 후보를 보존하려고 낮춘 값이 아니라 이전 gate와 실제 최솟값 사이에서 확인된 양의 경계다. 후자는 release CAD가 허용하는 범위 안에서 penetration과 zero-touch를 분리하는 진단값이다. 어느 값도 hardware 공차가 아니며 connector 조립오차, 실제 hand link 간격과 compliance를 측정하기 전에는 protocol status를 approved로 바꿀 수 없다.

추가 감사: intrinsic과 deployment contact gate 결속

기존 object-interaction config는 intrinsic endpoint가 최소 3 contact를 요구하는데 deployment에서 2 contact만 요구했다. Baseline nominal deployment의 실제 object-interaction evidence를 다시 집계하니 검사된 후보는 모두 3~5 contact였고, feasible 후보도 모두 3개 이상이었다. 즉 2-contact 완화는 계산 결과에 기여하지 않았고 ancestry만 느슨하게 만들었다.

문제원인해결과 결과
Deployment semantics가 intrinsic contact definition보다 약해질 수 있음Object ID만 비교하고 allowed hand geometry, minimum count와 contact distance를 cross-contract로 비교하지 않음Allowed geometry set은 exact match, minimum count는 intrinsic 이상, contact-distance tolerance는 intrinsic 이하만 허용한다. 위반은 후보 rejection이 아니라 ancestry error다.
Production object interaction이 2 contact를 허용이전 static playback용 config가 intrinsic 3-contact protocol과 함께 갱신되지 않음같은 named distal geometry에서 최소 3 contact로 통일했다. Baseline evidence에 2-contact feasible 후보가 없어 known survivor 보존을 위한 fallback은 아니다.
Non-intentional object clearance의 총 gate가 불명확Deployment base clearance 0과 shortlist residual 0.5 mm가 분리되어 문서상 절대 거리처럼 보일 수 있음Base gate를 0.5 mm로 올리고 shortlist/atlas residual 0.5 mm를 추가해 retained endpoint의 total separation을 1 mm로 구성했다. 두 값은 독립 측정 두 개가 아니다.

Allowed geometry 변경, minimum count 감소, contact-distance 증가를 각각 독립 subtest로 만들었고 모두 동일한 fail-closed ancestry 오류를 확인했다. Deployment·complete-path 소비자 54개 test와 downstream deployment·shortlist·atlas 40개 test가 통과했다. Source commit c8da10c은 GitHub main에 push했으며, 실행 중이던 revision-3 intrinsic run은 이 deployment-only source 변경을 입력으로 사용하지 않는다.

추가 감사: intrinsic collision model과 deployment asset 결속

Contact rule이 같아도 contact를 계산한 형상이 다르면 같은 evidence가 아니다. Full intrinsic chain은 vendored BODex Inspire-left URDF를 사용하고 robot assembly asset은 동일한 URDF와 mesh를 server asset directory로 복사해 사용한다. 두 URDF의 SHA-256은 mesh 상대경로가 달라 서로 다르지만, 실제 left-hand collision mesh 13개와 joint kinematics는 동일했다. 현재 asset이 맞다는 관찰만으로 향후 asset 교체를 막을 수 없으므로 별도 ancestry gate가 필요했다.

냉정한 현재 평가

이번 변경은 AutoDex보다 threshold 수를 늘린 것이 핵심이 아니다. 필터의 소유 단계, 단위, pass boundary와 탈락 근거를 분리하고 모든 worklist 후보에 대해 재현 가능하게 만든 것이 핵심이다. AutoDex의 first-success와 binary coverage는 데이터 수집과 정적 실험에는 실용적이지만 conveyor deadline, uncertainty와 moving contact를 다루는 최종 선택 규칙으로는 부족하다.

반대로 현재 BeltBench도 실제 동작이 증명된 것은 아니다. Endpoint와 sampled intrinsic path evidence는 continuous moving trajectory가 아니고, horizon grid는 continuous yaw/time certificate가 아니다. 실제 Pepsi schema-2 shortlist도 checksum mismatch 때문에 아직 생산하지 못했다. Stable pose 측정, current protocol full-chain regeneration, sampled task/stop family, accelerated oracle agreement, measured latency, connector metrology와 hardware moving-pick reliability가 모두 남아 있다.

다음 구현

  1. Current 12-direction intrinsic config와 exact source revision으로 full intrinsic evaluation, deployment와 schema-2 shortlist를 한 chain에서 재생성한다.
  2. 생성된 shortlist를 yaw/horizon atlas와 sampled task/stop path-family compiler에 연결하고 candidate decision completeness를 startup에서 다시 검증한다.
  3. Reference mesh oracle와 accelerated backend의 zero-false-accept agreement, p50/p95/p99, deadline miss와 cancellation latency를 기록한다.
  4. 실제 robot이 돌아오기 전에는 controller commit을 추가하지 않고 actual-time Viser에서 rejection ledger와 path decision을 함께 재생한다.

AutoDex selection 감사, grasp/path combined ranking, sampled path oracle가 앞뒤 evidence 경계를 설명한다.
