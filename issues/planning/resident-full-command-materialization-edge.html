ISSUE-061 · 2026-08-12 · resident full-command materialization edge

승인된 path-family만 actual cuRobo full command로 materialize한다.

Static holdout arm prefix로 cuRobo producer와 고해상도 validator의 수치 경로는 검증했지만, runtime이 선택한 Pepsi path-family를 complete arm-hand command로 만드는 운영 경로가 없었다. 이번 단계는 새 planner를 기존 animation에 바로 붙이지 않고, warm-start admission, resident template, moving-contact, object lifecycle와 exact cuRobo output 사이에 write-once compiler 경계를 추가했다.

현재 판정: Source-bound request, segmented object collision lifecycle와 actual cuRobo arm-prefix output을 파일 산출물로 조립하는 CLI는 구현했다. 고정 GPU 환경에서도 새 planner CLI가 정상 로드된다. 그러나 현재 저장된 Pepsi portfolio에는 execution-selected path-family와 그에 대응하는 admission/template/lifecycle가 없다. 따라서 기존 reference animation이나 nominal one-cell 자료를 복제해 actual command로 표시하지 않았고, GPU solve·MuJoCo·Viser same-command 검증도 아직 실행하지 않았다.

추가한 실행 경계

  1. Request compiler: accepted warm-start admission과 warmed GPU session을 exact resident catalog slot에 결속한다.
  2. Moving-contact compiler: request의 마지막 pre-contact target sample과 직전 sample에서 first-contact pose와 constant translation velocity를 복원하고, grasp와 connector transform으로 object-from-tool을 결정한다.
  3. Lifecycle compiler: moving contact 전에는 conveyor translation, contact 후에는 attachment FK, detach 후에는 static place 또는 conservative ballistic drop 상태를 고정한다.
  4. cuRobo planner: pinned source revision, accepted 512-sphere world proxy, exact static workcell과 locked hand state로 backend를 한 번 초기화한다.
  5. Exact-shape warmup: 실제 request와 동일한 horizon·seed·joint inventory로 cold 준비를 수행한 뒤에만 hot solve를 허용한다.
  6. Write mask assembly: measured start에서 certified latch까지 arm 내부 sample만 덮어쓰고 hand schedule, latch와 full suffix는 resident template 값으로 보존한다.
  7. Blocked output: producer result와 complete command는 별도 write-once 파일로 남지만 independent full-task validation과 controller 권한 전에는 실행 승인되지 않는다.

Viser와 MuJoCo는 planner thread에 넣지 않는다. 같은 command digest를 소비하는 독립 consumer로 유지해야 화면 렌더링이나 physics step이 control deadline을 늘리지 않는다. 현재 producer p99와 validator p99의 과거 직렬 합도 end-to-end 수치가 아니므로 perception, selection, moving-object update와 concurrent GPU load를 포함한 별도 benchmark가 필요하다.

남은 source blocker와 다음 순서

  1. Pepsi stable pose와 yaw/lateral/speed correction cell마다 독립 생성·검증된 path-family를 채운다. Nominal path를 누락 cell에 복제하지 않는다.
  2. Fresh track, encoder와 robot state에서 실제 execution candidate를 선택하고 accepted warm-start admission을 기록한다.
  3. 선택 family의 event trajectory와 resident template, moving-contact와 segmented object lifecycle을 이번 compiler로 materialize한다.
  4. 그 exact request를 resident cuRobo producer에 넣고 동일 output tensor를 고해상도 static collision, dynamic object, attached object와 release envelope validator에 전달한다.
  5. Continuous collision, dynamics, complete abort routes와 controller deadline까지 통과한 command만 validated lease로 승격한다.
  6. 그 뒤 동일 command digest를 MuJoCo measured rollout과 actual-asset Viser auto-loop에 전달한다.

Production path-family source blocker, Resident full-command template, Segmented object collision, cuRobo producer 검증을 함께 참고한다.
