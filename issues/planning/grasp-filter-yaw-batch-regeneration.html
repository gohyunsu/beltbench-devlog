ISSUE-028 · 2026-08-09 · grasp filtering and yaw batching

AutoDex의 필터는 참고하되, moving pick의 권한 기준으로 복사하지 않는다.

Pinned AutoDex source의 proposal generation, static simulation filter, cross-pose order, runtime planner와 hardware-stat order를 다시 대조했다. BeltBench는 contact·clearance·wrench·path·robot deployment를 서로 다른 hard-gate owner로 유지하고, 모든 gate를 통과한 뒤에만 coverage와 maximin을 적용한다. 동시에 12개 yaw마다 같은 intrinsic ancestry와 robot model을 다시 읽던 offline 병목을 shared batch로 교체했다.

현재 source: 5cd83fb이 shared preparation, yaw batch producer와 batch verifier를 구현했다. f8af1b5는 nominal shortlist가 full-yaw atlas의 whitelist가 될 수 없다는 권한 경계를 AGENTS와 방법론에 명시했다. 측정 resource 사용량을 반영한 0fff6a3은 순차 grasp PBS job을 1 CPU와 실제 메모리 여유에 맞췄다. 모든 산출물은 execution-blocked다.

BeltBench filter funnel

  1. Identity/provenance: object, stable pose, hand, provider revision, command joint, exact source checksum을 확인한다.
  2. Intrinsic endpoint: named contact, 최소 contact 수, allowed penetration, non-contact·self·support clearance와 signed force/moment 12방향 task-wrench quality를 검사한다.
  3. Intrinsic path: object-relative approach, closure와 required drop release를 sampled path 전체에서 검사한다.
  4. Robot deployment: exact intrinsic object manifest와 content-equivalent hand collision model을 결속하고 yaw·horizon마다 multi-seed IK, arm·hand·connector·workcell·object endpoint collision을 검사한다.
  5. Shortlist/atlas: horizon 또는 context support, static quality, support·assembly·object clearance, joint-limit과 length-normalized Jacobian singular-value threshold를 모두 hard gate로 적용한다.
  6. Ranking: 통과 후보만 coverage-first와 deterministic lexicographic maximin, configured diversity로 줄인다. 점수 합으로 실패 gate를 보상하지 않는다.
  7. Online/path authority: measured yaw uncertainty와 horizon bracket의 atlas 교집합, latest pose·robot state, complete task/stop path, timing·cutoff·reliability를 다시 검사한다.

Nominal shortlist를 atlas whitelist로 쓰지 않는 이유

한 nominal yaw에서 탈락한 grasp가 다른 yaw에서는 유일하게 유효할 수 있다. Nominal top-K를 full-yaw atlas 앞에 넣으면 context-specific reachability를 보기도 전에 후보를 영구 제거한다. 따라서 nominal schema-2 shortlist는 모든 후보의 decision vector와 ranking을 재현하는 diagnostic artifact다. Atlas는 complete verified intrinsic geometry-clear worklist에서 시작해 각 yaw×horizon cell의 hard gate를 독립 적용하고, online에서는 측정 uncertainty가 지지하는 cell의 공통 후보만 반환한다.

구현한 shared batch 경계

  1. prepare_screened_grasp_deployment()가 full intrinsic ancestry, exact object와 canonical hand collision model을 한 번 확인하고 robot, end effector, object와 combined collision checker를 한 번 load한다.
  2. Producer는 verified prediction batch의 source order를 따라 각 yaw의 motion prediction만 바꿔 endpoint IK·collision assessment를 생성한다.
  3. 각 assessment의 모든 direct source는 motion_prediction을 제외하고 exact same path여야 한다. 다른 robot, policy, workcell, semantics 또는 evaluator는 batch 중간에 들어갈 수 없다.
  4. 두 column yaw/absolute-assessment reference는 finite, strictly increasing, unique이고 공백 경로를 허용하지 않는다.
  5. 별도 batch verifier가 첫 assessment의 complete intrinsic/model ancestry를 확인하고 이후 assessment의 shared source와 각 prediction path·ID를 ordered batch에 다시 결속한다.

이 최적화는 gate를 줄이지 않는다. Full intrinsic 검증과 model load의 소유 단위를 yaw가 아니라 immutable batch로 올린 것이다. Verifier는 source·context·derived decision integrity를 확인하지만 IK/FCL을 다른 solver로 두 번째 계산하는 physical oracle은 아니다. 따라서 endpoint와 atlas는 prefilter diagnostic이고 complete trajectory의 independent full-mesh/continuous validator가 여전히 필요하다.

남은 권한 경계

Current intrinsic protocol과 stable pose, conveyor calibration은 provisional이다. Atlas endpoint는 30도 yaw grid와 mean object pose를 검사하며 저장된 positional covariance를 collision margin에 직접 넣지 않는다. 따라서 sample 사이 continuous yaw/time과 correction envelope의 권한은 complete path-family tube가 별도로 소유해야 한다. Endpoint IK와 collision은 complete moving task path, dynamics, stop path, controller limit, moving-contact timing, connector metrology 또는 hardware grasp success를 증명하지 않는다. Full-yaw batch와 atlas가 완료돼도 다음 단계는 sampled task/stop family의 실제 artifact producer, actual-time Viser replay, accelerated backend 대 full-mesh oracle agreement와 p50/p95/p99 측정이다. Continuous validator와 hardware가 없으므로 controller commit은 계속 구현하지 않는다.

Complete shortlist decision ledger, full-yaw atlas, sampled path oracle가 앞뒤 단계의 근거를 설명한다.
