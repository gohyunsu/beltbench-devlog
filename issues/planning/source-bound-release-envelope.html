ISSUE-063 · 2026-08-12 · source-bound analytic release envelope

Drop collision box를 사람이 정하지 않고 exact detach source에서 유도한다.

Drop 이후 로봇이 피해야 할 영역을 임의 크기의 box로 넘기면 시각적으로는 그럴듯해도 실제 detach pose, grasp, connector, robot FK와 ballistic motion을 보존하지 못한다. Offline compiler가 object-frame sphere와 exact detach FK, constant-acceleration release의 모든 축별 극값으로 보수적 AABB를 유도하고, lifecycle이 같은 task source인지 다시 확인하도록 경계를 바꿨다.

현재 효력: source c85435b는 분석적 release-envelope compiler와 recursive source verification을 구현한다. RTX 3090 planning 환경에서 전체 857 tests가 통과했고 14 tests는 optional dependency 조건으로 skip됐다. 이 결과는 source closure와 CPU-side contract 회귀이며, cuRobo full-task collision 또는 hardware execution authority가 아니다.

분석과 방법

Detach sample의 arm configuration으로 arm_base_from_tool을 계산하고, 선택 grasp의 object_from_hand_root와 connector transform을 결합해 arm_base_from_object_at_detach를 얻는다. Object sphere 중심은 이 transform으로 arm-base frame에 배치한다. Release 동안 orientation은 고정하고 translation만 다음 식으로 진행한다고 명시한다.

d(t) = v0 * t + 0.5 * a * t^2,  0 <= t <= duration

각 축에서 t=0, t=duration, 구간 내부에 존재하는 t=-v0/a를 평가한다. 모든 sphere 중심의 최소·최대에 sphere radius와 추가 collision padding을 더해 하나의 arm-base axis-aligned box를 만든다. 이는 fixed-orientation sphere proxy에 대한 분석적 AABB이며, 실제 물체 mesh의 자유회전이나 bin contact dynamics를 증명하지 않는다.

구현한 경계

  • ResidentReleaseEnvelope가 template, grasp, connector, sphere set, release motion digest와 exact detach object pose, 유도된 swept box를 함께 보존한다.
  • 필수 source는 resident template, grasp library, robot manifest, arm URDF, attached sphere set, release motion의 여섯 파일이다.
  • Builder는 여섯 파일을 disk에서 다시 읽고 전달 객체와 semantic equality를 검사한다. 선택 grasp ID는 library에서 정확히 한 항목으로 해석돼야 한다.
  • Pinocchio adapter는 사용한 URDF SHA-256과 tool frame을 노출한다. Builder는 manifest의 arm URDF와 arm-tip link에 일치하지 않는 FK adapter를 거부한다.
  • Collision bundle은 embedded envelope와 source artifact가 같은지 검사한 뒤 nested source checksum도 재검증한다.
  • Bundle 생성과 runtime load는 nested source를 다시 parse해 template, grasp, connector, robot, sphere, release semantics를 envelope metadata와 재대조한다.
  • Object lifecycle은 현재 template, grasp, connector, sphere set, release motion과 재계산한 detach pose가 envelope에 일치하지 않으면 fail-closed한다.
  • cuRobo adapter에는 envelope 내부의 derived swept_volume만 전달한다. 생성 방법과 provenance는 host-side gate에서 유지한다.

검증 결과

  • Targeted 51 tests: analytic internal extremum coverage, box tamper, arm-URDF·release source mutation, builder와 load-time source rejoin, stale lifecycle release, visualization semantic join, Pinocchio adapter 회귀를 통과했다.
  • 전체 suite: Ran 857 tests in 21.104s, OK (skipped=14).
  • 새 CLI의 import와 required argument surface를 같은 planning environment에서 확인했다.
  • 실제 Pepsi release envelope는 생성하지 않았다. Resident template, exact selected grasp-library artifact, task-specific release-motion JSON이 아직 없기 때문이다.

남은 한계와 다음 단계

분석적 AABB는 online robot collision에서 release object를 매 sample mesh update하지 않기 위한 보수적 표현이다. Object 회전, air drag, bin rim impact, bounce, hand-opening dynamics와 calibration 오차는 포함하지 않는다. 다음 단계는 execution-selected Pepsi path-family에서 full resident template과 release motion을 materialize하고, 같은 source chain으로 envelope와 collision bundle을 만든 뒤 graph-captured cuRobo의 세 collision pass가 한 full-task lease를 생성하는지 측정하는 일이다. 이후 같은 exact command를 MuJoCo measured rollout과 Viser에 연결하되, simulation 결과를 cuRobo 또는 hardware authority로 승격하지 않는다.
