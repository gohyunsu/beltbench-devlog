ISSUE-067 · 2026-08-12 · cuRobo dynamic collision qualification

Parity와 latency 증거가 실제 runtime gate까지 이어질 때만 cuRobo backend를 활성화한다.

기존 resident gate는 lifecycle과 geometry bundle digest를 확인했지만, 그 geometry가 HPP-FCL mesh oracle과 parity를 통과했고 해당 GPU workload가 deadline을 만족했다는 사실까지 catalog에 결속하지 않았다. 동적 corpus, candidate representation, target-GPU benchmark를 하나의 qualification receipt로 묶고 catalog, backend result, runtime assessment가 같은 SHA-256을 왕복하도록 수정했다.

현재 판정: 구조적 우회 경로는 닫혔지만 실제 Pepsi cylinder backend는 qualification을 받지 못한다. 독립 unsafe case가 없고, 402개 mesh-clear state 중 130개를 false positive로 거부하며, CUDA graph 없이 측정한 p99 63.210 ms가 10 ms sampled-gate deadline을 초과한다. 따라서 hardware authority는 계속 false다.

채택한 신뢰 경계

  1. Schema 3 corpus는 각 robot state와 함께 object pose, conveyor/contacting/attached/releasing/released/contained/placed lifecycle state를 저장한다.
  2. Acceptance policy schema 1.2는 candidate collision representation을 명시한다. Static 기본값을 묵시적으로 상속하지 않는다.
  3. Startup qualification은 capability, runtime policy, 1,000-trial benchmark, corpus, HPP-FCL oracle, candidate report와 parity comparison을 모두 재계산한다.
  4. Receipt는 backend source, configuration, workcell, object, lifecycle과 geometry bundle digest를 한 번에 결속한다.
  5. Process-local verified wrapper만 runtime gate를 구성할 수 있다. 저장된 receipt를 읽는 것만으로는 활성화되지 않는다.
  6. Catalog, backend call, compact result와 runtime assessment가 동일 qualification SHA를 반환해야 한다.

잘못된 continuous claim 수정

첫 구현은 moving object 안전을 이유로 resident sampled-gate policy에 continuous_collision을 추가했다. GPU 서버 전체 테스트의 test_resident_collision_gate_is_a_distinct_gpu_workload가 즉시 실패했다. 이 테스트는 sampled gate가 IK, trajectory optimization과 continuous collision을 수행했다고 주장하지 않도록 보호한다.

수정은 테스트 기대값을 낮추는 방식이 아니었다. 정책과 qualification의 필수 operation에서 continuous_collision을 제거하고, receipt와 assessment가 diagnostic이며 execution_authorized=false임을 유지했다. Continuous swept collision은 실제 kernel, 독립 evidence와 deadline benchmark를 가진 별도 gate로 구현해야 한다.

검증 결과

  • 동적 corpus round-trip에서 같은 robot joint와 다른 object pose가 서로 다른 state SHA를 가진다.
  • Candidate representation이 policy와 다르면 comparison이 거부된다.
  • 동적 unsafe state 하나를 candidate가 clear로 판단하면 qualification이 거부된다.
  • Benchmark robot configuration이 candidate configuration과 다르면 qualification이 거부된다.
  • Verified process object가 없거나 backend result의 qualification SHA가 다르면 runtime gate가 거부된다.
  • 기존 schema 2.0 diagnostic assessment는 qualification field 없이 동일 payload로 유지되고, qualified path만 schema 2.1을 쓴다.

남은 작업

  1. HPP-FCL mesh에서 pose, yaw, joint와 contact를 경계 안팎으로 perturb해 독립 clear/unsafe/boundary corpus를 생성한다.
  2. Hand distal link의 close robot-object proxy를 다시 만들고 zero false negative와 운영 가능한 false-positive rate를 달성한다.
  3. Sampled resident workload를 fixed CUDA graph로 구현해 실제 1,000-trial p99를 10 ms 아래로 낮춘다.
  4. 별도 continuous swept collision gate를 구현하고 sampled qualification과 혼합하지 않는다.
  5. Robust clearance가 uncertainty budget을 넘는 approach로 교체한 뒤 attach, bin release, abort와 MuJoCo/Isaac replay를 연결한다.
