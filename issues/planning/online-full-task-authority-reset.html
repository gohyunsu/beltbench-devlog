ISSUE-108 · 2026-08-30 · online full-task authority reset

Nearest grasp를 금지하지 않고 후보 검색과 실행 권한을 분리한다.

기존 Isaac positive demo는 RGB observation 뒤 resident full-command를 선택하고 시간·위치를 보정했다. 이는 perception과 controller 연결 회귀에는 유용하지만, 현재 object pose와 robot state에서 full task를 새로 생성하는 목표의 증거가 아니다. Production topology를 grasp retrieval, intercept batch, online motion generation, exact validation, maximin selection 순서로 다시 고정했다.

현재 효력: beltbench@7714470은 candidate-only nearest grasp와 observation-after-command causality 계약을 구현한다. 이 변경은 실제 cuRobo full-task command나 professor video를 생성하지 않았으며, 설정된 239 ms observation-to-command budget도 아직 RTX 측정 결과가 아니다.

문제 정의를 다시 고정한 이유

실제 시스템에서는 stable pose, planar position, full yaw, belt phase, 현재 arm/hand q/qd/qdd를 observation 이전에 알 수 없다. 따라서 이 값들로 결정되는 grasp, intercept time, IK branch, trajectory와 collision 결과도 online이어야 한다. 반면 CAD, stable-pose 후보, symmetry metadata, target-hand static grasp와 static 성공 evidence, calibration, collision model과 warmed solver resource는 offline/startup에 둘 수 있다.

기존 compatible_grasps()는 exact object·stable pose·hand·capability·quality gate 뒤 static margin으로 정렬하고 validated[0] 하나를 선택했다. 이는 정적 library resolution에는 타당하지만 현재 hand pose와 complete path를 고려한 online 후보 search는 아니다. 또한 문서의 “nearest-neighbor grasp 금지”가 다른 stable pose로 넘어가는 fallback과 같은 context 안의 bounded nearest shortlist를 구분하지 못했다.

Nearest grasp의 새 역할

경계허용금지
Hard context동일 object, admitted stable pose, target hand, task capability와 static evidence다른 object·pose·hand에서 이름이나 거리로 대체
거리현재 추정 object frame에서 hand-root translation과 SO(3) geodesic rotation의 bounded SE(3) 거리측정 yaw를 저장 yaw로 반올림하거나 stable pose를 nearest class로 변경
출력최대 K개의 planner candidate 또는 solver seedNearest 결과를 그대로 controller command로 실행
최종 판단현재 track·belt·robot state의 online full-path IK, collision, timing과 maximin 검증Static quality나 거리 하나로 pick 승인

Object-relative grasp는 측정된 full object pose로 직접 변환한다. 대칭성은 별도 source-closed equivalence가 승인된 경우에만 upstream canonicalization에 사용한다. 일반 비대칭 object에서는 full yaw를 보존한다.

Production stage 순서

RGB/encoder/robot state
  -> segmentation -> CAD pose -> planar fit -> acquisition gate
  -> constant-yaw belt tracking
  -> same-context grasp candidates
  -> future intercept candidate batch
  -> online full-task motion generation from current q/qd/qdd
  -> exact command validation
  -> robust maximin selection
  -> capacity-one future-start controller lease
  -> feedback, lifecycle, asynchronous evidence

resident_decision과 correction_envelope는 이 topology의 command authority가 아니다. 기존 full-command, path family와 trajectory는 회귀 또는 solver_seed_only로만 남는다. Cached command, precomputed-command execution authority, simulator truth와 CPU planner fallback은 admission에서 모두 false다.

개발 중 발견한 문제와 해결

문제원인해결과 결과
Nearest를 전부 금지하면 현재 state에 가까운 seed를 빠르게 찾을 수 없음Cross-pose fallback과 same-context shortlist를 같은 용어로 취급함Exact hard gate 뒤 candidate-only bounded nearest를 허용하고 execution authority를 별도 admission으로 이동했다.
초기 구현의 distance field를 payload에서 바꿔도 통과할 수 있음Transform에서 distance를 재계산하지 않고 저장 숫자의 범위와 정렬만 검사함Translation, rotation과 weighted distance를 exact transforms에서 재계산하고 1e-12 tolerance로 검증한다.
Direct dataclass 생성에서 NaN 또는 boolean generation이 비교식을 우회할 가능성Loader는 type을 검사했지만 direct constructor의 validate()가 모든 숫자 타입을 다시 확인하지 않음Candidate, batch, input, validation과 admission의 finite/type 검사를 직접 추가하고 변조 test를 만들었다.
Candidate batch와 command input의 track/robot ancestry가 따로 존재함각 artifact hash는 있었지만 서로 같은 source인지 비교하지 않음ID, SHA-256과 timestamp를 command admission에서 exact equality로 결속했다.
ADR 하단이 resident path-family D2를 production 순서로 유지함상단의 8월 29일 online decision 뒤 과거 구현 순서를 갱신하지 않음Event-driven online generation과 exact validation 순서로 교체하고 unbounded per-tick replanning만 기각했다.
전체 suite에서 기존 resident test 1건이 10초 deadline을 초과고비용 전체 suite 부하와 wall-clock fixture가 겹쳐 validated_lease_binding 전에 deadline이 지남전체 결과를 실패로 보존하고 같은 test를 단독 재실행했다. 단독 실행은 통과해 기능 회귀가 아니라 부하 민감 timeout으로 분류했다.

검증 결과

  • Online grasp, command admission과 realtime topology targeted suite: 45 passed.
  • 전체 suite: 2058 passed, 68 skipped, 1 failed, 113 subtests, 749.28초. 실패는 위의 기존 10초 wall-clock timeout이다.
  • 실패 test 단독 재실행: 1 passed, setup 포함 68.66초.
  • Distance 변조, cross-pose/hand/object fallback, timestamp 역전, simulator truth, cached/precomputed command authority와 rejected collision report를 모두 fail-closed로 확인했다.
  • RTX cuRobo integrated latency, actual online full-task command, Isaac measured execution과 영상은 아직 생성하지 않았다.

다음 단계

  1. NAS source-closed Pepsi와 banana grasp를 새 candidate batch 입력으로 materialize하되 runtime NAS traversal은 하지 않는다.
  2. 현재 track과 q/qd/qdd에서 복수 intercept와 approach-to-retreat command를 생성하는 provider-neutral orchestrator를 구현한다.
  3. RTX 3090의 warmed fixed-shape cuRobo backend를 연결하고 GPU failure를 no-pick으로 유지한 채 p50/p95/p99를 측정한다.
  4. 동일 core를 Isaac RGB, encoder, articulation feedback과 controller adapter에 연결하고 prim truth 없이 다양한 xy/yaw/speed/initial q trial을 실행한다.
  5. 통과한 measured trace에서만 단계 색상과 actual-time video를 생성한다.

이전 full-task 재감사와 AutoDex static filter 재감사가 이 변경의 이전 권한 경계를 설명한다.
