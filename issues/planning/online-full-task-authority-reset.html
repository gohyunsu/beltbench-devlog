프로젝트이슈
ISSUE-108 · 2026-08-30 · online full-task authority reset

Nearest grasp를 금지하지 않고 후보 검색과 실행 권한을 분리한다.

기존 Isaac positive demo는 RGB observation 뒤 resident full-command를 선택하고 시간·위치를 보정했다. 이는 perception과 controller 연결 회귀에는 유용하지만, 현재 object pose와 robot state에서 full task를 새로 생성하는 목표의 증거가 아니다. Production topology를 grasp retrieval, intercept batch, online motion generation, exact validation, maximin selection 순서로 다시 고정했다.

현재 효력: beltbench@3da1de5은 candidate-only nearest grasp, current-state online intercept, 4-candidate 5-phase cuRobo command generation, exact-command component validator 계약, GPU joint/subinterval/Jacobian 검사와 nearest-rank 비의존 maximin 선택까지 구현한다. 그러나 v28 sphere model은 source fit에 실패했으며 actual online target, 완전한 collision validator, controller admission과 Isaac RGB 실행도 아직 연결되지 않았다. 따라서 production pick과 professor positive video 권한은 없다.

문제 정의를 다시 고정한 이유

실제 시스템에서는 stable pose, planar position, full yaw, belt phase, 현재 arm/hand q/qd/qdd를 observation 이전에 알 수 없다. 따라서 이 값들로 결정되는 grasp, intercept time, IK branch, trajectory와 collision 결과도 online이어야 한다. 반면 CAD, stable-pose 후보, symmetry metadata, target-hand static grasp와 static 성공 evidence, calibration, collision model과 warmed solver resource는 offline/startup에 둘 수 있다.

기존 compatible_grasps()는 exact object·stable pose·hand·capability·quality gate 뒤 static margin으로 정렬하고 validated[0] 하나를 선택했다. 이는 정적 library resolution에는 타당하지만 현재 hand pose와 complete path를 고려한 online 후보 search는 아니다. 또한 문서의 “nearest-neighbor grasp 금지”가 다른 stable pose로 넘어가는 fallback과 같은 context 안의 bounded nearest shortlist를 구분하지 못했다.

Production stage 순서

RGB/encoder/robot state
  -> segmentation -> CAD pose -> planar fit -> acquisition gate
  -> constant-yaw belt tracking
  -> same-context grasp candidates
  -> future intercept candidate batch
  -> online full-task motion generation from current q/qd/qdd
  -> exact command validation
  -> robust maximin selection
  -> capacity-one future-start controller lease
  -> feedback, lifecycle, asynchronous evidence

resident_decision과 correction_envelope는 이 topology의 command authority가 아니다. 기존 full-command, path family와 trajectory는 회귀 또는 solver_seed_only로만 남는다. Cached command, precomputed-command execution authority, simulator truth와 CPU planner fallback은 admission에서 모두 false다.

Current-state full-task generator 구현

OnlineMotionGenerationRequest는 current track에서 만든 bounded intercept와 같은 generation의 robot q/qd/qdd, object/robot/connector/hand/workcell/motion-limit/drop-region hash를 결속한다. Candidate 순서는 nearest 기반 compute priority를 보존하지만 최종 선택 권한은 없다. OnlineFullTaskCartesianTargetBatch는 각 intercept의 full yaw와 object-relative grasp를 exact connector transform으로 arm-tip pregrasp/contact/lift target으로 바꾸고, fixed bin drop와 retreat target을 추가한다.

generate_online_full_task_motion()은 warmed provider-neutral fixed-batch backend를 다섯 번 호출한다. 순서는 pregrasp, moving contact, lift, bin transfer, retreat이며 closure와 drop은 시간화된 hold로 command에 삽입한다. 한 단계에서 실패한 candidate slot은 이후 모든 단계에서 inactive_padding으로 유지한다. 성공 slot만 실제 이전 endpoint q/qd/qdd에서 이어지고, contact와 transfer endpoint가 hold-entry 속도·가속도 bound를 만족하지 않으면 fail-closed한다.

Hand command는 controller에서 읽은 현재 상태에서 시작해 선택한 static grasp의 pregrasp, grasp, retention, release command를 piecewise quintic으로 연결한다. 결과는 replan cutoff, close start, contact, close complete, attach, release start, retention end, detach, open complete event와 7개 phase를 포함한다. Contact의 command-relative time과 intercept absolute timestamp는 exact하게 일치한다. 첫 waypoint는 GPU 반올림값이 아니라 요청에 결속된 현재 q/qd/qdd를 그대로 사용한다.

v28을 collision authority에서 제외한 이유

낮은 kernel latency와 collision geometry의 정확성은 별개다. v28 build report 자체가 sphere_fit_quality_accepted=false, execution_authorized=false를 기록한다. 5,882개 sphere를 사용했지만 arm base와 arm links, connector hand side, Inspire proximal links에서 uncovered gap, surface-gap p95, repair residual 또는 volume coverage 기준을 통과하지 못했다. 따라서 과거 holdout kernel이 빠르게 실행되었다는 사실로 source geometry 실패를 덮을 수 없다.

이번 진단은 같은 robot.yml을 wrist kinematics resource로만 사용하고 compute_spheres=false를 강제했다. 생성된 보고서도 collision_authorized_for_online_validation=false와 execution_authorized=false를 보존한다. Production collision은 replacement sphere model이 exact source-fit policy와 독립 mesh holdout을 통과한 뒤에만 같은 exact-command validator에 들어갈 수 있다.

왜 아직 검증된 Pepsi grasp라고 부를 수 없는가

NAS pose-resolution report는 provider inspire의 정적 성공을 source-000 2건, source-001 3건, source-002 0건으로 보존한다. 그러나 report 자체가 provider Inspire와 target inspire_left의 chirality·joint·contact mapping을 unresolved로 둔다. 별도 selected-100 Pepsi catalog의 2 success/1 failure는 Allegro hand다. 따라서 두 결과는 좋은 proposal prior이지만 현재 41개 target-left BODex grasp를 hardware_static으로 승격하지 못한다. Atlas grasp도 모두 validation_scope=unvalidated, atlas도 execution_blocked=true다.

이 한계를 loader가 숨기지 않는다. Production request는 provisional_grasp_not_admitted, exact object/pose/hand/capability source가 없으면 no_registered_grasp_source로 종료한다. Diagnostic에서 nearest candidate를 얻더라도 이후 현재 track의 intercept, 현재 robot state의 IK, complete-path collision·timing, closure·lift·drop·retreat와 maximin 검증을 모두 새로 실행해야 한다.

다음 단계

  1. 현재 provisional source를 승격하려 하지 말고, target-hand static qualification을 별도 evidence로 완료하거나 production no-pick을 유지한다.
  2. 새 online command를 기존 resident certificate로 위장하지 않는다. V28 sphere model은 제외하고 replacement model을 exact source-fit policy와 independent mesh holdout으로 먼저 적격화한다.
  3. b8303c4의 fixed identity/order 계약에 적격 GPU collision adapter를 연결한다. 이미 구현한 joint/workspace/singularity 검사와 함께 self/connector/world/time-indexed moving-object margin을 실제 생성 command에서 산출한다.
  4. 동일 core를 Isaac RGB, encoder, articulation feedback과 controller adapter에 연결하고 prim truth 없이 다양한 xy/yaw/speed/initial q trial을 실행한다.
  5. 통과한 measured trace에서만 단계 색상과 actual-time video를 생성한다.

이전 full-task 재감사와 AutoDex static filter 재감사가 이 변경의 이전 권한 경계를 설명한다.
