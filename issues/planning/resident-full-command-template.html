ISSUE-046 · 2026-08-11 · resident full-command template

전체 arm-hand event command를 먼저 고정하고, cuRobo는 arm prefix만 GPU에서 갱신한다.

Pre-contact capture의 범위를 바로잡은 뒤 splice 의미를 다시 검사했다. 단순히 first contact에서 기존 full-task reference suffix를 붙이는 방법도 안전하지 않았다. 현행 event schedule은 hand-close start가 first contact보다 앞서기 때문에, pre-contact request의 external hand hold와 source event trajectory의 hand closure가 이미 접촉 전에 충돌한다. 따라서 CPU에서 사후 suffix를 이어 붙이지 않고, close·contact·attach·lift·transfer·release·return 전체를 exact resident template으로 컴파일한 뒤 online cuRobo가 certified latch 전 arm prefix만 덮어쓰는 구조로 전환했다.

현재 효력: source 77f158d는 complete event request를 named arm/hand time/q/qd/qdd와 exact fixed sample count로 컴파일하고, dtype별 tensor digest·runtime session·event/latch index를 CUDA catalog metadata와 full-grid arm-prefix request에 결속한다. 아직 실제 cuRobo upload/solve, full output lease와 controller adapter가 없으므로 execution_authorized=false이며 기존 pre-contact capture를 full pick으로 승격하지 않는다.
2026-08-11 후속: source 6b23710에서 template schema를 1.2로 올려 grasp·connector digest를 직접 결속하고, first contact 이후 object collision lifecycle 입력을 구현했다. 자세한 state transition과 중첩 collision pass는 ISSUE-047에 기록한다.

발생한 문제

관찰직접 원인잘못된 해결의 위험
현재 fixed-shape request는 certified_preclose_external_hold다.온라인 입력은 arm prefix 최적화만 모델링하고 hand trajectory를 materialize하지 않는다.Reference hand closure를 나중에 붙이면 실제 planner request에 없던 command가 추가된다.
hand_close_start < first_contact다.움직이는 물체를 잡으려면 접촉 전에 closure가 시작되는 complete event schedule이 필요하다.Contact 시점 splice는 hand command 불연속을 이미 지나친다.
Catalog entry는 digest, joint names, count만 보존했다.Metadata가 complete suffix tensor와 event indices를 대신할 수 없었다.Close·attach·drop이 어느 sample인지와 실제 qd/qdd를 검증할 수 없다.
Pre-contact capture와 full reference의 provenance가 다르다.하나는 planner/controller 경로, 다른 하나는 offline animation·simulation reference다.CPU append는 실행되지 않은 suffix를 controller-consumed command처럼 보이게 한다.

원인 분석

문제는 suffix 파일 하나가 부족한 것이 아니라 command assembly의 권위가 정의되지 않은 것이다. Arm과 hand를 따로 생성한 뒤 contact에서 결합하면 event timing, interpolation, attachment collision semantics와 controller lineage가 분리된다. 실시간성을 이유로 이 결합을 online CPU 작업으로 남기면 매 trial의 allocation·serialization·검증 비용도 늘어난다. 올바른 경계는 complete synchronized command를 offline에 고정하고, online에서는 bounded prefix overwrite 한 번만 허용하는 것이다.

구현 후 재감사에서 찾은 fixed-shape 문제

첫 구현은 maximum sample interval만 고정하고 필요한 subdivision 수를 path마다 계산했다. 이는 각 template의 sample 수가 달라질 수 있어 fixed tensor shape와 CUDA graph replay 전제를 깨뜨린다. Offline compiler 입력에 exact sample count를 추가하고, 모든 critical boundary 구간에 최소 한 interval을 배정한 뒤 현재 interval 폭이 가장 큰 구간부터 deterministic하게 subdivision을 추가하도록 수정했다. 지정 수로 maximum interval을 만족할 수 없으면 template을 만들지 않는다. 따라서 catalog는 모든 path family에 같은 count를 요구할 수 있고 waypoint·event·latch exact sample도 유지한다.

cuRobo 충돌 방향

사수님의 질문에 대한 최종 방향은 cuRobo를 online collision authority로 채택하는 것이다. 기존 HPP-FCL을 online loop에 그대로 두는 이유는 없다. 다만 sphere/cuboid 근사와 attached-object semantics가 exact mesh와 다를 수 있으므로 HPP-FCL을 제거하지 않고 offline 독립 oracle로 역할을 바꾼다.

즉 “가능한 모든 모듈의 GPU화”가 아니라 “critical-path의 병렬 계산과 데이터를 resident GPU에 유지”하는 것이 목표다. 작은 predictor나 freshness gate까지 옮기면 host-device synchronization과 오류 처리가 늘어 오히려 tail latency가 악화될 수 있다. cuRobo의 평균 속도도 hard deadline 증거가 아니므로 fixed shape, preallocation, CUDA graph replay, host round-trip 제한과 target-GPU p99/deadline-miss benchmark가 별도로 필요하다.

구현한 해결

  1. ResidentEventCommandTemplate schema 1.2를 추가했다. Template은 complete task duration, exact fixed sample count, named arm/hand joints, source segment와 phase를 가진 time/q/qd/qdd samples와 grasp·connector digest를 보존한다.
  2. 모든 source waypoint를 exact sample index로 넣고, replan cutoff·close start·contact·close complete·attach·release·detach event를 원래 waypoint와 window에 결속한다.
  3. 모든 certified latch time을 subdivision boundary로 먼저 삽입한다. Reconstructed quintic의 arm/hand target이 latch certificate target과 exact 일치하지 않으면 compilation을 거부한다.
  4. Sampling은 source waypoint와 latch로 먼저 구간을 나눈 뒤 maximum interval 이하로 subdivision한다. Sample density를 바꿔도 physical event와 splice state가 이동하지 않는다.
  5. Bundle canonical digest, path-family plan digest, reusable event source SHA-256, event request canonical digest, motion-limit profile digest와 세 source file evidence를 모두 기록한다.
  6. Semantic verifier는 동일 bundle·request·motion profile에서 전체 sample과 binding을 재컴파일해 payload exact equality를 요구한다.
  7. compile_resident_event_command_template.py는 bundle의 declared event/motion source를 재해시하고 write-once template을 생성한 뒤 source verification과 semantic reproduction을 즉시 수행한다.
  8. 직접 dataclass 생성 경로도 boolean index, 비어 있는 ID, non-finite time을 거부하도록 fail-closed validation을 적용했다.
  9. Dense upload tensor를 time, all q, all qd, all qdd 순서로 explicit little-endian float32/float64 변환한 뒤 header와 함께 해시한다. Template digest와 tensor digest를 분리해 dtype·axis order drift를 숨길 수 없게 했다.
  10. ResidentFullCommandCatalogEntry는 runtime-session SHA, allocation, slot, upload event, template/tensor digest, full time grid, physical events와 exact latch arm/hand target을 보존한다.
  11. Catalog set verifier는 sample count, joint identity, dtype와 event-index layout이 같고 contact prefix count가 warmed runtime session과 일치할 때만 하나의 CUDA graph shape로 허용한다.
  12. ResidentFullCommandArmPrefixRequest는 measured start와 latch 사이 arm 내부 sample만 writable로 표시한다. Latch, 이후 arm suffix와 모든 hand sample은 resident immutable이며 moving-target collision은 같은 template의 start-to-contact index에 매핑된다.

의도한 online assembly

  1. Startup에서 accepted template 전체를 bounded GPU catalog에 한 번 upload한다.
  2. Runtime observation으로 path family와 certified latch를 고르고 template을 preallocated output slot에 device-to-device copy한다.
  3. cuRobo는 measured robot state부터 latch까지 arm sample만 overwrite한다. 첫 sample과 latch sample은 고정하고 내부 sample만 최적화한다.
  4. Splice에서 arm position·velocity·acceleration이 certificate tolerance 안인지 독립 validator가 확인한다. Hand schedule과 post-latch arm/hand suffix는 변경하지 않는다.
  5. Pre-attach object는 constant-yaw translating obstacle, contact phase는 named intentional pair, post-attach object는 attached geometry로 collision을 평가한다.
  6. 하나의 full-task resident output lease만 controller에 전달한다. CPU post-hoc suffix append와 mixed provenance는 금지한다.

검증 결과

  • 새 full-template 집중 테스트 5개가 통과했다.
  • Event trajectory, path-family와 기존 arm-prefix를 포함한 인접 회귀 46개가 통과했다.
  • 후속 lifecycle까지 포함한 planning 환경의 최신 전체 suite는 679개 중 674개 통과, 2개 기존 skip이었다. 3개 module import error는 선택적 cv2가 없는 기존 환경 분리 문제다.
  • Calibration 환경에서 calibration·pickplace·pose module의 14개 테스트가 모두 통과했다.
  • 새 CLI --help, 전체 package/script byte-compile와 git diff --check가 통과했다.

현재 제한과 다음 단계

  • Offline full template과 next-generation catalog/request 계약까지 구현했다. 기존 ResidentPathCatalogEntry, fixed-shape request, output lease, controller handoff와 capture는 계속 pre-contact scope이며 조용히 새 의미로 바꾸지 않았다.
  • Catalog의 upload event는 metadata일 뿐 device byte upload를 증명하지 않는다. 실제 GPU device-to-device template copy, cuRobo arm-prefix overwrite와 C2 splice validator는 아직 구현하지 않았다.
  • 기존 pre-contact object batch는 계속 first contact에서 끝난다. 별도 full-task lifecycle 입력이 contact-to-attach, attached transport와 release를 source-bound하게 닫았지만 아직 실제 cuRobo kernel로 실행하지 않았다.
  • Junjinyong server의 NVIDIA driver 535는 선택한 cuRobo V2 정책 최소 580.65.06보다 낮다. V2 parity·latency·deadline 결과를 주장할 수 없다.
  • 다음 구현은 cuRobo output을 하나의 full-task resident lease에 결속하고, C2 splice·pre/post-attach collision·event lineage를 독립 검증하는 것이다.
  • 그 다음 actual full command만 MuJoCo와 1x auto-loop Viser에 연결한다. Hardware 복구 후 controller interpolation, measured tracking과 grasp/drop 성공률을 검증한다.

Pre-contact replay boundary, cuRobo collision audit, Resident command lineage를 함께 참고한다.
