ISSUE-089 · 2026-08-26 · physical target is RGB, not RGB-D

깊이를 대체하는 fallback이 아니라, RGB-only 관측 계약과 검증 순서를 다시 닫는다.

실제 장비의 카메라가 RGB라는 사실을 기준으로 전체 D1 경계를 다시 감사했다. Metric 위치는 depth image가 아니라 알려진 CAD scale, stable tabletop pose, camera calibration과 belt plane에서 얻고, 초기 pose 이후의 이동은 encoder가 전파한다. 현재 Isaac RGB background mask와 FoundPose를 바로 연결한 방법은 개발 분할에서 실패했으므로 교수용 새 영상을 만들기 위해 threshold를 느슨하게 하지 않는다.

현재 판정: 센서, observation, planner 인터페이스의 RGB-only 전환은 구현됐다. 그러나 현재 RGB background mask 기반 pose는 qualification에 실패했다. 기존 r218은 역사적 actual-time integration diagnostic이지만 instance-mask 계보를 포함하므로 physical RGB camera의 segmentation/pose 증거가 아니다. 새 source-matched D1-D3 영상은 learned RGB mask와 pose development가 통과하기 전까지 보류한다.

고정한 실제 시스템 계약

synchronized raw RGB cameras
  -> calibration-bound in-memory rectification
  -> one batched object-mask backend
  -> one-shot RGB-to-CAD planar [x, y, yaw] acquisition
  -> exact measurement-time encoder registration
  -> 60 Hz constant-yaw translation propagation
  -> prevalidated intercept family selection
  -> collision gate -> future-start controller lease
  -> measured contact, release, bin containment
  • Object identity와 stable tabletop pose ID는 trial 전에 주어진다.
  • 초기 belt-frame x, y와 yaw는 RGB에서 측정한다. 물체가 belt 위에서 추가 회전하지 않는다는 가정만 사용한다.
  • Camera intrinsic/extrinsic, belt plane, belt axis, CAD scale과 stable pose가 metric scale을 제공한다. Observed depth, zero depth, simulator pose fallback은 금지한다.
  • FoundPose는 상류 event에서 한 번 실행할 수 있지만 매 frame stage가 아니다. 이후 위치는 encoder가 60 Hz로 전파한다.
  • GoTrack은 qualified initial pose 이후 선택 가능한 correction/tracking backend다. 초기 mask와 pose 실패를 대체하지 않는다.

왜 SAM3를 그대로 online에 넣지 않는가

AutoDex의 새 init 구조도 SAM3 mask와 FoundPose를 episode 초기에 한 번 실행하고 GoTrack으로 이어간다. 그러나 AutoDex 문서의 SAM3 mask stage는 약 2.5 s이고 전체 과거 init은 수십 초였다. BeltBench의 현재 upstream acquisition budget은 0.975 s이므로 동일 코드를 직렬로 복사하면 실제시간 event를 놓친다.

SAM3는 native RGB의 offline label 생성과 품질 비교에 활용할 수 있다. Online 후보는 resident batched YOLOE/FastSAM 또는 Pepsi용 compact segmenter로 제한하고, 두 camera를 한 batch로 처리한다. 선택 기준은 보기 좋은 mask가 아니라 mask IoU/경계 오차, downstream pose acceptance와 x/y/yaw error, cross-view 일관성, p95 latency와 source/weight digest다.

다음 구현 및 승격 순서

  1. R393의 공개 development RGB에 대해 object-only evaluator mask를 offline diagnostic으로 만들어 static-background shadow와 pose failure를 요인 분리한다. 이 mask는 runtime authority로 사용하지 않는다.
  2. SAM3 teacher와 YOLOE/FastSAM/compact model 후보가 같은 RgbSegmentationBackend contract를 구현하도록 별도 environment worker를 만든다. Model weight와 source hash, camera batch identity, latency를 report에 결박한다.
  3. Development RGB에서 mask quality와 downstream FoundPose/planar error를 함께 비교한다. Empty, duplicate object, out-of-belt, insufficient support와 cross-view disagreement는 fail-closed한다.
  4. Development가 기존 yaw/position/acceptance/latency gate를 통과한 뒤에만 sealed simulation holdout을 한 번 연다. Physical camera는 조명, motion blur, exposure, calibration drift와 capture skew를 포함한 별도 native holdout을 요구한다.
  5. 통과한 segmentation, pose, encoder, event command와 runtime profile로 새 perception admission과 command admission을 만든다. 이전 revision admission은 재사용하지 않는다.
  6. RTX 3090에서 raw RGB acquisition부터 D1 color transition, D2 collision/lease, D3 contact/release/containment까지 1.0x trial과 영상을 생성한다. Report가 통과한 trajectory만 표시한다.

검증

  • 660beb8: RGB segmentation provenance 대상 테스트 8개, 전체 1,455개 통과, 22개 skipped.
  • e790570: provider-neutral segmentation/source-closure 대상 24개, 전체 1,459개 통과, 22개 skipped.
  • RTX checkout을 incremental bundle로 exact fast-forward한 뒤 대상 24개 테스트를 다시 통과했다.
  • r397 qualification은 의도대로 exit 2와 qualified=false를 냈다. 실패 report를 성공 영상 재료로 사용하지 않는다.

Calibrated RGB와 known belt plane/stable pose로 초기 planar pose를 만들고 encoder로 이동을 전파하는 구조는 닫혔습니다. 다만 현재 background mask+FoundPose는 개발 세트에서 실패했기 때문에, 지금 보여드릴 기존 영상은 simulation integration diagnostic이며 physical RGB perception 성공 영상이라고 주장하지 않습니다. 다음 영상은 qualified learned mask를 실제 raw RGB causal edge에 연결한 뒤 생성하겠습니다.”
