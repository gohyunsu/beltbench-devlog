ISSUE-106 · 2026-08-30 · asymmetric RGB planar pose

Banana를 첫 비대칭 객체로 유지하되, RGB pose holdout 실패를 숨기지 않는다.

NAS 후보를 다시 비교한 결과 banana/source-001보다 먼저 시도할 일반 객체는 없었다. Banana는 watertight 비대칭 mesh, Inspire Left 정적 성공 prior, exact stable-pose mapping, FoundPose representation과 xArm6 pick atlas를 함께 갖는다. 다만 actual-speed 두 카메라 RGB에서 개발 split은 통과했지만 translated holdout은 실패했다. 따라서 object 선택은 유지하고 FoundPose pose authority는 보류한다.

실시간 해석

300–350 ms의 one-shot acquisition은 upstream event budget 안에는 들어가지만 15/30/60 Hz tracker로 사용할 수는 없다. 실제 online graph는 object가 넉넉한 upstream 구간에 들어오면 RGB planar pose를 한 번 얻고, 이후에는 belt encoder translation과 constant yaw를 60 Hz로 전파해야 한다. 이번 translated sweep의 반복 FoundPose는 steady-state 설계가 아니라 trigger 위치 변화에 대한 robustness stress test다.

그러나 이 구분이 holdout 실패를 없애지는 않는다. 초기 trigger가 16 mm 범위에서 달라질 수 있고 physical RGB는 더 큰 exposure·blur·calibration 변화를 가진다. 따라서 현재 banana FoundPose는 offline candidate이며 simulation·physical runtime authority는 아니다.

다음 단계

  1. YOLOE를 pixel-perfect silhouette가 아니라 object proposal/crop provider로 평가하는 별도 계약을 만든다. Wrong instance, ambiguity, object containment, crop stability와 latency를 gate한다.
  2. Proposal mask를 입력으로 CAD-constrained pose가 최종 x/y/yaw를 결정하게 하고, pose truth와 cross-camera consistency를 별도로 qualification한다.
  3. 새 upstream trigger-zone campaign을 만들어 위치 jitter, RGB renderer variation, segmentation과 timing을 함께 평가한다. 이번 holdout은 재사용하지 않는다.
  4. Pose가 atlas의 지원 yaw 60–210°에 들어올 때만 grasp를 반환하고 나머지는 no-pick으로 표시한다. Nearest-yaw fallback은 두지 않는다.
  5. Pepsi Light actual-time 영상은 symmetric baseline으로 유지하고, banana 영상은 perception→atlas→no-pick/pick decision→encoder tracking이 동일 trace로 닫힌 뒤 두 번째 시연으로 추가한다.

Banana pick atlas, RGB-only 관측 계약, planar backend 승격 원칙이 관련 경계를 설명한다.
