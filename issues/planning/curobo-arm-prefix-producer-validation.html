ISSUE-060 · 2026-08-12 · source-bound cuRobo arm-prefix producer

보수적 world proxy로 계획하고 같은 arm prefix를 고해상도 모델로 다시 검사한다.

Collision 계약과 holdout만 있던 상태에서 실제 cuRobo V2 TrajectoryOptimizer를 resident full-command의 arm-prefix 경계에 연결했다. Producer는 빠른 512-sphere proxy로 static world collision만 최적화한다. Hand schedule은 request 값으로 고정하고, self·connector·static world는 별도의 5,882-sphere validator가 같은 81-state tensor를 다시 검사한다. 이 분리는 “cuRobo를 사용한다”는 이름보다 어떤 모델이 어떤 판정 권한을 갖는지를 명확히 한다.

현재 판정: RTX 3090에서 0.8초 nontrivial arm prefix를 30회 측정했다. World-only producer는 p99 29.708 ms, 고해상도 sampled collision validator는 p99 14.119 ms였고 81개 state의 self/world/joint-bound positive count는 모두 0이었다. 두 수치의 직렬 합은 약 43.827 ms다. 그러나 이 입력은 collision holdout에서 고른 두 clear endpoint를 잇는 arm-prefix 진단이며 Pepsi moving-object full command가 아니다. Dynamic object, contact, attachment, continuous collision, dynamics, abort, controller와 hardware 실행은 여전히 차단한다.

고해상도 모델을 TrajectoryOptimizer에 직접 넣은 실험은 초기화 약 114초, 첫 solve 약 4.15초, warm solve 약 2.21초가 걸렸다. 이는 online producer로 사용할 수 없다. 반대로 512-sphere proxy는 각 sphere가 원 고해상도 sphere union을 포함하도록 만들었기 때문에 static world false negative를 막지만, 팽창한 sphere끼리의 self collision은 모든 holdout state를 unsafe로 만들었다. 따라서 proxy의 self cost를 임의로 신뢰하지 않고 self 판정 권한을 고해상도 validator에만 남겼다.

구현한 모듈 경계

  1. Contract: cuRobo revision, proxy robot/configuration, accepted proxy assessment, solver shape, latency·endpoint·joint trust-tube 한계와 collision 책임을 불변 policy/result로 보존한다.
  2. Planning: Vendor를 import하지 않고 nominal prefix seed 생성, raw C2 state 검증, exact request time 재표본화, start·latch boundary anchoring과 기존 full-command write mask 조립만 수행한다.
  3. Vendor adapter: 이미 초기화된 cuRobo solver만 감싸고 Torch/CUDA tensor, zero internal jerk boundary, one nominal seed, fixed dt와 raw result 추출을 담당한다.
  4. Benchmark: HPP-FCL과 proxy 양쪽에서 clear인 독립 v3 endpoint를 선택하고 cold warmup과 30회 steady-state latency를 분리한다.
  5. Validator: Producer report의 exact state grid를 8-state resident batch 11개로 나눠 고해상도 self/world/bound cost를 계산한다.

Arm과 hand 이름은 example policy에 xArm6/Inspire Left 기본값이 있지만 planner core는 request와 policy의 ordered named joints가 일치하는지만 확인한다. 다른 arm/hand는 새 robot config, lock state, collision proxy·validator qualification과 policy를 제공하면 같은 core를 사용한다.

아직 주장할 수 없는 것

  1. 이번 producer 입력은 실제 Pepsi grasp request/template/lifecycle에서 materialize한 command가 아니다.
  2. Hand closure, first contact, moving target의 time-indexed collision, attachment, lift, transfer, drop과 return suffix를 실제 cuRobo output으로 검증하지 않았다.
  3. 81개 sampled state 사이의 continuous collision, robot dynamics, stop·abort route와 controller deadline을 승인하지 않았다.
  4. 고해상도 validator의 cold model init은 약 100초 수준이므로 process 상주와 restart 운영 정책이 필수다.
  5. MuJoCo와 Viser가 이번 exact producer output을 소비하지 않았다. 기존 animation을 새 command의 실행 결과로 표시하지 않는다.

다음 단계

  1. 실제 Pepsi path-family에서 full-command request, resident template과 object collision lifecycle을 하나의 source bundle로 materialize한다.
  2. 현재 producer가 arm prefix 내부만 쓰고 hand·latch·suffix를 보존하는 actual full command를 생성한다.
  3. 같은 full command에 moving target, self/connector/static world, post-attach object, release envelope, continuous collision과 dynamics validator를 순서대로 연결한다.
  4. 검증된 exact command만 기존 MuJoCo measured rollout과 Viser 1.0x auto-loop에 전달한다.
  5. Perception과 candidate batch를 포함한 end-to-end concurrent load에서 p99, deadline miss와 stale-generation 폐기를 측정한다.

cuRobo V2 GPU 환경과 collision holdout, Resident full-command template, Full-task resident validation을 함께 참고한다.

공개 기록에는 재현 가능한 기술적 근거만 남기고 계정·주소·내부 경로는 기록하지 않는다.
