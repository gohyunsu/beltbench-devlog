ISSUE-040 · 2026-08-11 · cuRobo real-time collision audit

GPU에 옮길 수 있는 코드가 아니라, 제어 주기의 resident batch hot path만 cuRobo로 가속한다.

실시간성이 중요하다는 이유로 모든 모듈을 GPU로 옮기면 작은 상태기계와 장치 I/O까지 kernel launch와 host-device 동기화 비용을 부담한다. BeltBench는 deadline을 직접 줄이는 고정 크기 수치 연산만 GPU에 상주시킨다. cuRobo V2는 최종 온라인 충돌·arm-prefix 최적화 권위자 후보지만, 현재는 exact assembly parity와 서버 runtime 조건을 충족하지 못했으므로 HPP-FCL을 offline oracle로 유지한다.

현재 효력: source commit 474a9f3에서 cuRobo scene 변환을 보수적으로 수정했고, 4396cef에서 in-memory result와 synchronous artifact write 0회 gate를 추가했다. 56bb677은 warm-start 결과를 immutable CUDA lease로 교체했고, 9ba3183은 controller/allocator one-shot ownership을 추가했다. 이는 runtime contract와 collision activation gate의 완료이지 cuRobo online authority 활성화가 아니다. junjinyong A6000의 driver 535.161.07은 pinned V2 정책의 최소 580.65.06을 충족하지 않는다.

왜 지금 HPP-FCL이고, 최종 방향은 cuRobo인가

HPP-FCL을 online 최종안으로 고집한 것이 아니다. 실제 arm·hand·connector mesh와 self/world/contact semantics를 먼저 정확히 표현할 수 있어 현재의 reference oracle로 채택했다. cuRobo가 같은 장면에서 HPP-FCL의 충돌을 하나도 놓치지 않고 목표 GPU deadline을 만족하면 online authority를 cuRobo로 전환한다. 이 순서를 뒤집으면 빠른 collision checker를 얻는 대신 실제 connector나 손가락 충돌을 조용히 놓칠 수 있다.

공식 cuRobo V2는 CUDA graph, stream과 batched motion generation을 지원하므로 hot path의 기반으로 적합하다. 그러나 BeltBench의 문제는 일반적인 독립 start-to-goal batch가 아니다. 이미 인증된 hand/contact suffix는 고정하고 arm correction prefix만 최적화하며, 각 후보 시간의 이동 물체 pose와 허용 contact link가 달라진다. 따라서 stock BatchMotionPlanner를 그대로 호출하지 않고 custom rollout/cost adapter와 immutable suffix mask가 필요하다.

In-memory 결과 gate

이전 benchmark는 CUDA graph, resident buffer와 host-device 왕복 횟수를 검사했지만, solver가 반환 직전에 파일을 썼는지 또는 파일 reference만 반환했는지는 구분하지 못했다. 따라서 짧게 측정된 총 latency만으로 file-backed adapter가 통과할 수 있었다.

Realtime acceleration schema를 policy/capability 1.6, raw trial 1.3으로 올렸다. Target policy는 required_result_transport=in_memory와 maximum_synchronous_artifact_writes=0을 요구한다. Capability, raw trial, concrete backend instance 중 하나라도 filesystem transport를 선언하거나 한 trial이라도 동기 write를 관찰하면 activation이 실패한다.

56bb677에서 CanonicalArmPrefixWarmStartBackend는 in_memory를 선언한다. Trajectory/stop lease는 exact runtime-session hash, planning-buffer allocation, 서로 다른 slot, monotonic generation, fixed shape와 producer CUDA event를 결속한다. Validator는 동일 lease digest와 validation completion event를 반환한다. Slot이 재사용되면 generation이 달라져 stale result를 승인할 수 없다. BoundedAsyncWarmStartArtifactRecorder의 planner-side submit은 validation이나 materialization 없이 put_nowait만 수행하며, worker가 ancestry를 다시 검증한 후 sink를 호출한다. 9ba3183은 validated lease를 controller가 한 번만 take하고 consumer event가 결속된 allocator receipt 뒤에만 반환하도록 ownership blocker를 제거했다. Actual cuRobo kernel benchmark와 hardware adapter는 여전히 남아 있다.

Activation gate

  1. Actual xArm·Inspire·connector의 모든 collision link와 checked/ignored pair를 source-bound sphere model로 컴파일한다.
  2. Static, swept, self, world, moving target와 phase contact cases에서 HPP-FCL 대비 false negative가 0인지 검증한다.
  3. 고정 shape의 input/output tensor를 preallocate하고 world model, CUDA graph와 streams를 warm state로 유지한다.
  4. 전체 deadline뿐 아니라 H2D, IK, collision, trajopt, reduction, D2H 구간의 p50·p95·p99와 deadline miss를 측정한다.
  5. Timeout, stale observation, infeasible suffix, unsafe contact와 device error가 모두 no-command 또는 certified stop으로 닫히는지 검증한다.
  6. 동일 accepted trajectory를 MuJoCo와 이후 Isaac에서 비동기 rollout하고 measured trace만 Viser 1x loop로 재생한다.

검증 결과와 다음 순서

  • cuRobo scene/backend, assembly asset, real-time acceleration, arm-prefix planning과 collision backend 확장 회귀 45개가 통과했다.
  • Resident lease, canonical backend, runtime engine, async recorder와 controller ownership 집중 회귀 55개가 통과했다.
  • Planning 환경 전체 suite 661개에서 새 code failure 없이 2개가 skip됐고, OpenCV 미설치로 import되지 않은 3개 module은 calibration 환경에서 14개 모두 통과했다.
  • git diff --check를 통과했고 source 9ba3183을 GitHub main에 push했다.
  • 검증된 incremental bundle로 서버 source를 2085f4c에서 474a9f3, 이후 f868873까지 fast-forward했다. 기존 native build는 보존했다.
  • Source-bound endpoint screening 115689는 2,000개 중 140개를 유지했다. Full evaluation 115694는 10,313개 파일을 재검증해 117 geometry-clear diagnostic, 0 execution-authorized를 확인했다. Clock skew 때문에 timing evidence는 무효다.
  • Explicit connector manifest를 사용하는 deployment 115696, shortlist 115697, portfolio 115698을 모두 완료했다. Portfolio는 5.0초 intercept의 301-frame full-mesh diagnostic을 통과했지만 execution candidate는 비워 두었다.
  • Resident lease의 validation-to-controller-to-allocator ownership은 9ba3183에서 구현했다. 다음 순서는 actual adapter를 연결하고 driver 조건이 맞는 GPU에서 custom cuRobo rollout을 HPP-FCL corpus 및 50 ms target policy로 benchmark하는 것이다.

cuRobo의 runtime configuration, motion planner API, self-collision model과 installation requirements를 기준으로 감사했다. 이전 단계는 assembly와 physics validation, source-consistent path-family evidence에 기록했다.
