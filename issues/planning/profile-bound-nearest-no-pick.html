ISSUE-112 · 2026-08-31 · motion-limit-bound nearest no-pick

Nearest는 유지하되, 실행 한계로 검증되지 않은 경로는 버린다.

Predicted-intercept nearest top-K는 82개 grasp library를 빠르게 줄이는 데 유효하다. 그러나 가까운 자세는 짧은 동작, 충돌 회피, deadline 충족 또는 강건한 실행을 보장하지 않는다. 이번 재검증은 planner를 실제 execution motion-limit profile에 결속하자 이전 rank-3 command가 사라지고 네 후보가 모두 정당한 no-pick이 됨을 확인했다.

현재 효력: beltbench@1ac12c1은 resident cuRobo backend가 online request와 같은 motion-limit profile ID·SHA-256을 사용하도록 강제한다. RTX 3090 actual-time probe는 nearest rank 1–4를 실제로 계획했지만 모두 planner_insufficient_start_lead로 거절했다. path_generated=false이며 execution authority는 없다.

발견한 결함

이전 planner robot config와 independent validation에 쓰는 execution profile이 별도 파일이었지만 online backend는 profile identity를 계약으로 노출하지 않았다. 따라서 cuRobo가 더 빠른 속도·가속도 가정으로 경로를 만들고, 이후 validator가 더 엄격한 한계를 적용할 수 있었다. 이 상태에서 얻은 286-waypoint rank-3 command는 nearest가 옳았다는 증거가 아니라 planner와 validator의 모델이 달랐다는 증거다.

단순히 cuRobo 값을 execution profile로 덮어쓰는 것도 잘못이다. URDF 또는 source cspace가 더 엄격한 관절 한계를 갖는 경우 그 한계를 완화할 수 있기 때문이다. 각 관절의 position·velocity·acceleration·jerk 범위를 source model과 execution profile의 보수적 교집합으로 만들고, 빈 교집합이면 startup에서 실패하도록 했다.

구현

  1. OnlinePoseBatchPlannerBackend가 motion_limit_profile_id와 canonical motion_limit_profile_sha256을 반드시 제공하게 했다.
  2. Resident cuRobo factory는 ID 문자열이 아니라 실제 RobotMotionLimitProfile을 받아 source robot config의 joint order에 맞춰 conservative intersection을 적용한다.
  3. Online full-task context는 command policy, request source와 backend profile ID·hash가 하나라도 다르면 query 전에 fail-closed한다.
  4. Nearest retrieval, per-intercept top-K, fixed-batch grasp/time diversity와 nearest-rank-independent selection 규칙은 그대로 유지했다.

비판적 해석

이번 실패를 horizon 상수만 늘리거나 belt를 영상에서 느리게 만들어 해결하면 안 된다. 현재 canonical conveyor deck은 1 m이고 x=-0.4 m acquisition에서 pick corridor까지의 물리적 거리가 짧다. 측정되지 않은 belt 영역까지 prediction sample을 추가하면 실제 시스템 입력과 다른 simulation shortcut이 된다. 반대로 모든 cycle을 임의의 초기 arm state에서 시작하게 하는 것도 실제 생산 시스템의 운영 정책과 다르다. 로봇은 안전하게 검증된 standby pose로 복귀하고, 그 pose에서 upstream detection zone까지의 최소 lead를 workcell calibration으로 보장하는 편이 합리적이다.

또한 현재 compiler는 first contact 뒤 attach까지 arm을 정지시킨다. 움직이는 belt에서 closure 중 object-relative pose를 유지하려면 hand가 belt 속도를 따라가야 하므로 이 구간은 production semantics가 아니다. Contact-through-attach chase와 time-indexed moving-object collision을 구현하기 전에는 positive command가 생겨도 실행 가능하다고 볼 수 없다.

다음 순서

  1. Source-qualified standby pose와 measured/provisional workcell layout을 별도 typed contract로 만들고 acquisition lead, horizon과 sample capacity를 belt geometry·speed·motion profile에서 유도한다.
  2. 현재 perception/encoder track만으로 contact-through-closure target을 시간 일관되게 생성하고, simulator object truth 없이 relative chase residual을 검증한다.
  3. 생성된 exact command를 independent dynamics, partitioned self/connector/workcell collision, time-indexed object collision, contact order와 drop containment 순서로 통과시킨다.
  4. 완전한 validator latency와 controller lead를 측정한 뒤 nearest rank를 제외한 maximin으로 선택하고 Isaac RGB varied-yaw trial에 연결한다.
