ISSUE-023 · 2026-08-09 · path validation authority

Path-family 검증 보고서를 파일 이름이 아니라 의미와 배치 맥락으로 검증한다.

AutoDex의 grasp 필터와 BeltBench의 moving-path gate를 다시 대조하는 과정에서, continuous_path_tube라는 문자열과 파일 SHA-256만 맞으면 임의 보고서도 runtime 입력이 될 수 있는 결함을 발견했다. 보고서를 typed contract로 바꾸고 robot·object·workcell부터 실제 path까지 정확히 결속했다. 다만 실제 continuous validator를 구현한 것처럼 주장하지 않는다.

현재 효력: source commit 2a31d72가 typed report, exact metric schema, startup semantic verifier와 negative test를 구현한다. Bundle schema는 3.0, policy schema는 4.0으로 올렸다. 모든 결과는 계속 execution_blocked다.

AutoDex에서 실제로 거르는 기준

감사 기준은 public willi19/autodex-code:main 5ada1c0이다. 이름이 비슷한 site repository나 오래된 fork branch를 구현 source로 간주하지 않았다.

우리 방법론에서 채택한 filter

  1. Exact object·stable pose·hand·task·source identity가 맞지 않으면 proposal 단계에서 거부한다.
  2. Intrinsic 단계에서 named contact, bounded penetration, non-contact/self/support clearance, signed force·moment task wrench, approach·closure·release path를 독립 검사한다.
  3. Robot deployment 단계에서 선택한 manifest의 arm·hand·connector·workcell에 대해 IK, assembly/workcell/object clearance, joint와 singularity margin을 검사한다.
  4. Yaw×horizon atlas는 측정 yaw uncertainty가 걸치는 모든 cell의 hard-gated grasp 교집합만 반환한다. 빈 교집합은 unsupported다.
  5. Compiled path family는 complete phases, fixed contact/hand timing, correction support, latch, reusable/stop path와 exact 13개 continuous margin을 모두 요구한다.
  6. Live runtime은 fresh track·encoder·named robot motion state, support, correction, deadline, latest generation을 다시 검사한다.
  7. 모든 hard gate 뒤에만 full normalized-slack vector의 lexicographic maximin으로 비교한다. Provider order, first success, weighted sum, 가장 먼 intercept는 선택 기준이 아니다.
  8. 향후 physical commit은 moving-pick reliability lower bound, controller capability, watchdog와 stop authority를 별도로 요구한다.

발견한 결함

기존 verify_path_family_deployment_bundle_sources()는 validation report 파일의 SHA-256만 다시 계산했다. 파일 내용을 load하지 않았고, family summary와 비교하지 않았다. 따라서 공격자나 잘못된 compiler가 다음 순서로 거짓 certificate를 만들 수 있었다.

  1. 아무 텍스트 파일을 path_validation_report로 만든다.
  2. 그 파일의 새 SHA-256을 PathValidationEvidence에 기록한다.
  3. validation_scope="continuous_path_tube"라고 선언한다.
  4. Startup hash 검사를 통과한 뒤 production-shaped coordinator에 family를 전달한다.

더 나쁘게는 유효한 report를 다른 trajectory, latch, workcell 또는 robot bundle에 끼워 넣어도 report 자체가 그 맥락을 결속하지 않았다. 파일 무결성은 보장했지만 의미 무결성은 보장하지 않은 상태였다.

구현한 신뢰 경계

PathFamilyValidationReport와 PathFamilyValidationBinding을 별도 contract module로 만들었다. Canonical JSON SHA-256으로 다음 항목을 정확히 결속한다.

  • Bundle ID, schema, policy, arm, hand, connector, object, stable pose, conveyor calibration, workcell, atlas ID와 정렬된 전체 deployment source evidence
  • Family ID, grasp, task, support envelope, nominal anchor, complete phase timing과 correction tube
  • 전체 latch-region payload와 순서가 보존된 latch certificate digest
  • Reusable path, tracking tube, stop path digest
  • Validator backend와 pinned validator source digest
  • Validated phases, clearance minima, joint/singularity minima, exact normalized-slack vector와 frame count
  • Temporal coverage, parameter coverage, validated segment 수와 parameter cell 수

Negative test

  • Arbitrary text를 쓰고 report checksum까지 갱신해도 JSON/contract load가 실패한다.
  • 다른 reusable trajectory digest를 넣고 checksum을 갱신해도 family binding 비교가 실패한다.
  • Minimum environment clearance 요약값 하나를 바꾸고 checksum을 갱신해도 exact summary 비교가 실패한다.
  • 정상 sampled report에서 scope 문자열만 continuous로 바꾸면 coverage, capability와 metric schema가 맞지 않아 실패한다.
  • 같은 family를 다른 workcell ID의 bundle에 붙이면 deployment-context digest가 달라 실패한다.
  • Policy가 13개보다 작은 normalized-slack capacity를 선언하거나 예전 schema version을 사용하면 fail-closed한다.

검증 결과

  • Path-family, projection, runtime, warm-start와 engine 집중 test 56개가 local에서 통과했다.
  • Local full discovery는 365개를 수집했고 OpenCV import module 3개를 제외한 planning test 362개가 통과했다.
  • OpenCV가 있는 calibration 환경에서 해당 3개 module의 실제 test 14개가 통과했다. 총 실제 통과 수는 376개다.
  • junjinyong server를 source commit 2a31d72로 fast-forward한 뒤 동일하게 365개를 수집하고 planning 362개를 통과했다. 기존 untracked BODex native build는 변경하지 않았다.

아직 해결하지 않은 것

Typed report는 필요한 신뢰 경계지만 validator 계산을 증명하지 않는다. 현재 Python Coal/hpp-fcl binding과 Pinocchio 경로는 discrete frame collision·distance query를 제공하며, 기존 301-frame playback validation도 sampled oracle이다. Capability 문자열을 썼다고 continuous swept collision이나 correction-tube 전체가 계산되는 것은 아니다.

  1. Checksummed atlas와 robot/workcell manifest에서 complete approach·chase·close·attach·lift·transfer·release·contain·return·stop path를 생성하는 production path compiler를 구현한다.
  2. Reference sampled oracle와 대조 가능한 conservative continuous validator backend를 선택하고, 시간 segment와 correction parameter cell마다 zero false-accept 기준을 검증한다.
  3. Startup에서 pinned validator를 실제 재실행해 typed report를 재생성하거나 독립적으로 재현하고, 저장된 report와 exact 비교한다.
  4. 그 뒤에만 recorded cadence latency와 cancellation을 측정한다. Source hashing과 report 재현은 startup/offline에 두고 online loop에는 resident bounded query만 남긴다.
  5. Controller simulation, calibration/metrology와 physical reliability evidence가 없으면 controller commit은 계속 구현하지 않는다.

AutoDex와 BeltBench grasp authority 감사, production-shaped runtime harness, path-family bundle 계약이 각각 앞 단계의 기준과 runtime 의미를 설명한다.
