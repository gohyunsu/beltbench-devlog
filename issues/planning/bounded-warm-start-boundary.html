ISSUE-021 · 2026-08-08 · bounded warm start

Warm-start admission과 실행 가능한 trajectory 사이에 측정 가능한 검증 경계를 둔다.

AutoDex의 grasp filtering은 proposal과 정적 배치 적합성을 줄이는 근거다. BeltBench에서는 이 결과를 moving command로 승격하지 않고, 정확한 fused-track projection과 robot motion state를 한 번의 bounded solver 입력으로 묶은 뒤 별도 validator가 전체 path와 stop path를 다시 통과해야만 다음 controller 경계로 전달하도록 했다.

현재 효력: 90eba81이 generic warm-start admission, backend descriptor, bounded runner와 independent-validation 계약을 구현한다. 실제 accelerated solver, validator와 controller commit은 없으므로 모든 결과는 execution_blocked=True다.

AutoDex filter 재검토 결론

기준 source는 willi19/autodex-code의 main, commit 5ada1c077f60bae9af6f27b07619218f58422e50이다. 다시 확인한 결과 provider residual, sampled pregrasp sphere, squeeze overlap, 단일 gravity hold, scene set cover, first-success runtime planning 중 어느 하나도 conveyor moving grasp의 최종 승인 기준으로 사용할 수 없다.

채택한 선택·거부 순서

  1. Object, stable pose, arm, end effector, connector, workcell, calibration과 모든 source checksum의 exact identity를 요구한다.
  2. Arm-independent intrinsic 단계에서 named contact, penetration, non-contact·self·support clearance, signed force·moment wrench, approach·closure·release를 hard gate로 사용한다.
  3. Deployment atlas에서는 측정 yaw uncertainty와 continuous intercept horizon이 걸치는 모든 yaw × horizon cell의 grasp 교집합만 남긴다.
  4. Path-family 단계에서 lateral·speed·intercept·horizon support, complete phases, joint dynamics, collision, singularity, timing, latch, correction과 stop evidence를 요구한다.
  5. Runtime은 fresh fused track·encoder·calibration과 named robot position·velocity·acceleration을 사용해 retain → certified latch → 한 번의 bounded warm start 순서만 허용한다.
  6. 모든 hard gate 뒤에만 전체 normalized-slack vector의 lexicographic maximin을 적용하고 switch에는 bottleneck hysteresis를 추가한다.

모듈 경계

  • beltbench/contracts/path_family_warm_start.py: backend capability, exact admission, measured result, independent validation과 acceptance diagnostic을 정의한다.
  • beltbench/planning/path_family_warm_start.py: trusted admission builder와 interception-scoped one-shot runner만 소유하며 특정 arm, hand, solver 이름을 하드코딩하지 않는다.
  • beltbench/planning/path_family_runtime.py: maximin 순서에서 solver+validator 예산이 effective deadline 안에 드는 첫 family만 한 번 admission한다.
  • config/planning/path-family-deployment-policy.example.json: solver 20 ms와 independent validation 10 ms를 별도 draft budget으로 둔다.

검증 결과

  • Trusted batch/decision splicing, generation 분리, cutoff 우선 deadline, one-shot admission, backend exception·waypoint 초과, dispatch 지연, late artifact 제거, digest binding, complete margin vector와 validation budget을 테스트했다.
  • 관련 path-family·projection·runtime·atlas·tracking 61개가 local과 junjinyong planning 환경에서 각각 통과했다.
  • Local planning discovery 307개 중 OpenCV import 전용 3개를 제외한 304개와 calibration 환경 14개, 실제 총 318개가 통과했다.
  • Server source는 90eba81이며 기존 untracked BODex build directory와 native library는 수정하거나 삭제하지 않았다.

남은 위험과 다음 구현

현재 backend는 deterministic test fixture뿐이다. Synchronous Python 호출은 blocking solver를 중간에 취소하지 못하고 늦게 반환된 결과만 폐기한다. 실제 control loop에 넣기 전에는 GPU warm-start solver와 별도 continuous validator를 nonblocking process 또는 worker boundary로 구현하고, cancellation latency를 측정해야 한다.

또한 trajectory·stop-path artifact를 runtime session이 직접 저장하고 다시 SHA-256으로 검증해야 하며, reference oracle agreement, actual path compiler, controller commit·watchdog, post-contact lift와 bin-drop handoff가 남아 있다. 따라서 이번 단계는 AutoDex grasp를 moving system에 안전하게 전달하는 권한 경계를 정의한 것이지 실시간 grasp 실행을 완성한 것이 아니다.

Trusted projector가 입력 evidence를 만들고, real-time architecture ADR이 다음 backend와 controller 구현 순서를 정의한다.
