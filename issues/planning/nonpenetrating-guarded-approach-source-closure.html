ISSUE-079 · 2026-08-18 · nonpenetrating guarded approach source closure

pregrasp부터 first contact까지의 권한을 3상태로 분리하고 실제 planning report에 구현 source를 결속한다.

Interaction profile과 dense validator는 guarded proximity를 알고 있었지만 moving-tool planner의 target은 allow_hand_contact boolean만 전달했다. 이 표현은 접촉 전 근접과 bounded contact를 구분하지 못해 close 시작부터 first contact 전까지 shallow penetration을 허용할 수 있었다. Target contract를 clearance / guarded_proximity / bounded_contact로 교체하고, RTX 3090에서 같은 Pepsi rank-1 입력을 처음부터 다시 계산해 61/61 moving target과 301/301 dense frame을 통과시켰다.

최종 판정: pregrasp=3.6 s, close_above_object=4.1 s, contact=4.4 s다. 24개 guarded frame의 minimum signed robot-object distance는 0.064159 mm로 양수였고 colliding pair와 조기 contact geometry는 모두 0개였다. Source-closed report schema 1.2의 413개 transitive file을 재검증했다. 새 private MP4는 1080p, 15 fps, 12초, 180/180 unique frame, capture RTF 0.986962이고 SHA-256은 5af892099db5903e193f8795ebb4504b234262b4587b33843b4fd6d4cb7efe91이다. 저장된 planned command의 검증과 1× 재생 증거이며 causal perception, online planning 또는 physics execution 증거는 아니다.

발견한 계약 불일치

  • Object interaction schema 3은 pregrasp와 close_above_object를 guarded phase로 선언하고 dense playback validator도 nominal penetration을 거부했다.
  • 반면 TimedToolTarget은 allow_hand_contact와 require_hand_contact만 가졌다. Generator는 close keyframe부터 allow를 true로 만들고 first contact부터 require를 true로 만들었다.
  • Reference sampled IK backend는 allow가 true인 intended hand pair에 admissible_hand_contact를 적용했다. 따라서 contact state로 전환되기 전에도 configured penetration limit 안의 충돌이 통과할 수 있었다.
  • 이 결함은 최종 301-frame validator가 다시 잡을 수 있지만, coarse planner와 dense validator가 서로 다른 안전 의미를 사용한다는 사실 자체가 잘못이다. 후단 validator를 앞단 계약 오류의 fallback으로 사용해서는 안 된다.

수정한 불변조건

  1. 3상태 target: TimedToolTarget.hand_interaction_mode를 추가하고 기존 boolean을 제거했다. require_hand_contact는 mode가 bounded_contact일 때와 정확히 동치여야 한다.
  2. 시간 구간: t < pregrasp는 clearance, pregrasp ≤ t < contact는 guarded proximity, t ≥ contact는 bounded contact다. Close keyframe까지 exact pregrasp hand command를 유지하고 그 이후 contact까지 손을 닫는다.
  3. 비침투: Guarded mode는 named distal geometry의 positive uncertainty clearance만 면제한다. Signed nominal penetration은 크기와 무관하게 실패하며 contact count에도 포함하지 않는다.
  4. Profile 일치: Backend 입구에서 target mode와 ObjectInteractionSemantics.hand_interaction_mode를 대조한다. Profile에 없는 phase가 guarded를 자칭해 clearance를 우회하면 planning 전에 실패한다.
  5. 공통 mode vocabulary: CPU reference와 CUDA cylinder query가 같은 typed mode set을 사용한다. CUDA reduction은 guarded threshold를 0으로 두고 bounded penetration threshold는 contact 이후에만 적용한다.

Source closure 재감사

첫 RTX 재계산은 기능적으로 통과했지만 report의 source list를 다시 보니 interaction JSON과 intercept_search.py만 포함하고 실제 enforcement가 있는 tool_trajectory.py와 mode 정의가 있는 object_interaction.py를 hash하지 않았다. 따라서 성공 report 하나만으로 3상태 구현을 재현할 수 없었다.

Portfolio report schema를 1.2로 올리고 tool_trajectory_backend와 object_interaction_contract를 필수 source label로 추가했다. 1.0/1.1은 역사적 source set으로 계속 읽지만 현재 guarded evidence로 승격하지 않는다. 1.2 payload가 selected request evidence를 누락하지 않도록 serialization 분기도 함께 수정했다.

실시간성 및 권한 판정

최종 RTX reference run은 coarse search 117.559701 s, dense refinement 81.126961 s다. 합계 약 198.7초이므로 이것은 online inference가 아니다. HPP-FCL exact-mesh 계산은 CPU-bound였고, RTX 3090은 동일 guarded mode의 CUDA parity test에 사용했다. GPU가 있는 서버에서 돌았다는 이유로 reference planning이 GPU 가속 또는 real-time이라고 표현하지 않는다.

selected_diagnostic_candidate는 BODex bodex-193463c5eabd9911, intercept 4.6 s이고 selected_execution_candidate는 null이다. Grasp/stable-pose 승인, measured latency, calibration, connector seating, controller와 moving-contact hardware validation이 없기 때문이다. 영상은 D2 planned-command playback이며 기존 Isaac D1 perception과 causal하게 연결되지 않았다.
