ISSUE-113 · 2026-09-01 · partitioned moving-object collision holdout

Moving-object collision을 GPU 보수 근사와 exact mesh의 명시적 분할로 검증한다.

Nearest grasp top-K는 후보를 빠르게 줄이는 데 유효하지만, 현재 RGB pose와 robot state에서 새로 만든 trajectory의 안전을 보장하지 않는다. 이번 단계는 움직이는 물체, robot, conveyor와 table의 시간별 관계를 동일 corpus에서 검사하고, cuRobo와 HPP-FCL이 소유할 collision domain을 겹침 없이 고정한 뒤 독립 holdout에서 false negative 0을 확인했다.

현재 효력: beltbench@0f56eb3에서 같은 exact mesh의 bounded threshold query를 final holdout 전에 고정했다. 2,682/2,682 decision, FN 0, FP 0을 확인했지만 final corpus core가 2.004초이고 coverage도 discrete state에 한정되므로 execution_authorized=false다.

Nearest grasp의 위치

단계허용 범위
검색Exact object, inferred stable-pose class, hand, capability와 evidence가 일치한 resident library에서 predicted intercept마다 top-8을 다시 조회한다.
계획각 grasp/time pair를 현재 robot feedback에서 fresh full-task trajectory로 생성한다.
검증동일 trajectory tensor를 dynamics, timing, self/workcell/connector와 이번 time-indexed moving-object collision backend가 독립 검사한다.
선택통과 후보만 robust maximin으로 고른다. Nearest rank와 distance는 final score와 command authority에 들어가지 않는다.

따라서 nearest를 쓰면 안 되는 것이 아니라 nearest-1을 곧바로 실행하면 안 된다. 실제 생성 후보에서는 robot-object approach가 약 27.4 mm 침투한 사례도 확인됐으므로, 기하학적으로 가까운 정적 grasp라는 사실은 moving trajectory 안전 증거가 아니다.

검증과 남은 병목

  • 관련 local regression은 29/29를 통과했다.
  • Final oracle 2,682 states는 28.36 s, GPU component는 11.90 s, exact evaluation core는 8.44 s였다. 이는 offline corpus throughput이며 observation-to-command latency가 아니다.
  • Resident selected-link path는 아래 RTX 측정에서 state당 p95 약 2.44~2.51 ms였다. 수십·수백 trajectory sample에 직렬 적용하면 실시간 budget을 넘는다.
  • 다음 구현은 qualified GPU rejection 뒤 exact process sharding을 적용한 고정 크기 shortlist batch와 end-to-end p95 측정이다. CPU permissive fallback이나 cached validation은 두지 않는다.
  • Continuous/swept exact coverage까지 검증한 뒤 동일 generated tensor에 complete validator를 연결하고, nearest와 무관한 maximin selection, future-start controller lease, Isaac RGB actual-time 실행 순으로 닫는다.

Exact threshold query의 final parity

99a7a8d에서 HPP-FCL security_margin을 사용하는 bounded exact-mesh query를 추가했다. 이 query는 signed distance를 끝까지 계산하지 않고 요구 clearance 통과 여부만 판정한다. 반환된 lower bound를 실제 최소 margin으로 오인하지 않도록 report 측정 타입은 decision_only로 제한했다. 45a69cd에서는 새 family를 만들지 않고 동일 Pinocchio/HPP-FCL exact mesh family 안에서 backend ID, query semantics와 configuration SHA로 구분했다.

Nearest online data plane과 partitioned self-collision을 함께 보면 후보 검색, 정적 robot 충돌과 움직이는 object 충돌의 권한 경계를 구분할 수 있다.
