ISSUE-030 · 2026-08-10 후속 감사 · grasp filter and retention

AutoDex의 정적 grasp filter를 moving conveyor의 실행 기준으로 과장하지 않고, task 사건과 actual-time reference까지 닫는다.

AutoDex가 실제로 거르는 조건과 BeltBench가 채택한 조건을 최신 public branch에서 다시 대조했다. 정적 후보 생성·collision·hold·coverage는 유용하지만 moving grasp의 상대 속도, arm-hand 동기 closure, release와 controller authority를 증명하지 않는다. 후속 구현은 첫 접촉 q_grasp와 운반 유지 q_sqz를 분리하고, intrinsic·deployment·shortlist·event·Viser·hardware evidence가 같은 retention 명령을 사용하도록 결속한다.

현재 효력: source commit 368375c까지 first-contact/retention 분리와 runtime path-family 선택을 startup-verified resident event request에 결속한다. 보정 resolution은 identity, 비활성 family의 timing-only absolute_schedule, 새 joint reference가 필요한 unmaterialized를 구분한다. Active phase 또는 spatial·yaw·belt-speed 보정은 독립 재검증된 결과가 없으면 계속 fail-closed한다. Current Pepsi artifact는 새 retention/contact gate 이전 결과이고 protocol·stable pose·hardware evidence도 없으므로 실행 권한은 계속 차단한다.

감사 source와 branch

2026-08-10에도 willi19/autodex-code remote를 다시 fetch했다. 공개 remote branch는 main 하나이며 감사 commit은 5ada1c077f60bae9af6f27b07619218f58422e50이다. 로컬에는 이름이 같은 과거 checkout과 개인 fork가 함께 있으므로 working tree HEAD를 신뢰하지 않고 autodex/autodex-code:origin/main의 blob을 직접 읽었다. Site repository인 autodex, GoTrack perception, BODex proposal generator와 grasp acceptance를 같은 모듈로 취급하지 않았다.

BeltBench가 채택한 기준

  1. Proposal boundary: provider success·residual·순서는 source와 생성 맥락으로 보존하되 acceptance에 사용하지 않는다.
  2. Intrinsic endpoint: first contact와 retention 각각에 named allowed contact, 최소 contact 수, bounded penetration, non-contact object·self·support clearance와 signed force·moment task-wrench margin을 독립 hard gate로 둔다.
  3. Intrinsic path: object-relative approach, pregrasp-to-contact closure, contact-to-retention과 task에 필요한 release 전 경로를 sample별로 검사한다. Endpoint success가 path failure를 덮지 못한다.
  4. Robot deployment: exact arm·hand·connector·object·workcell ancestry에서 IK, assembly/workcell/object clearance, joint-limit과 singularity margin을 검사한다.
  5. Yaw·horizon atlas: 측정 yaw uncertainty와 intercept horizon이 걸치는 모든 cell의 hard-gated grasp 교집합만 online candidate로 반환한다. 빈 교집합에는 nominal fallback이 없다.
  6. Portfolio selection: 모든 threshold를 통과한 후보에만 coverage를 적용하고, redundancy는 dimensionless normalized slack의 deterministic lexicographic maximin으로 정렬한다.
  7. Moving path: complete task·stop path, deadline, tracking·correction tube, latch와 continuous/swept collision evidence를 endpoint grasp와 별도 authority로 요구한다.
  8. Moving contact: exact contact q/qdot, Jacobian, object pose·twist와 connector-aware object-from-tool transform으로 pose와 상대 선·각속도를 각각 hard gate한다.
  9. Runtime·physical authority: fresh synchronized track·encoder·robot state, latest generation과 stop slack을 다시 검사한다. Hardware reliability와 controller commit은 geometry와 분리한다.

AutoDex의 pregrasp collision과 scene coverage라는 개념은 채택했지만 구현 threshold와 authority는 그대로 복사하지 않았다. Squeeze overlap과 단일 gravity hold는 참고 diagnostic일 수 있으나 moving execution 승인에는 사용하지 않는다.

발견한 task-state 결함

기존 EventScheduledTrajectoryRequest.task_mode는 허용 문자열만 검사했다. 따라서 pick_and_drop이라고 선언하면서 release 사건이 하나도 없는 trajectory가 유효할 수 있었고, 실제 test fixture도 이 모순을 포함했다. 시각화가 attach 뒤 임의로 object를 떨어뜨리면 그럴듯해 보이지만 grasp의 release capability와 hand command가 trajectory에 존재한다는 증거는 아니었다.

Schema 2.0은 task mode를 정확한 event state machine으로 바꿨다.

  • pick_only: hand_close_start < contact < hand_close_complete <= attach
  • pick_and_drop: pick 사건 뒤 attach < release_open_start < detach
  • pick_and_place: pick 사건 뒤 attach < placement_contact <= release_open_start < detach
  • 선택적인 replan_cutoff은 closure 시작 뒤에 올 수 없다.
  • Task에 없는 추가 사건, 필수 사건 누락과 물리적으로 뒤집힌 순서는 모두 거부한다.

Release task는 선택 grasp가 drop_release 또는 tabletop_release capability와 명시적 release_command를 가져야 한다. Release 시작은 exact retention command를 유지하고 detach는 selected release command에 도달하며, 두 boundary의 prescribed hand velocity·acceleration은 0이어야 한다.

Actual-time desired reference

EventTrajectoryReferenceTimeline은 저장 frame을 선형 보간하지 않고 같은 piecewise quintic을 actual time에 평가한다. Attach 전 object는 측정된 초기 orientation을 유지한 채 contact pose와 belt velocity에서 평행이동한다. Attach 뒤에는 robot-neutral FK protocol과 exact object-from-tool transform으로 tool을 따라가며, detach 뒤에는 명시적 static place 또는 ballistic drop display model을 적용한다.

Viser adapter는 실제 robot·hand·connector·object·workcell asset identity를 확인하고 arm, hand, connector, object, conveyor·table·bin, path, frames와 전체 label을 독립 제어한다. 기본 Play와 Loop는 켜져 있다. FK는 visualization 환경의 yourdfpy를 사용해 Pinocchio·cuRobo·controller SDK를 renderer에 끌어오지 않는다.

이 layer는 status panel에서 desired event-trajectory reference라고 표시하며 command나 measured feedback이 아니다. Position-only legacy PickPlayback를 새 evidence로 자동 승격하지 않는다. 별도 release-motion JSON도 display input일 뿐 checksum으로 결속된 execution artifact가 아니다.

해결

  • Grasp library schema를 6.0으로 올리고 exact retention_command를 payload와 SHA-256에 포함했다. Hardware reliability evidence와 requirement도 schema 2.0에서 complete grasp digest가 같아야만 trial을 합친다.
  • Retention policy를 pregrasp + gain × (first_contact - pregrasp)로 명시하고 command joint뿐 아니라 모든 mimic joint의 URDF limit 교집합으로 clip한다. Gain은 hand 이름 분기가 아니라 intrinsic protocol 입력이다.
  • First-contact와 retention에서 contact identity·count·penetration·non-contact/self/support clearance·task-wrench를 각각 검사하고, contact-to-retention path도 별도 hard gate로 추가했다. Static quality와 support margin은 두 endpoint의 보수적 minimum이다.
  • Deployment는 같은 arm grasp configuration에서 first-contact와 retention hand assembly/object collision을 모두 저장한다. 허용된 hand geometry의 얕은 penetration만 명시 threshold까지 contact로 세고, arm·비접촉 hand·초과 penetration은 static, timed tool, sampled path와 playback 모두 hard failure다. Deployment threshold는 intrinsic보다 느슨할 수 없다.
  • Shortlist maximin vector에 retention object/self/support slack을 넣고 hand diversity도 first-contact와 retention separation의 큰 값을 effective mimic-aware joint range로 정규화한다. Source verifier는 proposal·protocol·URDF로 retention을 재계산해 assessment의 치환을 거부한다.
  • Event trajectory는 hand_close_start=pregrasp, contact=grasp, hand_close_complete=attach=retention, release_open_start=retention, detach=release를 exact equality로 검사한다. Position-only legacy playback은 retention animation을 보여도 contact timing evidence로 승격하지 않는다.
  • Intrinsic Viser는 approach·closure·retention·release 네 경로와 first-contact/retention contact evidence를 저장 sample 그대로 반복 재생한다.

2026-08-10 후속: moving intercept가 exact first contact를 건너뛴 결함

Retention을 library와 intrinsic/deployment gate에 추가한 뒤 실제 moving intercept 경로를 다시 추적했다. _moving_tool_targets는 hand를 pregrasp_command에서 retention_command까지 한 번에 보간하고 마지막 grasp frame에서 즉시 object를 attach했다. 따라서 선택된 grasp_command는 digest와 정적 평가에는 존재했지만 동적 closure의 어느 target에도 정확히 사용되지 않았다. AutoDex의 q_pre → q_grasp → q_sqz 의미를 보존한다고 문서화한 상태와 실제 trajectory가 달랐다.
