ISSUE-097 · 2026-08-28 · tested-episode stable-pose resolution

NAS grasp를 실시간 검색하지 않고, 실제 시험 pose만 stable-pose class에 source-close한다.

Runtime 입력은 object ID와 RGB이며 tabletop pose는 주어지지 않는다. 따라서 NAS scene 이름으로 grasp를 고르는 경로를 만들지 않고, 실제 AutoDex episode의 초기 pose를 원본 분류식으로 재현해 offline evidence를 먼저 확정했다.

현재 판정: BeltBench 2d948f5에서 다중 stable-pose fail-closed router와 tested-episode pose-resolution contract를 구현했다. RTX 3090에서 NAS 원본을 전부 재해시한 불변 report b0b74737056f1f5d...를 만들었고 exact replay도 확인했다. 성공 5건은 source-000 2건, source-001 3건, 뒤집힌 source-002 0건이다. Hand와 moving-pick 검증이 없으므로 runtime 및 execution 권한은 false다.

발생한 문제와 원인

문제원인위험
Tabletop pose가 runtime 요청에 없다.물체는 임의의 안정 자세, 위치와 초기 yaw로 들어오며 RGB가 이를 측정해야 한다.Caller가 pose ID를 넘기거나 가장 가까운 atlas로 fallback하면 perception 실패를 숨긴다.
초기 pool 요약은 scene metadata별 성공 수를 사용했다.secondary scene pose_idx는 후보 scene snapshot이고 일부 generator scene은 누락 또는 drift 상태다.Scene ID를 실제 episode pose로 오인하면 다른 자세의 grasp를 선택한다.
AutoDex 성공 5건만 pose 측정 근거가 있다.Tested episode에는 pose_world.npy와 C2R.npy가 있지만 untested 95개에는 없다.나머지 후보에 이웃 scene이나 성공 후보의 pose class를 상속하면 출처가 열린다.
Provider hand가 단순히 Inspire Left라고 확정되지 않는다.NAS command는 6 DOF지만 chirality, URDF root, joint 순서, 단위와 connector transform의 target-hand 결속이 없다.수치 배열을 그대로 보내면 잘못된 손 또는 잘못된 joint에 명령할 수 있다.
NAS를 online lookup으로 쓰려는 유혹이 있다.후보와 결과가 이미 NAS에 있으므로 event마다 검색하면 구현은 쉬워 보인다.NFS traversal, JSON parse, hash와 fallback search가 latency를 비결정적으로 만든다.

선택한 분류 절차

  1. 기존 candidate pool 100개와 모든 source artifact를 SHA-256으로 다시 검증한다.
  2. Staged candidate set의 세 transform과 provider tabletop 000.npy, 008.npy, 014.npy가 배열 단위로 정확히 같은지 one-to-one으로 확인한다.
  3. symmetry.json의 단일 Cinf local axis를 읽고 정규화한다.
  4. Tested candidate마다 checksummed pose_world.npy와 C2R.npy를 읽어 AutoDex와 동일하게 inv(C2R) @ pose_world를 계산한다.
  5. 각 tabletop pose에 대해 world-z yaw를 해석적으로 제거하고 local Cinf 회전을 36개 sample로 접어 rotation geodesic error를 계산한다.
  6. 최소 error 5도 이하, runner-up margin 20도 이상일 때 pose mapping만 accept한다. 이 accept는 grasp 또는 실행 성공 권한이 아니다.
  7. 결과와 모든 입력 URI, resolved URI, size, digest를 content-addressed JSON으로 기록하고 exact replay 외 overwrite를 거부한다.

ResidentStablePoseEventSelector는 startup에 모든 supported pose의 selector가 있는지 확인하고, RGB가 latch한 pose만 O(1) map lookup으로 선택한다. Identity, calibration, track ancestry 또는 pose coverage가 다르면 terminal no-pick이며 다른 pose나 과거 trajectory로 fallback하지 않는다.

뒤집힌 Pepsi에 대한 결론

현재 예시 시각화의 뒤집힌 pose는 source-002다. 실제 AutoDex 성공 5건 중 이 class는 0건이므로 “shared data에서 검증된 뒤집힌 grasp를 찾아 바로 실행”할 수 없다. 먼저 provider hand 의미를 Inspire Left에 정확히 변환할 수 있는지 확인하고, usable proposal이 없으면 BODex나 다른 generator로 source-002 object-relative grasp를 생성해야 한다. 그 뒤 hand-object penetration/contact/retention, connector와 xArm IK, conveyor timing, changed-command collision, abort route와 moving-pick trial을 별도로 통과시킨다.

남은 차단 조건

  1. 세 source pose를 canonical Isaac settling campaign으로 measured stable-pose set으로 승격한다.
  2. Provider inspire의 chirality, hand-root, joint 이름, 순서, 단위와 command 범위를 Inspire Left에 source-close한다.
  3. source-000과 source-001 성공 후보를 target hand에 transfer한 뒤 독립 검증하고 source-002 grasp를 생성 또는 확보한다.
  4. RGB만으로 세 known class와 open-set을 구분하는 sealed holdout과 original-cadence latency를 통과한다.
  5. Pose별 atlas, cuRobo changed-command gate, phase-aware stop route와 60 Hz controller를 실제 Isaac runner에 연결한다.
  6. 서로 다른 pose가 서로 다른 resident command를 선택하는 actual-time trace와 영상을 RTX 3090에서 생성한다.
