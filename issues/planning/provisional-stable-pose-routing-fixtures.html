ISSUE-102 · 2026-08-28 · provisional stable-pose routing fixtures

기각된 settling 결과도 버리지 않고 세 pose의 offline screening fixture로 제한해 재사용한다.

264-trial campaign을 통과한 것처럼 바꾸지 않고, candidate orientation과 실제 관찰된 support-height 통계만 source-closed provisional pose로 materialize했다. 이 fixture는 기존 512개 Inspire Left proposal을 세 class에 cross-screen하기 위한 입력이며 runtime atlas는 아니다.

현재 판정: BeltBench e6c48a3에서 settling report 재현부터 pose JSON 생성·검증까지 하나의 offline compiler로 닫았다. 실제 fixture set digest는 928e1734e3eb...24b21이고 exact replay는 created=false였다. Manifest는 qualification_accepted=false, runtime_eligible=false, execution_authorized=false를 유지한다.

왜 새 pose를 임의로 만들지 않았나

선택지문제채택 여부
Legacy upside_down covariance를 세 class에 복사source-000/001의 실제 settling 분산과 무관한 수치가 된다.기각
Candidate transform에 임의 1 mm·1° uncertainty 부여재현 가능한 관찰 근거가 없고 threshold가 결과에 맞춰질 수 있다.기각
Rejected report 전체 폐기Orientation class, support height와 dispersion이라는 유효한 diagnostic evidence까지 잃는다.기각

Pose orientation은 staged candidate set에서 가져오고 z support height는 class metrics로 교체했다. Covariance는 z dispersion과 p95 tilt를 diagonal proxy로 기록한다. 이 값은 통계적으로 보정된 physical covariance가 아니며 manifest limitation에 그 사실을 고정했다. Planar x/y/yaw는 stable pose에 넣지 않고 RGB observation이 측정한다.

Source와 권한 경계

  1. Qualification report의 모든 source digest를 다시 확인한다.
  2. Raw 264 trials로 report의 class/global metrics와 rejection을 재현한다.
  3. Candidate set과 report의 class ID, object, digest가 정확히 같은지 확인한다.
  4. 세 pose와 compiler source·Git revision을 content-addressed manifest에 기록한다.
  5. Pose가 바뀌거나 runtime 권한이 true로 위조되면 verifier가 거부한다.

Artifact는 paradex2://hyunsu/beltbench/stable-poses/v1/provisional-fixtures/pepsi_light/928e1734e3eb...24b21/에 있다. Runtime은 이 NAS 경로를 읽지 않는다. 이후 cross-screening 결과가 있더라도 measured pose와 physical execution 승격은 별도 gate다.

발생한 문제와 해결

증상원인해결·결과
서버에서 신규 test 4개가 setup 단계에서 실패기존 settling test helper가 rigid-object config를 repository root가 아니라 process CWD 기준으로 찾았다.ecc08e2에서 __file__ 기준 root로 교체했다. 서버 기본 CWD에서 fixture·settling 8/8 통과.
처음 manifest 설계는 compiler digest만 기록향후 코드 변경 시 어느 Git checkout으로 재현할지 부족했다.40자 source revision을 생성·검증 API의 필수 입력과 manifest identity로 추가했다.
Campaign accepted 여부를 pose status와 결합할 위험Isaac acceptance도 physical measured pose를 뜻하지 않는다.Report acceptance는 별도 필드로 보존하고 모든 fixture status는 항상 provisional로 고정했다.
