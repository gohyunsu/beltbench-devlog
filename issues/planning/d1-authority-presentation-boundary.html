ISSUE-075 · 2026-08-13 · D1 authority and presentation boundary

실시간 perception 권위 측정과 교수용 MP4 부하를 서로 다른 pass로 분리한다.

Isaac sensor, FoundPose, CAD translation과 60 Hz encoder prediction을 한 영상에 보여 주되, 영상 조합과 인코딩이 control-path 실시간성의 근거를 오염시키지 않아야 한다. 먼저 MP4가 없는 D1 authority pass를 닫고, 같은 설정과 source임을 다시 증명한 non-authoritative presentation pass만 영상 worker를 사용할 수 있도록 실행 경계를 구현했다.

현재 판정: source beltbench@356941a에서 RTX 3090의 D1 authority와 presentation 두 pass를 모두 닫았다. Presentation은 8초 동안 120/120 frame을 encode했고 drop/error 0, control RTF 0.998, presentation RTF 0.941을 기록해 professor_video_ready=true다. 다만 이 판정은 실제 Isaac sensor를 이용한 perception까지만 검증한다. 화면의 static arm과 PLANNING BLOCKED는 오류가 아니라 D2 planning, cuRobo, controller와 grasp 실행이 아직 승격되지 않았다는 명시적 경계다.

확보한 교수용 D1 영상

실제 xArm6, Inspire Left, 흰색 connector, Pepsi Light upside-down stable pose, conveyor, robot table과 drop bin을 같은 Isaac scene에 표시한다. 두 perception camera의 RGB/depth/mask panel, FoundPose acquisition의 파란색 GPU reservation, CAD/encoder tracking의 청록색 전환과 누적 correction이 실제 측정 시간축을 따른다. 영상 SHA-256은 594775c35591e1833d424b44ca2581e7835290275eac0b8ca5c0d204d0c503b7이다.

구현 절차

  1. Authority pass: --presentation-mode none으로 실제 60 Hz physics, 15 Hz synchronized RGB-D, one-time FoundPose yaw, 15 Hz CAD x/y와 60 Hz encoder prediction만 측정한다.
  2. 보고서 종료: pose error, ingress health, deadline miss와 control RTF를 trace에 기록하고 D1 report 본문에 canonical SHA-256을 넣는다. Report는 계속 planning_authority=not_connected_d1, execution_authorized=false다.
  3. Presentation admission: --presentation-mode async_video는 --accepted-authority-report가 없으면 시작하지 않는다. Schema, pass 상태, source revision, trial 설정, 모든 source file hash, trace file hash와 report canonical hash를 Isaac bootstrap 전에 검사한다.
  4. 비동기 표시: overview RGB와 두 camera의 RGB-D/mask를 하나의 고정 Linux memfd slot에 복사한다. JSON-lines pipe에는 generation, stage, 시간과 짧은 표시 metadata만 전송한다.
  5. Capacity one: 이전 frame이 encode 중이면 새 diagnostic frame을 버린다. Queue를 늘리거나 control loop가 worker를 기다리지 않는다. 모든 tick은 encoded/drop/error 중 하나로 계수하며 manifest가 허용한 최대 1 drop을 넘으면 실패한다. 최종 r10은 drop 없이 120/120을 encode했다.
  6. 종료 후 처리: worker drain·종료, trace/report serialization과 progress failure 기록은 measured loop 밖에서만 수행한다.

발생한 문제와 수정

문제원인수정결과
경량 video worker import가 HPP-FCL 누락으로 실패beltbench.visualization과 beltbench.simulation package initializer가 모든 planning, MuJoCo, Viser module을 eager import했다.기존 public export 이름을 유지하는 PEP 562 lazy loader로 교체했다.OpenCV worker와 progress journal import 시 HPP-FCL·MuJoCo가 load되지 않음을 확인했고 기존 public API 32 tests가 통과했다.
영상 worker 실패 시 control loop가 process 종료와 JSON 기록을 수행진단 실패 처리와 cleanup 위치가 임계 루프 안에 있었다.루프에서는 failure code와 client 비활성화만 하고 worker close와 progress write를 finally로 이동했다.Measured loop 안의 artifact write와 최대 수 초의 process wait 경로를 제거했다.
Source hash가 맞아도 report의 passed 필드 변경을 즉시 탐지하지 못함Report 자체 canonical digest와 trace 재검증이 없었다.본문 canonical SHA-256, trace SHA-256과 source hash 전체를 presentation admission에서 다시 계산한다.Report, trace, source 또는 설정 하나가 바뀌면 simulator startup 전에 fail-closed한다.
첫 로컬 shared-memory process test 2개 skip기존 conda-forge Python 3.10 build가 Linux WSL 위에서도 os.memfd_create를 노출하지 않았다./tmp/beltbench-video-smoke에 system Python 3.13 venv를 만들고 NumPy 2.5.2, headless OpenCV 5.0.0.93만 설치해 같은 test를 다시 실행했다.고정 slot round-trip, worker ready handshake, compose, MP4 encode/close를 포함한 신규 9/9 tests가 0.737초에 통과했다.
RTX 통합 실행 재개 불가Tailscale endpoint는 SSH key exchange에서 정체됐지만 workstation direct endpoint는 접근 가능했다. 네트워크 경로 문제와 Isaac 자체 문제를 구분하지 못한 상태였다.Tailscale 경로를 우회해 direct endpoint로 접속하고, 작업 경로를 /home/hyunsu/.agile/projects 아래로 제한했다.동일 RTX 3090 host에서 단계별 실행과 evidence 회수가 가능해졌다.
r01-r03가 report를 닫지 못하거나 timing gate에 실패직접 script 실행의 import context, report hasher 이름 오류, 실제 workload와 맞지 않는 25 ms age/100 ms peak 기준이 순서대로 드러났다.Module entry point, report closure와 D1 전용 sensor-ingress/soft-real-time policy를 각각 수정했다.실패를 숨기지 않고 다음 run에서 report가 항상 닫히고 원인 code가 남도록 했다.
r04-r07에서 yaw 또는 acquisition deadline이 run마다 불안정Isaac RTX render와 FoundPose가 한 GPU를 동시에 점유했고 v6의 0.8초 component 한계를 integrated limit처럼 사용했다. Selector 변경 실험은 오히려 최대 yaw error를 2.876 rad까지 악화시켰다.기존 selector를 유지하고 v7 full-yaw 12-sample sweep으로 0.9초 yaw/0.95초 total을 재검증했다. Acquisition 동안 FoundPose가 GPU를 독점하고 Isaac은 새 sensor render/read를 hold하되 60 Hz physics와 encoder prediction은 계속 실행하도록 schedule을 분리했다.v7은 12/12, yaw error 최대 0.102 rad, position error 최대 0.333 mm, yaw acquisition 최대 0.718초, total 최대 0.743초로 통과했다.
r08-r09가 거의 통과했지만 correction 1건 또는 video frame 1건으로 rejectr08의 CAD/encoder disagreement는 모든 correction 성공만 허용하던 정책과 충돌했다. r09의 capacity-one worker는 의도대로 control을 막지 않고 1 frame을 폐기했지만 zero-drop verifier가 이를 실패 처리했다.모든 correction rejection과 presentation tick을 report에 보존하고, manifest에서 각각 최대 1건만 명시적으로 허용하도록 바꿨다. Timeout이나 미계수 frame을 fallback으로 성공 처리하지 않는다.r10 authority와 presentation이 모두 통과했고 최종 presentation에서는 실제 drop/error가 0이었다.

실행 이력과 다음 승격

  1. r01-r07: import, report closure, 부정확한 deadline, yaw variation과 single-GPU contention을 차례로 분리했다. 이 run들은 acceptance evidence가 아니다.
  2. r08: GPU ownership으로 acquisition과 RTF를 회복했으나 camera correction rejection 1건을 발견해 실패했다.
  3. r09: authority는 통과했으나 presentation capacity-one worker의 frame 1건이 drop되어 기존 zero-drop gate에 실패했다.
  4. r10: 같은 source와 manifest의 authority를 먼저 통과시킨 뒤 그 canonical digest를 presentation admission에 결속했다. 두 pass와 영상 closure가 모두 통과했다.
  5. D2: fused track을 resident path-family query와 changed-candidate/final-commit cuRobo gate에 연결하고 camera-to-future-start lease 시간을 측정한다.
  6. D3: 승인된 exact arm/hand command로 contact, attach, transport, release, bin containment와 retreat를 Isaac measured state에서 닫은 뒤에만 grasp demo 영상을 만든다.
