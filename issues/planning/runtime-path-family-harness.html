ISSUE-022 · 2026-08-09 · runtime vertical slice

검증된 grasp와 path-family를 최신 관측에서 실제 시간 순서로 선택한다.

문서와 개별 계약만 연결해 놓고 real-time pipeline이라고 부르지 않는다. 실제 projector, coordinator, bounded warm-start 경계, capacity-one scheduler와 causal recorder를 한 실행 경로로 묶고, 선택되거나 거부된 결과를 발생 시간 그대로 Viser가 재생할 수 있는 첫 production-shaped vertical slice를 구현했다.

현재 효력: 3e3de99이 runtime engine, latest-generation mailbox와 deferred causal session을 구현한다. 09df7f4는 서버에서 발견한 non-usrmerge Linux test 결함을 수정한다. 모든 trajectory는 계속 execution_blocked이며 controller command 권한이 없다.

Grasp 선택 기준을 다시 연결한 결론

AutoDex source 감사 결과는 바뀌지 않았다. BODex residual과 provider 순서, zero-margin sampled sphere collision, squeeze overlap, 한 방향 gravity hold, scene set cover, coverage 순서의 첫 planning 성공은 proposal 생성과 static diagnostic에는 유용하지만 moving conveyor command의 승인 기준은 아니다.

모든 hard gate 뒤 후보 비교는 complete normalized-slack vector의 lexicographic maximin이다. 현재 active family가 유효하면 유지하고, switch는 certified latch와 hysteresis 개선을 모두 요구한다. Cutoff 뒤에는 grasp와 topology를 바꾸지 않으며 bounded correction을 벗어나면 stop을 권고한다.

실제로 연결한 실행 경로

  1. RuntimePlanningObservation이 같은 generation의 fused planar track, conveyor motion, stable pose, calibration, tracking policy, named robot motion snapshot과 commit deadline을 묶는다.
  2. PathFamilyRuntimeEngine이 실제 ResidentPathFamilyProjector를 호출하고 그 exact batch로 PathFamilyRuntimeCoordinator를 호출한다. 다른 bundle에 결합된 projector는 시작 시 거부한다.
  3. Retain·correct·latch·switch만 exact compiled path digest를 노출한다. stop_active는 stop 대상 identity가 있어도 reusable candidate를 노출하지 않는다.
  4. Warm start가 필요하면 한 번만 admission한다. Backend가 없거나 실패하면 artifact 없이 거부하고, 성공 결과도 exact trajectory·stop-path digest의 독립 validation을 통과해야 한다.
  5. LatestGenerationRuntimeHarness의 mailbox는 capacity one이다. 더 최신 observation은 pending과 in-flight generation을 supersede하고, 늦게 끝난 stale result를 recorder나 selection으로 되돌리지 않는다.
  6. RuntimePlanningSessionRecorder는 measured interval 동안 bounded object reference와 tracepoint만 메모리에 둔다. JSON, SHA-256과 filesystem write는 종료 뒤 수행한다.
  7. 모든 generation이 selected, rejected, superseded 또는 failed terminal을 가진 뒤에만 전체 session과 causal assessment를 만들고 staging tree를 atomic rename한다.

Scheduler와 evidence 불변식

  • 새 observation과 그것이 supersede하는 generation은 하나의 preflighted transaction이다. Event capacity가 부족하면 recorder와 mailbox 모두 바뀌지 않는다.
  • Harness 시작 시 8 × maximum_generation_count + 1 event를 담을 수 있어야 한다. 이전 generation이 complete trajectory rejection으로 끝나고 마지막 generation이 diagnostic selection되는 최악 경로를 예약한다.
  • Blocking Python backend를 강제 중단할 수 있다고 주장하지 않는다. Production solver는 cancellation latency를 측정한 nonblocking process/worker 뒤에 있어야 하며 late return은 폐기한다.
  • Observation artifact는 camera ID와 fused-track source를 기록하지만 raw sensor payload를 포함했다고 주장하지 않는다.
  • Viser playback은 arm, end effector, object, stable pose와 workcell이 runtime request와 모두 같아야 한다. Startup hash를 종료 시 다시 검사하며 중간 변조 시 session directory를 만들지 않는다.
  • 거부만 발생한 session도 fake playback 없이 보존한다. Playback이 있어도 planned_only이며 measured robot/object feedback으로 표시하지 않는다.

Actual-time smoke와 Viser

한 local smoke는 synthetic continuous-path certificate와 precompiled active family를 사용하되 engine, projector, coordinator, monotonic recorder와 causal assessor는 실제 구현을 사용했다. Object는 upside-down stable pose의 Pepsi Light이며 actual xArm6 URDF, Inspire-left URDF, 양쪽 CAD mount mesh connector, conveyor, 고정 table과 open drop bin을 가진 schema-2 playback 301 frame을 연결했다.

9개 event와 7개 artifact가 causal assessment를 통과했고 Viser는 causal_replay=true로 실제 mesh와 session을 load해 1x 자동 반복했다. 이 값은 단 한 번의 orchestration smoke다. Camera transport, pose estimation, ROS callback, warm solve, continuous validation, dispatch, controller response가 빠졌으며 p95·p99나 real-time 보장이 아니다.

검증 결과

  • Runtime engine, projection, coordination, warm start, causality, session과 Viser 집중 test 66개가 local과 junjinyong에서 모두 통과했다. Server 집중 실행은 1.874초였다.
  • Planning discovery는 최종 362개 항목을 수집했다. OpenCV가 없는 planning 환경의 3개 import module을 제외한 359개 실제 test가 통과했다.
  • 그 3개 module은 OpenCV가 있는 calibration 환경에서 실제 test 14개가 모두 통과했다. 중복 import placeholder를 제외한 총 실제 통과 수는 373개다.
  • Bundle/projector mismatch, missing backend, failed warm start, stop action, stale supersession, capacity transaction, undersized policy, context splice, playback mutation, rejection-only session을 negative test로 고정했다.
  • Source HEAD 09df7f4와 server HEAD가 같고 server의 기존 untracked BODex native build는 수정하거나 삭제하지 않았다.

남은 신뢰 경계와 다음 순서

ResidentPathFamilyProjector 생성자는 bundle과 atlas의 구조적 상속을 검사하고 engine은 exact bundle 결합을 검사한다. 그러나 이것만으로 source file을 다시 hash하지 않는다. Production bootstrap은 timing 시작 전에 verify_path_family_deployment_bundle_sources()로 atlas, compiler/policy, reusable/tracking/stop path, latch certificate와 validation report를 모두 재검증해야 한다. 이번 synthetic fixture는 그 production source evidence가 아니다.

  1. 실제 checksummed atlas에서 complete reusable path와 stop path를 만드는 production path compiler를 구현한다.
  2. Reference oracle과 비교 가능한 accelerated warm-start solver와 별도 continuous validator를 nonblocking worker로 연결한다.
  3. Recorded camera·encoder·controller snapshot을 원래 cadence로 replay해 p50/p95/p99, worst case, miss, supersession, cancellation과 memory high-water를 측정한다.
  4. ROS 2 경계에는 Python JSON recorder 대신 LTTng/ros2_tracing 또는 동등한 low-overhead tracepoint adapter를 둔다.
  5. Controller simulation에서 commit, setpoint, measured robot/object, watchdog, stop과 bin containment를 독립 feedback으로 기록한다.
  6. 실제 calibration·connector metrology·hardware reliability lower bound가 준비된 뒤에만 physical commit authority를 추가한다.

AutoDex와 BeltBench grasp authority 감사, bounded warm-start 경계, causal session 계약이 각각 이 runtime의 offline 입력, update 권한과 evidence 의미를 설명한다.
