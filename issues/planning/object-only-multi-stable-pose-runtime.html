ISSUE-096 · 2026-08-28 sixth update · D2 admission to exact command

Object ID만 주어진 이벤트에서 stable pose, yaw와 위치를 함께 추정해 resident grasp로 라우팅한다.

기존 demo는 pepsi_light/upside_down처럼 stable-pose ID가 startup과 event에 이미 주어진다고 가정했다. 목표 작업에서는 물체 종류만 주어지고, 물체는 belt 위의 임의의 물리적 stable pose와 초기 yaw·위치로 들어온다. 따라서 pose를 입력으로 받는 경계를 폐기하고 RGB 관측이 pose class와 평면 상태를 함께 결정하도록 바꿨다.

현재 판정: revision ed8c662에서 exact visual-mesh support 측정과 source-closed collision identity를 적용한 뒤 RTX 3090·Isaac Sim 4.5.0에서 264회 frozen settling campaign을 실행했다. 모든 trial의 물체-평면 clearance는 통과했지만 side pose의 return rate와 global drop의 unresolved rate가 정책을 통과하지 못해 전체 결과는 accepted=false, execution_authorized=false다. 이어 3731c1b에서 공유 pepsi_light/Inspire 후보 100개를 전수 source-close했다. 기존 데이터를 적극적으로 재사용할 수 있는 입력 경계는 확보했지만 pose·hand·moving-task qualification이 남아 있어 runtime 권한은 계속 false다.
2026-08-28 정정: 위 pool의 secondary scene별 성공 분포를 실제 stable-pose 성공 분포로 읽으면 안 된다. 2d948f5에서 tested episode의 inv(C2R) @ pose_world를 원본 대칭 분류식으로 재현한 결과, 성공 5건은 source-000 2건과 source-001 3건이며 뒤집힌 source-002는 0건이다. 자세한 원인과 immutable NAS report는 ISSUE-097에 기록한다.
2026-08-28 네 번째 업데이트: 1d43501에서 object-only D1→D2 composition root를 추가했다. Event API는 stable-pose ID, NAS root와 online grasp provider를 받지 않는다. 하나의 source-closed resident deployment와 하나의 0.95 s provisional event budget으로 RGB multi-pose acquisition, fresh-generation confirmation, encoder track과 complete pose-specific selector map을 함께 생성한다. 실제 FoundPose backend fixture는 두 RGB generation을 소비한 뒤 side selector만 호출했고, RTX 3090 전체 회귀는 1,774 passed, 15 skipped, 92 subtests passed였다. 이 결과는 D1→D2 구조 검증이며 RGB 정확도, qualified Pepsi deployment, cuRobo command lease 또는 D3 실행 권한은 증명하지 않는다.
2026-08-28 다섯 번째 업데이트: 49404af부터 bececf2까지, 이미 exact request와 object lifecycle이 준비됐다는 경계 아래 full-command producer, preallocated producer slot, complete abort catalog, independent validator result와 validated lease를 하나의 deadline으로 조립했다. 모든 reject·deadline·identity mismatch는 정확한 slot을 영구 quarantine한다. RTX 3090에서 CUDA-only 테스트 2개와 전체 회귀 1,779 passed, 17 skipped, 92 subtests를 통과했다. 33×10 contract fixture의 30회 CUDA publication은 enqueue p99 4.235 ms, synchronized completion p99 4.302 ms였고 77.112 ms allocation·warmup은 startup으로 분리했다. 이는 작은 command의 CPU 검증·pinned staging·H2D·CUDA event publication 증거일 뿐 cuRobo planning, collision, 실제 xArm/Inspire command 크기나 end-to-end latency가 아니다. D2 admission→exact request 변환과 concrete full-task validator는 아직 없다.
2026-08-28 여섯 번째 업데이트: 147614c에서 PathFamilyWarmStartAdmission 이후의 단절을 닫았다. ResidentFullTaskAdmissionRuntime은 admission과 startup-resident route를 시작 시 digest로 snapshot하고 기존 commit deadline을 교체하지 않은 채 request, moving contact, object lifecycle과 full-task inference를 순서대로 실행한다. Event 중 source 변조는 publication 전에 거부하고, publication 후 admission drift나 compute/validation budget 초과는 정확한 slot을 quarantine한다. 관련 29개 테스트와 RTX native 전체 회귀 1,784 passed, 17 skipped, 92 subtests가 통과했다. 그러나 object-only multi-pose selector가 robot-state snapshot을 포함한 admission을 실제로 발행하는 production adapter와 concrete cuRobo validator는 아직 없다.

실시간 acquisition과 routing

  1. Event 입력은 object ID, camera/calibration identity와 timestamp이며 stable-pose ID는 받지 않는다.
  2. 한 RGB generation에서 FoundPose correspondence inference를 한 번만 수행한다. 지원 pose마다 GPU network를 다시 실행하지 않는다.
  3. 같은 correspondence에 대해 지원 pose 수만큼 bounded constrained planar solve를 병렬 수행한다. 각 가설은 pose별 symmetry와 yaw period를 보존한다.
  4. 별도 sealed holdout으로 검증된 calibrator가 known pose들과 unknown/open-set의 비교 가능한 normalized cost를 만든다. Raw solver RMSE는 selection authority가 아니다.
  5. Policy가 margin, unknown rejection와 연속 generation 확인을 통과한 pose만 track에 한 번 latch한다. Latch 이후 pose switch나 nearest-pose fallback은 금지한다.
  6. 선택된 pose의 planar estimate로 위치와 초기 yaw를 만들고, 이후에는 belt encoder로 평행이동만 갱신한다. 물체가 belt 위에서 계속 회전한다는 motion model은 사용하지 않는다.
  7. Latched pose ID로 startup-resident grasp atlas와 interception planner를 O(1) 조회한다. Object, arm, end-effector, workcell과 calibration ancestry가 모두 맞아야 한다.
  8. ResidentMultiStablePoseEventRuntime만 이 D1→D2 경계를 조립한다. Stable-pose confirmation은 retry failure가 아니며, pipeline과 causal layer에 다른 event budget을 줄 수 없다.

“임의 tablepose”의 정확한 범위

여기서 임의 stable pose는 object mesh에 대해 사전에 열거하고 인식·grasp·moving-task qualification을 완료한 유한한 물리적 resting-pose 집합 중 어느 것이든 들어올 수 있다는 뜻이다. 미등록된 접촉 상태, 불안정하게 기대어 있는 물체나 학습 범위 밖 6D pose까지 자동으로 처리한다는 뜻이 아니다. Unsupported pose, unknown score 우세, pose margin 부족, planar fit 실패, stale generation 또는 해당 atlas 부재는 모두 no-pick이다.

공유 데이터에 대한 현재 증거

초기 catalog에는 legacy pepsi/008/Allegro episode 세 개만 들어 있었다. 이 snapshot만 보고 공유 데이터 전체가 세 episode라고 판단한 것은 조사 범위 오류였다. AutoDex interactive manifest가 가리키는 실제 experiment lineage를 따라가자 별도의 pepsi_light/Inspire candidate pool 100개와 완전한 physical episode 다섯 개가 확인됐다.

세 raw object mesh는 파일명과 저장 tree가 달라도 41,392,081 byte와 SHA-256 10d134c7…b81e가 정확히 같았다. 따라서 legacy pepsi와 pepsi_light의 이 source object identity는 이름 추론이 아니라 byte identity로 연결할 수 있다. 후보의 wrist_se3.npy는 object-relative hand-root pose이며 pregrasp와 grasp는 각각 6-DOF Inspire command다. 다만 provider ID inspire가 BeltBench의 exact inspire_left joint·mount profile과 같다는 권한은 아직 별도 해소가 필요하다.

중요한 source defect도 발견했다. 후보가 생성될 때 사용한 것으로 보이는 generator scene tree와 현재 object_processing snapshot을 비교하면 32개 scene은 내용이 다르고 68개는 generator 쪽 파일이 없다. 정확히 동일하게 남은 generator scene은 0개다. 특히 성공 후보 두 개의 옛 scene pose ID는 현재 secondary snapshot과 다르다. 따라서 provider pose ID를 BeltBench stable-pose ID로 직접 승격하지 않고, newer scene metadata는 secondary_scene_snapshot_only로 보존했다.

3731c1b의 importer는 후보 100개를 성공 여부로 먼저 거르지 않는다. success/failure/untested를 삼상 상태로 보존하고, 성공 후보는 candidate result와 physical experiment result의 scene·episode·outcome이 일치하며 planned wrist, executed hand command, object pose와 camera-to-robot transform이 모두 유효할 때만 join한다. 첫 RTX 실행은 checkout이 Python environment에 설치되지 않아 import에서 중단됐고 source 및 registry write는 발생하지 않았다. Checkout을 명시적으로 Python path에 둔 뒤 재실행해 100개와 모든 source digest를 검증했다.

생성된 append-only record는 250,929 byte, payload SHA-256 74981cae…efede7다. 결과는 success=5, untested=95, scene 상태는 drift=32, missing=68이었다. 같은 명령으로 전체 source를 다시 re-hash했을 때 created=false와 같은 digest가 재현됐다. Record 자체는 runtime_eligible=false, hardware_reliability_eligible=false이며 NAS scan은 offline onboarding에만 허용한다.

별도로 object_processing commit 9aaa4ce의 pepsi_light gallery에는 MuJoCo settling으로 얻은 후보 3개가 있다. 형상상 side 1개와 양쪽 end 2개이며, 기존 upside-down fixture의 support height는 세 번째 후보와 일치한다. 그러나 gallery JSON은 source mesh digest와 settling trial 원본을 함께 봉인하지 않으므로 이 기록만으로 status=measured를 부여하지 않는다. Canonical mesh digest를 결속하고 Isaac settling 재검증을 통과한 뒤에만 deployment pose로 승격한다.

df26485의 stager는 repository URL과 revision을 Git에서 직접 읽고 catalog가 tracked 상태이며 HEAD와 동일한지 확인한다. 그 뒤 exact info JSON, object manifest, visual GLB와 collision GLB만 임시 디렉터리에 복사하고 모든 digest·transform을 재검증한 후 원자적으로 publish한다. 실제 v2 bundle은 15 MB, 후보 3개, payload SHA-256 200c745e…263a2이며 execution_authorized=false다.

Canonical cylinder axis에 대한 세 후보의 world-up projection은 약 0, +0.99998, -0.99999로 side·upright·upside-down class를 분리한다. 기존 upside-down fixture는 세 번째 source pose와 직접 회전 오차 약 0.0168°로 일치한다. 이 결과는 기존 single-pose demo frame을 보존할 근거지만, 다른 두 pose의 grasp나 random-drop completeness를 증명하지 않는다.

448be81은 object-frame world-up vector를 source symmetry group으로 quotient한다. Pepsi 후보의 pairwise class distance는 side↔두 end가 각각 약 89.76°, 89.61°, 두 end가 약 179.37°다. 실제 infinite-fold axis만 continuous로 처리하고 finite generators는 bounded exact rotation group으로 닫는다. Class center 분리는 2 × class radius + runner-up margin보다 커야 하므로 허용 반경 전체에서 margin을 보존한다. 이 평가는 semantic candidate를 선택할 뿐 pose를 measured로 승격하거나 grasp를 공급하지 않는다.

현재 blocker와 다음 작업

  1. Settling campaign은 수행됐지만 현재 backend가 정책에서 기각됐다. 후보 세 개를 measured로 승격하지 않으며 같은 holdout에 맞춘 threshold·damping 튜닝도 하지 않는다.
  2. Tested episode 5건의 pose는 해소됐지만 untested 95건의 source pose는 unresolved다. Secondary scene ID를 복원하려 하지 않고, object-relative proposal pool 전체를 exact target hand와 각 supported stable pose의 cross-product에서 offline 재평가한다.
  3. Provider inspire의 joint order, command unit, left-hand variant와 mount frame을 exact Inspire Left deployment profile에 결속한다. 이름이나 6-DOF shape만으로 동일 hand라고 판단하지 않는다.
  4. 기존 100개를 먼저 intrinsic·deployment·moving-task gate로 qualification한다. 해당 pose에서 통과 후보가 없을 때만 offline generator를 실행하며 online 생성 fallback은 두지 않는다.
  5. 지원 pose와 unknown/non-stable holdout을 포함한 Isaac RGB campaign으로 comparable cost calibrator와 admission threshold를 검증한다.
  6. Object-only multi-pose selector가 latched track, 같은-generation conveyor state와 measured robot state로 production RuntimePlanningObservation을 만들고 exact path-family admission을 발행하도록 연결한다. 147614c는 admission 이후만 닫았으므로 D1→D3 causal closure를 주장하지 않는다.
  7. Nominal dynamic world, attached-object transport, release envelope, dynamics와 모든 abort route를 실제로 실행하는 concrete resident cuRobo validator를 구현한다. Fixture outcome이나 producer 자기검증을 independent authority로 사용하지 않는다.
  8. 실제 xArm/Inspire width와 full task horizon으로 producer→CUDA slot→validator→validated lease 전체 latency를 재측정한다. 현재 33×10 publication p99는 이 gate를 대체하지 않는다.
  9. 검증된 최소 deployment bundle을 local NVMe에 resident-load한 뒤 새 multi-pose Isaac composition runner에서 actual-time trace와 영상을 만든다. 기존 single-pose runner에 pose switch 조건문을 추가하지 않는다.
