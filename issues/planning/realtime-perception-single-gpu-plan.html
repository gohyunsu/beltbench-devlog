ISSUE-074 · 2026-08-13 · real-time perception and single-GPU scheduling

모든 단계를 빠르게 돌리는 대신, 임계 경로를 작게 만들고 GPU 소유권을 시간축으로 분리한다.

교수 시연에 필요한 것은 1.0x로 보이는 애니메이션이 아니라 실제 Isaac RGB-D generation이 pose acquisition, tracking, bounded decision, collision gate와 controller로 인과적으로 이어지는 실행이다. 첫 D1을 위해 FoundPose를 상주 process로 만들고 initial yaw, CAD translation, encoder prediction의 권한을 분리했다. 한편 RTX rendering과 FoundPose를 합친 실행에서 workstation 응답 정체가 발생해, dependency process 분리만으로는 단일 GPU contention이 해결되지 않는다는 운영 문제도 드러났다.

현재 판정: FoundPose full-yaw component qualification과 resident IPC, 15/60 Hz tracking core는 통과했다. NVIDIA 공식 우회 옵션을 사용한 Isaac 4.5 최소 RTX smoke도 통과했다. 그러나 actual Isaac sensor와 FoundPose를 합친 D1은 report를 닫지 못했고 SSH command channel도 timeout되었으므로 integrated D1 = not accepted다. 원인은 추가 격리 실험 전에는 확정하지 않는다.

실시간 task를 제한한 가정

  • Object identity와 안정 tabletop pose identity는 trial 전에 주어진다.
  • 초기 belt-frame 위치와 yaw는 sensor로 관측한다.
  • 물체는 초기 yaw와 lateral 위치를 유지하고 calibrated belt 방향으로 평행이동한다.
  • 지원하지 않는 yaw, 위치, 속도, grasp 또는 path cell은 online 생성으로 숨기지 않고 no_pick이다.
  • Grasp 생성, intrinsic qualification, path family, contact/release/stop command와 mesh oracle 검증은 offline이다.

구현한 경계

  1. Zero-copy worker: Linux memfd의 고정 RGB/mask slot과 JSON-lines metadata만 사용한다. Depth, object truth와 velocity는 worker에 전달하지 않는다.
  2. Single-flight: pending acquisition은 하나뿐이며 stale request queue를 만들지 않는다. Model과 representation은 startup에 한 번 load한다.
  3. Pose state machine: idle → acquiring → tracking/fault 전이에서 v6 yaw evidence, 같은 generation CAD x/y와 camera order를 검사한다.
  4. Multi-rate tracker: camera correction은 15 Hz, encoder prediction은 60 Hz다. 같은 timestamp correction은 허용하되 generation ancestry를 바꾸지 않는다.
  5. Bounded runtime: camera, planning, command mailbox를 각각 capacity one으로 유지한다. cuRobo는 camera frame마다 실행하지 않는다.

단일 GPU 실행 계획

  1. Startup: Isaac, FoundPose, 이후 cuRobo를 순차 warm-up한다. Model load, USD conversion, world upload와 allocation은 trial timing에서 분리하되 별도 cold-start 시간으로 기록한다.
  2. Acquire: Isaac rendering과 FoundPose만 GPU를 사용한다. cuRobo와 live MP4 encode는 금지한다. Object는 upstream에서 0.8초와 commit reserve를 모두 확보한다.
  3. Track: FoundPose를 idle로 두고 15 Hz CAD correction과 60 Hz CPU prediction을 실행한다. Resident atlas/path lookup은 fixed-size CPU query다.
  4. Commit: candidate가 바뀌거나 final commit할 때만 FoundPose와 상호배타로 cuRobo를 실행한다. Timeout은 CPU planner fallback이 아니라 reject다.
  5. Execute: 60 Hz controller, feedback와 lifecycle monitor만 command authority를 가진다. 일반 global replanning은 금지하고 certified phase/time correction 또는 stop만 허용한다.
  6. Publish: raw trace가 닫힌 뒤 sensor panel과 stage color를 MP4로 조합한다. Presentation RTF는 control RTF와 별도다.

다음 승격 기준

  • D1-A: Isaac scene+sensors만 원 cadence에서 다시 통과하고 host health, VRAM, CPU RSS와 stage heartbeat를 기록한다.
  • D1-B: 같은 sensor generation을 raw bundle로 기록한 뒤 Isaac 없이 resident FoundPose+CAD+tracker를 replay한다.
  • D1-C: live Isaac와 worker를 결합하되 video writer를 제거하고 authority trace만 기록한다. 15 Hz generation, 60 Hz prediction, pose error와 deadline miss가 모두 통과해야 한다.
  • D1-D: 통과한 immutable trace에서 교수용 perception video를 후처리한다.
  • D2: verified path-family를 track에 연결하고 changed candidate/final commit에서만 cuRobo exact-command gate와 future-start lease를 측정한다.
  • D3: 같은 lease로 Isaac arm/hand를 제어하고 contact, attach, transport, release, bin containment와 retreat를 measured simulator state에서 닫는다.

현재 교수님께 보여 줄 수 있는 범위

현재 확실히 보여 줄 수 있는 영상은 ISSUE-073의 D0 actual-asset sensor diagnostic과 기존 source-bound Viser planning diagnostic이다. FoundPose component 수치와 architecture diagram은 설명 자료로 사용할 수 있지만, 오늘 실패한 D1 시도는 영상이나 integrated demo로 제시하지 않는다. 다음 교수용 영상은 D1-C raw trace가 통과한 뒤 만든 perception 단계 영상이며, grasp 성공 영상이라는 표현은 D3 measured execution 이후에만 사용한다.
