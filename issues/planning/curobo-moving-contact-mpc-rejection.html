ISSUE-092 · 2026-08-27 · moving-contact MPC source audit and rejection

빠르지만 목표를 따르지 않는 cuRobo MPC 경로를 producer에서 제외한다.

Moving-contact prefix를 매 camera correction마다 GPU에서 갱신하려고 pinned cuRobo MPC를 연결했다. 초기 결과는 warm p99 약 5.9 ms였지만 target position error가 118.9 mm였고 모든 vendor success가 false였다. 단순 weight tuning보다 먼저 objective, constraint와 source identity를 분해해 이 수치가 무엇을 의미하는지 검증했다.

현재 판정: MPCSolver + lbfgs_retarget_mpc는 BeltBench moving-command producer로 기각한다. Goal, weight, preview, graph mode와 source joint goal을 바꿔도 consumed action tensor가 변하지 않았다. cuRobo는 resident GPU collision과 candidate/IK evaluation에 유지하되, latency만으로 command authority를 부여하지 않는다.

Source에서 확인한 원인

  • Upstream _get_result는 pose convergence를 계산하지만 success에는 넣지 않고 constraint aggregate만 반환한다.
  • self_collision_check=false는 optimizer rollout에만 적용되고 metrics rollout에는 적용되지 않아 self-collision이 vendor success에 남는다.
  • Metrics의 cspace tensor는 joint-limit 항과 squared-L2 regularization을 합친다. 따라서 <=0 결과를 순수 dynamics feasibility로 사용할 수 없다.
  • Scene, self, cspace를 이름별로 분리하고 exact output에는 별도 position·velocity·acceleration·jerk limit validator를 적용해야 한다.

잘못된 입력도 보존한다

첫 source 재실행에서는 기존 report와 다른 event request를 선택해 200 mm error가 나왔다. File/canonical digest가 기존 bf23.../d98...와 다름을 발견해 결과를 덮어쓰지 않고 별도 run으로 보존한 뒤 exact request로 재실행해 118.940 mm를 재현했다. Directory 이름이나 최근 파일을 source identity로 사용하지 않고 canonical digest를 결속해야 하는 이유다.

교체 방향

  1. Offline compiler가 grasp와 complete command family, stop route, collision·timing·uncertainty certificate를 만든다.
  2. Online event path는 RGB pose와 encoder prediction으로 fixed-capacity family를 조회하고, bounded correction tube 안에서 intercept time을 갱신한다.
  3. cuRobo는 candidate change와 final commit에서 represented scene collision과 batched IK/candidate evaluation을 수행한다. Vendor aggregate를 generic feasibility로 사용하지 않는다.
  4. Arm/hand/object/connector의 self·world·moving-object·attached-object collision과 motion limits는 각각 명시된 independent validator가 담당한다.
  5. Correction tube 밖, stale track, missed deadline이나 invalid contact는 unbounded replan이 아니라 no-pick 또는 certified stop으로 전환한다.

재도입 조건

새 moving optimizer는 latency 측정 전에 action-sensitivity test를 통과해야 한다. Goal pose, objective weight와 seed를 독립적으로 바꿨을 때 command tensor가 예상 방향으로 변하고, exact endpoint tracking·motion limits·named collision scopes·stop coverage를 통과해야 한다. 그 전에는 Viser나 Isaac animation에 optimizer output이라는 label을 붙이지 않는다.
