ISSUE-111 · 2026-08-31 · qualified nearest online data plane

Nearest grasp는 버리지 않고, 후보 검색에만 사용한다.

Nearest 하나를 곧바로 실행하면 현재 robot state, 충돌, 도달 시간과 강건성을 무시한다. 반대로 nearest를 전혀 쓰지 않으면 이미 검증된 정적 grasp library를 효율적으로 좁힐 수 없다. BeltBench는 exact object·stable pose·hand·capability 안의 nearest top-K를 빠른 검색 순서로 사용하고, 최종 실행 후보는 observation 이후 생성·검증한 complete command의 maximin margin으로 다시 고른다.

현재 효력: beltbench@0632e2a은 Pepsi Light/source-001/Inspire Left/drop_release의 qualified grasp 82개를 상주 index에 올리고, predicted intercept별 nearest top-K부터 fresh full-task command 생성까지 하나의 source-closed planning session으로 실행한다. 독립 timing·grasp lifecycle/maximin 계약은 존재하지만 connector/workcell/time-indexed moving-object collision과 drop containment, measured RGB inference, integrated selection·handoff와 Isaac feedback이 아직 한 application graph에서 완결되지 않았으므로 execution_authorized=false다.

문제와 판단

질문채택한 기준

이 기준은 ISSUE-108의 원칙을 실제 qualified library와 bounded online data path로 갱신한다. ISSUE-110의 upside-down source-002는 proposal 42개가 있어도 unvalidated이므로 여전히 no-pick이며, source-001의 82개를 가져다 쓰지 않는다.

해결 절차

  1. NAS 원본 ancestry와 intrinsic 결과를 다시 검증해 source-001의 offline_intrinsic grasp 82개를 exact registry로 결속했다. Library SHA-256은 0cdb9986...8d32다.
  2. 97caf52와 1d45c05에서 context·capability·quality gate를 startup-only immutable index로 옮기고 numeric nearest와 evidence hashing을 분리했다.
  3. b6c2909에서 current robot state와 resident robot-model FK lineage를 query에 결속했다. 별도 robot model을 다시 적재하지 않는다.
  4. 1c2860a와 18afb30에서 stable-pose composition, covariance propagation, belt prediction과 grasp-time interception을 bounded vectorized data path로 분리했다.
  5. Canonical JSON, digest와 deep replay는 control callback 밖의 evidence worker로 이동했다. 기존 synchronous API는 compatibility/evidence 경로로만 남겼다.

실패한 시도와 원인

RTX workstation의 첫 smoke run은 구현 오류가 아니라 import 단계에서 종료됐다. 실행 environment에 이전 BeltBench package가 설치돼 있어 새 contract module을 찾지 못한 것이 직접 원인이었다. Authoritative checkout을 명시해 다시 실행했고 package mutation이나 algorithm fallback 없이 통과했다. 이 문제는 배포 시 revision뿐 아니라 import root도 고정해야 한다는 재현성 조건으로 남겼다.

이 수치는 kernel/data-plane 검증이다. Calibration, RGB track과 robot state는 contract를 만족하도록 변화시킨 synthetic fixture이며 실제 RGB inference가 아니다. 다음 순서

  1. OnlineInterceptQuery를 materialized evidence로 우회하지 않고 current-state cuRobo full-task target과 command generation에 직접 연결한다.

  3. Nearest rank를 제외한 complete-command maximin으로 후보를 고르고 fail-closed controller lease를 발급한다.

2026-08-31 갱신: Timing을 독립 검증하고 actual handoff lead를 재확인

72ac7f4는 생성된 command와 exact motion request를 하나의 validation workspace에 결속한다. OnlineCommandTimingValidationComponent는 command event에서 contact 상대 시간을 다시 읽어 planned start와 합치고, predicted contact timestamp, tolerance와 motion-plan deadline을 독립적으로 검사한다. 같은 component가 grasp evidence scope, prediction validity와 latency evidence status를 robustness 값으로 내보내지만 nearest rank와 distance는 읽지 않는다.

구현 중 발견한 설계 오류

첫 초안은 timing check 완료 이후 selection + handoff p95만 deadline에서 뺐다. 그러나 mandatory check order에서 timing 뒤에 self/connector/workcell/moving-object collision, contact order와 drop containment가 남는다. 이 설계는 아직 실행하지 않은 validation 시간을 누락해 start slack을 과대평가한다. 커밋 전에 field와 scope를 remaining_pipeline_latency_p95_s, timing_check_completion_to_controller_commit으로 고쳐 남은 validator 전체, maximin과 handoff를 포함하도록 했다.

예시 profile의 0.18초는 기존 reserve를 옮긴 provisional 값일 뿐 측정 결과가 아니다. 따라서 latency_evidence_valid=false이고 robust selection을 통과할 수 없다. Complete component set을 고정한 뒤 RTX 3090에서 timing-check completion부터 controller commit까지 p50/p95/p99를 측정해야 measured로 승격할 수 있다.

P95 예측과 actual time의 역할 분리

P95 slack이 양수여도 현재 run이 느리면 command start를 이미 놓칠 수 있다. Selection은 maximin 전에 실제 selection_completed_timestamp_s + controller_handoff_lead_s와 후보의 planned start를 다시 비교한다. 더 높은 margin 후보라도 실제 lead를 잃으면 제외한다. 테스트에서는 원래 maximin winner였던 이른 후보를 늦은 selection 시각으로 탈락시키고, start lead가 남은 다른 후보가 선택되는 것을 확인했다.

2026-08-31 갱신: Predicted-intercept nearest를 source-complete evidence로 보존

55a1f44와 436417f는 observation-time nearest batch와 predicted-intercept nearest batch의 역할을 자료구조에서 분리한다. 기존 grasp_batch는 current robot-state FK, exact object·stable pose·hand context와 source library의 root evidence로 유지한다. 새 PredictedInterceptGraspEvidence는 각 selected prediction sample의 object_from_current_hand reference, top-K grasp 전체, distance/rank와 root batch digest를 보존한다.

새 online materialization은 predicted_grasp_evidence_complete=true를 명시한다. 이 marker가 있으면 target, motion result, timing/contact validator는 반드시 candidate의 prediction_sample_index와 연결된 evidence에서 grasp ID·SHA-256·retrieval rank가 모두 일치하는 항목을 찾아야 한다. Observation-time batch에 같은 grasp ID가 있더라도 fallback하지 않는다. Marker가 없는 기존 batch만 historical compatibility 경로를 유지하며 current per-intercept evidence로 주장할 수 없다.

이번 재검토에서 더 큰 공백은 nearest가 아니라 moving-object collision authority였다. 현재 Pepsi finite-cylinder contract는 명시적으로 online_collision_authority=false다. 따라서 빠른 CUDA cylinder reduction이 한 command를 clear로 판정해도 mandatory moving_object_collision check를 채울 수 없다. 2026-09-01 갱신: 현재-state distance miss는 미래 interception을 중단하지 않는다

현재 hand와 acquisition 시점 object pose 사이의 bounded nearest query가 비어 있어도 물체가 belt를 따라 평행이동하면 미래 object_from_current_hand는 달라진다. 따라서 no_grasp_within_retrieval_bounds를 grasp library 부재나 context 불일치와 같은 terminal no-pick으로 처리하면, 곧 도달 가능한 grasp/time 후보를 prediction 전에 잘못 버린다.

분류처리이유
현재-state 거리·회전 bound 밖Prediction을 계속하고 선택된 각 미래 intercept에서 exact-context index를 다시 queryBelt translation으로 reference transform이 변하므로 현재 miss는 일시적일 수 있음
등록 source 없음, 호환 grasp 없음, provisional 미승인즉시 no-pick미래 물체 위치가 object·stable pose·hand·capability·evidence 부재를 해결하지 않음
미래 query 후보Fresh full-task generation과 independent validation 대상으로만 사용Nearest rank·distance에는 실행 권한이 없음

문제, 원인, 수정, 결과

공통 planning session이 모든 current-state nearest no-pick을 조기 종료한 것이 원인이었다. Orchestrator는 이제 거리 bound miss만 intercept-requeryable로 분류하고 나머지 구조적 실패는 그대로 terminal로 유지한다. 회귀 fixture에서 현재 최소 translation distance는 0.188812 m, 선택된 미래 시점 최소값은 0.058001 m였다. 0.07 m bound를 적용하자 현재 query는 의도대로 비었지만 미래 query가 후보를 반환했고 motion generation까지 진행했다. Source 부재가 한 stage에서 끝나는 반대 경계도 포함해 관련 grasp/session/interception 회귀는 41 passed, 5 subtests passed다.

해석: 이번 수정은 nearest를 최종 선택기로 바꾼 것이 아니다. 물체 이동을 무시한 잘못된 조기 종료를 없애고, 원래 설계대로 predicted intercept마다 nearest top-K를 다시 계산하게 한 것이다. 이후 command는 여전히 complete validation, nearest-rank 비의존 maximin과 future-start handoff를 통과해야 한다.
