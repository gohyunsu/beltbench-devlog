ISSUE-111 · 2026-08-31 · qualified nearest online data plane

Nearest grasp는 버리지 않고, 후보 검색에만 사용한다.

Nearest 하나를 곧바로 실행하면 현재 robot state, 충돌, 도달 시간과 강건성을 무시한다. 반대로 nearest를 전혀 쓰지 않으면 이미 검증된 정적 grasp library를 효율적으로 좁힐 수 없다. BeltBench는 exact object·stable pose·hand·capability 안의 nearest top-K를 빠른 검색 순서로 사용하고, 최종 실행 후보는 observation 이후 생성·검증한 complete command의 maximin margin으로 다시 고른다.

현재 효력: beltbench@18afb30은 Pepsi Light/source-001/Inspire Left/drop_release의 qualified grasp 82개를 상주 index에 올리고, current track·encoder·stable pose·robot-state lineage를 유지한 prediction과 interception data path를 제공한다. 아직 RGB inference, full-task cuRobo와 Isaac feedback이 연결되지 않았으므로 execution_authorized=false다.

문제와 판단

질문채택한 기준
Nearest grasp를 써도 되는가?같은 exact context 안의 top-K retrieval에는 사용한다.
가장 가까운 하나를 실행해도 되는가?안 된다. Nearest rank는 최종 robustness score와 maximin selection에 들어가지 않는다.
다른 stable pose의 grasp를 빌릴 수 있는가?안 된다. Qualified exact source가 비면 no-pick 또는 별도 grasp generation으로 보낸다.
대칭 물체는 yaw를 생략해도 되는가?검증된 symmetry equivalence가 있을 때만 quotient한다. 기본값은 측정한 full yaw다.

이 기준은 ISSUE-108의 원칙을 실제 qualified library와 bounded online data path로 갱신한다. ISSUE-110의 upside-down source-002는 proposal 42개가 있어도 unvalidated이므로 여전히 no-pick이며, source-001의 82개를 가져다 쓰지 않는다.

해결 절차

  1. NAS 원본 ancestry와 intrinsic 결과를 다시 검증해 source-001의 offline_intrinsic grasp 82개를 exact registry로 결속했다. Library SHA-256은 0cdb9986...8d32다.
  2. 97caf52와 1d45c05에서 context·capability·quality gate를 startup-only immutable index로 옮기고 numeric nearest와 evidence hashing을 분리했다.
  3. b6c2909에서 current robot state와 resident robot-model FK lineage를 query에 결속했다. 별도 robot model을 다시 적재하지 않는다.
  4. 1c2860a와 18afb30에서 stable-pose composition, covariance propagation, belt prediction과 grasp-time interception을 bounded vectorized data path로 분리했다.
  5. Canonical JSON, digest와 deep replay는 control callback 밖의 evidence worker로 이동했다. 기존 synchronous API는 compatibility/evidence 경로로만 남겼다.

실패한 시도와 원인

RTX workstation의 첫 smoke run은 구현 오류가 아니라 import 단계에서 종료됐다. 실행 environment에 이전 BeltBench package가 설치돼 있어 새 contract module을 찾지 못한 것이 직접 원인이었다. Authoritative checkout을 명시해 다시 실행했고 package mutation이나 algorithm fallback 없이 통과했다. 이 문제는 배포 시 revision뿐 아니라 import root도 고정해야 한다는 재현성 조건으로 남겼다.

검증 경계

이 수치는 kernel/data-plane 검증이다. Calibration, RGB track과 robot state는 contract를 만족하도록 변화시킨 synthetic fixture이며 실제 RGB inference가 아니다. FK는 별도 report이고, IK, five-phase full-task generation, independent exact-command collision validation, hand/controller handoff와 Isaac physics feedback도 이번 합계에 없다. 따라서 stage median을 단순 합산해 observation-to-command latency라고 부르거나 실제 grasp demo가 완성됐다고 주장하지 않는다.

다음 순서

  1. OnlineInterceptQuery를 materialized evidence로 우회하지 않고 current-state cuRobo full-task target과 command generation에 직접 연결한다.
  2. 동일 command digest에 대해 IK, environment/self-collision, timing, approach·closure와 uncertainty margin을 독립 validator에서 완결한다.
  3. Nearest rank를 제외한 complete-command maximin으로 후보를 고르고 fail-closed controller lease를 발급한다.
  4. 같은 application graph에 Isaac RGB sensor와 physics/controller adapter를 연결해 varied-yaw actual-time positive/no-pick trial을 기록한다.

2026-08-31 갱신: Motion request와 target도 data path로 분리

dd23221은 in-memory intercept와 동일 current robot-state object에서 motion deadline을 만들고, candidate/grasp object에서 connector를 거쳐 pregrasp·contact·lift·drop·retreat target을 직접 조합한다. Source-complete request와 target batch는 비동기 materializer가 기존 payload로 재현한다. 같은 candidate ID를 가진 다른 yaw·position evidence도 complete candidate digest 비교로 거부한다.

첫 RTX smoke에서 request와 target p50은 1.113 ms와 3.974 ms였다. 원인은 계산량이 아니라 builder가 upstream 및 derived contract를 중복 검증한 구조였다. a2dd9d4에서 gate를 삭제하지 않고 derived validation을 분리해, 반복 smoke는 0.592 ms와 1.833 ms로 감소했다.

Qualified grasp 82개에서 매 query마다 intercept pair 32개와 planning target 4개가 유지됐고 server regression 84개가 통과했으며 optional dependency 1개가 skip됐다. Report SHA-256은 d9947c37...551c다. Data path 최대값은 20.390 ms였으므로 hard real-time upper bound는 아직 아니다.

운영 경계: 1.6초 evidence를 camera frame마다 생성하지 않는다. Selected·terminal·명시적 sample generation만 bounded latest-only worker에 보내고 stale backlog는 폐기·계수한다. 그러나 RGB, FK, IK, joint trajectory, 독립 command validation, controller와 Isaac이 아직 제외됐으므로 실행 권한은 계속 없다.

다음 구현은 resident full-task planner가 materialized target batch가 아니라 target query를 직접 소비하고, lightweight generation result를 독립 validator로 넘기는 일이다.

2026-08-31 갱신: Nearest의 기준 시점을 intercept로 이동

0a2a490에서 먼저 provenance 오류를 제거했다. 기존 latency fixture는 합성 calibration과 stable pose를 measured로 표시해 production gate를 통과했다. 수치 성능 측정에는 쓸 수 있어도 measured-input 증거가 될 수 없는 구조였다. measured와 provisional_diagnostic를 상호 배타적으로 분리했고, 후자는 두 source가 모두 provisional이며 tracking도 measured calibration을 요구하지 않을 때만 통과한다. Evidence와 execution authority는 계속 차단된다.

첫 cuRobo 연결에서 발견한 실패

  1. 0a2a490: nearest top-8을 얻었지만 motion batch 네 칸이 모두 nearest-1 grasp의 서로 다른 시간으로 채워졌다. 원인은 grasp-major 이중 loop였다.
  2. 2c1f387: grasp와 시간을 diagonal round-robin으로 배치해 네 grasp를 넣었다. 두 후보는 no-solution, 두 후보는 planner_segment_start_mismatch였다.
  3. 3c0d33c: trajectory를 바꾸지 않는 observer로 계측하니 mismatch는 position 1.1920929e-7 rad, velocity와 acceleration은 0이었다. cuRobo float32 1 ULP 수준이므로 941087f에서 수치 재현 tolerance만 1e-6으로 명시했다.
  4. 941087f: 다섯 phase는 생성됐지만 계획 1.01초, pre-contact 약 2.4초, validation/handoff reserve 0.23초에 비해 물체를 x=-0.14 m에서 보고 horizon을 3초로 둔 입력은 늦었다. 결과는 planner_insufficient_start_lead였다.
  5. 5ad4ef8: 물체를 x=-0.4 m에서 관측하고 contact corridor는 [-0.18, 0.2] m로 유지한 채 encoder constant-yaw prediction horizon만 5초로 늘렸다. 그러나 관측 순간 object pose 기준 nearest가 upstream 위치에 따라 바뀌면서 네 pregrasp가 모두 no-solution이 됐다.
핵심 원인: moving pick에서 nearest의 reference는 acquisition 순간의 object_from_current_hand가 아니다. 각 predicted intercept object pose에 현재 FK hand pose를 투영한 reference여야 한다. Query 비용은 top-8 기준 약 0.1 ms이므로 이를 offline으로 옮길 이유도 없다.

5bec63f는 selected intercept time마다 resident 82-grasp index를 다시 조회한다. 첫 GPU batch는 가능한 한 서로 다른 time과 grasp ID를 포함한다. 그 결과 네 후보 모두 cuRobo의 pregrasp, moving contact, lift, transfer, retreat 다섯 phase에서 solution을 반환했다. 세 후보는 future-start lead가 부족했고 가장 늦은 contact 후보는 timing을 통과했지만 286 samples가 기존 상한 256을 넘어 거부됐다.

250c919는 trajectory를 downsample하지 않고 bounded command capacity를 384 samples로 조정했다. 50 Hz 기준 7.68초 상한이며 관측된 286 samples를 포함한다. 최종 RTX 3090 결과는 다음과 같다.

남은 권한 경계

이 결과는 실제 resident cuRobo가 online-generated target에서 complete arm/hand command를 만든 첫 positive지만 실행 성공은 아니다. RGB, calibration, stable pose, encoder와 drop pose는 provisional fixture다. Producer는 static-world planning만 수행했고 independent self/connector/world collision, time-indexed moving-object collision, timing, approach·closure, uncertainty validation과 maximin selection이 없다. 따라서 execution_authorized=false를 유지하며, 다음 구현은 동일 command를 독립 validator에 넘기는 일이다.
