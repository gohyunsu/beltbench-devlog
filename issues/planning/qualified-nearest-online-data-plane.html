ISSUE-111 · 2026-08-31 · qualified nearest online data plane

Nearest grasp는 버리지 않고, 후보 검색에만 사용한다.

Nearest 하나를 곧바로 실행하면 현재 robot state, 충돌, 도달 시간과 강건성을 무시한다. 반대로 nearest를 전혀 쓰지 않으면 이미 검증된 정적 grasp library를 효율적으로 좁힐 수 없다. BeltBench는 exact object·stable pose·hand·capability 안의 nearest top-K를 빠른 검색 순서로 사용하고, 최종 실행 후보는 observation 이후 생성·검증한 complete command의 maximin margin으로 다시 고른다.

현재 효력: beltbench@18afb30은 Pepsi Light/source-001/Inspire Left/drop_release의 qualified grasp 82개를 상주 index에 올리고, current track·encoder·stable pose·robot-state lineage를 유지한 prediction과 interception data path를 제공한다. 아직 RGB inference, full-task cuRobo와 Isaac feedback이 연결되지 않았으므로 execution_authorized=false다.

문제와 판단

질문채택한 기준
Nearest grasp를 써도 되는가?같은 exact context 안의 top-K retrieval에는 사용한다.
가장 가까운 하나를 실행해도 되는가?안 된다. Nearest rank는 최종 robustness score와 maximin selection에 들어가지 않는다.
다른 stable pose의 grasp를 빌릴 수 있는가?안 된다. Qualified exact source가 비면 no-pick 또는 별도 grasp generation으로 보낸다.
대칭 물체는 yaw를 생략해도 되는가?검증된 symmetry equivalence가 있을 때만 quotient한다. 기본값은 측정한 full yaw다.

이 기준은 ISSUE-108의 원칙을 실제 qualified library와 bounded online data path로 갱신한다. ISSUE-110의 upside-down source-002는 proposal 42개가 있어도 unvalidated이므로 여전히 no-pick이며, source-001의 82개를 가져다 쓰지 않는다.

해결 절차

  1. NAS 원본 ancestry와 intrinsic 결과를 다시 검증해 source-001의 offline_intrinsic grasp 82개를 exact registry로 결속했다. Library SHA-256은 0cdb9986...8d32다.
  2. 97caf52와 1d45c05에서 context·capability·quality gate를 startup-only immutable index로 옮기고 numeric nearest와 evidence hashing을 분리했다.
  3. b6c2909에서 current robot state와 resident robot-model FK lineage를 query에 결속했다. 별도 robot model을 다시 적재하지 않는다.
  4. 1c2860a와 18afb30에서 stable-pose composition, covariance propagation, belt prediction과 grasp-time interception을 bounded vectorized data path로 분리했다.
  5. Canonical JSON, digest와 deep replay는 control callback 밖의 evidence worker로 이동했다. 기존 synchronous API는 compatibility/evidence 경로로만 남겼다.

실패한 시도와 원인

RTX workstation의 첫 smoke run은 구현 오류가 아니라 import 단계에서 종료됐다. 실행 environment에 이전 BeltBench package가 설치돼 있어 새 contract module을 찾지 못한 것이 직접 원인이었다. Authoritative checkout을 명시해 다시 실행했고 package mutation이나 algorithm fallback 없이 통과했다. 이 문제는 배포 시 revision뿐 아니라 import root도 고정해야 한다는 재현성 조건으로 남겼다.

검증 경계

이 수치는 kernel/data-plane 검증이다. Calibration, RGB track과 robot state는 contract를 만족하도록 변화시킨 synthetic fixture이며 실제 RGB inference가 아니다. FK는 별도 report이고, IK, five-phase full-task generation, independent exact-command collision validation, hand/controller handoff와 Isaac physics feedback도 이번 합계에 없다. 따라서 stage median을 단순 합산해 observation-to-command latency라고 부르거나 실제 grasp demo가 완성됐다고 주장하지 않는다.

다음 순서

  1. OnlineInterceptQuery를 materialized evidence로 우회하지 않고 current-state cuRobo full-task target과 command generation에 직접 연결한다.
  2. 동일 command digest에 대해 IK, environment/self-collision, timing, approach·closure와 uncertainty margin을 독립 validator에서 완결한다.
  3. Nearest rank를 제외한 complete-command maximin으로 후보를 고르고 fail-closed controller lease를 발급한다.
  4. 같은 application graph에 Isaac RGB sensor와 physics/controller adapter를 연결해 varied-yaw actual-time positive/no-pick trial을 기록한다.
