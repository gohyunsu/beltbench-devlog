ISSUE-084 · 2026-08-24 · runtime-profile-bound Isaac rerun audit

14단계 runtime profile을 실제 Isaac evidence에 결속하고 실패 run을 그대로 감사한다.

통합 영상에 단계 이름만 표시하는 대신, pipeline profile의 identity·deadline·실행 상태를 staged manifest와 report에 source-closed하게 결속했다. 이어서 acquisition gate, encoder ingress, current-state estimation, future projection과 resident decision을 독립 계측하고 authoritative trace를 영상 조립에서 분리했다. RTX 3090에서 실제 Isaac RGB-D, FoundPose, CAD tracking, exact command selection과 PhysX articulation servo를 반복 실행했으나 최신 source의 presentation은 FoundPose yaw repeatability와 단일-yaw command cell 때문에 최종 acceptance를 통과하지 못했다. 이후 비접촉 hand/object 판정을 중앙화하고 guarded 구간의 모든 timestamp가 검사에 포함되는지 강제했다. r88에서 드러난 stale-frame 재진입은 backend-neutral admission으로 제거했지만 r89는 yaw와 CAD deadline에서 다시 거부됐다. 별도로 r87 검증 궤적의 actual-asset planning 영상은 확보했으나 causal perception 영상으로 승격하지 않는다.

현재 판정: revision 4b1e3e7에서 비침투 guarded interval을 CPU validation 전 경로와 audit에 강제했고, 3aa9be9에서 resume 전용 flush를 sensor backend 공통 admission으로 교체했다. r89의 sensor ingress는 통과했지만 yaw 0.09740 rad와 CAD 38.951 ms로 authority가 거부되어 presentation을 시작하지 않았다. r87 planning-only 영상은 검증된 geometry를 보여주는 보조 자료일 뿐이다. 교수님께 제시할 accepted integrated 기준선은 계속 r72다. 아래 r81은 실제 perception과 servo animation이 완주됐지만 timing gate를 통과하지 못한 진단 영상이다.

남은 blocker와 다음 순서

  • FoundPose full-yaw qualification 최대 오차 0.1018 rad와 runtime repeatability가 command gate 0.08 rad보다 나쁘다. 같은 frame의 두 camera가 서로 동의해도 함께 틀릴 수 있으므로 camera-consensus만으로 해결되지 않는다. Upstream temporal reacquisition 또는 texture-aware yaw refinement를 구현하고 original cadence에서 반복 검증해야 한다.
  • 현재 prevalidated command는 nominal yaw 하나만 갖는다. 임계값을 완화하기보다 yaw/context별 source-closed path family를 offline compile하고, online에서는 measured yaw와 uncertainty가 포함되는 validated cell만 선택해야 한다.
  • Trace publisher와 video assembly는 분리됐고 authority timing은 통과했다. 그러나 no-pick가 1,000회 반복되는 presentation에서는 JSON snapshot과 반복 decision이 함께 증가한다. Reject reason이 불변이면 decision을 event-driven으로 retain하고 trace schema도 고정-width field layout으로 줄이는 최적화가 필요하다.
  • r89에서 backend-neutral freshness gate는 통과했지만 accepted age 50 ms 뒤 CAD 38.951 ms가 발생했다. 60 ms capture-to-decision 한도와 25 ms CAD 한도를 동시에 보장하려면 단순 산술상 CAD 이전 age는 35 ms보다 작아야 하며, 실제 gate에는 sensor read·fusion·queue reserve도 포함해야 한다. 이 reserve-aware policy를 original cadence stress campaign으로 먼저 qualification한다.
  • Controller feedback profile은 2 ms로 통일했고 accepted-command run에서 충분한 margin을 확인했다. 실제 hardware claim 전에는 future-start lease, controller-native clock과 stop budget을 별도로 구현해야 한다.
  • correction_envelope, resident cuRobo gate, future-start controller handoff와 measured lifecycle이 아직 없다. 이 네 단계를 구현하기 전 complete real-time inference demo를 주장하지 않는다.
  • 현재 영상은 rigid-object contact, attachment, slip, release와 bin containment를 측정하지 않는다. Full-task 영상은 release/contact schedule과 simulator dynamics가 같은 source-closed command에서 통과한 뒤 별도 생성한다.
