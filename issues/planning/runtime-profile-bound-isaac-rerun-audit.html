Runtime profile 계약·adapter·staged binding에 대한 focused suite는 34 passed다. Planning environment 전체 회귀는 1,090 passed, 18 skipped였고, 해당 Python이 os.memfd_create를 제공하지 않아 실패한 FoundPose worker 3개는 별도 bodex environment에서 모두 통과했다. 즉 기능 실패와 host Python capability 차이를 분리해 기록했으며 skip이나 fallback으로 숨기지 않았다.

남은 blocker와 다음 순서

  • FoundPose full-yaw qualification 최대 오차 0.1018 rad가 command gate 0.08 rad보다 크고 acquisition latency도 이번 run에서 800 ms를 넘었다. Multi-frame/multi-view acquisition과 no-pick 정책을 함께 재검증한다.
  • Publisher 0.5 ms 계약과 현재 frame-build/copy 측정 범위가 맞지 않는다. Critical-loop snapshot 발행과 비동기 영상 조립을 분리한 뒤 각각 deadline을 다시 정의한다.
  • Feedback 2 ms/4 ms 불일치는 실제 controller clock·command lease·stop budget 없이 결정할 수 없다. 현재는 더 엄격한 D3a gate를 유지한다.
  • correction_envelope, resident cuRobo gate, future-start controller handoff와 measured lifecycle이 아직 없다. 이 네 단계를 구현하기 전 complete real-time inference demo를 주장하지 않는다.
  • 현재 영상은 rigid-object contact, attachment, slip, release와 bin containment를 측정하지 않는다. Full-task 영상은 release/contact schedule과 simulator dynamics가 같은 source-closed command에서 통과한 뒤 별도 생성한다.
