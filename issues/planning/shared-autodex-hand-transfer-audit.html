ISSUE-098 · 2026-08-28 · shared AutoDex hand transfer audit

NAS grasp를 버리지 않되 Inspire Right pose를 Inspire Left 실행 pose로 오인하지 않는다.

Object ID만 주어진 실시간 이벤트에서 NAS를 검색하는 대신, shared AutoDex 후보를 offline에 source-close하고 target-hand 재최적화 seed로만 승격하는 경계를 구현했다. 오른손과 왼손의 6개 command 의미가 같다는 사실은 wrist와 contact geometry가 같다는 뜻이 아니다.

현재 판정: BeltBench 4fca11f에서 hand compatibility 감사기를 구현했다. 실제 Pepsi pool 100개의 wrist·pregrasp·grasp 총 300개 파일은 원본 BODex archive와 모두 일치했다. 그러나 archive에 producer revision과 hand manifest가 내장되지 않았고 audited source는 Inspire Right를 가리키며 Right/Left URDF kinematics도 다르다. 따라서 proposal_seed_eligible=true지만 direct_grasp_transfer_eligible=false, runtime_eligible=false, execution_authorized=false다.

선택한 해결 구조

  1. Shared candidate pool과 모든 원본 artifact를 먼저 재해시한다.
  2. 442,211,743 byte 원본 zip 자체를 SHA-256으로 고정하고, 선택된 각 candidate의 세 payload를 zip member와 byte digest로 비교한다.
  3. 동시기 AutoDex source revision과 vendored BODex Right config·URDF를 기록하되 producer revision이 archive에 내장되지 않았다는 결함을 보존한다.
  4. Provider와 target URDF에서 6개 independent command, mimic limit과 wrist → base_link fixed joint를 직접 읽는다.
  5. Side prefix를 제거한 command semantic order와 radian limit이 같을 때만 Left 재최적화 seed로 허용한다.
  6. Side 이름을 정규화한 URDF joint tree의 origin, axis, parent/child, limit과 mimic signature를 비교한다. Signature가 다르면 direct root/contact transfer를 거부한다.
  7. Target-left wrist/contact 재최적화, intrinsic grasp, robot/workcell yaw-horizon, moving retention/release를 별도 필수 action으로 기록한다.

BODex import frame 계약 수정

감사 과정에서 기존 importer가 wrist_se3.npy를 곧바로 object_from_hand_root로 저장하는 문제를 발견했다. 2ca4251에서 import schema를 갱신해 provider_saved_root_link, target_hand_root_link, provider_saved_root_from_target_hand_root를 필수 입력으로 만들었다. Adapter는 이제 object_from_saved_root @ saved_root_from_target_root를 명시적으로 계산하며 identity fallback을 두지 않는다.

실행 중 문제, 원인과 해결

증상원인해결 및 결과
기본 Python에서 단위 테스트 import 실패Base 환경에 NumPy가 없었다.고정된 planning 환경으로 전환해 frame adapter 14개, hand audit 인접 회귀 총 21개를 통과했다.
서버가 GitHub commit을 fetch하지 못함비대화형 서버 checkout에 private remote credential이 없고 origin은 과거 bundle이었다.기존 checkout commit을 prerequisite로 하는 incremental Git bundle을 전송하고 검증한 뒤 clean detached checkout을 정확한 commit으로 이동했다.
SFTP 기반 전송 실패서버의 SFTP subsystem이 비활성화돼 있었다.SSH stdin으로 bundle을 전달하고 git bundle verify와 prerequisite 검사를 통과했다.
첫 audit CLI에서 BeltBench module import 실패Isaac Python에 checkout이 editable install돼 있지 않아 script directory만 import path에 들어갔다.Source root를 명시한 PYTHONPATH로 재실행했고 실제 report 생성과 exact replay가 통과했다.
Isaac Python에서 BODex importer test import 실패Sensor simulation 환경에는 의도적으로 planning 의존성인 trimesh가 설치되지 않았다.Isaac 환경을 오염시키지 않고 기존 BODex 전용 환경으로 분리해 17/17을 통과했다.

실시간 파이프라인에 미치는 영향

Online 경로는 바뀌지 않는다. NAS audit과 Right→Left 재최적화는 offline이다. Stable-pose별 Left grasp가 독립 gate를 통과하면 최소 deployment bundle만 local NVMe에 stage하고 시작 시 메모리/GPU에 올린다. RGB event는 stable-pose class와 (x,y,yaw)를 추정해 resident atlas를 O(1)로 선택하고, encoder가 translation만 전파한다. 지원하지 않는 pose 또는 qualified Left grasp가 없는 pose는 다른 atlas나 NAS 후보로 fallback하지 않고 no-pick이다.

남은 작업

  1. 기존 Left upside-down 2,000 proposal의 정확한 pose/frame ancestry를 새 frame contract로 재검증한다.
  2. source-000/001에는 Right command를 seed로 사용해 Left wrist/contact를 재최적화하고, source-002는 기존 Left batch를 먼저 평가한다.
  3. 각 stable pose에서 intrinsic contact·support·approach·closure·retention·release gate를 통과시킨다.
  4. xArm/connector/workcell의 yaw×intercept-horizon deployment를 평가해 pose별 resident atlas를 컴파일한다.
  5. RGB pose latch가 서로 다른 atlas와 command family를 선택하는 actual-time Isaac trace와 영상을 생성한다.
