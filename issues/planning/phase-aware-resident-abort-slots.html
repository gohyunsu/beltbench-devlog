ISSUE-093 · 2026-08-27 · phase-aware resident abort startup

정지 경로 계약을 실제 CUDA resident slot과 fail-closed controller 경계로 연결한다.

기존 구현은 phase별 abort catalog, O(1) selector와 activation receipt를 정의했지만 실제 Isaac worker는 정지 경로가 설치되지 않았다고 보고했다. 계약이 있다는 이유만으로 readiness flag를 바꾸지 않고, exact artifact 설치와 controller 전환을 별도 모듈로 구현했다.

현재 판정: revision 55f9bad에서 source-bound startup bundle, CUDA upload event, one-shot slot backend와 full-task controller state machine을 구현했다. RTX 3090 fixture smoke는 통과했지만 production Pepsi abort route와 실제 RGB event runner 연결은 없으므로 professor-ready 판정은 계속 차단한다.

발생한 문제와 영향

문제영향
Catalog와 selector는 있었지만 concrete slot backend가 없었다.테스트 metadata는 통과해도 controller가 어느 bytes를 실행하는지 증명할 수 없었다.
Actual event runner는 prevalidated_stop_route_installed=false였다.RGB perception, contact와 containment가 동작해도 fault 시 안전한 task cancellation이 없었다.
처음 구현에서 uploader, activation adapter와 controller를 한 파일에 모았다.장치 소유권, protocol translation과 state-machine 책임이 섞여 유지보수가 어려웠다.
Fresh progress만 확인하고 nominal command time을 교차검증하지 않았다.Latch index를 너무 일찍 보고하거나 latch를 지난 뒤 전환하면 C2 경계가 깨질 수 있었다.

해결 절차

  1. Validated lease, abort catalog, exact command와 object-collision lifecycle을 inline으로 묶는 immutable startup bundle을 추가했다.
  2. 모든 route에서 command digest, canonical dense tensor digest, collision lifecycle digest, source slot·event와 accepted collision·dynamics·terminal-region pass를 다시 대조한다.
  3. Canonical time/q/qd/qdd tensor를 startup에만 CUDA로 upload하고 named event를 synchronize한 뒤에만 capability를 발급한다.
  4. Activation adapter는 metadata-only protocol translation만 유지하고 CUDA slot ownership은 별도 backend로 분리했다.
  5. Full-task worker는 nominal command를 exact latch까지 유지한 뒤 같은 arm/hand motion-target edge에서 resident abort로 전환한다.
  6. Missing·stale·regressed·source-mismatched progress, early/late latch, command-time regression과 servo 예외는 모두 latched protective-stop 상태로 닫았다.

구현 중 발견한 결함과 수정

첫 state machine은 command timestamp regression을 servo 적용 후 검사했다. 또한 protective-stop 판정 뒤 다음 호출에서 nominal command가 다시 적용될 수 있었다. 검사를 side effect 앞으로 이동하고 protective-stop을 영구 latch했으며, route selection 및 servo 예외도 동일한 fail-closed 상태로 통합했다.

초기 파일 구조도 다시 뜯어고쳤다. Generic activation adapter는 기존 크기로 복원하고, CUDA uploader/slot backend와 phase-aware full-task controller를 각각 독립 모듈로 분리했다. Online fallback, NAS read, tensor copy와 global abort planning은 추가하지 않았다.

남은 경계

  • 현재 route는 unit fixture다. Independently planned production Pepsi retreat가 아니며 safe-hold 증거로 사용할 수 없다.
  • CUDA tensor는 resident지만 Isaac servo는 source-verified CPU quintic sampler를 소비한다. 실제 controller는 resident slot bytes를 직접 소비해야 한다.
  • 현재 admitted RGB event runner는 새 full-task worker를 생성하지 않는다. 따라서 기존 professor-readiness blocker는 그대로다.
  • Hardware protective-stop response, controller feedback clock, xArm/Inspire transport와 moving-object fault timing은 검증되지 않았다.

다음 단계

  1. Actual Pepsi full command에서 precontact, contact-commit, attached, release-commit와 post-release route를 독립 계획한다.
  2. Exact remaining command와 각 abort route를 GPU collision, dynamics, terminal-region 및 HPP-FCL parity validator로 통과시킨다.
  3. Accepted bundle을 local NVMe에 stage하고 actual Isaac articulation runner에 연결한다.
  4. 각 phase의 injected fault, missed latch, stale feedback와 servo failure를 실제 60 Hz 시간축에서 재생하고 영상을 생성한다.
