ISSUE-069 · 2026-08-13 · approach offset experiment and uncertainty scope

효과 없는 approach offset 탐색을 제거하고 pose uncertainty의 적용 대상을 분리했다.

접근 거리를 늘리면 robot-object 여유가 커질 것이라는 가설을 실제 36-candidate exact-mesh 실험으로 검증했지만, 병목은 접근 시작점이 아니라 close_above_object/contact의 공통 terminal geometry였다. 동시에 object pose covariance가 고정 workcell margin에도 차감되는 수식 오류를 schema 8에서 수정했다.

현재 판정: cuRobo를 runtime 방향에서 제외하지 않는다. 정적 batch kernel은 유망하지만 현재 Pepsi 동적 proxy path는 precontact에서 거부되고 전체 402-sample pass는 deadline을 만족하지 않는다. 다른 grasp/precontact geometry와 commit-time uncertainty envelope를 먼저 확보해야 한다.

발생한 문제와 원인

문제원인결과
Offset 3개가 같은 margin을 냈다.Offset은 초기 approach waypoint만 바꾸고 close/contact의 object-relative pose와 hand closure는 바꾸지 않는다.후보 수와 계산은 3배가 됐지만 병목 phase와 pair는 변하지 않았다.
모든 후보의 robust collision slack이 음수였다.최대 object effective margin은 1.129459 mm인데 open-loop pose inflation은 6.195-6.390 mm였다.임계값 완화가 아니라 다른 grasp/contact geometry와 최신 tracking update 기반 commit bound가 필요하다.
Pose uncertainty가 workcell margin에도 적용됐다.min(environment, object) - uncertainty가 서로 다른 불확실성 원인을 하나로 합쳤다.물체 pose가 달라도 변하지 않는 belt/table clearance가 부당하게 감소했다.
cuRobo를 쓰면 자동으로 실시간이 된다는 해석 위험이 있었다.정적 batch kernel과 동적 full-lifecycle 진단의 shape, parity, graph 조건이 다르다.정적 qualification만으로 동적 runtime authority를 주장할 수 없다.

Workcell margin은 22-55 mm로 충분해 모든 경우 robot-object가 병목이었다. 같은 grasp/time의 세 offset은 모두 동일한 수치를 냈다. 따라서 offset portfolio를 production contract에 유지할 근거가 없다.

해결

  1. 실험성 approach-offset grid와 schema 변경을 production code에서 제거하고 단일 명시적 approach offset 계약으로 복귀했다.
  2. Correction portfolio는 coarse search가 robot-object gate를 통과하지 못하면 coarse_robot_object_invalid로 fail closed한다.
  3. Intercept report schema 8의 collision slack을 min(environment margin, robot-object margin - pose inflation)으로 정의했다.
  4. Schema 3-7은 기존 수식으로 계속 읽고 검증하며, report schema와 수식 scope가 다르면 거부한다.
  5. 다음 grasp producer는 approach 시작 거리 대신 object-relative precontact/contact pose, hand closure와 allowed-contact identity를 함께 바꿔야 한다.

cuRobo 재검토

  • 서버 환경: RTX 3090 24 GiB, driver 535.309.01, PyTorch 2.5.1+cu121, cuRobo source 8e734f3.
  • 독립 정적 batch-8 kernel: synchronized-host p99 1.449 ms, 1,000 trials, deadline miss 0.
  • 현재 동적 cylinder proxy: 402 samples, batch 64, p50 약 62.98 ms, CUDA graph replay 없음.
  • 동적 proxy는 conveyor/contacting 구간에서 최대 -4.435872 mm margin으로 후보를 거부했다. 이는 넓은 contact mask로 숨기지 않고 exact mesh oracle과 representation parity를 재검증한다.

검증과 다음 단계

  • Schema 8 회귀는 environment margin 12 mm, object margin 100 mm, pose inflation 5 mm에서 collision slack을 12 mm로 유지한다.
  • Schema 7로 같은 새 수치를 표기하면 uncertainty scope mismatch로 거부된다.
  • 관련 contract/integration test 23개가 GPU 서버 격리 checkout에서 통과했다.
  • 전체 회귀는 896 tests, 21.804 s, OK, 14 skipped로 통과했다.

다음 구현 순서는 contact/precontact geometry가 robust bound를 만족하는 grasp의 선택 또는 생성, correction family 재컴파일, attach-to-bin/drop·cutoff·abort suffix, 고정 shape CUDA graph collision lifecycle, observation-to-lease p99 측정이다. 물체 pose covariance는 최신 commit update의 측정 bound로 제한하고 calibration·controller·geometry error는 별도 evidence로 유지한다.
