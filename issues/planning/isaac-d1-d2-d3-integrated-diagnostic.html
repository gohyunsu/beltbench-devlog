ISSUE-080 · 2026-08-18 · Isaac D1-D2-D3 integrated diagnostic

실제 Isaac RGB-D 측정부터 command 선택과 계획 상태 재생까지 한 시간축으로 연결한다.

RTX 3090의 Isaac 4.5에서 두 camera RGB-D와 instance mask를 읽고, FoundPose yaw와 CAD translation, encoder propagation으로 Pepsi Light의 planar track을 만들었다. 이 exact track이 301-frame guarded command를 선택하고 xArm6와 Inspire Left의 planned state를 미래 시각부터 재생해 bin 위 release까지 도달했다. 12초 control RTF는 0.9996, wall-lateness p95는 20.0 ms였고 교수용 720p 영상과 source-closed report를 확보했다.

현재 판정: professor_video_ready=true인 actual-time 통합 진단이다. D1 perception은 실제 simulator sensor 출력으로 구동됐고 D2 command 선택도 그 exact track을 사용했다. 그러나 D2 충돌 근거는 301개 discrete HPP-FCL sample이며 D3는 controller나 dynamics가 아닌 planned-state playback이다. 따라서 execution_authorized=false, swept_collision_authorized=false를 유지하며 real-time grasp execution 성공으로 부르지 않는다.

문제와 영향

  • 초기 물체를 belt 중앙이 아니라 upstream edge x=-0.5 m에서 시작하자 후반부 camera 관측범위를 벗어난 RGB-D가 registration failure로 누적됐다. 실제 알고리즘 거부와 관측 불가를 섞으면 D1 health 판정이 잘못된다.
  • Tracking correction이 매번 partial silhouette의 depth bounds로 초기화됐다. 이미 encoder-seeded track이 있는데 이를 버리면서 correspondence 탐색 max가 약 40 ms까지 늘고 25 ms deadline을 세 번 넘었다.
  • FoundPose one-shot yaw는 같은 장면에서도 run별 변동을 보였다. 12-yaw qualification의 최대 오차는 0.1018 rad였지만 r13은 0.1415 rad까지 벗어났다. 한 favorable run은 반복 강건성을 증명하지 않는다.
  • D2 query가 immutable 301-frame playback 전체를 physics tick마다 다시 validate해 평균 약 16.4 ms를 썼다. 여섯 번의 연속 query가 wall-time backlog를 만들어 p95 lateness 121 ms로 presentation을 실패시켰다.
  • cuRobo native swept-world API는 매우 빨랐지만 adversarial intermediate collision을 cuboid, mesh, ESDF 모두에서 놓쳤다. 이를 continuous collision authority로 승격하면 false accept가 발생한다.

해결 절차

  1. Source-closed command: guarded pregrasp → close_above_object, exact first contact, attachment, bin-clear transfer와 release가 301/301 discrete HPP-FCL frame을 통과한 playback·validation·audit 세 파일을 startup에서 함께 검증했다.
  2. Observation semantics: 입력 point 또는 correspondence가 부족한 RGB-D는 ModelRegistrationObservationUnavailable로 분리했다. 횟수와 원인은 report에 남기되 geometry·quality·encoder disagreement는 계속 fail-closed했다. Unavailable 처리 시간도 deadline 통계에서 빼지 않았다.
  3. Encoder-seeded correction: Acquisition만 depth bounds seed를 사용하고, tracking correction은 exact measurement-time conveyor state에 대한 encoder prediction으로 CAD fit을 시작했다. Partial-view outlier가 사라지고 correction max가 40.3 ms에서 19.3 ms로 줄었다.
  4. Command-bound authority: Broad D1 yaw 기준 0.12 rad와 command가 허용하는 0.08 rad를 혼용하지 않았다. r15부터 authority도 0.08 rad를 적용해 D1은 통과하지만 D2가 거부하는 영상을 배제했다.
  5. Startup/runtime 분리: Playback, source digest, 301-frame collision, guarded audit는 PrevalidatedCommandSelector 생성 시 한 번만 검사했다. Live track query는 O(1) identity·freshness·residual·uncertainty·lead 검사만 수행했다.
  6. Staged presentation: Preflight, authority, presentation을 분리하고 presentation이 prior authority report와 모든 source hash를 다시 확인하게 했다. Diagnostic 입력 네 개는 all-or-none이며 authority 단계에는 전달할 수 없다.

회귀 검증

Local 전체 suite는 1,060개를 558.897초에 실행했다. Assertion failure는 없고 skip 18개, WSL에 Linux memfd가 없어 발생한 FoundPose worker 오류 3개만 남았다. 같은 3개를 RTX Linux 서버에서 다시 실행해 3/3 통과했다. Integrated source 관련 focused suite는 서버에서 25/25 통과했다.

아직 증명되지 않은 것과 다음 단계

  • One-shot FoundPose는 r13 outlier를 냈다. Upstream position을 포함한 반복 yaw qualification, deterministic inference 조건, no-pick 비율을 먼저 측정해야 한다.
  • 현재 D2는 command 하나를 고르는 진단이다. 여러 grasp/context/path-family 후보의 bounded resident maximin 선택과 command-change/final-commit collision gate가 아직 없다.
  • cuRobo native finite sweep는 formal adversarial probe에 실패했다. Representation parity와 false-negative 0인 별도 complete-command gate가 생기기 전에는 online collision authority를 부여할 수 없다.
  • D3를 Isaac ArticulationController 또는 동일한 controller contract에 연결해 commanded state와 measured state, contact, attachment, release, bin containment을 비교해야 한다.
  • Physical camera와 conveyor encoder adapter는 같은 timestamped contract로 추가하되, simulator time이나 truth pose를 재사용하면 안 된다.
