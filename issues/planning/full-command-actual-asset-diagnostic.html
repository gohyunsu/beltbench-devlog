ISSUE-052 · 2026-08-11 · full-command actual-asset diagnostic

Planning-validated full command를 실제 자산 Viser 경계에 연결한다.

실시간 inference demo에서 cuRobo가 생성·검증한 full command를 확인하려면 arm, hand, connector, object와 workcell을 같은 시간축에서 재생할 수 있어야 한다. 그러나 시각화가 controller feedback이나 physics 결과처럼 보이면 검증 권한이 뒤섞인다. 따라서 기존 pre-contact capture는 유지하고, exact full output과 validation lineage를 별도의 actual-time diagnostic으로 닫았다.

현재 효력: source 025e3fe는 planning-validated full-command의 closed scenario, 상태별 replay와 actual-asset Viser CLI를 구현한다. Fixture lease는 구조 테스트일 뿐 실제 cuRobo V2 kernel, controller consumption, MuJoCo rollout 또는 hardware grasp 증거가 아니다.

문제와 영향

  1. Pre-contact와 full task의 계보 혼합: 기존 resident capture는 first contact까지만 controller 이후 복사한다. 여기에 별도 reference suffix를 붙이면 attach·transport·release가 실제 command였던 것처럼 보인다.
  2. Validated라는 표시의 과장: Final lease 파일 하나만 읽으면 output, producer slot, request, object lifecycle과 actual scene asset이 정말 같은 실행 후보인지 확인할 수 없다.
  3. Attached object의 시각적 부유: Lifecycle pose를 단순 선형 보간하면 interpolated arm FK와 object가 어긋나 hand가 물체를 놓친 상태로 이동할 수 있다.
  4. 시각화의 deadline 침범 위험: Viser용 FK, mesh load와 status 계산을 planning thread에 넣으면 GPU 가속 이득과 p99 latency를 악화시킨다.
  5. 구형 connector manifest: 로컬 actual-asset 파일은 strict runtime이 의도적으로 거부하는 paired_mount_meshes를 계속 가리켜 기존 viewer도 시작할 수 없었다.

8개 source를 닫은 이유

Scenario는 full-command output, producer lease, validated lease, arm-prefix request, object collision lifecycle, robot manifest, object manifest와 workcell만 정확히 허용한다. 각 파일 SHA-256을 고정한 뒤 semantic loader가 다음을 다시 계산한다.

  • Output payload digest와 dtype-dependent time/q/qd/qdd tensor digest
  • Producer lease digest와 allocation·slot·generation·completion event
  • Request, template, runtime session, joint order, duration과 fixed sample count
  • Nominal validation pass 전체의 command·tensor·lifecycle digest
  • Arm, hand, object, stable pose, grasp와 connector transform identity
  • Conveyor와 terminal support obstacle가 workcell에 실제 존재하는지

Abort catalog와 validator policy 전체를 viewer에서 재실행하지는 않는다. 그 source closure는 validation producer의 책임이며 viewer는 supplied lease를 execution authority로 승격하지 않는다.

상태별 actual-time 구현

  • Planner sample time에서는 exact output joint와 exact lifecycle object pose를 표시한다.
  • Sample 사이 joint는 output contract에 선언된 quintic Hermite q/qd/qdd로 평가한다.
  • Attach 전 object는 초기 yaw를 고정하고 lifecycle의 belt velocity로 평행이동한다.
  • Attach 이후 detach 전에는 interpolated arm state, 선택 URDF FK와 checksummed object/tool relation으로 object pose를 다시 계산한다.
  • 모든 exact attached sample에서 URDF FK와 lifecycle pose의 translation·rotation 오차를 검사한다. Mount나 URDF가 다르면 floating animation 대신 startup을 거부한다.
  • Detach 이후는 lifecycle sample의 SE(3) 보간으로 release·contained 상태를 보인다. 이는 ballistic physics를 재계산한 결과가 아니다.
  • Playback은 1.0x actual time, Play와 Loop가 기본 on이다. Arm, hand, 흰색 paired connector, object, workcell, path, frames와 전체 label을 제어한다.

후속 계층 재검토

2026-08-11 후속: source 5db1d1c에서 command interpolation을 Viser 모듈 밖으로 이동했다. 시각화와 simulation이 같은 수치 계약을 사용하되 서로를 import하지 않도록 수정했다.

첫 구현의 replay class는 exact sample·quintic joint 계산과 object의 belt/FK/release display를 함께 소유했다. Viser에서는 동작하지만 MuJoCo adapter가 이를 재사용하면 simulation이 visualization 계층에 의존하고, 시각 pose가 measured physics state로 잘못 유입될 위험이 있었다.

  • ResidentFullCommandTrajectory는 request/output digest, template, session, joint order와 exact time grid를 검증하고 command q/qd/qdd만 평가한다. Viser와 MuJoCo를 import하지 않는다.
  • Viser replay는 neutral trajectory에 constant-yaw belt pose, attached URDF FK와 post-detach lifecycle display만 합성한다.
  • ResidentFullCommandServoReference는 validated lease를 output payload/tensor에 다시 결속하고 independent hand command를 URDF mimic rule에 따라 full joint position·velocity로 확장한다.
  • 현재 결과는 desired-servo 입력 경계다. Existing MJB는 구형 event handoff와 initial observation에 결속되어 있으므로 resident lifecycle initial pose, collision semantics, preflight hash, timestep, actuator order와 object free joint admission 전에는 실행하지 않는다.

구현 중 발견과 수정

  1. Nominal pass role 오판: 첫 lineage 강화에서 role을 nominal_full_command로 추정해 테스트가 pass 집합을 찾지 못했다. 실제 typed contract의 nominal/abort를 확인하고 nominal pass만 displayed output에 재결속했다.
  2. Read-only test 오류: Base Python compile과 conda help가 __pycache__·temporary file을 쓰지 못해 실패했다. 코드 오류로 분류하지 않고 분리 conda 환경의 writable test로 재실행했다.
  3. Planning env의 OpenCV 부재: 전체 suite에서 calibration, pickplace, pose artifact 3개가 import 오류를 냈다. 기존 환경 분리 원칙대로 calibration 환경에서 해당 14개를 별도 검증했다.
  4. Stale connector schema: Actual xArm/Inspire smoke가 구형 paired_mount_meshes에서 fail-closed했다. Runtime fallback을 추가하지 않고 기존 compiler로 append-only paired_assembly_meshes manifest를 만들고 모든 공개 명령 예시를 새 파일로 변경했다.
  5. 실제 V2 산출물 부재: Test fixture를 Pepsi/xArm 실결과처럼 포장해 서버를 띄우지 않았다. CLI와 actual URDF/CAD load까지만 검증하고 real command scenario는 실제 adapter output을 기다린다.

검증 결과

  • 새 scenario round-trip, checksum, semantic lineage, nominal pass 위조, 상태별 pose source와 attached FK mismatch 테스트 5개가 통과했다.
  • 후속 neutral trajectory, mimic-aware full-hand servo와 foreign validated lease rejection을 추가해 full-command 집중 테스트 18개가 통과했다.
  • Full-command visualization, full-task validation과 producer output 집중 테스트 17개가 통과했다.
  • 후속 Planning 전체 700개 중 695개 통과, 2개 skip, 3개는 기존 cv2 환경 분리 import 오류다. Calibration 환경 14개는 모두 통과했다.
  • 전체 compile, public API 8-source export, builder와 Viser CLI help가 통과했다.
  • Strict paired-assembly manifest로 실제 xArm6 6-joint URDF FK와 Inspire Left connector asset load를 확인했다. 물리 seating과 transform은 여전히 provisional이다.

현재 제한과 다음 단계

Full-command Viser 경계는 준비됐지만 실제 cuRobo V2 output·validation lease가 없으므로 계획 품질이나 실시간성을 증명하지 않는다. A6000 target의 현 driver도 선택한 V2 policy 최소 조건을 만족하지 않아 kernel graph, parity와 p99를 측정하지 못했다. 또한 post-detach display는 lifecycle interpolation이며 contact와 containment physics가 아니다.

  1. 지원 driver GPU에서 fixed-shape cuRobo V2 producer와 19-slot validator를 구현해 real output/lease를 materialize한다.
  2. 동일 verified full command를 MuJoCo desired-control adapter로 보내고 commanded state와 measured rollout을 별도 trace로 기록한다.
  3. Target GPU 1,000 trial에서 sensor-to-command p99, deadline miss 0, one readback과 HPP-FCL false negative 0을 확인한다.
  4. Hardware가 준비되면 controller one-shot lease, measured feedback, moving-contact timing과 grasp/drop success를 검증한다.

Full-task resident validation, Pre-contact replay boundary, Explicit paired connector를 함께 참고한다.
