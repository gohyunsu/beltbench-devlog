ISSUE-015 · 2026-08-08 · architecture decision

매 frame의 전역 planning이 아니라, offline path compilation과 bounded online update로 전환한다.

현재 reference pipeline은 필터 근거와 fail-closed 동작을 검증하지만 coarse planning과 dense validation에 수백 초가 걸린다. 이를 평균적으로 빠르게 만드는 방식으로는 실시간 목표를 만족할 수 없다. Conveyor task의 제한된 운동을 명시적 runtime 가정으로 만들고, offline path family·online retain/latch/warm-start·replan cutoff·controller authority로 계산을 다시 나눴다.

현재 효력: revision b0c3c56은 production 방향 ADR과 첫 constrained belt-state 계약을 구현한다. 실제 encoder adapter, multi-camera filter, path-family compiler, controller는 아직 없으므로 real-time 또는 hardware-ready 상태가 아니다.
2026-08-09 timing 경계: revision 08ffc9b는 collision-free geometric path, event-preserving time-parameterization, bounded latch/stop, late phase correction을 서로 다른 capability로 확정했다. 현재 구현은 fixed-schedule diagnostic까지이며 production parameterizer는 아직 없다.

확정한 hybrid 구조

  1. Offline compiler: grasp, yaw·lateral·speed·intercept cell, IK branch, path family, latch region, uncertainty-inflated path tube, hand-close timing, lift/drop/stop segment를 계산한다.
  2. Startup: 모든 source를 한 번 검증하고 fixed-size atlas·path·collision field를 resident로 올리며 backend capability와 clock synchronization을 확인한다.
  3. Online perception: expensive 6D method는 acquisition/recovery에 사용하고, multi-camera planar filter와 encoder가 `(x,y,yaw)`·belt phase·velocity·covariance·residual을 갱신한다.
  4. Online planner: 현재 path retain, precompiled path latch, 한 번의 fixed-budget warm start 순서로만 갱신한다. Dynamic retry나 unbounded global search는 없다.
  5. Commit/cutoff: cutoff 전에는 hard gate와 hysteresis를 만족할 때만 path를 바꾼다. Cutoff 후에는 prevalidated belt-direction phase correction만 허용하고 tube를 벗어나면 abort한다.
  6. Controller: command generation, measured feedback, jerk/velocity limits, watchdog, stop, hand trigger를 별도 authority에서 확인한다.
  7. Evidence: observation·prediction·planning·commit·setpoint·measured state·contact를 append-only timestamp event로 기록해 Viser가 실제 상대 시간에 재생한다.

Arm과 hand는 독립적으로 retime하지 않는다. close_start, contact, attach, release-open start, detach와 cutoff는 공동 semantic window이며 deadline 안에 valid schedule이 없으면 reject한다. Attach 전에는 hand와 물체의 상대 pose drift뿐 아니라 상대 선속도와 각속도를 검사해야 한다. Viser의 conveyor → attached 상태 전환은 이 물리 조건의 증거가 아니다.

R1: constrained belt state 구현

ConveyorMotionState는 encoder-derived longitudinal position·velocity·acceleration, 3×3 covariance, calibration ID, sequence, monotonic timestamp를 갖는다. FusedPlanarObjectTrack은 object/stable pose identity, belt `(x,y,yaw)`, covariance, observed longitudinal/lateral velocity, yaw rate, contributing camera IDs와 camera disagreement를 갖는다.

ConveyorTrackingPolicy는 camera 수, track/state age, timestamp skew, covariance, camera disagreement, belt-speed residual, lateral slip, yaw rate, speed·acceleration, prediction horizon을 hard gate로 정의한다. predict_fused_planar_conveyor_motion은 gate를 모두 통과한 두 state를 timestamp 정렬하고 encoder velocity·acceleration에서 1D displacement와 covariance를 analytic하게 전파한다. Yaw와 lateral pose는 유지된다.

기존 predict_constant_orientation_belt_motion과 --belt-speed-m-s 스크립트는 atlas·scenario용 offline utility로 명시했다. Runtime에서 새 계약을 우회하는 fallback으로 사용하지 않는다.

검증 결과

Contract round-trip, boolean-as-generation 거부, camera 수·불일치, lateral slip, yaw rate, speed residual, calibration status, timestamp skew·staleness, deterministic acceleration propagation, constant yaw/lateral pose, covariance growth, no general-motion fallback, encoder reorder/mutation을 검사했다.

Planning 환경에서는 OpenCV 전용 세 module을 제외한 실제 test 249개가 통과했고, calibration 환경의 해당 14개도 통과해 총 263개를 확인했다. 관련 집중 test 34개와 전체 compileall, diff whitespace 검사도 통과했다. 관리형 서버 planning 환경에서 R1과 기존 runtime 관련 28개를 재실행해 모두 통과했다. GPU latency나 실제 camera/encoder throughput을 측정한 결과는 아니다.

남은 위험과 구현 순서

  • R1 publisher인 실제 encoder adapter와 multi-camera fuser가 없다. 현재는 contract와 deterministic predictor만 있다.
  • Path-family deployment bundle, latch region, correction tube, replan cutoff와 hysteresis가 아직 없다.
  • 현재 sequential RollingInterceptPlanner는 diagnostic reference 이름과 역할을 더 명확히 분리해야 한다.
  • Single-generation trace를 observation arrival·supersession·command·feedback event session으로 확장해야 actual-time replay가 된다.
  • Accelerated backend는 reference false-accept 0 조건과 p50/p95/p99·worst-case·deadline miss를 측정해야 한다.
  • Hardware 전에는 closed-loop simulation에서 jitter, bias, speed change, frame loss, saturation, abort를 검증해야 한다.

다음 구현은 append-only runtime event session과 exact timestamp Viser replay다. 동시에 path-family contract를 설계하되, ideal animation을 실제 execution처럼 보이게 만드는 방식은 사용하지 않는다.

단일-generation runtime trace와 grasp filter 감사가 이 ADR의 선행 기록이다.
