ISSUE-065 · 2026-08-12 · source-bound moving-pick prefix

정지 pre-stage와 움직이는 접촉 궤적의 경계를 실제 데이터로 다시 고정한다.

71개의 display waypoint를 모두 정지점으로 해석한 기존 command를 거부한 뒤, 308-frame nominal source에서 arm derivative를 복원하고 hand closure를 별도로 timing했다. 핵심은 cuRobo를 무조건 궤적 전체에 적용하는 것이 아니라, 현재 endpoint backend는 정지 pre-stage에만 사용하고 비영 contact derivative를 보존하는 moving prefix는 독립 gate로 검증하는 것이다.

현재 결과: source 683c5ee에서 Pepsi-light upside-down, xArm6, Inspire-left, paired CAD connector의 2.0초 v6 prefix를 만들었다. Analytic joint dynamics, first-contact pose/twist, contact-to-attach chase가 통과했다. RTX 3090의 5,882-sphere cuRobo 모델에서 200 Hz arm-hand 403-state static workcell screening은 전부 clear였고 p99는 61.839 ms였다. 60 FPS actual-time Viser는 실제 mesh를 121 frame으로 자동 반복한다. Moving target/attached object continuous collision, suffix, MuJoCo, controller와 hardware 권한은 아직 없다.

문제 정의

입력 grasp는 AutoDex에서 물리 검증된 exact object·stable pose·hand 항목이 있으면 우선 재사용하고, 없으면 BODex 같은 generator 결과를 같은 독립 filter로 통과시킨다. 이 grasp는 object-relative hand pose와 closure command를 제공할 뿐, conveyor에서 움직이는 물체의 접촉 시간, arm twist, collision, stop 또는 controller command를 제공하지 않는다.

이번 단계의 목적은 완전한 pick-and-drop demo가 아니라 다음 producer boundary를 실제 artifact로 닫는 것이었다.

  1. 별도 planner가 arm을 첫 commit configuration에 정지 pre-stage한다.
  2. Actual-time prefix가 approach, chase, close, first contact, attach를 수행한다.
  3. Contact와 attach에서 arm 속도를 0으로 만들지 않고 belt translation을 추종한다.
  4. Hand는 arm display frame을 따라가지 않고 자체 velocity·acceleration·jerk limit으로 닫힌다.
  5. 동일한 exact command를 collision query와 Viser가 소비한다.

cuRobo 방향 수정

World-only endpoint backend에 v3 moving prefix를 seed로 주면 10/10 solve와 p99 29.884 ms가 나왔다. 그러나 latch velocity error가 0.161626 rad/s였고 joint 3·6 seed deviation이 0.05 rad trust tube를 넘었으며 sampled jerk ratio가 1.2869였다. 즉 solver success와 짧은 latency는 moving grasp success가 아니다.

현재 합리적인 역할 분리는 다음과 같다. cuRobo endpoint optimizer는 measured state에서 zero-derivative commit configuration까지의 pre-stage에 사용한다. Moving prefix는 source-bound q/qd/qdd를 유지한다. 향후 cuRobo custom trajectory optimization을 넣으려면 contact/attach의 intermediate pose, twist와 derivative를 hard constraint로 보존하는 별도 backend와 acceptance evidence가 먼저 필요하다.

Collision에는 cuRobo를 사용했다. Arm과 움직이는 hand를 합친 exact request를 최대 5 ms 간격으로 sampling하고 실제 5,882-sphere assembly와 5 mm static workcell clearance로 검사했다. 처음에는 403개 상태를 51번 호출하는 30-trial 구성이 1분 이상 걸렸다. horizon=128로 크게 묶는 시도도 이 고해상도 모델에서 더 느렸다. Holdout에서 이미 검증한 batch=8, horizon=1 형상으로 복귀하자 resident steady-state p99 61.839 ms가 나왔다. 약 2분의 model load는 startup에만 허용하고 hot path에서는 process-resident checker를 재사용해야 한다.

검증과 남은 단절

  • 최종 GPU planning suite: Ran 866 tests in 21.662s, OK (skipped=14). Source-motion rejection을 포함한 targeted test도 8/8 통과했다.
  • Viser startup은 pepsi_light/upside_down, xarm.urdf, inspire_left.urdf, paired_assembly_meshes를 실제로 출력했다.
  • 현재 collision report는 sampled sphere self/static-world/joint-bound만 포함한다. Moving target contact mask, attached object, swept continuous collision과 abort는 포함하지 않는다.
  • Attach-to-bin release suffix가 없으므로 넉넉한 상자에 떨어뜨리는 전체 animation과 MuJoCo rollout은 아직 production command가 아니다.
  • Perception, prediction, selection, all collision passes, lease와 cancellation을 한 trace에서 측정하지 않아 end-to-end real-time claim은 하지 않는다.

다음 순서

  1. Pre-contact moving target을 time-indexed obstacle로 넣고 first contact에서 허용 hand geometry만 mask하는 resident cuRobo pass를 구현한다.
  2. Attach 이후 object sphere attachment, bin-above transfer, stationary open, ballistic detach, retreat/home suffix와 stop/abort를 exact tensor로 만든다.
  3. 완성된 동일 tensor를 MuJoCo에 실행해 measured state/contact를 기록하고 measured Viser replay로 전환한다.
  4. Nominal 이후 yaw, belt speed, timing, lateral/longitudinal correction cell을 같은 gate로 재생성한다.
  5. Hardware가 가능해지면 calibration, perception latency, controller/hand timing과 slow-belt moving reliability를 측정한다.
