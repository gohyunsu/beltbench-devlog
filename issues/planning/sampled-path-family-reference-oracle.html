ISSUE-025 · 2026-08-09 · sampled path oracle

AutoDex의 정적 grasp filter를 moving path hard gate로 확장하되, 실제 sampled 계산과 원본 경로를 분리하지 않는다.

이전 단계는 path-family compiler가 요구할 metric 계약을 정의했지만 실제 값을 계산하는 reference producer는 없었다. 기존 301-frame playback validator도 robot collision을 하나의 최소 거리로 합치고 dynamics, singularity, correction grid와 cutoff stop을 제공하지 않았다. AutoDex 선택 기준과 BeltBench 채택 기준을 다시 대조한 뒤, arm·hand 이름에 독립적인 task/stop path 계약과 13-metric sampled oracle, transitive source verification을 구현했다.

현재 효력: source commit f22a6a2가 reference oracle을 구현했다. 1d36021은 current playback을 label만 바꾼 sampled task와 discrete splice를 보존하는 cutoff stop producer를 추가했고, 9466532와 81e9c8d가 exact manifest reference, 재현 verifier와 direct-script 회귀를 결속했다. 결과는 계속 offline sampled_reference이고 실행 차단 상태다.

AutoDex 선택 기준 재검토

감사 기준은 계속 willi19/autodex-code:main의 5ada1c077f60bae9af6f27b07619218f58422e50이다. gohyunsu/autodex-code:main의 사이트 history나 저장소 이름을 알고리즘 근거로 사용하지 않았다.

BeltBench가 실제 채택한 filtering 순서

  1. Source, object, stable pose, hand, task와 command identity가 맞는 proposal만 import한다.
  2. Arm-independent intrinsic 단계에서 named contact 수·침투, non-contact/self/support clearance, signed force·moment wrench, approach·closure·release를 hard-gate한다.
  3. Deployment 단계에서 선택한 arm·hand·connector·workcell의 IK, self, arm/hand assembly, workcell, non-intentional object clearance와 joint/singularity margin을 검사한다.
  4. Atlas는 측정 yaw uncertainty와 horizon을 지지하는 모든 cell의 grasp 교집합만 bounded prefilter로 반환한다.
  5. Path-family는 complete phase, fixed hand/contact schedule, named dynamics, correction cell, task path와 cutoff stop path를 검사한다.
  6. Runtime은 fresh track·encoder·robot state, support, correction, cutoff와 deadline을 다시 검사한다. 모든 hard gate 뒤에만 normalized slack의 lexicographic maximin을 적용한다.
  7. Moving hardware reliability, controller capability와 watchdog가 없으므로 physical commit은 계속 별도 미구현 경계다.

구현한 방법

  • RobotMotionLimitProfile은 arm과 end effector의 임의 named joint에 SI position unit, lower/upper position, maximum velocity·acceleration·jerk를 선언한다. Stop duration, splice velocity·acceleration 오차, terminal velocity·acceleration tolerance와 draft/manufacturer/measured authority도 source와 함께 기록한다.
  • SampledRobotObjectPath는 특정 joint 수나 xArm/Inspire 이름 없이 task와 stop을 모두 표현한다. Strict time, 고정 joint order와 object-state transition을 검사하며 stop은 pickup을 강제하지 않는다.
  • Task playback adapter는 명시적으로 arm, end effector와 task mode를 받아 기존 playback을 generic task path로 변환한다. Emergency stop은 별도 path로 생성해야 한다.
  • Correction design은 nominal 한 cell과 longitudinal, timing, lateral, yaw, belt-speed residual 5축 각각의 양·음 boundary를 요구한다. 최소 11개 cell이며 full Cartesian grid나 continuous tube라고 부르지 않는다.
  • Reference oracle은 raw collision pair를 self, assembly, workcell로 분류하고 robot/object query에서 intended hand contact를 제외한 non-intentional clearance를 별도로 계산한다. Exact workcell obstacle tuple은 checker 내부에서 찾지 않고 호출자가 명시적으로 전달한다.
  • 비균일 sample time에서 joint velocity, acceleration, jerk를 계산하고 각 named limit의 residual ratio를 취한다. Arm Jacobian은 joint range와 characteristic length로 단위를 맞춘 최소 singular value를 계산한다.
  • Stop path는 replan cutoff의 exact robot/object state에서 시작하고 task derivative history와 splice continuity, 최대 정지 시간, terminal velocity·acceleration, 계속 이동하는 conveyor object, 충돌과 dynamics를 모두 검사한다.
  • 13개 sampled metric은 policy의 observed margin, required margin, unit와 capability를 그대로 보존한다. correction_support와 stop_path는 cell 통과 비율이며 일반적으로 1.0 hard gate다.

Source binding과 schema 변경

  • Bundle source에는 arm_collision_semantics, assembly_collision_semantics, object_interaction_semantics, motion_limits를 추가했다. Bundle schema는 5.0이다.
  • Validation report schema는 3.0이다. Validator source뿐 아니라 assessment reference/hash, exact sampled plan hash와 complete deployment-context hash를 보존한다.
  • 각 assessment cell은 write-once task/stop path reference와 실제 serialized file SHA-256을 보존한다. In-memory path와 declared digest가 다르면 oracle 실행 전 거부한다.
  • Startup verifier는 report와 assessment를 다시 hash한 뒤 22개 transitive path를 모두 reload한다. Cell ID·좌표·reference uniqueness, 11개 필수 axis cell, frame count, task/stop role, arm·hand·object·stable pose·task identity, motion-limit profile ID·authority와 calibration ID를 bundle과 다시 비교한다.
  • Compiled family에서 original plan digest를, bundle에서 deployment context digest를 독립적으로 다시 계산한다. Report 파일 hash만 바꿔 다른 assessment를 붙이는 방식은 실패한다.

2026-08-09 실제 Pepsi path 연결

Current schema-2 source를 얻기 위해 nominal yaw의 8개 shortlist 후보를 CPU reference planner로 다시 평가했다. PBS job 115150은 8 search 중 한 후보를 dense refinement했고, bodex-a9b299caeade8d79의 5.0초 intercept가 301-frame full-frame geometry 검사를 통과했다. Coarse search는 160.917초, refinement는 139.468초였다. Verifier는 968개 source를 재검증했고 job은 12분 50초, exit 0으로 끝났다. Protocol, stable pose, calibration과 controller authority가 provisional이므로 report는 diagnostic_selected=true, execution_selected=false다.

Playback은 pepsi_light, upside_down, xarm6, inspire_left와 exact manifest reference를 포함한다. Producer는 global 3.0초의 approach부터 label만 canonical phase로 바꾸고 시간을 0으로 옮겼다. Robot, hand, object pose와 sample time은 수정하지 않았다. Contact 전 global 4.0초, 즉 canonical 1.0초를 cutoff로 사용해 별도 stop을 생성했다.

Exact open command 0은 URDF lower bound와 같아 position margin도 0이다. 이는 AutoDex/BeltBench grasp geometry나 301-frame collision 통과로 보상할 수 없는 독립 trajectory 실패다.

반대로 cutoff stop은 task의 discrete velocity·acceleration을 exact splice하고 마지막 세 joint sample을 같게 만들어 transition failure가 없었다. 그러나 stop limit은 draft이고 collision·continuous segment·controller 검증이 아직 없으므로 실행 가능한 brake라는 뜻은 아니다. 현재 task는 명백히 path-family hard gate를 통과하지 못하며, template 시간을 늘려 숫자만 맞추는 대신 controller-sourced limit을 입력으로 받는 time-parameterization backend가 approach, closure, release와 return을 함께 다시 생성해야 한다.

냉정한 현재 평가

이번 구현은 임의 metric을 입력하는 compiler 앞에 실제 sampled 계산과 transitive path provenance를 세웠다는 점에서 필요하다. 그러나 11개 axis cell은 correction corner interaction을 놓칠 수 있고 frame sampling 사이 충돌을 보장하지 않는다. Finite difference는 controller가 실제 실행할 interpolation과 동일하다는 보장도 없다. Draft motion limit은 제조사 또는 측정 controller limit으로 교체되기 전 승인값이 아니다.

또한 이 oracle은 offline correctness authority라서 interception deadline 안에서 실행할 대상이 아니다. Real-time 경로는 verified resident atlas/path family, bounded retain/latch와 최대 한 번의 warm start를 사용해야 한다. 가속 collision/dynamics backend는 이 oracle과 zero false-accept 비교를 통과한 뒤에만 online validator 후보가 될 수 있다.

다음 구현

  1. Current sampled producer의 portfolio report와 atlas-query ancestry를 명시적으로 결속한다. Playback ID 문자열에서 grasp를 추론하지 않는다.
  2. Controller-sourced xArm·Inspire limit과 state를 받는 time-parameterization backend로 release 한-frame jump를 제거한다. Draft limit을 느슨하게 바꿔 현재 path를 통과시키지 않는다.
  3. Nominal과 axis boundary 이후 correction corner를 adaptive하게 추가하고, failure surface 근처를 우선 탐색한다. 그래도 sampled 결과는 continuous로 승격하지 않는다.
  4. Pinocchio/HPP-FCL reference 결과와 GPU collision backend의 pair별 distance·gate decision을 비교한다. False accept가 하나라도 있으면 online 후보에서 제외한다.
  5. Continuous segment collision과 controller interpolation/dynamics를 검증하는 별도 backend를 구현하고 report scope를 continuous_path_tube로 유지한다.
  6. Measured calibration, connector metrology, supervised static/moving trials와 controller watchdog가 준비될 때까지 execution authority를 추가하지 않는다.

Metric/compiler 계약, AutoDex selection authority 감사, 실시간 아키텍처 결정이 각각 앞 단계 근거를 설명한다.
