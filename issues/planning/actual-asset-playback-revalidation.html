ISSUE-036 · 2026-08-10 · actual mesh diagnostic

재생 가능한 animation이 유효한 grasp path라는 뜻은 아니다.

xArm6, Inspire Left, paired connector CAD, upside-down Pepsi Light, 수직 배치 conveyor, robot table과 drop bin을 실제 manifest로 로드했다. 그러나 현행 collision/contact contract로 경로를 다시 검사하자 후보는 명확히 탈락했다.

발견한 문제

기존 대표 파일 local/planning/xarm6-inspire-left-pepsi-light-bin-drop-schema2-runtime.json은 301 frame, 10초 animation이지만 object state가 conveyor → attached로 직접 바뀐다. First contact와 retention을 분리한 현행 schema는 conveyor → contacting → attached를 요구하므로 이 파일은 이제 loader 단계에서 거부된다.

옛 validation report의 valid=true는 당시의 더 약한 state semantics에서 계산된 결과다. 현재 source와 contract에 재결속하지 않고 이 결정을 가져오면 안 된다.

재생성 절차

현행 generate_pick_playback.py와 실제 robot/object/workcell manifest를 사용해 새 append-only local artifact를 만들었다.

  • Playback: local/planning/xarm6-inspire-left-pepsi-light-bin-drop-v4-playback.json, SHA-256 c92f54514a3e96cfb51c47847ce65c085b35831dc647b803ecaa922a17357540
  • Validation: local/planning/xarm6-inspire-left-pepsi-light-bin-drop-v4-validation.json, SHA-256 dc5637bbef57967d1aacf5ae18c09b4c8122b399a728c337bf4ea0497c2a3907
  • Object state: 4.8초 first contact부터 5.0초 attach 전까지 contacting
  • Viewer scene: arm=xarm.urdf, hand=inspire_left.urdf, connector=paired_mount_meshes, object=pepsi_light/upside_down

검증 결과

Full-frame mesh/contact/support 검사는 약 238초가 걸렸고 301 frame 중 163 frame이 invalid였다. 첫 실패는 4.6초 closing에서 시작해 10초 home까지 이어진다.

  • 비의도 hand-object 관통: hand base, little/ring link가 Pepsi collision mesh와 겹친다.
  • Attached contact 부족: 허용된 hand geometry의 접촉 수가 retention 요건에 미달한다.
  • Hand-workcell collision: transfer/retreat 구간에서 여러 distal finger link가 conveyor deck clearance를 위반한다.
  • Drop containment 실패: release 후 object가 지정된 drop-bin-floor support/containment 조건을 만족하지 않는다.
  • Invalid phase 분포: grasp 30, retreat 30, return-home 30, drop 23, lift 21, transfer 15, close 12, release 1, home 1 frame.

과거 v4 robust intercept search도 selected_candidate_id=null이며, nominal environment margin보다 pose-uncertainty inflation이 커 collision slack이 음수이고 measured latency evidence도 없었다. 이번 재검증은 그 fail-closed 결론과 일치한다.

구현한 방어선

구현 revision은 beltbench@ad66960이다.

  1. verify_playback_validation_report가 report의 exact label set과 playback, robot/object manifest, arm/assembly collision semantics, object interaction semantics의 SHA-256을 모두 다시 계산한다.
  2. Report frame의 timestamp, phase와 object state가 playback과 하나라도 다르면 viewer 진입 전에 거부한다.
  3. Viser는 현재 frame의 validation을 pass 또는 구체적인 FAIL 원인으로 표시한다.
  4. Animation은 1x auto-loop와 actual meshes를 유지하지만 startup log에 validation_report=False를 명시한다.

검증과 시행착오

  • Playback·runtime visualization 관련 24 tests가 1.273초에 통과했다.
  • Python 3.10 compile과 변경 파일 git diff --check를 통과했다.
  • 8초/25초 buffered smoke는 Viser socket만 보이고 scene completion log가 flush되지 않았다. python -u로 다시 실행해 actual assets와 paired connector 로드 및 validation_report=False를 확인했다.

다음 방법론

현재 후보를 임의로 clearance tolerance를 낮추거나 intended-contact 목록을 넓혀 살리는 것은 잘못이다. 먼저 collision-free grasp 후보를 다시 선택하거나 생성하고, object-relative pregrasp/contact/retention pose와 hand command를 함께 고정한 뒤, belt 접촉을 유지하는 closing chase, lift, bin transfer, release와 retreat 전체를 재계획해야 한다.

Full-mesh 301-frame 검증은 수 분이 걸리므로 offline path compilation에 둔다. Runtime은 startup-verified path family, correction tube와 최신 state의 bounded maximin 선택만 수행해야 한다. Continuous collision backend, measured calibration/latency, connector metrology와 hardware reliability가 없으므로 실제 실행 권한은 계속 차단한다.

현재 상태: 지정한 object·arm·hand·connector·conveyor·table·bin은 실제 mesh로 반복 재생된다. 그러나 이 특정 grasp/path는 검증 실패이며, 좋은 시각화 예시일 뿐 방법론의 accepted candidate가 아니다.
