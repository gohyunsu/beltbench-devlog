ISSUE-013 · 2026-08-08 · fail-closed rolling planner 구현

AutoDex 필터는 후보 근거로 감사하고, 움직이는 물체의 실행 가능성은 최신 상태에서 다시 판정한다.

정적 scene에서 성공한 grasp와 conveyor 위 움직이는 물체를 지금 잡을 수 있는 trajectory는 같은 판정이 아니다. AutoDex의 생성·simulation·runtime 필터를 실제 source revision에서 다시 확인하고, BeltBench에서는 offline grasp 자격, deployment context, exact rolling planning, controller commit을 서로 다른 권한 경계로 분리했다.

현재 효력: revision f39aad1의 rolling planner는 atlas lookup, bounded exact search, 최신 robot state, deadline, dense playback validation을 연결하지만 출력은 diagnostic_only다. 현재 CPU Pinocchio/HPP-FCL backend와 full-mesh validator는 실시간이 아니며 robot command를 보낼 수 없다.

감사 기준과 repository 혼동

알고리즘 source는 willi19/autodex-code의 2026-08-08 원격 main, commit 5ada1c로 고정했다. willi19/AutoDex는 project site다. 로컬의 gohyunsu/autodex-code checkout도 site fork였고, 별도 nested checkout 52add68은 현재 원격 HEAD가 아니었다. 따라서 working tree 이름을 신뢰하지 않고 git ls-remote로 HEAD를 확인한 뒤 저장된 upstream/main object를 git show로 감사했다.

감사한 AutoDex source revision과 BeltBench 구현 commit을 각각 기준점으로 사용한다.

Inspire hand에서는 backward heuristic 자체가 우회된다. 이는 그 수치가 일반적인 grasp quality 기준이 아니라 특정 robot·hand 배치 heuristic임을 보여 준다. 또한 cross-pose compiler는 {order: ...} dictionary를 쓰지만 extract_selected.py는 legacy list를 slice하므로, 감사 revision의 cross-pose → selected-100 경로에는 schema 불일치가 있다. 따라서 selected_100을 품질 top-100이나 확실히 재현된 moving-pick 후보로 취급하지 않는다.

BeltBench가 채택한 계층

  1. Proposal: provider threshold와 source checksum을 보존하지만 권한은 없다.
  2. Intrinsic: exact identity, named contact, contact count, penetration, non-contact/self/support clearance, signed force·moment task wrench, approach·closure·release capability를 arm과 독립적으로 검사한다.
  3. Deployment: arm·hand·connector·workcell 조합의 IK, self/cross/environment/object collision, joint·singularity margin을 yaw×horizon context별로 검사한다.
  4. Atlas: 모든 hard gate 뒤 context coverage와 maximin slack으로 bounded resident 후보를 만든다. 측정 yaw uncertainty가 지지하는 cell 교집합이 비면 거부한다.
  5. Rolling exact planning: 최신 planar pose prediction과 timestamped arm·hand state에서 candidate-time pair만 다시 계획한다.
  6. Dense validation: bounded prefix의 저장 playback을 독립 검사한다. 유효한 후보가 없으면 playback을 내보내지 않는다.
  7. Controller commit: 최신 generation, controller limits, measured latency, hardware scope를 다시 확인해야 한다. 이 단계는 아직 구현하지 않았다.

Runtime workload 계약

예제 policy는 candidate-time pair 8개, distinct grasp 4개, dense refinement 2개, robot state age 100 ms로 작업량을 제한한다. 긴 horizon의 rank 1이 짧은 horizon 전체를 밀어내지 않도록 horizon 사이를 round-robin한다. 한 grasp는 atlas가 실제 지원한 horizon에 대해서만 exact planning하며, unsupported yaw·큰 uncertainty·빈 교집합에서 nominal yaw나 stale shortlist를 사용하지 않는다.

이 수치는 안전 인증이나 latency 측정값이 아니다. Atlas lookup p95 약 1.8 ms만 측정됐고 exact CPU planning과 dense reference validation은 수 분 단위다. Production에서는 GPU batched IK/FK/Jacobian, conservative SDF와 bounded continuous checker를 같은 contract 뒤에 구현하고 p50/p95/p99·missed deadline·cancellation을 recorded replay로 측정해야 한다.

검증 결과

핵심 runtime, trajectory, intercept contract, portfolio 집중 test 22개가 통과했다. 전체 planning discovery는 실제 test 237개가 통과했고 OpenCV가 없는 planning 환경에서 세 module만 import되지 않았다. 같은 세 module을 calibration 환경에서 실행한 14개가 모두 통과해 총 251개 실제 test를 확인했다. 전체 compileall과 git diff --check도 통과했다.

Negative test는 unsupported yaw에서 backend를 부르지 않는지, stale robot state, in-flight supersession, 이전 generation 재계획 금지, post-planning deadline miss, dense validation 전부 실패, 같은 generation의 payload 변경, measured robot state binding, backend의 잘못된 identity·horizon을 검사한다.

남은 위험과 다음 단계

  • Reference continuation IK는 시작 endpoint와 sampled target을 검사하지만 연속 collision-free motion, velocity·acceleration·jerk, controller tracking을 증명하지 않는다.
  • CPU full-mesh validator는 online backend가 아니다. 동일 contract의 accelerated checker와 reference agreement benchmark가 필요하다.
  • EvidenceRecorder, recorded observation/replanning replay, 실제 시간축 Viser overlay는 아직 rolling decision과 연결되지 않았다.
  • Controller commit coordinator, abort/stop semantics, xArm·Inspire feedback adapter는 hardware 복귀 후 별도 구현·검증해야 한다.
  • Pepsi upside-down stable pose, intrinsic protocol, calibration, connector metrology, latency와 moving-pick hardware scope가 provisional이므로 실행은 계속 차단한다.

다음 구현은 recorded observation stream을 동일 rolling contract에 넣고, generation·atlas support·exact candidate·rejection·selected diagnostic을 실제 시간으로 Viser에 반복 재생하는 evidence path다. 그 뒤 accelerated backend를 교체해 reference 결과와 차이를 측정하며, planning core를 다시 설계하지 않고 hardware adapter와 commit gate를 추가한다.

Full-yaw atlas 기록과 intrinsic grasp 평가 기록이 이 구현의 선행 evidence다.
