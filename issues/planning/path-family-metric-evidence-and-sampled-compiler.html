ISSUE-024 · 2026-08-09 · reproducible path evidence

AutoDex의 grasp filter를 제안 근거와 실행 근거로 분리하고, path margin을 재현 가능한 계약으로 만든다.

AutoDex의 정적 grasp 선택 기준을 다시 읽고 BeltBench가 실제로 채택한 기준을 코드까지 대조했다. 정규화 점수만 남기면 어떤 단위와 임계값으로 계산했는지 재현할 수 없고, 기존 301-frame playback을 continuous path 증거로 오인할 위험이 있었다. Policy가 요구한 실제 margin·단위·검증 capability를 보고서와 warm start에 결속하고, 명시적 sampled validator 결과만 조립하는 fail-closed compiler를 구현했다.

현재 효력: source commit 2abb840이 구현한다. Sampled compiler의 출력은 항상 execution_blocked이며 production runtime coordinator가 거부한다. 실제 continuous compiler·validator와 controller commit은 아직 없다.

AutoDex에서 확인한 선택 기준

감사 기준은 willi19/autodex-code:main의 5ada1c0이다. 사이트 저장소나 관련 없는 fork history를 구현 근거로 사용하지 않았다.

BeltBench가 채택한 기준

  1. Object, stable tabletop pose, hand, task, source identity가 정확히 일치하는 proposal만 받는다.
  2. Named intended contact, 최소 contact 수, 제한된 penetration, non-contact·self·support clearance, signed force·moment task wrench, approach·closure·release path를 intrinsic hard gate로 검사한다.
  3. 선택한 arm·hand·connector·workcell에서 IK, assembly·workcell·object clearance, joint position margin과 singularity margin을 deployment hard gate로 검사한다.
  4. 측정 yaw uncertainty와 intercept horizon이 걸치는 모든 atlas cell에서 공통으로 살아남은 grasp만 반환한다. 빈 교집합은 fallback 없이 unsupported다.
  5. Compiled path는 complete phase, contact와 hand timing, latch, correction support, reusable/stop path, collision·dynamics·timing metric 전체를 요구한다.
  6. Runtime은 fresh track·encoder·named robot position/velocity/acceleration, support, correction, cutoff, deadline와 latest generation을 다시 검사한다.
  7. 모든 hard gate를 통과한 뒤에만 전체 normalized-slack vector의 lexicographic maximin으로 비교한다. Provider order, first success, weighted sum, 가장 먼 intercept는 선택 규칙이 아니다.
  8. Physical commit은 별도 moving-pick reliability lower bound, controller capability, watchdog와 stop authority가 생길 때까지 구현하지 않는다.

구현한 해결

  • PathValidationMetricRequirement은 metric ID, 양의 required margin과 고정 unit를 policy에 선언한다. Policy schema는 5.0이다.
  • PathValidationMetricEvidence는 observed margin, required margin, unit, 해당 metric을 검증한 capability와 파생 normalized slack을 함께 저장한다. Report schema는 2.0이다.
  • Startup verifier는 보고서 임계값이 deployment policy와 정확히 같은지, metric과 capability가 scope별 exact set인지, compact minima가 raw metric에서 재현되는지 검사한다. Bundle schema는 4.0이다.
  • Warm-start admission과 independent validation schema를 2.0으로 올리고, admission이 continuous policy의 13개 metric 요구를 그대로 전달하게 했다. 결과의 threshold·unit가 하나라도 다르면 acceptance가 실패한다.
  • SampledPathFamilyPlan과 SampledPathFamilyValidationResult를 분리하고 plan 전체 SHA-256과 deployment-context SHA-256을 validator 결과에 결속했다.
  • compile_sampled_path_family_bundle은 sampled capability와 metric 전체, policy threshold, artifact, latch, correction, atlas grasp/context 상속이 모두 있을 때만 report와 bundle을 조립한다.
  • Sampled report는 segment 수 0과 sampled_collision을 유지한다. swept_collision으로 relabel하지 않으며 runtime coordinator는 sampled bundle을 명시적으로 거부한다.

기존 301-frame 결과를 자동 변환하지 않은 이유

현재 playback report는 reference animation의 frame별 진단에는 유효하지만 assembly·self·workcell collision을 독립 항목으로 분리하지 않고, non-intentional object clearance, joint acceleration·jerk, singularity, correction support, stop path와 timing margin 전체를 제공하지 않는다. 없는 값을 visual clearance나 하나의 generic collision 값에서 추론하면 검증 근거를 새로 만들어내는 셈이다. 따라서 compiler는 실제 sampled validator가 13개 sampled metric과 capability를 명시적으로 제출할 때만 동작하며, 기존 playback은 그대로 historical diagnostic으로 남긴다.

Negative test와 검증 결과

  • Continuous policy를 sampled compiler에 넣거나 policy threshold를 낮추면 거부한다.
  • Capability 하나를 빼거나 required metric이 threshold 아래면 거부한다.
  • Atlas에 없는 grasp, 변경된 plan SHA-256, 다른 workcell의 context SHA-256을 거부한다.
  • Sampled bundle은 report byte SHA-256과 일치하지만 production coordinator 생성은 실패한다.
  • Local path-family 집중 test 65개가 16.833초에 통과했다.
  • Local planning discovery는 374개 중 371개가 통과했고, planning 환경에 cv2가 없어 calibration 관련 module import 3건만 실패했다. 별도 calibration 환경에서 해당 module의 실제 test 14개가 모두 통과해 총 실제 통과 수는 385개다.
  • junjinyong server를 source commit 2abb840으로 fast-forward했다. Path-family 65개가 13.811초에 통과했고 전체 374개 중 371개가 통과했으며, 같은 cv2 import 3건만 남았다.
  • 서버의 기존 untracked BODex build와 native extension은 변경하지 않았다.

남은 한계와 다음 구현

  1. 현재 compiler는 real planner나 validator backend가 아니라 명시적 evidence를 fail-closed하게 조립하는 경계다. 실제 sampled validator부터 13개 metric을 계산하도록 구현한다.
  2. Reference sampled oracle과 대조할 continuous swept-collision·correction-tube validator를 선택하고 zero false-accept 기준의 backend 검증을 만든다.
  3. Complete phase trajectory와 latch/correction/stop artifact를 생성하는 arm·hand-neutral continuous compiler를 구현한다. Draft policy 수치는 metrology와 controller spec 없이 승인값으로 사용하지 않는다.
  4. 가속 backend는 offline/reference 결과와 exact gate decision을 비교한 뒤에만 채택한다. Online loop에는 resident atlas/path lookup, bounded retain/latch와 최대 한 번의 warm start만 둔다.
  5. Controller simulation, current calibration, connector metrology와 physical moving-pick reliability가 생기기 전에는 command authority를 추가하지 않는다.

AutoDex grasp authority 감사, typed validation report 경계, production-shaped runtime harness가 각각 앞 단계의 근거와 실행 한계를 설명한다.
