ISSUE-085 · 2026-08-24 · planar yaw backend promotion architecture

검증되지 않은 PnP를 fallback으로 남기지 않고, task-constrained yaw backend를 단계적으로 교체한다.

두 camera PnP temporal fusion 1/12와 세 camera 0/12 실패 뒤에도 retry나 camera 추가를 반복하지 않았다. FoundPose texture correspondence와 주어진 stable pose·belt plane만 사용해 x/y/yaw를 푸는 경로를 구현하고, runtime에 바로 덧붙이기 전에 saved development, holdout, shared-memory worker parity, live D1 authority를 순서대로 통과하도록 승격 구조를 고정했다. 실제 runtime worker가 아직 PnP candidate type에 결합돼 있다는 구조적 결함도 명시했다.

현재 판정: ea5e60c에서 역할·deadline·GPU/CPU 배치·교체 순서를 ADR로 고정했다. Offline correspondence solver와 source-closed runner는 d37522d까지 로컬 40/40을 통과했지만 RTX saved campaign, compact worker parity와 live sensor run은 없다. 따라서 기존 PnP runtime도 새 planar backend도 pose authority가 아니며 새 causal 영상도 생성하지 않는다.

냉정한 구조 평가

현재 상태문제결정
Live worker가 FoundPoseViewCandidateSet을 JSON으로 반환Core가 unconstrained PnP와 method-specific type에 결합돼 새 solver가 통과해도 설정만으로 교체할 수 없다.Qualification 뒤 compact provider-neutral yaw assessment로 parent contract를 교체하고 PnP runtime route를 제거한다. 두 결과를 허용하는 silent union/fallback은 만들지 않는다.
Offline runner가 correspondence 전체를 report에 보존재현 evidence에는 유용하지만 live pipe로 보내면 serialization·allocation·latency 경계가 늘어난다.Runtime child가 GPU correspondence와 bounded 3-DOF solve를 끝낸 뒤 yaw/covariance/quality/timing만 반환한다.
작은 3-DOF solve가 CPU SciPy모든 모듈을 GPU로 옮기면 transfer·synchronization이 오히려 커질 수 있다.RTX에서 provider와 solver 시간을 분리 계측한다. CPU solver가 100 ms budget의 실질 병목일 때만 CUDA 이전을 검토한다.
RGB solver가 x/y도 계산Pepsi처럼 거의 원통형인 물체에서 RGB fit translation을 최종 위치로 쓰면 PnP depth 오류를 다른 이름으로 반복할 수 있다.RGB x/y는 diagnostic seed다. Track admission 위치는 independent depth/CAD 두 view와 encoder consistency gate가 소유한다.
GoTrack을 매 frame 사용 가능감사된 RTX 3090 4-camera 158 ms/frame도 현재 15 Hz, single-GPU 목표와 맞지 않는다.기본 steady state는 15 Hz CAD correction+60 Hz encoder prediction이다. GoTrack은 원 cadence accuracy/latency/contention holdout에서 이를 이길 때만 교체 후보가 된다.

0.9초 acquisition은 camera period가 아니라 upstream event budget이다. 물체를 arm 바로 앞에서 시작해 이 시간을 숨기면 안 된다. Camera age, yaw, CAD, decision, cuRobo commit, controller lead와 stop reserve가 path cutoff 전에 끝나는 spatial reserve를 belt coordinate로 증명해야 한다.

승격 순서

  1. 12 yaw의 temporal_index=0 saved development를 unchanged gate로 실행한다.
  2. Policy를 고정한 채 temporal_index=1..4 48-sample holdout을 실행한다.
  3. Long-lived memfd worker에서 같은 bundle의 compact result parity와 serialization deadline을 검증한다.
  4. 영상 없이 actual Isaac RGB-D D1 authority를 실행해 original cadence, spatial reserve와 canonical stage timing을 통과시킨다.
  5. Accepted source를 다시 검증한 별도 presentation run에서 실제 시간 영상을 만든다.
  6. D2 exact command/collision과 D3 articulation/contact lifecycle을 순차 연결한다.

남은 blocker

  • RTX saved development와 holdout 결과가 없다. 정확도·acceptance·GPU/CPU latency는 미확정이다.
  • Provider-neutral compact runtime result와 worker parity는 설계만 고정됐고 구현 전이다.
  • Yaw/context별 resident path family가 아직 한 nominal command를 대체하지 못했다.
  • Live D1 spatial reserve, D2 resident cuRobo lifecycle kernel, D3 measured contact/release가 없다.
  • Physical camera/conveyor/robot calibration, controller stop budget과 hardware validation은 별도 미완료다.
