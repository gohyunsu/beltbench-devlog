Reference animation과 실행용 full command를 다시 분리한다.

계약과 validator 수가 많다는 사실이 실제 demo가 작동한다는 뜻은 아니다. 최신 AutoDex·ParaDex upstream, CTMP와 cuRobo의 역할, RTX 3090 evidence, Pepsi 71-waypoint event request를 다시 대조했다. 가장 큰 단절은 30 Hz IK display sample을 매 frame rest-to-rest controller waypoint로 해석한 것이며, 이를 resident catalog로 승격하지 못하도록 먼저 차단했다.

현재 효력: source 2200243는 resident template materialization 전에 exact piecewise-quintic joint position·velocity·acceleration·jerk extrema를 다시 계산하고 실패 source를 거부한다. RTX 3090 고정 planning venv에서 전체 858 tests가 통과했고 14 tests는 optional dependency 조건으로 skip됐다. 이 변경은 잘못된 command 승격을 막을 뿐, Pepsi 실행 command를 새로 만들지는 않는다.

AutoDex에서 채택할 것과 채택하지 않을 것

AutoDex 논문은 generator를 교체 가능하게 두고, collision-monitored execution과 lift/hold physical label을 거친 database를 downstream retrieval·feasibility filtering에 제공한다. 따라서 BeltBench는 exact object·stable pose·hand에 맞는 validated grasp를 우선 retrieval하고, 없으면 BODex 등으로 생성한 뒤 같은 독립 gate를 적용한다. AutoDex 자체를 moving conveyor planner로 취급하지 않는다. 근거는 AutoDex paper와 최신 implementation source다.

실제 Pepsi artifact에서 발견한 실행 단절

  • Event request는 71 waypoints, 10.0초이며 hand close start 4.1초, first contact 4.4초, attach 4.6초, release open 7.2초, detach 7.233초를 선언한다.
  • Arm velocity는 71/71 waypoint가 전부 0, arm acceleration도 71/71 전부 0, hand velocity도 71/71 전부 0이다.
  • Contact waypoint 56과 57의 timestamp는 출력상 모두 4.4초지만 실제 차이는 8.881784197e-16 s다. Strictly increasing check를 통과하면서 interpolation derivative를 폭발시키는 numerical duplicate다.
  • Root cause는 compile_playback_event_trajectory()가 source waypoint마다 _zero_motion_target()을 사용하고 “preserve rest-to-rest quintics”를 명시한 데 있다. 이 compiler는 reference playback용이지 execution retimer가 아니다.
  • 중복 contact 하나를 제거하고 clamped C2 cubic spline으로 derivative를 복원해도 arm velocity ratio 최대 5.764, acceleration 12.706, jerk 63.429, hand velocity 39.532, acceleration 97.617, jerk 497.114였다.
  • 따라서 zero derivative만 중앙차분이나 spline으로 채우는 수선은 타당하지 않다. Semantic event timing, continuous arm path, hand closure schedule을 함께 최적화해야 한다.
  • 현재 reference는 contact 전에는 robot이 object와 같은 twist를 가져야 한다는 moving-contact gate도 통과하지 않는다. Zero arm velocity contact를 시각적으로 그럴듯한 grasp로 승격하면 안 된다.

수정한 fail-closed 경계

compile_resident_event_command_template()가 source identity를 확인한 직후 assess_piecewise_quintic_kinematics()를 실행한다. Continuous polynomial extrema에서 joint position, velocity, acceleration 또는 jerk failure가 하나라도 나오면 template sample을 만들기 전에 exact failure ID와 함께 중단한다. Load-time semantic verification도 같은 compiler를 재실행하므로, 과거에 생성된 template이 source mutation이나 새 limit에서 조용히 통과하지 않는다.

이 gate는 경로를 고치지 않는다. 자동 time scaling, failed sample 삭제, limit 확대, cuRobo 실패 시 CPU fallback도 하지 않는다. 실행용 producer가 별도로 accepted q/qd/qdd를 만들어야 한다.

현실적인 실시간 구조

새 ADR은 offline catalog compiler, bounded online inference, independent validation, controller lease, same-command MuJoCo/Viser의 다섯 경계를 고정한다. FoundPose는 초기 pose 후보, GoTrack 또는 대체 tracker는 temporal update로 둔다. Object는 calibration된 belt frame에서 initial yaw를 유지하고 +x 평행이동만 한다. Online hot path는 analytic prediction, resident maximin query, optional fixed-shape cuRobo arm-prefix solve, three lifecycle collision passes와 immutable handoff다.

RTX 3090에서 현재 확인한 atlas query p99 116.440 µs, static collision batch-8 p99 1.449 ms, world-only prefix p99 29.789 ms, high-resolution validator p99 14.076 ms는 component evidence다. Perception, all collision passes, host/device synchronization, cancellation, selection, controller serialization을 한 deadline trace로 측정하지 않았으므로 “실시간 pipeline”이라고 결론내릴 수 없다.

Conveyor CTMP 연구는 먼 거리의 noisy estimate를 기다린 뒤 home에서 전 경로를 시작하는 대신, bounded 초기 경로를 먼저 실행하고 perception update로 제한된 replanning을 수행한다. BeltBench도 trial 시작 전에 certified ready/staging pose로 이동하고 hand-close cutoff 이전에만 prefix를 갱신한다. 근거: Provably Constant-time Planning and Replanning for Conveyor Grasping. cuRobo는 GPU FK/IK, seeded trajectory optimization과 sphere trajectory collision에 사용한다. 근거: cuRobo API, trajectory optimization, collision representation.

검증 결과

  • Targeted resident-template tests: 6/6 통과.
  • 전체 suite: Ran 858 tests in 21.382s, OK (skipped=14).
  • Gate 적용 전 실제 Pepsi event request는 analytic dynamics assessment에서 모든 arm joint와 모든 hand command joint가 velocity·acceleration·jerk failure를 보였다.
  • Actual command, cuRobo full-task solve, segmented collision lease, MuJoCo measured replay와 hardware 실행은 생성하거나 성공했다고 표시하지 않았다.

다음 구현 순서

  1. Dense IK frame을 stop으로 쓰지 않는 derivative-aware moving-pick producer를 만든다. First contact의 object-relative pose와 linear/angular twist, contact-to-attach chase를 hard gate로 둔다.
  2. Attach 이후 transfer-above-bin, stationary release/open, ballistic detach, retreat/home suffix를 actual cuRobo output으로 생성한다. Hand closure는 arm prefix와 분리해 end-effector limits 아래 동기화한다.
  3. Exact combined tensor에 world/self/connector, pre-attach moving object, post-attach object, release-envelope collision과 full dynamics를 적용한다.
  4. Nominal뿐 아니라 correction cell을 같은 source와 acceptance gate로 생성하고 p50/p95/p99, deadline miss, cancellation을 한 trace에서 측정한다.
  5. 통과한 exact tensor 하나를 MuJoCo에 실행해 measured state/contact를 기록하고, 그 measured replay를 Viser 1.0x auto-loop에 표시한다.
