ISSUE-076 · 2026-08-14 · wall-clock Viser capture and planning boundary

Headless RTX 서버에서 actual-time planning 영상을 확보하되, 통과하지 않은 궤적을 성공 demo로 포장하지 않는다.

Isaac D1 perception 영상은 이미 확보했지만 planning geometry를 설명할 Viser 화면은 browser의 software WebGL 경고와 headless capture 지연 때문에 발표용 MP4로 닫히지 않았다. Private Xvfb와 headed Chrome을 wall-clock으로 녹화하고 frame·RTF·화면을 독립 검증하는 도구를 추가했다. 동시에 현재 moving-pick prefix가 robust execution gate에서 탈락한다는 사실을 영상과 기록에 그대로 남겼다.

현재 판정: capture tooling은 source beltbench@2e5486a에서 검증했다. 최종 planning diagnostic은 1920×1080, 15 fps, 6.0초, 90/90 unique frame, capture RTF 0.969로 통과했다. 그러나 이 영상은 Execution: blocked인 D2 planned prefix다. D1 perception과 causal join되지 않았고 robust clearance, measured latency, dynamic cuRobo parity와 full suffix도 통과하지 않았으므로 실제 grasp 성공 영상이 아니다.

문제와 영향

  • RTX workstation에는 재사용 가능한 desktop capture session이 없었고 system Xvfb도 설치돼 있지 않았다.
  • Chrome software WebGL 경고 toast가 scene 위에 남아 발표 화면을 가렸다.
  • WebGL canvas를 CDP나 JavaScript로 frame 단위 추출하면 browser animation보다 capture가 느려져 actual-time 주장을 할 수 없었다.
  • 수치상 MP4가 생성돼도 첫 frame이 warning이거나 빈 toast shell이 남는 경우가 있어 자동 수치 검증만으로 품질을 승인할 수 없었다.
  • D1 perception과 D2 planning을 이어 붙이면 실제로 연결되지 않은 두 evidence를 closed loop처럼 오해시킬 위험이 있었다.

입력 planning의 실제 상태

moving-pick-prefix-v6는 121 frame, 2.0초의 approach 60 → chase 30 → close 30 → attach 1 구간이다. 실제 xArm, Inspire Left, 두 connector CAD, upside-down Pepsi, conveyor, mounting table과 drop bin을 Viser에서 1.0× auto-loop한다. 저장된 playback을 읽을 뿐 viewer가 IK, collision 또는 grasp를 다시 계산하지 않는다.

최신 nominal planner에서 후보별 IK와 nominal robot/workcell/object 검사는 통과할 수 있었지만 최종 선택은 비어 있었다. 대표 후보의 nominal nonintentional margin은 0.844 mm인데 pose uncertainty inflation은 6.195 mm였고 robust collision slack은 -5.351 mm였다. Grasp evidence와 pipeline p95 latency도 아직 승인되지 않았다. 이 결과는 software failure가 아니라 현재 uncertainty 아래에서 실행을 차단해야 한다는 올바른 판정이다.

해결 절차

  1. 격리 display: system package를 변경하지 않고 Xvfb package를 project-local tool directory에 풀어 private display를 시작한다. TCP listen은 비활성화한다.
  2. 실제 browser clock: Headless frame API 대신 headed Chrome kiosk를 그 display에 띄우고 Viser의 Play/Loop wall-clock을 그대로 실행한다.
  3. 명시적 readiness: Connected, Robot:, Playback text와 canvas가 모두 나타난 뒤 settle 시간을 기다린다.
  4. Rendered text 판정: Light DOM과 open shadow root의 text node를 순회하고 Range.getBoundingClientRect(), display, visibility, opacity로 실제 렌더링 여부만 판단한다.
  5. 제한된 overlay 제거: 고유 warning token에서 화면 좌상단의 제한된 크기 container만 찾고 직접 display:none!important을 적용한다. 100 ms hider를 유지하고 capture 전에 visible text가 0인지 다시 검사한다.
  6. Wall-clock capture: ffmpeg x11grab로 지정 해상도·fps·duration을 녹화한다. Browser screenshot, canvas readback 또는 frame-by-frame fallback은 두지 않는다.
  7. Fail-closed acceptance: ffprobe dimensions/frame/duration, capture wall RTF와 framemd5 unique fraction 중 하나라도 기준을 벗어나면 최종 파일을 publish하지 않는다.
  8. Source 결속: MP4 SHA-256뿐 아니라 실행 중 변하지 않은 capture script SHA와 실제 Chrome/ffmpeg/ffprobe/Xvfb path를 JSON report에 기록한다. MP4와 report는 staging에서 모두 완성한 뒤 publish한다.
  9. 사람 검수: 자동 통과 뒤 contact sheet를 확인해 warning, loading frame, 빈 toast shell, asset 누락과 잘못된 camera view가 없는지 별도 판정한다.

교수님께 보여 줄 순서

  1. D1 perception: 실제 Isaac RGB-D/mask, FoundPose yaw acquisition, CAD correction과 60 Hz encoder propagation이 측정 시간으로 동작함을 보여 준다.
  2. D2 planning diagnostic: 실제 asset과 conveyor intercept geometry, approach/chase/close/attach 모듈 경계를 설명한다. 화면의 Execution: blocked를 숨기지 않는다.
  3. Gap 설명: 두 영상은 아직 causal join되지 않았으며 current path는 robust margin과 dynamic cuRobo gate를 통과하지 않았다고 명시한다.

다음 승격 조건

  1. D1 fused track을 같은 generation의 resident atlas/path-family query 입력으로 결속한다.
  2. Pose uncertainty보다 큰 실제 clearance를 갖는 grasp/path를 다시 생성하고 measured pipeline p95를 채운다. 기준을 낮춰 현재 후보를 통과시키지 않는다.
  3. 같은 exact command에 대해 dynamic-object cuRobo representation parity와 hot-path deadline을 통과시킨다.
  4. Future-start lease, controller acceptance, contact/attach/transport/release/bin containment와 abort를 한 source-closed Isaac trial로 측정한다.
  5. 그 뒤에만 perception부터 grasp/drop까지 한 영상에 통합하고 성공 demo로 표기한다.
