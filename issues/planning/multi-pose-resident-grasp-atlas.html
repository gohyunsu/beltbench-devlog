ISSUE-104 · 2026-08-28 · multi-pose resident grasp atlas

Shared grasp는 offline source로 사용하고, runtime에는 검증된 pose×yaw×시간 atlas만 상주시킨다.

Table pose를 사용자가 지정하지 않는 conveyor runtime을 위해 두 stable-pose 후보의 grasp를 같은 robot·workcell·timing gate로 다시 평가했다. 실시간 경로는 원격 저장소를 검색하지 않는다. Startup에 검증한 bounded atlas를 메모리에 올리고, RGB가 판별한 stable-pose class·belt-frame 위치·초기 yaw와 uncertainty로 후보를 조회한다.

현재 판정: 진단용 resident atlas의 RTX lookup은 10,000회 모두 0.36 ms 이하였다. 그러나 BeltBench 52e2048의 onboarding readiness 감사에서는 세 stable pose 모두 deployment atlas 컴파일 자격이 없었다. Shared archive의 96개 평가는 offline worklist로 재사용하지만, 88개 geometry-clear 후보 중 승인된 drop_release capability가 있는 grasp는 0개다. 따라서 현재 atlas는 lookup 구조와 latency를 검증하는 diagnostic이며 perception 또는 robot execution 권한이 아니다.

문제와 영향

이전 단일 pose 가정은 실제 RGB 입력에서 물체가 어느 안정 자세로 놓였는지 알 수 없다는 조건을 다루지 못했다. 반대로 event마다 shared data를 순회하거나 grasp를 새로 생성하면 latency가 비결정적이고 source ancestry도 흔들린다. 따라서 expensive evaluation을 offline으로 옮기고 online 작업량을 고정해야 한다.

Yaw coverage 진단

source-002 baseline은 30°와 60° context 사이 공통 grasp가 없었다. 두 집합을 합치는 대신 45° midpoint를 추가했다. 10,000회 uncertainty-aware query의 non-empty 결과는 9,114회에서 9,894회로 개선됐다. 평균 lookup은 0.181 ms, p99는 0.300 ms였다.

남은 106회는 lookup latency가 아니라 측정 yaw의 3σ support를 함께 만족하는 grasp가 없는 coverage 실패다. 현재는 no-pick으로 처리하며, 인접 yaw를 더 평가하거나 해당 stable pose의 grasp를 추가 생성하는 방법으로만 개선한다.

Table pose가 주어지지 않는 조건

여기서 임의 table pose는 모든 6-DoF 자세가 아니라 offline settling과 perception qualification으로 승인된 유한 stable-pose class 중 하나를 뜻한다. Runtime 입력은 object ID와 RGB frame이다. Backend가 stable-pose hypothesis, belt-frame x/y, yaw와 uncertainty를 산출하고, constant-orientation conveyor predictor가 intercept 위치를 계산한다.

Stable-pose class를 외부에서 지정할 필요는 없지만 RGB가 class를 안정적으로 판별했다는 qualification은 필요하다. 알려지지 않은 자세나 모호한 관측을 가장 가까운 class로 강제 배정하지 않는다.

2026-08-28 · Fresh-frame confirmation 연결

c270fee에서 stable pose가 한 frame만으로 latch되지 않는 경우를 공통 causal sensor runtime에 연결했다. 첫 fit이 통과했지만 confirmation 수가 부족하면 provider를 계속 poll하지 않고 현재 single-flight slot을 해제한다. 다음의 더 새로운 synchronized RGB generation을 다시 segmentation·pose fit에 사용하며, confirmation generation과 실패 retry를 별도로 기록한다.

기존 Isaac admitted-event runner는 RGB 전에 단일 command를 고정하는 baseline임을 명시했다. 따라서 여기에 pose별 조건문을 추가하지 않는다. 최신 protocol은 pose latch 후 resident atlas/path family를 고르고, 현재 x/y/yaw와 deadline에 맞춘 exact GPU command가 독립 validation을 통과한 뒤에만 simulation execution을 결속한다.

  • 관련 causal sensor·multi-pose·runner 회귀: 42 passed.
  • RTX workstation 전체 suite: 1,771 passed, 15 skipped, 92 subtests passed.
  • Unknown/open-set, nonmonotonic generation, pose routing mismatch는 계속 terminal no-pick이다.
  1. Simulation RGB worker·open-set calibrator를 실제 stable-pose deployment artifact로 만들고 class·x/y·yaw·covariance를 qualification한다.
  2. Unknown pose·모호한 yaw·가림을 포함한 synthetic holdout을 통과시킨다.
  3. Resident selection 이후 exact cuRobo command lease와 Isaac Sim camera/control loop를 actual-time trace로 결속한다.

2026-08-28 · Grasp onboarding readiness 재감사

“NAS에 grasp 파일이 있다”와 “event-time에 실행할 수 있다”를 기계적으로 분리했다. 새 readiness compiler는 각 stable pose의 transitive source chain, measured support pose, 승인된 intrinsic protocol, 요구 capability를 실패 없이 통과한 grasp가 모두 존재할 때만 deployment atlas 컴파일을 허용한다. NAS 경로 검색과 online grasp generation은 runtime 계약에서 명시적으로 금지한다.

세 source chain은 모두 digest 검증을 통과했지만 stable pose와 validation protocol이 모두 provisional이었다. Geometry-clear는 endpoint 진단일 뿐, moving interception·retention·transfer·release까지 통과했다는 뜻이 아니다. 기존 후보를 폐기하거나 처음부터 다시 생성하지 않고, 96개를 pose별 qualification worklist로 사용한다. 해당 pose에서 끝까지 살아남는 후보가 없을 때만 offline generator를 호출한다.

실시간 데이터 흐름

  1. Offline provider: Shared AutoDex/ParaDex/BODex 후보를 content-addressed snapshot으로 읽고 pose·hand·frame ancestry를 확인한다.
  2. Offline qualification: 승인된 stable-pose별로 grasp, guarded approach, moving retention, transfer와 drop_release를 독립 검증한다.
  3. Deployment compile: 통과한 bounded subset만 pose×yaw×intercept-time path family로 컴파일한다.
  4. Startup: bundle digest와 지원 pose coverage를 검증한 뒤 local NVMe와 GPU memory에 immutable slot으로 적재한다.
  5. Online: RGB가 stable-pose class와 belt-frame x/y/yaw를 추정하면 exact pose key로 O(1) 조회한다. NAS I/O나 grasp 생성은 수행하지 않는다.

사용자가 table pose를 주지 않는 것은 맞다. 다만 “임의 pose”는 unconstrained 6-DoF가 아니라 벨트 위에서 안정적으로 지지되는 승인된 유한 pose class 중 하나다. RGB가 class를 구분하지 못하거나 그 class에 qualified slot이 없으면 nearest-pose fallback 없이 no-pick한다.
