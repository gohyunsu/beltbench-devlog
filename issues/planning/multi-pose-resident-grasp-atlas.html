ISSUE-104 · 2026-08-28 · multi-pose resident grasp atlas

Shared grasp는 offline source로 사용하고, runtime에는 검증된 pose×yaw×시간 atlas만 상주시킨다.

Table pose를 사용자가 지정하지 않는 conveyor runtime을 위해 두 stable-pose 후보의 grasp를 같은 robot·workcell·timing gate로 다시 평가했다. 실시간 경로는 원격 저장소를 검색하지 않는다. Startup에 검증한 bounded atlas를 메모리에 올리고, RGB가 판별한 stable-pose class·belt-frame 위치·초기 yaw와 uncertainty로 후보를 조회한다.

현재 판정: BeltBench 9819954와 096ac17에서 source-closed pose context와 resident atlas를 구현했다. RTX 3090의 10,000회 lookup은 모두 0.36 ms 이하였다. 다만 한 pose의 adaptive yaw coverage는 9,894/10,000이므로 남은 구간은 fallback 없이 no-pick으로 닫는다. Stable-pose perception과 moving grasp capability 검증 전까지 실행 권한은 없다.

문제와 영향

이전 단일 pose 가정은 실제 RGB 입력에서 물체가 어느 안정 자세로 놓였는지 알 수 없다는 조건을 다루지 못했다. 반대로 event마다 shared data를 순회하거나 grasp를 새로 생성하면 latency가 비결정적이고 source ancestry도 흔들린다. 따라서 expensive evaluation을 offline으로 옮기고 online 작업량을 고정해야 한다.

주요 탈락 원인은 pregrasp IK였고 일부 후보는 clearance 또는 object collision에서 탈락했다. 두 pose 모두 같은 threshold를 사용했으며 결과에 맞춰 기준을 완화하지 않았다.

Yaw coverage 진단

source-002 baseline은 30°와 60° context 사이 공통 grasp가 없었다. 두 집합을 합치는 대신 45° midpoint를 추가했다. 10,000회 uncertainty-aware query의 non-empty 결과는 9,114회에서 9,894회로 개선됐다. 평균 lookup은 0.181 ms, p99는 0.300 ms였다.

남은 106회는 lookup latency가 아니라 측정 yaw의 3σ support를 함께 만족하는 grasp가 없는 coverage 실패다. 현재는 no-pick으로 처리하며, 인접 yaw를 더 평가하거나 해당 stable pose의 grasp를 추가 생성하는 방법으로만 개선한다.

Table pose가 주어지지 않는 조건

여기서 임의 table pose는 모든 6-DoF 자세가 아니라 offline settling과 perception qualification으로 승인된 유한 stable-pose class 중 하나를 뜻한다. Runtime 입력은 object ID와 RGB frame이다. Backend가 stable-pose hypothesis, belt-frame x/y, yaw와 uncertainty를 산출하고, constant-orientation conveyor predictor가 intercept 위치를 계산한다.

Stable-pose class를 외부에서 지정할 필요는 없지만 RGB가 class를 안정적으로 판별했다는 qualification은 필요하다. 알려지지 않은 자세나 모호한 관측을 가장 가까운 class로 강제 배정하지 않는다.

검증과 다음 작업

  • Pose-context compiler·atlas·fallback 관련 테스트 62/62 통과.
  • RTX workstation 전체 suite: 1,768 passed, 15 skipped, 92 subtests passed.
  • 현재 stable-pose campaign, open-set RGB qualification, retention·moving-contact capability가 승인되지 않아 production deployment는 만들지 않았다.
  1. Simulation RGB sensor의 stable-pose class·x/y·yaw·covariance 출력을 현재 runtime contract에 연결한다.
  2. Unknown pose·모호한 yaw·가림을 포함한 synthetic perception qualification을 수행한다.
  3. Resident selection 이후 cuRobo exact planning과 Isaac Sim camera/control loop를 actual-time trace로 결속한다.
