ISSUE-107 · 2026-08-30 · physics-time no-pick replay

실패한 RGB pose를 성공 애니메이션으로 바꾸지 않고, planner 앞에서 멈춘다.

Banana source-001의 두 Isaac RGB frame, YOLOE proposal, FoundPose planar retry와 pose admission을 한 물리시간 축에 재생했다. 최신 frame 재시도로 개별 측정은 회복됐지만 고정된 전체 pose 품질 기준이 실패했으므로 pose를 publish하지 않았고 atlas·planner·robot command도 호출하지 않았다.

120 frames · 30 fps · 1280×720 · 4.0 s · simulation time scale 1.0×

문제원인해결과 결과
Retry report가 선택 결과만 남겨 전체 시간을 재현할 수 없음실패 후 버려진 attempt의 stage duration이 schema에 없었음64e97e9에서 schema 1.2로 모든 실제 소비 attempt의 YOLOE·FoundPose 시간을 보존하고 합계·순서를 검증했다.
개별 pose measurement 수락이 component 승인처럼 보일 수 있음Provider measurement quality와 corpus-level pose qualification이 다른 gate임Diagnostic admission 계약을 별도로 만들고 production runtime admission은 수정하지 않았다. Component 불합격이면 pose publish부터 command까지 모두 false다.
두 번째 frame이 첫 attempt 완료 전에 도착함Generation 319는 100.000 ms에 도착하지만 capacity-one worker는 127.473 ms까지 사용 중임Arrival과 processing index를 분리했다. 최신 generation을 하나만 보존하고 worker가 빈 즉시 처리한다.
단계 텍스트만으로 상태 전환을 읽기 어려움Sensor, proposal, pose, admission과 planner가 같은 표현을 사용함RGB·YOLOE·FoundPose를 서로 다른 색으로 표시하고 pose admission 실패는 빨강, 미실행 atlas·planner는 회색으로 유지했다.
단계가 늘어나 planner row가 화면 밖으로 밀림고정 row spacing이 7단계 history를 수용하지 못함a0e8e9d에서 사용 가능한 panel 높이에 맞춰 간격을 계산한다. 최종 contact sheet에서 planner row까지 확인했다.

렌더는 clean revision a0e8e9d에서 수행했다. Source MP4는 120/120 frame, 30 fps, 4.000 s이며 render report의 source revision·trace SHA·capture SHA와 독립 계산한 해시가 일치한다. 위 player는 브라우저 호환성을 위해 같은 120 frame을 H.264로 재인코딩한 presentation derivative이며 판단 근거가 아니다.

다음 경계

  1. 동일 queue와 typed admission을 저장 frame replay가 아닌 하나의 live Isaac sensor process에 연결해 camera capture, YOLOE와 FoundPose의 wall-clock contention을 측정한다.
  2. 현재 열린 120 sample의 threshold를 조정하지 않는다. 별도 미개봉 위치·yaw corpus에서 pose component가 승인되어야만 encoder state와 resident atlas query를 실행한다.
  3. Atlas가 지원하는 60–210° yaw에서만 grasp를 반환하고 나머지는 명시적 no-pick으로 유지한다. Nearest-yaw 또는 Pepsi fallback은 금지한다.
  4. Positive banana 영상은 pose 승인 뒤 exact selected pose→encoder propagation→atlas→planning→physics grasp가 한 orchestration core에서 실제로 실행될 때만 생성한다.

RGB FoundPose qualification과 source-001 pick atlas가 앞뒤 권한 경계를 설명한다.
