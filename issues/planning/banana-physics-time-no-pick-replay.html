ISSUE-107 · 2026-08-30 update · live RGB no-pick integration

저장된 추론 시간 재생을 넘어 실제 Isaac RGB와 GPU inference를 한 시간축에서 구동한다.

Banana source-001의 두 Isaac RGB를 60 Hz physics loop에서 읽고 resident YOLOE와 FoundPose를 실제로 실행했다. 개별 pose estimate는 수락됐지만 사전 고정된 component-level pose qualification이 실패했으므로 pose publish, atlas, planner와 command를 모두 차단했다. 이 영상은 live perception 통합 증거이지만 positive grasp demo는 아니다.

왜 다른 물체로 바꾸지 않았나

NAS 후보를 다시 대조해도 banana/source-001보다 먼저 시도할 비대칭 target-hand 물체는 없었다. Banana만 Inspire Left 성공 prior 7개, 명확한 stable-pose mapping, watertight symmetry=none mesh, 독립 screening을 통과한 xArm6/Inspire grasp 1개와 FoundPose representation을 함께 갖는다. blue_vase는 차순위지만 non-watertight contact surface를 먼저 교체하거나 검증해야 한다. pepsi_light는 positive full-task 기준선으로 유지하되 비대칭 일반화 근거로 사용하지 않는다.

문제원인해결과 결과
Retry report가 선택 결과만 남겨 전체 시간을 재현할 수 없음실패 후 버려진 attempt의 stage duration이 schema에 없었음64e97e9에서 schema 1.2로 모든 실제 소비 attempt의 YOLOE·FoundPose 시간을 보존하고 합계·순서를 검증했다.
개별 pose measurement 수락이 component 승인처럼 보일 수 있음Provider measurement quality와 corpus-level pose qualification이 다른 gate임Diagnostic admission 계약을 별도로 만들고 production runtime admission은 수정하지 않았다. Component 불합격이면 pose publish부터 command까지 모두 false다.
두 번째 frame이 첫 attempt 완료 전에 도착함Generation 319는 100.000 ms에 도착하지만 capacity-one worker는 127.473 ms까지 사용 중임Arrival과 processing index를 분리했다. 최신 generation을 하나만 보존하고 worker가 빈 즉시 처리한다.
단계 텍스트만으로 상태 전환을 읽기 어려움Sensor, proposal, pose, admission과 planner가 같은 표현을 사용함RGB·YOLOE·FoundPose를 서로 다른 색으로 표시하고 pose admission 실패는 빨강, 미실행 atlas·planner는 회색으로 유지했다.
단계가 늘어나 planner row가 화면 밖으로 밀림고정 row spacing이 7단계 history를 수용하지 못함a0e8e9d에서 사용 가능한 panel 높이에 맞춰 간격을 계산한다. 최종 contact sheet에서 planner row까지 확인했다.
첫 live run이 Isaac 시작 전에 실패YOLOE overlay에 독립 Python이 있다고 가정했고 FoundPose adapter가 덧붙이는 representation 상대경로도 중복 지정함FoundPose CUDA 환경을 공통 base Python으로 명시하고 representation root를 dataset asset root로 수정했다. 실패 artifact는 삭제하지 않았다.
두 번째 live run이 20 ms segmentation deadline에서 종료격리 benchmark 예산을 Isaac renderer와 FoundPose가 함께 쓰는 통합 GPU에 그대로 적용했고 timeout이 process exception으로 전파됨전체 950 ms acquisition budget은 유지하면서 segmentation 50 ms, FoundPose 770 ms로 재배분했다. Timeout은 terminal runtime fault로 기록하고 control loop와 failure video는 끝까지 보존한다.
개별 pose 수락 뒤 planner가 실행될 위험Measurement gate와 frozen component qualification이 서로 다른 권한임b36998a live run에서 event estimate는 보존하되 publication을 차단했고 selector 호출 0회를 trace로 확인했다.

다음 경계

  1. 한 번의 21.740 ms segmentation을 분포로 과장하지 않는다. 고정한 별도 위치·yaw corpus에서 live YOLOE와 FoundPose latency·정확도·deadline miss를 함께 측정한다.
  2. 현재 열린 120 sample에 threshold를 맞추지 않는다. 별도 미개봉 위치·yaw corpus에서 pose component가 승인되어야만 encoder state와 resident atlas query를 실행한다.
  3. Atlas가 지원하는 60–210° yaw에서만 banana grasp를 반환하고 나머지는 명시적 no-pick으로 유지한다. Nearest-yaw 또는 Pepsi fallback은 금지한다.
  4. 교수님께는 현재 revision으로 다시 source-close한 pepsi_light positive sensor-to-drop 영상과 이 banana live no-pick 영상을 한 쌍으로 제시한다.

RGB FoundPose qualification과 source-001 pick atlas가 앞뒤 권한 경계를 설명한다.
