ISSUE-072 · 2026-08-13 · perception-to-runtime evidence boundary

Camera capture부터 runtime command까지 하나의 검증된 시간축으로 연결한다.

기존 Viser의 3.3초 upstream 구간은 물체가 belt 상류에서 들어오는 모습을 설명하지만 실제 perception이 실행됐다는 증거는 아니었다. 반대로 runtime session은 exact fused track 이후의 planning과 handoff를 기록하지만 capture 이전 구간을 소유하지 않았다. 두 경로가 서로 배타적이어서 하나의 애니메이션으로 이어 붙여도 capture→planning→command 인과관계를 증명할 수 없었다. 이번 변경은 measured perception stage DAG, 입력·timing provenance, exact fused track, runtime receipt와 event trajectory의 semantic join을 분리된 계약으로 추가했다.

현재 판정: source-closed replay를 만들 수 있는 계약과 Viser adapter는 구현됐다. 그러나 실제 multi-camera recording, FoundPose/pose-update timing, activated cuRobo gate와 동일 command의 MuJoCo feedback이 아직 없으므로 현재 8096은 계속 execution-blocked actual-time desired animation이다.

발생한 문제

관찰원인그대로 둘 때의 위험
Precommand lead-in과 runtime replay를 동시에 선택할 수 없었다.전자는 legacy playback의 시각화 budget, 후자는 fused track 이후 causal session으로 서로 다른 clock과 source set을 사용했다.임의 duration을 measured latency처럼 보이게 하거나 실제 runtime 증거를 버리고 예쁜 animation만 남긴다.
Checksummed moving-contact trajectory면 runtime track과 무관해도 viewer가 열릴 수 있었다.각 artifact의 무결성은 확인했지만 prediction의 command-start/contact object pose와 event reference를 교차 검증하지 않았다.서로 다른 object trajectory를 splice해도 개별 checksum은 모두 통과하는 semantic mismatch가 생긴다.
단계 시간을 단순 합산하기 쉬웠다.두 camera의 capture·preprocess·pose backend는 병렬 실행될 수 있는데 선형 stage 목록만 생각했다.실제 end-to-end latency보다 긴 값을 만들거나 병렬 구조의 dependency 오류를 숨긴다.
Measured라는 문자열만으로 timing을 신뢰할 수 있었다.Raw timer source, resolution, input manifest와 stage별 timing basis를 별도 source로 결속하지 않았다.재현할 수 없는 숫자가 실시간성 승인에 사용된다.

Fail-closed 검증 규칙

  1. 모든 stage는 하나의 track_publish ancestor이며 dependency보다 먼저 시작할 수 없다.
  2. Camera마다 정확히 하나의 capture와 acquisition 또는 tracking-update primary pose stage가 있어야 한다.
  3. Fusion camera set, fused track contributing camera set과 input manifest camera set이 같아야 한다.
  4. Measured replay/live mode는 monotonic clock, raw timing measurement와 replay/live input manifest가 없으면 거부한다.
  5. Runtime session은 perception trace와 payload가 완전히 같은 track ID, generation, calibration과 timestamp를 받아야 한다.
  6. Planning receipt는 perception publish보다 빠를 수 없으며 transport latency를 별도로 계산한다.
  7. Runtime prediction은 command start와 moving contact를 모두 포함해야 하고, 두 시점의 object pose가 event reference와 일치해야 한다.
  8. Trace 자체는 측정됐더라도 execution authority를 얻지 않는다. Collision, handoff와 controller gate는 독립적으로 남는다.

시간축 동작

통합 viewer는 recorded camera timestamp를 0으로 옮긴 하나의 display clock을 사용한다. Runtime activation 전에는 첫 arm/hand command를 hold하고, object는 fused track의 constant-orientation conveyor model로 과거 위치까지 해석적으로 전파한다. Runtime command가 활성화되면 검증된 exact event trajectory와 feedback 시간으로 전환한다. Viewer가 sleep을 삽입하거나 독립 duration을 추측하지 않는다.

이 구조는 현재 가정인 “stable tabletop pose는 주어지고 초기 planar position과 yaw는 측정하며, belt 이동 중 yaw는 고정되고 translation만 발생한다”를 그대로 보존한다. FoundPose는 acquisition adapter 후보이고 GoTrack 또는 다른 previous-pose update backend는 별도 adapter 후보다. Released GoTrack에 없는 frame-to-frame optical-flow tracker를 있다고 가정하지 않는다.

구현 중 발견한 추가 결함

처음에는 perception trace와 runtime session이 exact fused track을 공유하면 충분하다고 판단했다. Synthetic negative test에서 runtime prediction과 무관한 moving_contact도 자체 checksum만 맞으면 viewer input에 들어갈 수 있음을 확인했다. 원인은 source integrity와 cross-artifact semantic continuity를 같은 것으로 취급한 것이었다. Projection source track identity, prediction time coverage, command-start/contact object pose equality를 추가해 unrelated contact reference를 명시적으로 거부했다.

교수 시연에서 보여줄 범위

  1. 8096에서 Pepsi upside-down stable pose가 상류에서 들어와 xArm/Inspire가 contact·attach·bin drop·return하는 1.0x desired animation을 보여준다.
  2. 화면을 실제 robot demo라고 부르지 않고 desired reference / execution blocked라고 먼저 명시한다.
  3. Offline grasp/path compilation과 online track→prediction→resident query→GPU gate→handoff를 분리한 architecture를 한 장으로 설명한다.
  4. Measured, provisional, missing evidence 표를 보여주고 현재 perception 3.3초가 budget이며 26.288853초 command와 release 1-frame failure가 실제 상태임을 말한다.
  5. 다음 milestone을 recorded multi-camera input부터 exact track, runtime, cuRobo gate, MuJoCo feedback까지 source-closed한 1.0x replay 한 건으로 제한한다.

남은 gate

  1. Original cadence multi-camera recording과 calibration source를 확보해 acquisition과 tracking-update latency를 별도로 측정한다.
  2. FoundPose/pose-update/fusion adapter가 새 trace contract를 직접 emit하게 하고 p50/p95/p99/max 및 deadline miss를 기록한다.
  3. Pepsi continuous path family의 release 1-frame failure를 수정하고 display용 frame filtering을 제거한다.
  4. Exact xArm/Inspire/object/world resident representation으로 cuRobo parity와 deadline qualification을 통과한다.
  5. 같은 immutable command를 MuJoCo에 입력해 measured robot/object/contact feedback을 만든다.
  6. 위 source가 모두 갖춰진 뒤에만 integrated scenario를 생성한다. 현재 fixture로 가짜 measured scenario를 만들지 않는다.
