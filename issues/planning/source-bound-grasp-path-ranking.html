ISSUE-026 · 2026-08-09 · source-bound robust ranking

Atlas에서 통과한 grasp의 여유를 최종 path 선택까지 잃지 않는다.

AutoDex의 grasp filtering 순서와 BeltBench의 intrinsic, deployment, atlas, path-family gate를 다시 코드 기준으로 감사했다. 각 단계의 hard gate는 분리되어 있었지만, live atlas query가 계산한 grasp별 최악 normalized slack이 projection 이후 사라져 최종 latch·switch·warm-start 순위에는 path와 correction margin만 남는 문제를 발견했다. Trusted projection 계약을 확장하고 전체 순위를 하나의 lexicographic maximin 규칙으로 통일했다.

현재 효력: source commit c820a2a가 구현한다. 이는 bounded diagnostic selection의 무결성을 높인 것이며 continuous path, measured reliability, controller commit 권한을 새로 만들지 않는다.

AutoDex 원본에서 다시 확인한 기준

감사 기준은 willi19/autodex-code:main의 5ada1c077f60bae9af6f27b07619218f58422e50이다. Public AutoDex paper가 설명하는 reusable physical outcome과 로컬 source의 실제 구현을 구분했다.

발견한 문제

현상원인위험
Projector의 bounded truncation은 grasp+path+correction slack을 사용하지만 coordinator는 path+correction만 사용_PreparedProjection의 atlas candidate가 serialized RuntimePathFamilyProjection으로 전달되지 않음서로 다른 grasp의 path가 모두 hard gate를 통과하면 약한 contact·deployment bottleneck이 최종 latch 순위에서 숨겨질 수 있음
Projection artifact에서 최종 grasp ranking 근거를 재현할 수 없음Required atlas context ID만 남고 각 context 교집합의 worst-case margin은 소실왜 한 grasp/path가 다른 후보보다 앞섰는지 event replay에서 설명할 수 없음
기존 schema가 새 의미를 구분하지 못함필수 ranking evidence 추가가 backward-compatible하지 않음이전 request를 새 선택 의미로 잘못 해석할 수 있음

구현한 수정

  • RuntimePathFamilyProjection에 grasp_context_normalized_slacks를 필수로 추가했다. 값은 projector가 live yaw covariance와 intercept horizon으로 질의한 모든 required atlas cell의 grasp별 worst case다.
  • Metric은 정렬된 고유 ID, finite value와 hard-gate slack >= 1을 강제한다. 누락, 중복, threshold 미달은 projection contract에서 거부한다.
  • Resident evaluator는 grasp metric을 grasp_context/... namespace로 보존하고 path validation, live correction vector와 합친다.
  • Candidate truncation, latch, switch hysteresis와 warm-start seed ranking이 모두 합쳐진 벡터를 worst-to-best로 정렬한 lexicographic maximin을 사용한다. Weighted sum, provider order, first success는 사용하지 않는다.
  • Projection batch schema를 2.0, runtime request schema를 3.0으로 올렸다. decide_projected의 exact batch/request equality가 source vector mutation과 splicing을 계속 차단한다.

반례로 검증한 선택 변화

두 path가 모두 support, correction과 latch gate를 통과하는 fixture를 만들었다. path-b의 path slack은 1.8로 path-a의 1.2보다 좋지만, path-b grasp의 live atlas bottleneck을 1.05로 두었다. 이전 coordinator라면 path-b를 선택했지만 수정 후에는 combined bottleneck 1.2의 path-a를 선택한다. 이는 grasp quality로 실패를 보상하는 규칙이 아니라, 모든 독립 hard gate를 먼저 통과한 후보 사이에서 가장 약한 실행 여유를 숨기지 않는 규칙이다.

검증 결과

  • Path-family runtime, projection, engine, warm-start 집중 test 45개가 통과했다.
  • Planning 전체 discovery는 새 반례를 포함해 386개 중 383개가 통과했다. 실패 3건은 기존과 동일한 cv2 import 분리다.
  • Calibration 환경에서 OpenCV 의존 test 14개가 모두 통과했다. 중복 import failure를 제외한 실제 고유 통과 수는 397개다.
  • Missing grasp slack, duplicate metric, projection round-trip, exact atlas source vector와 combined maximin 선택을 각각 검사한다.

냉정한 현재 평가

이번 수정은 이미 계산한 독립 grasp evidence를 최종 선택에서 버리는 논리 결함을 제거했다. Dynamic Grasping with Reachability and Motion Awareness의 coarse-to-fine filtering과 previous-plan reuse 원칙에도 부합하지만, 논문의 learned motion quality를 검증 없이 hard gate로 가져오지는 않았다.

Atlas margin은 sampled yaw/horizon context의 worst case이지 continuous-yaw certificate가 아니다. Path margin도 현재 실제 생성된 Pepsi/xArm/Inspire continuous family가 아니라 contract와 reference evidence 단계다. 실제 controller limit, swept collision, calibration, connector metrology, moving-pick reliability와 watchdog가 없으므로 실행 권한은 계속 차단한다.

다음 구현

  1. 같은 combined metric vector를 runtime event/session에 명시적으로 표시해 actual-time Viser에서 선택 bottleneck의 시간 변화를 재생한다.
  2. 실제 sampled task/stop path artifact 생산 경로를 하나의 offline compiler command로 연결하고, sampled 결과를 continuous로 승격하지 않는다.
  3. 가속 backend는 offline mesh oracle과 zero false-accept agreement, p50/p95/p99, deadline miss와 cancellation latency를 기록한 뒤에만 online 후보가 된다.
  4. Controller simulation과 measured reliability gate가 준비되기 전에는 commit adapter를 추가하지 않는다.

Sampled path oracle, AutoDex selection 감사, 실시간 아키텍처에서 앞 단계 근거를 확인할 수 있다.
