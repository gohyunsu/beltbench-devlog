ISSUE-101 · 2026-08-28 · canonical stable-pose binding

보존된 proposal의 pose 별칭을 canonical stable-pose class에 결속한다.

NAS의 512개 Inspire Left proposal을 다시 생성하지 않고 사용하되, provider-facing upside_down 문자열을 runtime atlas key로 직접 사용하지 않는다. Exact source digest와 symmetry-aware class 판정을 별도 artifact로 고정했다.

현재 판정: BeltBench 81c9969에서 proposal snapshot, stable-pose artifact, candidate set과 equivalence policy를 하나의 fail-closed binding contract로 묶었다. 실제 Pepsi Light 결과는 upside_down → source-002이며 binding digest는 122894565449...16c54다. 이는 class ancestry만 닫으며 qualified grasp, runtime 또는 execution 권한은 부여하지 않는다.

문제와 영향

문제왜 위험한가결정
upside_down과 source-002 이름 체계가 분리됨Perception 출력과 grasp atlas key를 문자열 하드코딩으로 연결하면 다른 stable pose가 추가될 때 잘못된 grasp family를 선택할 수 있다.Offline에서만 digest-bound class binding을 만들고 이후 atlas key는 canonical candidate ID를 사용한다.
두 representative transform이 정확히 같지 않음Support yaw와 settling 오차가 포함된 pose를 exact matrix equality로 비교하면 같은 물리적 resting class를 거부한다.기존 settling classifier의 C∞ symmetry quotient를 재사용하고 exact-transform 여부와 높이 차이는 별도 진단값으로 보존한다.
Class match를 실행 승인으로 오인할 수 있음Pose class가 맞아도 contact, retention, robot/workcell, moving-pick 검증은 남는다.provisional_class_binding, runtime_eligible=false, execution_authorized=false를 schema invariant로 고정한다.
NAS lookup이 event path로 유입될 수 있음실제 snapshot 검증은 수 초가 걸려 perception·control deadline과 맞지 않는다.Binding과 qualification은 offline에서 수행하고, runtime은 local NVMe에 stage된 resident atlas만 조회한다.

구현 경계

Builder는 먼저 proposal snapshot의 2,571개 direct evidence를 재검증하고, candidate bundle의 object manifest·mesh digest·source pose catalog를 다시 확인한다. 그 뒤 기존 StablePoseEquivalenceModel로 proposal pose representative를 분류한다. 새로 대충 만든 각도 계산이나 pose 이름 lookup table은 없다.

Artifact는 snapshot closure와 manifest, stable-pose 파일, candidate set, equivalence policy의 digest를 기록한다. 선택된 class, 모든 class 거리, support-height 차이와 exact-transform 여부도 함께 저장한다. Position과 yaw는 이 artifact에서 추론하지 않고 RGB runtime observation이 측정해야 하므로 runtime_yaw_required=true다.

이 경계 이후의 offline screening과 atlas compiler는 source-002를 사용한다. Event acquisition은 object ID만 받고 RGB에서 stable-pose class, planar position과 yaw를 latch한다. 지원되지 않거나 불확실한 class는 no-pick이며 NAS를 검색하거나 open-ended grasp synthesis를 실행하지 않는다.

발생한 문제, 원인과 해결

증상원인해결 및 결과
처음 snapshot digest 확인에서 FileNotFoundErrorManifest 파일명을 snapshot-manifest.json으로 추정했지만 실제 contract는 manifest.json이다.Snapshot root를 먼저 열거해 실제 파일을 확인하고 모든 후속 명령에서 exact path를 사용했다.
Local 기본 Python에서 테스트 import 실패Base 환경에 NumPy가 없고 read-only 세션에서는 기본 temp directory도 만들 수 없었다.기존 beltbench-planning 환경과 쓰기 가능한 test process를 사용했다. 별도 임시 환경이나 중복 dependency를 만들지 않았다.
신규 test fixture 4개가 setup에서 실패공용 candidate staging helper에 넘긴 parent directory를 만들지 않았다.Fixture가 parent를 명시적으로 생성하도록 수정했고 신규 12개 인접 test가 모두 통과했다.
Exact transform은 false같은 upside-down class지만 support yaw가 다르고 높이도 0.1 mm 차이 난다.Matrix equality를 완화하지 않았다. Class equivalence와 exact equality를 분리해 둘 다 기록했다.
