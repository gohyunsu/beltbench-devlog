ISSUE-078 · 2026-08-14 · guarded pregrasp and validated drop playback

접촉 전 guarded approach와 bin-clear transfer를 분리해 301-frame moving pick-and-drop을 통과시킨다.

80 mm pregrasp offset만 늘려서는 마지막 접촉 전 sample의 clearance 모순을 해결할 수 없었다. 접촉 전 근접과 실제 contact를 명시적으로 분리하고, drop-bin wall을 넘는 attached-object sweep를 workcell 수치에서 다시 산출했다. 그 결과 source-closed BODex rank 1 후보의 4.6초 intercept가 301/301 frame sampled HPP-FCL 검증을 통과했고, actual asset Viser playback을 1× wall-clock 영상으로 확보했다.

현재 판정: private MP4는 1920×1080, H.264, 15 fps, 12.0초, 180 frame이며 capture RTF는 0.986349, unique frame fraction은 1.0이다. SHA-256은 a039e735e776fa495354a48ae6ce9c44735e16bf1dcca4618957c310d42a21ce이다. 이 결과는 선택된 planned command가 301-frame sampled validator를 통과했고 1×로 재생됨을 증명한다. selected_execution_candidate는 의도적으로 비어 있으며, causal Isaac perception-to-control trial이나 physics/contact execution을 증명하지 않는다.

문제와 영향

  • 이전 robust path는 마지막 접촉 전 frame에서 intended distal hand geometry와 Pepsi 사이 거리가 약 4.245 mm까지 줄었다. 이 구간에 일반적인 positive uncertainty clearance를 그대로 요구하면 물체에 접근하면서 동시에 물체에서 멀리 떨어져 있으라는 모순이 생긴다.
  • Object-relative pregrasp를 60 mm에서 80 mm로 늘리면 approach 시작점은 멀어지지만 접촉 직전 endpoint는 바뀌지 않는다. Offset만 반복해서 키우는 것은 원인을 고치지 못한다.
  • Guarded approach를 적용한 뒤 coarse moving approach는 통과했지만, 기존 80 mm lift는 attached Pepsi 중심을 bin wall top 아래에 남겼다. Dense validation에서 lift phase 3 frame이 drop-bin-wall-right와 충돌했다.
  • Planning 결과가 통과해도 CPU reference search와 refinement가 약 197초 걸리면 online inference가 아니다. 1× 영상과 real-time planner를 동일한 주장으로 묶으면 안 된다.

직접 원인

Moving-tool schedule은 keyframe 사이 구간을 왼쪽 keyframe의 phase로 기록한다. 따라서 pregrasp → close_above_object Cartesian 이동은 hand가 exact pregrasp command를 유지하더라도 pregrasp phase다. 기존 interaction semantics는 close_above_object만 guarded로 선언했기 때문에 바로 앞 구간의 intended distal geometry가 일반 non-contact clearance를 요구받았다.

Guarded는 collision 예외가 아니다. 선언된 distal contact geometry에 대해서만 접촉 전 positive uncertainty clearance를 면제한다. Signed nominal penetration은 계속 실패하고, contact count와 bounded penetration은 declared first-contact 이후 contacting, attached, releasing state에서만 평가한다. Arm, palm, non-contact finger geometry에는 예외가 없다.

Drop 측 원인은 endpoint IK가 아니라 transfer sweep였다. Object center의 pickup 높이는 0.141052 m, bin wall top은 0.240 m다. 이전 0.080 m lift의 중심 높이는 0.221052 m라 wall top에도 못 미쳤다. 새 0.200 m lift에서 wall 위 가용 envelope는 0.141052 + 0.200 - 0.240 - 0.065 = 0.036052 m다. 필요한 envelope는 최대 pose inflation 0.006390 m, environment clearance 0.001 m, minimum collision slack 0.002 m를 더한 0.009390 m이므로 약 26.7 mm의 잔여가 생긴다.

해결 절차

  1. Source-closed candidate regeneration: 512개 BODex proposal을 exact source와 80 mm object-relative pregrasp 조건으로 다시 screen했다. 46개를 full evaluation하고 43개를 deployment 판단으로 넘겼으며, 30개가 shortlist hard gate에 eligible, 최종 8개가 diversity-aware shortlist에 남았다.
  2. Guarded phase contract: object interaction schema 3의 guarded_hand_proximity_phases에 pregrasp와 close_above_object를 모두 선언했다. Validator regression은 named distal geometry의 nonpenetrating proximity만 통과시키고 nominal penetration과 조기 contact counting은 계속 거부한다.
  3. Bin-clear envelope: drop profile의 lift를 0.080 m에서 0.200 m로 바꿨다. Workcell wall, predicted object z, object sweep radius, covariance inflation과 clearance policy에서 최소 lift envelope를 계산하는 profile regression을 추가했다.
  4. Independent dense validation: portfolio search가 만든 playback을 별도 full-frame HPP-FCL validator로 다시 읽어 301 frame의 robot/workcell, robot/object, object/environment, support와 named contact semantics를 검사했다.
  5. Presentation capture: actual xArm6, Inspire Left, paired connector CAD, upside-down Pepsi, conveyor, robot mounting table과 drop bin을 Viser에서 autoplay/loop로 재생했다. Private Xvfb와 headed Chrome을 사용해 1× wall-clock capture를 독립 검사했다.

실시간성에 대한 냉정한 판정

이번 reference run의 coarse search는 116.497초, 한 candidate의 full-frame refinement는 80.556초였다. 합계 약 197.053초이므로 현재 planner를 camera observation 뒤 online으로 실행하는 것은 불가능하다. 영상이 1×로 움직인다는 사실은 저장된 command의 시간축이 실제 시간과 맞다는 뜻이지, command가 deadline 안에 생성됐다는 뜻이 아니다.

실시간 inference는 이번 결과를 runtime 알고리즘으로 최적화하는 방식이 아니라 역할을 다시 배치해야 한다. BODex generation, intrinsic grasp validation, broad IK/collision search와 yaw/horizon path-family compilation은 offline에서 수행한다. Startup은 source와 resident catalog를 검증하고, online hot path는 fresh fused track, bounded catalog query, 한 번의 fixed-budget correction, cuRobo exact-command collision gate와 controller handoff만 수행해야 한다. HPP-FCL은 offline exact-mesh oracle로 남기고, cuRobo는 같은 command에 대해 false negative 0 parity와 measured p99 deadline을 통과한 경우에만 online authority가 된다.

아직 증명되지 않은 것

  • Intrinsic grasp protocol은 provisional이고 upside-down stable pose는 측정 승인되지 않았다. 따라서 grasp_evidence_valid=false다.
  • Pipeline latency p95 evidence가 없어 latency_evidence_valid=false이며 selected_execution_candidate=null이다.
  • 별도 D1 영상의 Isaac RGB-D/FoundPose perception이 이번 D2 request를 causal하게 생성하지 않았다.
  • Hand closure dynamics, attachment/contact force, controller tracking, release와 bin containment을 Isaac articulation이나 hardware에서 검증하지 않았다.
  • 301-frame sampled check는 continuous swept collision certificate가 아니다.

다음 절차

  1. 이번 selected diagnostic을 complete arm-hand command와 lifecycle로 materialize하고 dynamics/contact schedule gate를 통과시킨다.
  2. 같은 command를 HPP-FCL exact mesh와 cuRobo representation에 입력해 dynamic object parity false negative 0을 만든 뒤 resident CUDA hot-path p95/p99를 측정한다.
  3. Isaac D1 fused generation이 bounded selection request를 실제로 발행하고, accepted command가 simulated controller, contact, attachment와 drop을 수행하는 D1→D2→D3 한 trial을 만든다.
  4. Color-coded stage state와 generation ID를 simulation 화면과 immutable trace에 함께 기록해 perception, planning, validation, control 전환을 causal하게 대조한다.
  5. Measured latency, approved grasp/stable-pose evidence와 simulation contact gate가 모두 닫히기 전에는 execution success 영상으로 부르지 않는다.
