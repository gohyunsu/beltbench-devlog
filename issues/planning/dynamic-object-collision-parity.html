ISSUE-066 · 2026-08-12 · dynamic object collision parity

cuRobo를 채택하되, 정적 collision용 sphere를 움직이는 물체 접촉 권한으로 재사용하지 않는다.

Pepsi moving-pick v6의 2초 prefix를 200 Hz exact event grid로 검사했다. 정적 self/workcell/joint collision은 통과했지만, 움직이는 Pepsi에 대한 두 GPU proxy가 독립 HPP-FCL 메시 oracle의 402개 clear state 중 각각 158개와 130개를 false positive로 거부했다. 문제를 숨기기 위해 contact mask를 넓히지 않고 robot-object representation parity와 robust clearance를 다음 release gate로 분리했다.

현재 결과: source e0b11bf는 shared object timeline, semantic-first time grid, source-bound finite-cylinder contract와 CUDA reduction을 구현한다. HPP-FCL exact mesh는 402/402 sample을 통과했지만 최소 pre-contact policy slack은 0.090922 mm뿐이다. Cylinder GPU diagnostic은 130개 sample을 거부하고 p99 63.210 ms여서 online_collision_authority=false, accepted=false를 유지한다.

시간축 수정

  1. Contact와 attach를 기준으로 source path clock과 exact event request를 정렬했다.
  2. 전체 prefix에서 object rotation이 일정하고 translation velocity가 일정한지 fail-closed 검증했다. 물체는 알려지지 않은 초기 yaw를 유지한 채 belt 방향으로 평행이동한다.
  3. Uniform sample과 semantic event가 1 ps 이내면 uniform 값을 버리고 exact semantic timestamp를 보존했다.
  4. 수정된 2초 grid는 402개 strict-increasing sample, 최대 5 ms 간격이며 극소 duplicate interval이 없다.
  5. Viser playback도 같은 semantic-first builder를 사용해 close start, contact와 attach를 반드시 포함한다.

HPP-FCL 수치의 비판적 해석

402개 exact mesh frame은 모두 현행 draft rule을 통과했다. 그러나 conveyor 상태의 최소 robot-object 거리는 0.590922 mm이고 요구 clearance는 0.5 mm다. 남는 policy slack은 0.090922 mm뿐이다. 이는 calibration, planar pose, yaw, tracking latency, controller tracking과 mesh-model error를 흡수할 수 있는 현실적인 robust margin이 아니다. 따라서 “메시가 통과했다”를 “실행 가능하다”로 승격하지 않는다. Grasp 또는 approach를 다시 생성·순위화해 훨씬 큰 pre-contact clearance를 확보해야 한다.

Contacting/attached 상태의 메시 최소 거리는 1.280587 mm이고 네 개의 허용 finger geometry가 접촉했다. 반면 cylinder GPU는 left_ring_2를 limiting link로 약 1.962 mm 위반했다. 이는 object cylinder만의 문제가 아니라 정적 self/workcell holdout에서 맞춘 robot hand sphere가 close object contact를 표현하는 정확도가 별도로 검증되지 않았음을 보여준다.

채택한 collision 역할

  1. Pinocchio/HPP-FCL은 offline exact-mesh false-negative oracle이다. Online fallback으로 호출하지 않는다.
  2. cuRobo는 online GPU planner와 self/static-world collision backend로 유지한다. 해당 v28 sphere model은 독립 1,522-state holdout에서 이 범위의 parity를 통과했다.
  3. Moving robot-object와 intended contact는 별도 corpus와 geometry backend를 가져야 한다. Static sphere parity를 자동 상속하지 않는다.
  4. Contact geometry는 semantic geometry에서 cuRobo link로 one-to-one mapping될 때만 mask한다. Broad grasp_contact_link_names disable은 사용하지 않는다.
  5. Finite cylinder는 near-cylindrical object에 사용할 수 있는 교체형 candidate backend다. Arbitrary object에는 checksummed mesh, voxel 또는 다른 qualified fixed-shape backend가 필요하다.

실시간 경로 수정

전체 402-state command를 매 perception frame마다 검사하는 구조는 폐기한다. Offline에서 grasp/path family와 exact mesh를 인증하고, runtime에는 resident family의 compact correction, intercept time, IK/trajopt warm start와 robust reduction만 평가한다. Full source-bound command gate는 latch/commit 시 한 번 수행한다. Deadline, freshness, cancellation, controller lease는 host I/O와 결합된 CPU state machine으로 남긴다.

현재 cylinder p99 63.210 ms는 batch 64, synchronized host, no CUDA graph 조건의 전체 command diagnostic이다. 10 ms hot-path 증거가 아니다. 다음 측정은 resident FK/static-world와 object narrow phase를 분리하고, 실제 online correction shape를 fixed CUDA graph로 capture한 뒤 observation-to-lease p99를 측정해야 한다.

다음 순서

  1. Pre-contact robust clearance가 uncertainty budget을 넘는 grasp/approach를 다시 생성하거나 재순위화한다.
  2. Safe, near-boundary, penetration, non-intentional link, intended contact와 attached perturbation을 포함한 HPP-FCL robot-object corpus를 만든다.
  3. Selected GPU geometry를 zero false negative와 false-positive budget으로 검증한다.
  4. Fixed CUDA graph hot path를 구현하고 observation-to-lease p99를 측정한다.
  5. Attach-to-bin, generous-bin release, cutoff stop, abort와 MuJoCo/Isaac exact-command rollout을 연결한다.
