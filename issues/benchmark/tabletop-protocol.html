BENCH-001 · draft

Static tabletop pick → basket place.

This is the first common target for the Modular/AutoDex and VLA tracks. It deliberately removes object motion so that each stack can be debugged and compared before the conveyor introduces timing and prediction.

Task contract

FieldProtocol
Object setTen AutoDex-training “seen” objects; publish IDs, mesh/version, mass, and graspable region.
Initial placementOne predeclared tabletop region, randomized pose within documented bounds.
Terminal successObject is picked, transported, released inside the basket, and remains there after a fixed settle time.
Trials10 independent attempts per object; 100 trials per method/version.
Reset ruleReturn robot to a fixed safe pose and re-place the object after every attempt.

Log schema

trial_id, method, git_commit, object_id, seed,
calibration_id, initial_pose, perception_ms, planning_ms,
execution_ms, predicted_pose, grasp_success, place_success,
recovery_attempts, failure_code, video_path, notes

Metrics

  • Task success ratio: basket placement successes / total trials.
  • Grasp precision: correct stable grasps / attempted grasps.
  • Inference latency: perception and policy/planning time reported separately.
  • End-to-end latency: image acquisition to grasp-command issuance.
  • Recovery: whether a failed attempt makes a local retry rather than resetting unnecessarily.

Dependencies

Requires the completed xArm connectivity record in ISSUE-001, camera calibration from ISSUE-002, and the runnable software stack in ISSUE-003. The moving-belt protocol will extend—not replace—this contract.
